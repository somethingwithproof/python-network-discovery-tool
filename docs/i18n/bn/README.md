hostcensus হলো আপনার পরিচালিত নেটওয়ার্কগুলোতে পুনরাবৃত্তিযোগ্য সার্ভিস ইনভেন্টরি তৈরির জন্য একটি Python CLI। এটি ডিভাইসগুলো কী কী সার্ভিস উন্মুক্ত করছে তা রেকর্ড করে, সময়ের সাথে পর্যবেক্ষণগুলোর তুলনা করে এবং Kadupul ইম্পোর্ট স্ক্রিপ্ট তৈরি করে। ডিফল্ট ব্যাকএন্ড root ছাড়াই asyncio সকেট ব্যবহার করে; ঐচ্ছিক Nmap ডিসকভারি কনফিগার করা সার্ভিস পোর্টগুলোর বাইরের হোস্টগুলোকেও শনাক্ত করতে পারে।

## কেন hostcensus

এককালীন একটি পোর্ট রিপোর্ট এটি ব্যাখ্যা করতে পারে না যে পরবর্তী পর্যবেক্ষণে আসলেই পরিবর্তন হয়েছে নাকি সেটি কেবল ব্যর্থ হয়েছে। hostcensus সুস্পষ্ট সার্ভিস স্টেট, সীমাবদ্ধ প্রোব, পুনরায় ব্যবহারযোগ্য স্ক্যান প্রোফাইল এবং স্থানীয় হিস্ট্রি একত্রিত করে। অপারেটররা একই স্কোপ পুনরাবৃত্তি করতে পারেন, ত্রুটিগুলো পরীক্ষা করতে পারেন এবং অনিশ্চিত পর্যবেক্ষণগুলোকে নিশ্চিত পরিবর্তন থেকে আলাদা করতে পারেন।

- **সার্ভিস প্রমাণ:** SSH শনাক্তকরণ, MySQL গ্রিটিংস, HTTP হেডার, TLS সার্টিফিকেট পর্যবেক্ষণ এবং SNMP ডিসকভারি বা ক্রেডেনশিয়ালযুক্ত system-MIB কুয়েরি।
- **পুনরাবৃত্তিযোগ্য স্কোপ:** নামকরণ করা TOML প্রোফাইল, সংযোজনযোগ্য বর্জন তালিকা, কনফিগারযোগ্য সার্ভিস, হোস্ট/প্রোব সীমা এবং সীমাবদ্ধ ওয়ার্কার।
- **ট্র্যাফিক পাঠানোর আগে পরীক্ষা:** স্থানীয় প্রিফ্লাইট টার্গেট, টুল, গন্তব্যে অ্যাক্সেস, হিস্ট্রি স্কিমা এবং কনফিগার করা TLS CA বান্ডিল যাচাই করে।
- **ইনভেন্টরি হিস্ট্রি:** ট্রানজ্যাকশনাল SQLite স্ন্যাপশট সমস্ত পর্যবেক্ষণ সংরক্ষণ করে; তুলনামূলক বিশ্লেষণে স্ক্যানার ব্যর্থতা এবং অজানা স্টেটগুলো দৃশ্যমান থাকে।
- **আন্তঃক্রিয়াশীল আউটপুট:** টার্মিনাল, JSON এবং CSV রিপোর্ট, সংস্করণযুক্ত ফাইল স্ন্যাপশট এবং Kadupul ইম্পোর্ট স্ক্রিপ্ট।

CI সিস্টেম Linux এবং macOS-এ Python 3.12, 3.13 এবং 3.14 কভার করে, পাশাপাশি একটি নিয়ন্ত্রিত Compose ইন্টিগ্রেশন ল্যাবও অন্তর্ভুক্ত রয়েছে। কোডটি আধুনিক টাইপ এলিয়াস, টাইপকৃত প্রিফ্লাইট ফলাফল, keyword-only slotted প্রোফাইল এবং কাঠামোবদ্ধ async ক্লিনআপ ব্যবহার করে এবং একই সাথে ওই রানটাইম সংস্করণগুলো বজায় রাখে। SemVer সামঞ্জস্য চুক্তি এবং GitHub রিলিজ প্রক্রিয়ার জন্য [সংস্করণ ও রিলিজ](../../../docs/releasing.md) দেখুন। রিলিজ ব্যাজটি চেকআউটের পরিবর্তে প্রকাশিত আর্টিফ্যাক্টগুলোকে নির্দেশ করে: বর্তমানে সর্বশেষ প্রকাশিত ট্যাগ হলো `v0.3.0`, যেখানে এই চেকআউটে প্যাকেজ সংস্করণ `3.0.0` ব্যবহৃত হচ্ছে। এখানে নথিভুক্ত ইনভেন্টরি বৈশিষ্ট্যগুলো ব্যবহার করতে চেকআউট থেকে ইনস্টল করুন।

[ইনস্টলেশন](#install) দিয়ে শুরু করুন, এরপর [প্রোফাইল এবং হিস্ট্রি](#inventory-profiles-preflight-and-local-history) দেখুন। ইন্টিগ্রেশনের বিস্তারিত জানতে [সার্ভিস ফিঙ্গারপ্রিন্ট](#fingerprints), [ফাইল তুলনা](#inventory-diff) এবং [Kadupul এক্সপোর্ট](#kadupul-export) দেখুন।

## ইনস্টলেশন

Python 3.12 বা তার নতুন সংস্করণ প্রয়োজন; Python 3.12–3.14 পরীক্ষিত ম্যাট্রিক্সের অন্তর্ভুক্ত। এই চেকআউট থেকে লক করা রানটাইম ডিপেন্ডেন্সিগুলো ইনস্টল করুন:

```bash
uv sync --locked
uv run hostcensus --help
uv run hostcensus --version
uv run hostcensus preflight 127.0.0.1
uv run hostcensus scan 127.0.0.1 --services ssh -o loopback.json
```

ঐচ্ছিক Nmap হোস্ট ডিসকভারির জন্য আপনার প্ল্যাটফর্মের প্যাকেজ ম্যানেজার ব্যবহার করে Nmap এক্সিকিউটেবল ইনস্টল করুন; কোনো অতিরিক্ত Python প্যাকেজের প্রয়োজন নেই। Nmap-এর XML আউটপুট মূল ডিপেন্ডেন্সি defusedxml দিয়ে পার্স করা হয়, ফলে এনটিটি এক্সপ্যানশন প্রত্যাখ্যাত হয়। hostcensus সরাসরি `PATH`-এ পাওয়া `nmap` চালায় একটি নির্দিষ্ট আর্গুমেন্ট তালিকা, প্রিফিক্স আকারের সাথে বৃদ্ধি পাওয়া সময়সীমা এবং 64 MiB আউটপুট সীমাসহ। ডিফল্ট ব্যাকএন্ডের জন্য Nmap প্রয়োজন হয় না।

## netprobe থেকে মাইগ্রেশন

hostcensus হলো netprobe-এর নতুন নাম, যা 3.0.0 সংস্করণে প্রকাশিত হয়েছে। প্রকল্পটি কখনোই কোনো নামে PyPI-এ প্রকাশিত হয়নি, তাই ইনস্টলেশনগুলো চেকআউট বা GitHub রিলিজ থেকেই করা হয়েছে। GitHub রিপোজিটরিটির নাম অপরিবর্তিত রয়েছে।

| আগে | এখন | সামঞ্জস্যতা |
| --- | --- | --- |
| ডিস্ট্রিবিউশন `netprobe` | `hostcensus` | চেকআউট থেকে পুনরায় ইনস্টল করুন; পুরনো নামে কোনো প্যাকেজ নেই। |
| `netprobe` কমান্ড | `hostcensus` | `netprobe` এখনও চলে এবং stderr-এ একটি অবচয় সতর্কতা লাইন প্রিন্ট করে। এক্সিট কোড এবং stdout অপরিবর্তিত রয়েছে। পরবর্তী মেজর রিলিজে এটি সরিয়ে ফেলা হবে। |
| `NETPROBE_*` এনভায়রনমেন্ট ভ্যারিয়েবল | `HOSTCENSUS_*` | যখন এর সমতুল্য `HOSTCENSUS_*` সেট করা থাকে না, তখন `NETPROBE_*` ভ্যারিয়েবল ব্যবহৃত হয় এবং stderr-এ একটি সতর্কতা দেখায় যেখানে শুধু ভ্যারিয়েবলের নাম থাকে, মান নয়। উভয়ই সেট করা থাকলে `HOSTCENSUS_*` প্রাধান্য পায়। পরবর্তী মেজর রিলিজে এটি সরিয়ে ফেলা হবে। |
| `import netprobe`, `python -m netprobe` | `import hostcensus`, `python -m hostcensus` | **ব্রেকিং পরিবর্তন।** কোনো ইম্পোর্ট শিম ইনস্টল করা নেই; ইম্পোর্টগুলো আপডেট করুন। |
| Docker ইমেজ ট্যাগ `network-discovery:test` (শুধুমাত্র CI) এবং কন্টেইনার ইউজার `netprobe` | `hostcensus:test`, ইউজার `hostcensus` | রেজিস্ট্রিতে কোনো ইমেজ কখনো প্রকাশিত হয়নি। ইমেজটি পুনরায় বিল্ড করুন এবং `hostcensus` এন্ট্রিপয়েন্ট ব্যবহার করুন। |
| `netprobe.toml`, `netprobe-history.sqlite3` | `hostcensus.toml`, `hostcensus-history.sqlite3` | নতুন নামের ফাইলটি না থাকলে, পুরনো ডিফল্ট নামের বিদ্যমান ফাইলটি সতর্কতাসহ এখনও ব্যবহৃত হয়। সুনির্দিষ্ট `--config` এবং `--history` পাথগুলো অপরিবর্তিত থাকে। |
| `"format": "netprobe-report"` বা `"netprobe-snapshot"` এবং `netprobe_version` ফিল্ডসহ রিপোর্ট ও স্ন্যাপশট | `hostcensus-report`, `hostcensus-snapshot`, `hostcensus_version` | `diff` এবং `export` এখনও পুরনো নামে লেখা ফাইল লোড করে, এবং প্রকাশিত JSON স্কিমা উভয় বানানই গ্রহণ করে। নতুন ফাইলগুলোতে নতুন নাম ব্যবহৃত হয়। SQLite হিস্ট্রি ডেটাবেসগুলো অপরিবর্তিত রয়েছে এবং আগের মতোই লোড হয়। |
| `netprobe export` থেকে তৈরি Kadupul স্ক্রিপ্ট | `hostcensus export` থেকে তৈরি স্ক্রিপ্ট | পুরনো স্ক্রিপ্টগুলো কাজ করতে থাকে এবং চলার সময় এখনও `NETPROBE_SNMP_*` পড়ে। নতুন স্ক্রিপ্টগুলো `HOSTCENSUS_SNMP_*` পড়ে। |

## সংক্ষিপ্ত উদাহরণ

Development অনুচ্ছেদে বর্ণিত ইন্টিগ্রেশন ল্যাবের tester কন্টেইনার থেকে চালানো হয়েছে; আউটপুট সংক্ষিপ্ত করা হয়েছে:

```console
$ hostcensus scan 172.30.57.8/29 --services ssh,http,snmp --save-snapshot after.json
┃ IP Address   ┃ Hostname       ┃ SSH ┃ SNMP ┃ MySQL ┃ Open services  ┃ Status ┃
│ 172.30.57.10 │ hostcensus-it-s… │ ✅  │  ❌  │  ❌   │ ssh:22         │ UP     │
│              │                │     │      │       │ OpenSSH_10.0   │        │
│ 172.30.57.13 │ hostcensus-it-w… │ ❌  │  ❌  │  ❌   │ http:80        │ UP     │
│              │                │     │      │       │ nginx/1.28.3   │        │

$ hostcensus diff before.json after.json; echo "exit=$?"
Warning: targets differ: 172.30.57.10 vs 172.30.57.8/29
│ new host │ 172.30.57.13 │ http:80/tcp  │ hostcensus-it-web-1.hostcensus-it_lab   │
exit=3

$ hostcensus export after.json -o kadupul-import.sh --template 1
$ grep 57.13 kadupul-import.sh
add --description=hostcensus-it-web-1.hostcensus-it_lab --ip=172.30.57.13 --template=1 --version=0 --avail=ping --ping_method=tcp --ping_port=80 '--notes=hostcensus: http:80/tcp nginx/1.28.3'
```

## কাঠামো

| মডিউল | দায়িত্ব |
| --- | --- |
| `cli.py` | কমান্ড অপশন, প্রোফাইল রেজোলিউশন, প্রিফ্লাইট, স্ক্যানিং এবং রিপোর্টিং |
| `scanner.py`, `probes.py` | টার্গেট সম্প্রসারণ, সীমাবদ্ধ ওয়ার্কার, হোস্ট ডিসকভারি এবং সার্ভিস পর্যবেক্ষণ |
| `config.py`, `profiles.py` | সার্ভিস সংজ্ঞা এবং যাচাইকৃত ইনভেন্টরি প্রোফাইল |
| `models.py`, `output.py` | ফলাফলের ধরন এবং টার্মিনাল/JSON/CSV রেন্ডারিং |
| `history.py`, `diff.py` | SQLite হিস্ট্রি এবং সংস্করণযুক্ত ফাইল-স্ন্যাপশট তুলনা |
| `preflight.py` | স্থানীয় পরীক্ষা এবং সীমাবদ্ধ Nmap সংস্করণ অনুসন্ধান |
| `export.py` | যাচাইকৃত এবং কোট করা Kadupul ইম্পোর্ট স্ক্রিপ্ট |

প্রতিটি সার্ভিস পর্যবেক্ষণে তার ঘোষিত পরিচয়ের থেকে স্টেট আলাদাভাবে রেকর্ড করা হয়। রিড এবং সময়সীমা সীমাবদ্ধ থাকে; প্রোবের ব্যতিক্রমগুলো হোস্ট ত্রুটিতে সংরক্ষিত হয়। SQLite হিস্ট্রি ট্রানজ্যাকশন, সুস্পষ্ট সংযোগ ক্লিনআপ এবং রিড-অনলি তালিকা ও তুলনার পথ ব্যবহার করে। SNMP সিক্রেটগুলো কেবল এনভায়রনমেন্ট ভ্যারিয়েবল বা সিক্রেট ফাইলের মাধ্যমে প্রবেশ করে; ইনভেন্টরি হিস্ট্রিতে কার্যকর নন-সিক্রেট সেটিংস সংরক্ষিত হয়। স্ক্যান পাইপলাইন, এর সীমা এবং ট্রাস্ট সীমানা সম্পর্কে জানতে [আর্কিটেকচার](../../../docs/architecture.md) এবং অনুমোদিত ব্যবহারের জন্য [SECURITY.md](../../../SECURITY.md#authorized-use) দেখুন।


## ব্যবহারবিধি

শুধুমাত্র আপনার নিজের পরিচালিত নেটওয়ার্কগুলো স্ক্যান করুন।

```bash
hostcensus scan 192.168.1.0/24              # table of alive hosts
hostcensus scan 192.168.1.1 -o results.json # JSON report
hostcensus scan 10.0.0.0/24 -o report.csv   # CSV report
hostcensus scan 10.0.0.0/24 -q -o out.json  # no table, file only
hostcensus scan 10.0.0.0/24 --format json | jq '.devices[]'  # JSON report on stdout
```

| অপশন | অর্থ |
| --- | --- |
| `NETWORK` | CIDR, IP বা হোস্টনেম; `--profile` ব্যবহার করলে ঐচ্ছিক। IPv6 স্কোপ আইডেন্টিফায়ার প্রত্যাখ্যাত হয়। |
| `-o, --output PATH` | একটি রিপোর্ট লিখুন। ফরম্যাট এক্সটেনশন অনুযায়ী নির্ধারিত হয় (`.json`, `.csv`); অন্য এক্সটেনশনের ক্ষেত্রে JSON ব্যবহৃত হয়। |
| `-f, --format json\|csv\|kadupul\|auto` | রিপোর্ট ফরম্যাট নির্দিষ্ট করুন। `--output` ছাড়া এর কোনো প্রভাব নেই। `.sh` দিলে `kadupul` নির্বাচিত হয়। |
| `-v, --verbose` | ডিবাগ লগিং। |
| `-q, --quiet` | ফলাফল, অগ্রগতি এবং তথ্যমূলক লগ বন্ধ রাখে; সতর্কতা ও ত্রুটি তখনও stderr-এ প্রদর্শিত হয়। |
| `--backend asyncio\|nmap` | হোস্ট ডিসকভারি। `asyncio` (ডিফল্ট) সরাসরি সার্ভিস পোর্টগুলোতে প্রোব পাঠায়; `nmap` প্রথমে একটি nmap পিং সুইপ চালায় এবং এর জন্য `PATH`-এ `nmap` এক্সিকিউটেবল থাকা প্রয়োজন। |
| `--timeout SECONDS` | যেসব প্রোবের নিজস্ব বাজেট সেট করা নেই সেগুলোর জন্য অপেক্ষার সময় (ডিফল্ট 1.0)। সার্ভিস টেবিলে `timeout` সেট করা না থাকলে বিল্ট-ইন কানেক্ট প্রোবগুলো 0.3s ব্যবহার করে। |
| `--concurrency N` | একসাথে চলমান সর্বোচ্চ প্রোব সংখ্যা (ডিফল্ট 256)। |
| `--deadline SECONDS` | nmap সুইপসহ পুরো স্ক্যান এই সময়ের পর বন্ধ করে দেয় (ডিফল্ট 3600, সর্বোচ্চ 604800; এনভায়রনমেন্ট `HOSTCENSUS_DEADLINE`)। যে হোস্টগুলোর কাজ শেষ হয়েছে সেগুলো `"complete": false` সহ রিপোর্টে লেখা হয়, কোনো হিস্ট্রি বা স্ন্যাপশট লেখা হয় না এবং `scan` কোড 4 নিয়ে এক্সিট করে। |
| `--config PATH` | TOML সার্ভিস সংজ্ঞা এবং ঐচ্ছিক নামকরণ করা `[profiles]` সেটিংস। |
| `--profile NAME` | নামকরণ করা একটি প্রোফাইল ব্যবহার করুন; `--config` বাদ দিলে ডিফল্টভাবে `hostcensus.toml` ব্যবহৃত হয়। |
| `--exclude IP/CIDR` | একটি বর্জন যোগ করুন; প্রয়োজন অনুযায়ী পুনরাবৃত্তি করুন। একটি বর্জিত IPv4 হোস্ট তার সাথে সম্পর্কিত IPv6 ঠিকানাগুলোকেও বর্জন করে: IPv4-mapped (`::ffff:a.b.c.d`), NAT64 (`64:ff9b::/96`) এবং 6to4। IPv4-mapped টার্গেট এবং বর্জনগুলোকে সেগুলোর নির্দেশিত IPv4 ঠিকানা হিসেবেই গণ্য করা হয়। |
| `--max-hosts N` | বর্জনের আগে যাচাইকৃত ঠিকানার সীমা (ডিফল্ট/সর্বোচ্চ সীমা 65,536)। |
| `--history PATH` | একটি ঐচ্ছিক SQLite হিস্ট্রি ডেটাবেসে সম্পন্ন স্ক্যান রেকর্ড করুন। |
| `--services NAMES` | যে ক্রমে সার্ভিস নামগুলো পরীক্ষা করতে হবে তার কমা-বিভক্ত তালিকা (ডিফল্ট: সব)। |
| `--ports SPEC` | `NAME=PORT` (একটি সার্ভিস সরানো) বা `PORT` (`tcp-PORT` নামে একটি সাধারণ TCP পরীক্ষা যোগ করা)-এর কমা-বিভক্ত তালিকা। |
| `--snmp-community-file PATH` | system MIB কুয়েরির জন্য SNMPv2c কমিউনিটি ধারণকারী ফাইল। এনভায়রনমেন্ট: `HOSTCENSUS_SNMP_COMMUNITY` (মান) অথবা `HOSTCENSUS_SNMP_COMMUNITY_FILE` (পাথ)। |
| `--snmp-user` | SNMPv3 ব্যবহারকারী। এনভায়রনমেন্ট: `HOSTCENSUS_SNMP_USER`। |
| `--snmp-auth-protocol`, `--snmp-auth-key-file PATH` | `MD5`, `SHA` (ডিফল্ট), `SHA224`, `SHA256`, `SHA384`, `SHA512` এবং পাসফ্রেজ ধারণকারী একটি ফাইল। এনভায়রনমেন্ট: `HOSTCENSUS_SNMP_AUTH_PROTOCOL`, `HOSTCENSUS_SNMP_AUTH_KEY` অথবা `HOSTCENSUS_SNMP_AUTH_KEY_FILE`। |
| `--snmp-priv-protocol`, `--snmp-priv-key-file PATH` | `DES`, `AES` (ডিফল্ট), `AES128`, `AES192`, `AES192C`, `AES256`, `AES256C` এবং পাসফ্রেজ ধারণকারী একটি ফাইল। এনভায়রনমেন্ট: `HOSTCENSUS_SNMP_PRIV_PROTOCOL`, `HOSTCENSUS_SNMP_PRIV_KEY` অথবা `HOSTCENSUS_SNMP_PRIV_KEY_FILE`। |
| `--save-snapshot PATH` | `hostcensus diff`-এর জন্য একটি সংস্করণযুক্ত স্ন্যাপশটও লিখুন। |
| `--tls-ca-file PATH` | সিস্টেম স্টোরের পরিবর্তে এই PEM বান্ডিলের বিপরীতে HTTPS সার্টিফিকেট যাচাই করুন। এনভায়রনমেন্ট: `HOSTCENSUS_TLS_CA_FILE`। |

ডিফল্টভাবে প্রতিটি হোস্টে SSH (TCP 22), SNMP (UDP 161), MySQL (TCP 3306), HTTP (TCP 80) এবং HTTPS (TCP 443) পরীক্ষা করা হয়। TCP পোর্টগুলো পূর্ণ কানেক্টের মাধ্যমে পরীক্ষা করা হয়। SNMP পরীক্ষা করা হয় একটি SNMPv3 ইঞ্জিন-ডিসকভারি রিকোয়েস্টের মাধ্যমে, যার উত্তর যেকোনো SNMPv3 এজেন্ট ক্রেডেনশিয়াল ছাড়াই দিতে বাধ্য; শুধুমাত্র v1/v2c সমর্থনকারী এজেন্টগুলো এই প্রোবে শনাক্ত হবে না। asyncio ব্যাকএন্ডে যেকোনো প্রোব উত্তর পেলে (সংযোগ প্রত্যাখ্যানসহ) একটি হোস্টকে সক্রিয় ধরা হয়, তাই যে হোস্ট প্রতিটি প্রোব ড্রপ করে তার `alive=false` এবং ত্রুটি "Host is down" হয়; তবে এটি প্রমাণ করে না যে হোস্টটি প্রকৃতপক্ষে বন্ধ রয়েছে। `--backend nmap` ব্যবহার করলে nmap নির্ধারণ করে কোন হোস্টগুলো সক্রিয় (root হিসেবে ICMP, অন্যথায় TCP 80/443)।

### ফিঙ্গারপ্রিন্ট

প্রতিটি খোলা সার্ভিস লগইনের আগে যা পাঠায় তা থেকে ফিঙ্গারপ্রিন্ট করা হয়। কেবল SNMP কুয়েরি ছাড়া অন্য কিছু অথেনটিকেশন করে না, এবং সেটিও কেবল তখনই যখন আপনি ক্রেডেনশিয়াল সরবরাহ করেন।

| প্রোব | যা পড়ে | `version` | `details` কীসমূহ |
| --- | --- | --- | --- |
| `ssh` | RFC 4253 শনাক্তকরণ লাইন | সফটওয়্যার, যেমন `OpenSSH_10.0` | `protocol`, `software`, `comments` |
| `mysql` | MySQL/MariaDB প্রাথমিক হ্যান্ডশেক | সার্ভার সংস্করণ | `server_version`, `flavor`, `auth_plugin`, অথবা `error_code`/`error` |
| `http` | `HEAD /` প্রতিক্রিয়া | `Server` হেডার | `status`, `server` |
| `https` | TLS হ্যান্ডশেক, সার্টিফিকেট, `HEAD /` | `Server` হেডার | `tls_version`, `cert_verified`, `cert_verify_error`, `cert_subject`, `cert_issuer`, `cert_sans`, `cert_not_before`, `cert_not_after` (UTC ISO 8601), `cert_self_signed`, `status`, `server` |
| `snmp` | SNMPv3 ডিসকভারি; ক্রেডেনশিয়ালসহ sysDescr, sysObjectID, sysName-এর GET | sysDescr | `engine_id`; ক্রেডেনশিয়ালসহ `snmp_version`, `sys_descr`, `sys_object_id`, `sys_name`, অথবা `snmp_error` |

একটি হোস্টনেম টার্গেট প্রতি হোস্টে একবারই রিজলভ করা হয় এবং প্রতিটি প্রোব সেই ঠিকানায় সংযুক্ত হয়, যা ফলাফলে `address` হিসেবে রেকর্ড করা হয়; নামটি কেবল TLS SNI, সার্টিফিকেট যাচাইকরণ এবং HTTP `Host` হেডারের জন্য ব্যবহৃত হয়। কোনো নাম রিজলভ না হলে `unknown` স্টেট এবং `Cannot resolve` ত্রুটি দেখা যায়। রিভার্স DNS নামগুলো কেবল তখনই রাখা হয় যখন সেগুলোতে বৈধ হোস্টনেম অক্ষর থাকে এবং একসাথে সর্বোচ্চ 16টি লুকআপ চলে। HTTPS সিস্টেম স্টোর বা `--tls-ca-file`-এর বিপরীতে সার্টিফিকেট এবং হোস্টনেম যাচাইকরণ ব্যবহার করে। স্ক্যানের জন্য ট্রাস্ট স্টোর একবার লোড করা হয় এবং প্রতিটি HTTPS প্রোবে পুনরায় ব্যবহার করা হয়। TCP কানেক্ট এবং TLS হ্যান্ডশেক আলাদাভাবে সময়সীমা নির্ধারণ করে, তাই যে পোর্ট সংযোগ গ্রহণ করে কিন্তু হ্যান্ডশেক আটকে রাখে তা `filtered` নয়, বরং `tls_error` সহ `open` হয়। যাচাইকরণ ব্যর্থ হলে ফলাফলে `cert_verified: false` এবং `cert_verify_error` রেকর্ড হয়; এটি দুর্বল সেটিংস নিয়ে পুনরায় চেষ্টা করে না বা HTTP রিকোয়েস্ট পাঠায় না। যাচাইকরণ সফল হওয়ার পরেই কেবল সার্টিফিকেটের বিস্তারিত এবং HTTP হেডার সংগ্রহ করা হয়। প্রাইভেট-CA সার্ভিসগুলোর জন্য সঠিক CA বান্ডিল সরবরাহ করুন। পুরনো রিপোর্টগুলোতে `cert_read_unverified` থাকতে পারে, যা বর্তমান প্রোবগুলো আর তৈরি করে না।

SNMP সিক্রেটগুলো কেবল এনভায়রনমেন্ট ভ্যারিয়েবল বা ফাইল (`--snmp-*-file`, অথবা সংশ্লিষ্ট `HOSTCENSUS_SNMP_*_FILE` ভ্যারিয়েবল) থেকে পড়া হয়, কমান্ড-লাইন মান থেকে কখনোই নয়, কারণ প্রসেস তালিকায় অন্য স্থানীয় ব্যবহারকারীরা তা দেখতে পারেন। মানসহ `--snmp-community`, `--snmp-auth-key` এবং `--snmp-priv-key` ব্যবহার করলে এক্সিট কোড 2 নিয়ে বের হয়ে যায় এবং প্রতিস্থাপন অপশনের নাম দেখায়। একটি সিক্রেট ফাইল অবশ্যই অশূন্য UTF-8 এবং সর্বোচ্চ 4096 বাইটের হতে হবে; শেষের একটি নিউলাইন উপেক্ষা করা হয় এবং একই সিক্রেটের জন্য ভ্যারিয়েবল ও ফাইল উভয়ই সেট করা একটি ত্রুটি। ত্রুটির বার্তায় ফাইলের নাম উল্লেখ থাকে কিন্তু এর বিষয়বস্তু কখনো প্রিন্ট হয় না। স্ক্যান রিপোর্ট এবং হিস্ট্রিতে ইচ্ছাকৃতভাবে কোনো ক্রেডেনশিয়াল মান অন্তর্ভুক্ত করা হয় না। এক্সপোর্টারের একটি আলাদা, সুস্পষ্ট `--include-credentials` অপশন রয়েছে যা নিচে বর্ণিত হয়েছে। একটি কমিউনিটি SNMPv2c নির্বাচন করে; একটি ইউজার SNMPv3 নির্বাচন করে, যেখানে auth কী দেওয়া থাকলে অথেনটিকেশন এবং উভয় কী দেওয়া থাকলে প্রাইভেসি সক্রিয় হয় (`snmp_security_level` কোনটি তা রেকর্ড করে)। hostcensus একটি কমিউনিটির সাথে v3 ইউজার মেশাতে, auth কী ছাড়া প্রাইভেসি কী ব্যবহার করতে, বা ইউজার ছাড়া কী ব্যবহার করতে এক্সিট কোড 2 দিয়ে প্রত্যাখ্যান করে এবং ব্যর্থ v3 কুয়েরি কখনোই v2c বা নিম্ন নিরাপত্তা স্তরে পুনরায় চেষ্টা করে না। যে এজেন্টগুলো কেবল v1/v2c সমর্থন করে সেগুলো ক্রেডেনশিয়ালহীন v3 ডিসকভারি উপেক্ষা করে, তাই কেবল কমিউনিটি সরবরাহ করলেই সেগুলোকে খোলা হিসেবে দেখা যায়।

সংরক্ষণ বা প্রদর্শনের আগে ব্যানার টেক্সট কেবল প্রিন্টযোগ্য অক্ষরে সীমিত করা হয় এবং সর্বোচ্চ 256 অক্ষরে কাটা হয়। রিডের পরিমাণও সীমাবদ্ধ: প্রতি লাইনে 4 KiB, MySQL গ্রিটিংয়ের জন্য 4 KiB, HTTP হেডারের জন্য 16 KiB। 32 অক্টেটের চেয়ে দীর্ঘ একটি SNMP ইঞ্জিন ID সংরক্ষণের আগে কেটে ছোট করা হয়। HTTP এবং HTTPS বন্ধনীর মধ্যে থাকা IPv6 ঠিকানা এবং পোর্ট 80 বা 443 না হলে পোর্টসহ একটি Host হেডার পাঠায়। স্প্রেডশিট ফর্মুলা ট্রিগার দিয়ে শুরু হওয়া CSV সেলগুলোর শুরুতে প্রিফিক্স যুক্ত করা হয় যাতে সেলটি টেক্সট হিসেবেই থাকে।

### সীমাবদ্ধতা

একটি রান সর্বোচ্চ 65,536টি ঠিকানা, 64টি সার্ভিস এবং 524,288টি প্রোব (হোস্ট গুণ সার্ভিস) গ্রহণ করে; এর চেয়ে বড় অনুরোধ কিছু পাঠানোর আগেই এক্সিট কোড 2 নিয়ে বের হয়ে যায়। `--concurrency` সর্বোচ্চ 4096 সকেটে সীমাবদ্ধ। প্রতিটি প্রোবের নিজস্ব বাজেটের চার গুণ একটি কঠোর সময়সীমা থাকে। সার্ভিস নিজে `timeout` সেট না করলে কানেক্ট প্রোবগুলো (`tcp`, `ssh`, `mysql`, `http`) 0.3 সেকেন্ড ব্যবহার করে। SNMP এবং HTTPS আলাদাভাবে সেট করা না থাকলে `--timeout` (ডিফল্ট 1.0) ব্যবহার করে। যে প্রোব সময়সীমায় পৌঁছে যায় সেটি `errors`-এ "probe timed out" সহ `unknown` হিসেবে রিপোর্ট হয়। স্থানীয় সকেট ব্যর্থতাও (যেমন ফাইল ডেস্ক্রিপ্টর শেষ হয়ে যাওয়া) ত্রুটি রেকর্ডসহ `unknown` হয়; সেগুলো কখনোই ফিল্টার্ড পোর্ট বা ডাউন হোস্ট হিসেবে গণ্য হয় না। প্রোবিংয়ের আগে hostcensus `--concurrency` যোগ 64 ডেস্ক্রিপ্টর ধারণের জন্য ওপেন-ফাইল সফট লিমিটকে হার্ড লিমিটের দিকে বাড়ায়; তা করতে না পারলে `open files` প্রিফ্লাইট পরীক্ষা ব্যর্থ হয় এবং ট্র্যাফিক পাঠানোর আগেই `scan` কোড 1 নিয়ে এক্সিট করে। Nmap ডিসকভারি 30-সেকেন্ডের হোস্ট টাইমআউট ব্যবহার করে। nmap-এ একটি প্রিফিক্স CIDR আকারে পাঠানো হয়, এবং nmap প্রদত্ত ঠিকানার চেয়ে কম ঠিকানা রিপোর্ট করলে (যেমন কোনো নাম রিজলভ করতে না পারলে) হোস্টগুলোকে ডাউন চিহ্নিত করার বদলে সুইপটি এক্সিট 1 দিয়ে ব্যর্থ হয়। একটি হোস্টনেম টার্গেট একবার রিজলভ করা হয় এবং nmap-কে সেই ঠিকানা দেওয়া হয়, যাতে ডিসকভারি এবং প্রোব একই মেশিনে পৌঁছায়। একটি সম্পূর্ণ প্রিফিক্স হলো একটি nmap প্রসেস যার সাবপ্রসেস সময়সীমা প্রতি 256 ঠিকানার জন্য 35 সেকেন্ড, পূর্ণসংখ্যায় উন্নীত। বর্জনসহ সুইপগুলোতে 256 হোস্টের ব্যাচ এবং প্রতিটি ব্যাচের জন্য 35-সেকেন্ডের সময়সীমা ব্যবহৃত হয়। রেঞ্জের আকার নির্বিশেষে ওয়ার্কার তৈরি সীমাবদ্ধ থাকে। রিভার্স DNS এবং হোস্টনেম রেজোলিউশনের জন্য আলাদা দুই-সেকেন্ডের সময়সীমা থাকে; যে রিজলভার কল কখনো ফেরে না সেটিকে নিজস্ব থ্রেডে পরিত্যাগ করা হয়, তাই এটি hostcensus-কে এই সীমাগুলোর বাইরে চালু রাখতে পারে না। একসাথে সর্বোচ্চ 16টি লুকআপ চলে, এবং পরিত্যাক্ত কল ফেরত না আসা পর্যন্ত তার স্লট ধরে রাখে, ফলে আটকে থাকা থ্রেডের সংখ্যা সীমাবদ্ধ থাকে; যদি সব 16টি আটকে যায়, পরবর্তী লুকআপগুলো স্লটের জন্য দুই-সেকেন্ডের সময়সীমার বাইরে অপেক্ষা করে (যা স্লট খালি হলে শুরু হয়) যতক্ষণ না `--deadline` স্ক্যানটি থামিয়ে দেয়। `deadline` ছাড়া লাইব্রেরি হিসেবে ব্যবহৃত `NetworkScanner` এমন স্লটের জন্য অনির্দিষ্টকাল অপেক্ষা করতে পারে। এগুলোর ওপরে `--deadline` (ডিফল্ট এক ঘণ্টা) পুরো রানের সময়সীমা নির্ধারণ করে।

### সার্ভিস কনফিগার করা

একটি TOML ফাইলের মাধ্যমে সার্ভিসগুলো পরিবর্তন করা যায়:

```toml
[services.ssh]          # same name as a built-in: replaces it
port = 2222
timeout = 0.5

[services.admin-ui]     # a new service, probed like HTTPS
port = 8443
probe = "https"
```

`probe` হলো `tcp`, `ssh`, `mysql`, `http`, `https` অথবা `snmp`-এর যেকোনো একটি এবং সার্ভিসের নাম কোনো প্রোব হলে সেটিই ডিফল্ট হয়, অন্যথায় `tcp` হয়। শুধুমাত্র `snmp` UDP ব্যবহার করে। সার্ভিসের নাম ছোট হাতের অক্ষর, সংখ্যা, `-` এবং `_` দিয়ে গঠিত হয়। দুটি সার্ভিস একই পোর্ট এবং প্রোটোকল শেয়ার করতে পারে না; হিস্ট্রি সেই জোড়ার জন্য একটি স্টেট রেকর্ড করে। `timeout` ঐচ্ছিক, সেকেন্ডে পরিমাপ করা হয় এবং অন্তত 0.05 হতে হয়। কানেক্ট-ধরনের প্রোবগুলো (`tcp`, `ssh`, `mysql`, `http`) ডিফল্টভাবে 0.3 সেকেন্ড হয়। সার্ভিসে `timeout` সেট করা না থাকলে `snmp` এবং `https` স্ক্যানের `--timeout` ব্যবহার করে। সার্ভিসের আগে থেকেই কোনো বাজেট থাকলে `--timeout` সেটি প্রতিস্থাপন করে না।

JSON রিপোর্টগুলো সংস্করণযুক্ত নথি (`"format": "hostcensus-report"`, `"version": 1`) যা `devices`-এর পাশে টার্গেট, প্রোব করা সার্ভিস এবং সেটিংস রেকর্ড করে; `-o` ছাড়া `--format json` দিলে টেবিলের বদলে stdout-এ রিপোর্ট লেখে। প্রতিটি JSON আউটপুটের একটি প্রকাশিত স্কিমা রয়েছে; [JSON আউটপুট](../../../docs/json-output.md) দেখুন। ডিভাইসগুলোতে মূল `ip`, `alive`, `ssh`, `snmp`, `mysql`, `hostname` এবং `errors` ফিল্ড থাকে এবং একটি `services` তালিকা যোগ হয় যাতে প্রতিটি প্রোবের `name`, `port`, `protocol`, `state` (`open`, `closed`, `filtered`, অথবা প্রোব স্থানীয়ভাবে ব্যর্থ হলে বা সময়সীমা পার হলে `unknown`), `version` এবং `details` থাকে। CSV আউটপুটে খোলা সার্ভিসগুলোর জন্য শেষে `services` এবং `versions` কলাম যুক্ত হয়। `ssh`, `snmp` এবং `mysql` বুলিয়ান মানগুলো ঠিক ওই নামের সার্ভিসগুলোকে অনুসরণ করে।


<a name="inventory-profiles-preflight-and-local-history"></a>

## ইনভেন্টরি প্রোফাইল, প্রিফ্লাইট এবং স্থানীয় হিস্ট্রি

নামকরণ করা প্রোফাইলগুলো বিদ্যমান `[services]` সংজ্ঞার সাথে একটি TOML ফাইল শেয়ার করে। [hostcensus.example.toml](../../../hostcensus.example.toml)-কে `hostcensus.toml`-এ কপি করুন এবং আপনার পরিচালিত নেটওয়ার্কগুলো সেট করুন:

```toml
[profiles.office]
network = "192.168.1.0/24"
exclusions = ["192.168.1.1"]
services = "ssh,http,https,mysql"
concurrency = 32
timeout = 1.0
max_hosts = 256
backend = "asyncio"
```

```bash
hostcensus profiles --config hostcensus.toml
hostcensus preflight --profile office --config hostcensus.toml
hostcensus scan --profile office --config hostcensus.toml -o report.json
```

`preflight` ঠিক `scan`-এর মতোই অপশন এবং প্রোফাইল রিজলভ করে, যার মধ্যে ওপেন-ফাইল পরীক্ষার জন্য `--concurrency`-ও রয়েছে, তাই প্রিফ্লাইট পাস করার অর্থ হলো `scan` একই পরিকল্পনা নিয়ে শুরু করবে।

প্রোফাইলগুলোতে `network`, `exclusions`, `services`, `ports`, `backend`, `timeout`, `concurrency` এবং `max_hosts` গ্রহণ করা হয়। `services` এবং `ports` বিদ্যমান কমা-তালিকা সিনট্যাক্স ব্যবহার করে। সুস্পষ্ট CLI অপশন প্রোফাইল সেটিংসকে ওভাররাইড করে; একাধিকবার `--exclude` দিলে তা প্রোফাইলের বর্জনের সাথে যোগ হয়। `--profile`-এর সাথে দেওয়া একটি সুস্পষ্ট নেটওয়ার্ক অবশ্যই ওই প্রোফাইলের IP/CIDR স্কোপের অন্তর্ভুক্ত হতে হবে। সরাসরি স্ক্যানের জন্য হোস্টনেম এখনও সমর্থিত, তবে IP বর্জনের সাথে তা একত্রে ব্যবহার করা যায় না। হোস্ট সীমা বর্জনের আগে প্রয়োগ হয়; মোট প্রোব সীমা পরেও প্রযোজ্য থাকে। বর্জিত হোস্টগুলো সার্ভিস পরীক্ষা এবং ঐচ্ছিক Nmap ডিসকভারি উভয় থেকেই বাদ দেওয়া হয়।

প্রতিটি স্ক্যান টার্গেট ট্র্যাফিক পাঠানোর আগে স্থানীয় প্রিফ্লাইট পরীক্ষা চালায়: টার্গেট/প্রোব সীমা, গন্তব্য অ্যাক্সেস, ঐচ্ছিক Nmap এক্সিকিউটেবল/র‍্যাপার উপলব্ধতা, হিস্ট্রি স্কিমা এবং কনফিগার করা TLS CA বান্ডিল। `preflight` JSON রিপোর্ট দেয় এবং টার্গেট স্ক্যান করে না বা হিস্ট্রি ডেটাবেস তৈরি করে না। এটি বিদ্যমান বিষয়বস্তু পরিবর্তন না করে গন্তব্য অ্যাক্সেস পরীক্ষা করতে সাময়িকভাবে একটি সহোদর ফাইল লেখে। ডিফল্ট asyncio ব্যাকএন্ডের জন্য এখনও Nmap বা root কোনোটিরই প্রয়োজন হয় না। গন্তব্য পাথগুলো অবশ্যই পরস্পরের থেকে এবং ইনপুট কনফিগারেশন থেকে আলাদা হতে হবে, যার মধ্যে হার্ড লিংকও অন্তর্ভুক্ত; গন্তব্য সিমলিংকগুলো প্রত্যাখ্যাত হয়। ব্যর্থ পরীক্ষা 1 রিটার্ন করে; অবৈধ স্কোপ/কনফিগারেশন 2 রিটার্ন করে।

রিপোর্ট এবং এক্সপোর্ট লেখার জন্য `O_NOFOLLOW` সমর্থন প্রয়োজন। Windows-সহ যেসব প্ল্যাটফর্মে এটি নেই, সেখানে গন্তব্য না খুলে বা ট্রাঙ্কেট না করেই এই লেখাগুলো ব্যর্থ হয়। নতুন রিপোর্ট এবং এক্সপোর্ট স্ক্রিপ্টগুলো কেবল মালিকের জন্য পঠনযোগ্য-লেখাযোগ্য (মোড 0600) হয়; বিদ্যমান ফাইল প্রতিস্থাপন করলে তার অনুমতি সংরক্ষিত থাকে। রিডারবিহীন কোনো নেমড পাইপে লিখতে গেলে অপেক্ষা না করেই সাথে সাথে ব্যর্থ হয়। একটি নতুন `--history` ডেটাবেসও কেবল মালিকের জন্য তৈরি হয়; বিদ্যমান একটির মোড অপরিবর্তিত থাকে। লগ বার্তাগুলো সর্বদা stderr-এ যায়, যাতে stdout-এ কেবল ফলাফল থাকে। ক্রেডেনশিয়ালযুক্ত এক্সপোর্টগুলো সর্বদা মোড 0600 বাধ্যতামূলক করে।

হিস্ট্রি ঐচ্ছিক এবং বিদ্যমান JSON স্ন্যাপশট ও `diff` কমান্ডের পরিপূরক:

```bash
mkdir -p output
hostcensus scan --profile office --history output/inventory.sqlite3
# Repeat later with the same targets and service selection.
hostcensus scan --profile office --history output/inventory.sqlite3
hostcensus history --history output/inventory.sqlite3 --limit 20
hostcensus compare 1 2 --history output/inventory.sqlite3
hostcensus compare 1 2 --history output/inventory.sqlite3 -o output/changes.json
```

`history` থেকে প্রাপ্ত ID ব্যবহার করুন; উদাহরণটি একটি নতুন ডেটাবেস ধরে নেওয়া হয়েছে। স্ন্যাপশটগুলো UTC শুরু/শেষ সময়, প্যাকেজ সংস্করণ, কার্যকর নন-সিক্রেট সেটিংস, সারসংক্ষেপ এবং প্রতি-হোস্ট ত্রুটিসহ সমস্ত হোস্ট/সার্ভিস পর্যবেক্ষণের সাথে ট্রানজ্যাকশনালভাবে সংরক্ষিত হয়। অসম্পূর্ণ হোস্ট পর্যবেক্ষণগুলো ধরে রাখা হয়। বাতিল হওয়া রানগুলো সংরক্ষণ করা হয় না। বিদ্যমান রিপোর্ট, স্ন্যাপশট, এক্সপোর্ট এবং স্ক্যান এক্সিট-কোড চুক্তিগুলো সংরক্ষিত থাকে।

`history` সমস্ত ঐতিহাসিক ডিভাইস পেলোড না পড়েই JSON সারসংক্ষেপ তালিকাভুক্ত করে। `compare` দুটি সংরক্ষিত স্ক্যান পড়ে, অভিন্ন টার্গেট পরিচয় এবং নির্বাচিত পোর্ট দাবি করে, এবং সাড়া দেওয়ার ক্ষমতা, স্ট্যাটাস ও পোর্ট-স্টেট পরিবর্তনগুলো রিপোর্ট করে। আগের স্ক্যান ID অবশ্যই পরের ID-এর পূর্বে হতে হবে। যখন উভয় স্ক্যানেই `timeout` বা `backend` রেকর্ড করা থাকে এবং সেগুলোর মান ভিন্ন হয়, তখন রিপোর্টটি একটি সতর্কতা তালিকাভুক্ত করে এবং তারপরও পর্যবেক্ষণগুলোর তুলনা করে। ভিন্ন অপেক্ষার সময় একটি ফিল্টার্ড পোর্টকে খোলা হিসেবে দেখাতে পারে। স্ক্যানার ত্রুটি এবং অজানা পোর্ট পর্যবেক্ষণগুলোকে নিশ্চিত অদৃশ্য হওয়া বা বন্ধ হওয়া হিসেবে গণ্য না করে অনিশ্চিত হিসেবে চিহ্নিত করা হয়: ত্রুটিযুক্ত হোস্টগুলো `uncertain_hosts`-এ প্রদর্শিত হয়, এবং `unknown` জড়িত প্রতিটি পোর্ট পরিবর্তন (উভয় স্ক্যানেই অজানা থাকাসহ) `port_changes`-এর পরিবর্তে `unconfirmed_ports`-এ তালিকাভুক্ত হয়, কেবল পরবর্তী স্ক্যানে খোলা থাকা পোর্ট বাদে, যা একটি পোর্ট পরিবর্তন হিসেবে গণ্য হয়। `compare` এবং `diff` একই নিয়মে পোর্ট শ্রেণিবদ্ধ করে। `no_longer_responding` মানে সাড়া না পাওয়া, ডিভাইস সরিয়ে ফেলার প্রমাণ নয়। স্ক্যান এক্সিট কোড 0 মানে এই নয় যে প্রতিটি হোস্ট সাড়া দিয়েছে: প্রতি-হোস্ট ত্রুটিগুলো পরীক্ষা করুন। পরিবর্তন থাকুক বা না থাকুক তুলনা সফল হলে 0 রিটার্ন করে; বিদ্যমান ফাইল `diff` তার এক্সিট কোড 3 চুক্তি বজায় রাখে। অসমর্থিত বা ক্ষতিগ্রস্ত হিস্ট্রি 1 রিটার্ন করে।

হিস্ট্রি ইনভেন্টরি তথ্য সংরক্ষণ করে, তাই যথাযথভাবে সুরক্ষিত একটি স্থানীয় ডিরেক্টরি বেছে নিন। প্রোফাইল ফাইল এবং সংরক্ষিত সেটিংসে SNMP ক্রেডেনশিয়াল থাকে না; ক্রেডেনশিয়াল পরিচালনা বিদ্যমান রানটাইম অপশন/এনভায়রনমেন্টের মাধ্যমেই অব্যাহত থাকে।

<a name="inventory-diff"></a>

## ইনভেন্টরি diff

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot monday.json
hostcensus scan 10.0.0.0/24 -q --save-snapshot tuesday.json
hostcensus diff monday.json tuesday.json             # table
hostcensus diff monday.json tuesday.json -f json     # JSON on stdout
```

একটি স্ন্যাপশট হলো `format: "hostcensus-snapshot"`, `version: 1`, hostcensus সংস্করণ, UTC তৈরির সময়, টার্গেট, স্ক্যান রেকর্ড করে থাকলে `timeout` এবং `backend`, প্রোব করা সার্ভিসসমূহ এবং `-o` রিপোর্টের মতো একই আকারের সক্রিয় হোস্টসমূহসহ একটি JSON। ডাউন হোস্টগুলো বাদ দেওয়া হয়। `diff` সাধারণ `scan -o` JSON রিপোর্টও গ্রহণ করে, এমনকি `services` ফিল্ড আসার আগের রিপোর্টগুলোও।

`diff` নতুন এবং অদৃশ্য হওয়া হোস্ট, উভয়টিতে থাকা হোস্টগুলোর খোলা বা বন্ধ হওয়া পোর্ট এবং যেসব সার্ভিসের `version` পরিবর্তিত হয়েছে তা রিপোর্ট করে। দুটি স্ক্যানের মধ্যে কেবল একটিতে প্রোব করা পোর্টগুলোর তুলনা করা হয় না, এবং একটি সতর্কতা তা জানিয়ে দেয়। ব্যর্থ পর্যবেক্ষণগুলো কখনোই "কোনো পরিবর্তন নেই" হিসেবে পড়া হয় না: কোনো পোর্ট যদি যেকোনো একটি স্ক্যানে `unknown` থাকে এবং পরেরটিতে খোলা না থাকে, তবে তা `closed`-এর পরিবর্তে `unconfirmed`-এর অধীনে তালিকাভুক্ত হয়, যেখানে `before` হলো `open`, `unknown` বা `not-open` (প্রোব করা হয়েছে এবং বন্ধ বা ফিল্টার্ড) এবং `after` হলো `unknown` বা `not-open`; আগের প্রোব ব্যর্থ হলেও কোনো পোর্ট এখন খোলা থাকলে তা `opened`-এর অধীনে রিপোর্ট হয়। কোনো হোস্টের সব প্রোব যদি যেকোনো একটি স্ক্যানে উত্তর ছাড়া ব্যর্থ হয়, তবে সেটি `vanished_hosts`-এর পরিবর্তে `unsettled_hosts`-এর অধীনে (`before`/`after` হিসেবে `up`, `uncertain` বা `absent` সহ, উভয় স্ক্যানেই ব্যর্থ হলে বা অন্য ফাইলে না থাকলেও) তালিকাভুক্ত হয়; পরবর্তী স্ক্যানে এটি সাড়া দিলে এর খোলা পোর্টসহ নতুন হোস্ট হিসেবেও রিপোর্ট হয়। এই কারণেই স্ন্যাপশটগুলো সেই ব্যর্থ হোস্টগুলোকে রেখে দেয়। টার্গেট ভিন্ন হলে এবং উভয় ফাইলে টাইমআউট বা ব্যাকএন্ড রেকর্ড করা থাকলে এবং সেই মানগুলো ভিন্ন হলে একটি সতর্কতাও প্রদর্শিত হয়। `-o PATH` JSON রূপটি একটি ফাইলেও লেখে।

`--deadline` দ্বারা থামানো স্ক্যানের (`"complete": false`) রিপোর্টে কেবল যে হোস্টগুলোতে পৌঁছানো গেছে সেগুলোরই তালিকা থাকে, তাই `diff` এবং `export` এটি এক্সিট কোড 2 দিয়ে প্রত্যাখ্যান করে। `--allow-partial` দিলে stderr-এ সতর্কতাসহ এটি গ্রহণ করা হয়: তখন অসম্পূর্ণ স্ক্যান যে হোস্টগুলোকে মোটেও তালিকাভুক্ত করেনি সেগুলোকে `diff` অদৃশ্য হওয়ার বদলে `unsettled_hosts`-এর অধীনে `unscanned` হিসেবে তালিকাভুক্ত করে (যে হোস্টটিকে ডাউন হিসেবে তালিকাভুক্ত করেছে সেটি তখনও অদৃশ্য হিসেবেই থাকে), `partial`-কে true সেট করে এবং কখনোই কোনো পরিবর্তন নেই বলে রিপোর্ট করে না, আর `export` স্ক্রিপ্ট হেডারে একটি সতর্কতা লেখে।

`diff` এক্সিট কোড: `0` কোনো পরিবর্তন নেই, `3` পরিবর্তন পাওয়া গেছে, পর্যবেক্ষণ নিশ্চিত করা যায়নি, অথবা অসম্পূর্ণ ইনপুট (`unsettled_hosts` এবং `unconfirmed`-সহ যেকোনো তালিকা অশূন্য হলে বা `partial` true হলে `changed` true হয়), `2` একটি ফাইল অনুপস্থিত, অপঠনযোগ্য, সমর্থিত স্ন্যাপশট নয়, বা `--allow-partial` ছাড়া অসম্পূর্ণ, `1` `-o` ফাইল লেখা যায়নি।

## Kadupul এক্সপোর্ট

[Kadupul](https://github.com/kadupulhq/kadupul) (Cacti 1.2.31-এর একটি ফর্ক)-এ কোনো বাল্ক ডিভাইস ফাইল ইম্পোর্ট সুবিধা নেই। স্ক্রিপ্ট থেকে ডিভাইস যোগ করার এর সমর্থিত উপায় হলো `cli/add_device.php`, প্রতি কলে একটি ডিভাইস, `--option=value` আর্গুমেন্টসহ। `hostcensus export` সেই কলগুলোর একটি POSIX `sh` স্ক্রিপ্ট লেখে:

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot inventory.json
hostcensus export inventory.json -o kadupul-import.sh --template 1
# or in one step, with template 0: hostcensus scan 10.0.0.0/24 -q -o kadupul-import.sh

# on the Kadupul server, as the user that owns the install:
export HOSTCENSUS_SNMP_COMMUNITY=...        # only if the script asks for it
KADUPUL_ROOT=/var/www/html/kadupul sh kadupul-import.sh
```

প্রতিটি সক্রিয় হোস্ট `php "$KADUPUL_ROOT/cli/add_device.php" --description=... --ip=... --template=N ...`-এ রূপান্তরিত হয়:

- যেসব হোস্টে স্ক্যানের SNMP কুয়েরি সফল হয়েছে সেগুলো `--version=2 --community=...` অথবা `--version=3 --username=... --authproto=... --password=...` (এবং authPriv-এর জন্য অতিরিক্ত `--privproto`/`--privpass`), `--port` এবং `--avail=snmp` পায়। SNMPv3 এক্সপোর্টের জন্য `--snmp-user` প্রয়োজন, এবং noAuthNoPriv প্রত্যাখ্যাত হয় কারণ `add_device.php`-এর জন্য একটি v3 পাসওয়ার্ড আবশ্যক।
- অন্যান্য হোস্টগুলো `--version=0 --avail=ping` পায়, সাথে প্রথম খোলা TCP পোর্ট হিসেবে `--ping_method=tcp --ping_port=`, অথবা কোনোটি না থাকলে ICMP।
- `--notes` খোলা সার্ভিস এবং সংস্করণগুলো তালিকাভুক্ত করে। `--description` সাধারণ অক্ষর (বর্ণ, সংখ্যা, `.`, `_`, `-`) হলে রিভার্স-DNS নাম হয়, অন্যথায় IP হয়, এবং এটিকে অনন্য করা হয়, কারণ `add_device.php` একটি বিদ্যমান বিবরণকে সেই ডিভাইসের আপডেট হিসেবে গণ্য করে।

প্রতিটি মান `shlex.quote` দিয়ে যাচাইকৃত এবং শেল-কোট করা হয়। ডিফল্টভাবে কোনো SNMP সিক্রেট লেখা হয় না: স্ক্রিপ্টটি রান টাইমে `HOSTCENSUS_SNMP_COMMUNITY`, `HOSTCENSUS_SNMP_AUTH_KEY` বা `HOSTCENSUS_SNMP_PRIV_KEY` সম্প্রসারিত করে এবং কোনোটি সেট করা না থাকলে থেমে যায়। এর পরিবর্তে `--include-credentials` ওই এনভায়রনমেন্ট ভ্যারিয়েবলগুলোর মান স্ক্রিপ্টে লিখে দেয়, 0600 মোডে তৈরি করে এবং একটি সতর্কতা লগ করে। `add_device.php` নিজেই কমিউনিটি প্রিন্ট করে এবং আর্গুমেন্ট হিসেবে সিক্রেট গ্রহণ করে, যা প্রতিটি কল চলার সময় Kadupul সার্ভারের প্রসেস তালিকায় দৃশ্যমান থাকে।

ডুপ্লিকেট এবং ত্রুটির জন্য `add_device.php` 1 নিয়ে এক্সিট করে; স্ক্রিপ্টটি চলতে থাকে, ব্যর্থতা গণনা করে এবং কোনো ডিভাইস যোগ করা না গেলে 1 নিয়ে এক্সিট করে। টেমপ্লেট আইডিগুলো `php cli/add_device.php --list-host-templates` থেকে আসে। `export` এক্সিট কোড: `0` লেখা হয়েছে, `2` অপঠনযোগ্য ইনপুট, `--allow-partial` ছাড়া অসম্পূর্ণ স্ক্যান বা নিরাপদে এক্সপোর্ট করা যায় না এমন ডেটা, `1` স্ক্রিপ্ট লেখা যায়নি।

## সংস্করণ এবং রিলিজ প্রক্রিয়া

hostcensus [Semantic Versioning](https://semver.org/spec/v2.0.0.html) অনুসরণ করে: সামঞ্জস্যপূর্ণ ফিক্স প্যাচ সংস্করণ বাড়ায়, সামঞ্জস্যপূর্ণ বৈশিষ্ট্য/অবচয় মাইনর সংস্করণ বাড়ায় এবং ব্রেকিং সামঞ্জস্য পরিবর্তন মেজর সংস্করণ বাড়ায়। কমান্ড ও অপশন, এক্সিট কোড এবং JSON স্কিমাগুলো হলো পাবলিক চুক্তি; নিরাপত্তা ফিক্সের জন্য আগে পরিবর্তন করার প্রয়োজন না হলে অবচিত আচরণ পরবর্তী মেজর রিলিজ পর্যন্ত কাজ করতে থাকে (সেক্ষেত্রে চেঞ্জলগে কারণ উল্লেখ থাকে)।

release-please `main`-এ থাকা Conventional Commit শিরোনাম থেকে একটি রিলিজ PR খোলে, যা `pyproject.toml`, `uv.lock` এবং `CHANGES.md` আপডেট করে। এটি মার্জ করলে `vMAJOR.MINOR.PATCH` ট্যাগ এবং একটি খসড়া GitHub রিলিজ তৈরি হয়, যাতে CI একটি পরীক্ষিত হুইল, সোর্স ডিস্ট্রিবিউশন এবং চেকসাম সংযুক্ত করে; GitHub তার অ্যাটাস্টেশন API-এর মাধ্যমে ওই ফাইলগুলোর জন্য বিল্ড অ্যাটাস্টেশন সংরক্ষণ করে। ফাইলগুলো সংযুক্ত হলে একজন রক্ষণাবেক্ষণকারী খসড়াটি পর্যালোচনা করে প্রকাশ করেন। রিলিজ কখনোই প্রতিস্থাপন করা হয় না।

PyPI ট্রাস্টেড পাবলিশিং ঐচ্ছিক এবং এর জন্য প্রকল্পের মালিকানা, একজন ট্রাস্টেড পাবলিশার এবং `pypi` এনভায়রনমেন্ট প্রয়োজন। এটি API টোকেন পুনর্নির্মাণ বা সংরক্ষণ না করেই একই পরীক্ষিত রিলিজ আর্টিফ্যাক্টগুলো প্রকাশ করে। এই পাবলিক রিপোজিটরির ট্যাগযুক্ত রিলিজগুলো GitHub আর্টিফ্যাক্ট অ্যাটাস্টেশন তৈরি করে; প্রাইভেট ফর্কগুলোর জন্য একটি সমর্থিত প্ল্যান এবং সুস্পষ্ট সম্মতি প্রয়োজন। সেটআপ, সঠিক কমান্ড এবং পুনরায় চেষ্টার জন্য [সম্পূর্ণ রিলিজ নির্দেশিকা](../../../docs/releasing.md) দেখুন।

## ডেভেলপমেন্ট

```bash
uv sync --locked                 # runtime plus the default `dev` group
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=hostcensus
uv build --no-build-isolation
uv run twine check --strict dist/*.whl dist/*.tar.gz
```

ডেভেলপমেন্ট টুলগুলো `pyproject.toml`-এর [PEP 735](https://peps.python.org/pep-0735/) ডিপেন্ডেন্সি গ্রুপে (`dev`, `fuzz`, `build`) থাকে, তাই সেগুলো কখনোই প্রকাশিত প্যাকেজ মেটাডেটায় আসে না। `uv.lock` হলো একমাত্র লকফাইল; CI `uv sync --locked` দিয়ে ইনস্টল করে এবং লকফাইল পুরনো হলে ব্যর্থ হয়। `uv python`, mise (`mise exec python@3.14 -- uv sync --locked`) অথবা যেকোনো Python 3.12+ দিয়ে ইন্টারপ্রেটার নির্বাচন করুন।

CI ন্যূনতম 90% প্যাকেজ কভারেজ বাধ্যতামূলক করে। ইউনিট টেস্টগুলোতে নিয়ন্ত্রিত লুপব্যাক সার্ভার এবং অফলাইন প্রোফাইল/হিস্ট্রি/রিলিজ-ভ্যালিডেটর কেস অন্তর্ভুক্ত রয়েছে; Compose ল্যাব একটি বিচ্ছিন্ন ব্রিজে OpenSSH, MariaDB, nginx এবং net-snmp চালায়। এটি `make test-integration` দিয়ে চালান। [CONTRIBUTING.md](../../../CONTRIBUTING.md) এবং [রিলিজ টুলিং](../../../scripts/README.md) দেখুন।

রানটাইম কন্টেইনারটি কোনো হোম ডিরেক্টরি, কোনো শেল লগইন এবং কোনো pip ছাড়াই UID/GID 10001 হিসেবে চলে এবং `/app/output`-এ লিখতে পারে। মাউন্ট করা যেকোনো আউটপুট ডিরেক্টরিতে ওই ইউজারকে লেখার অনুমতি দিন। এর কোনো অতিরিক্ত ক্ষমতার প্রয়োজন হয় না এবং এটি রিড-অনলি রুট ফাইলসিস্টেমের সাথে কাজ করে, তাই এটি এভাবে চালানো যায়:

```sh
docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp -v "$PWD/out:/app/output" IMAGE scan 192.0.2.0/28 -o /app/output/report.json
```

এই কন্টেইনারে Nmap তার সুবিধাহীন TCP ডিসকভারি আচরণ ব্যবহার করে। Trivy রিপোর্ট করা সংশোধনযোগ্য যেকোনো HIGH বা CRITICAL দুর্বলতায় CI ইমেজ বিল্ড ব্যর্থ করে।

## সাপ্লাই-চেইন পরীক্ষা

[OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/somethingwithproof/python-network-discovery-tool) main-এ এবং সাপ্তাহিকভাবে চলে, এর প্রকৃত স্কোর প্রকাশ করে এবং ফলাফলগুলো GitHub কোড স্ক্যানিংয়ে আপলোড করে। অ্যাকশন এবং কন্টেইনার বেসগুলো অপরিবর্তনীয় হ্যাশ দ্বারা পিন করা থাকে; Python ডিপেন্ডেন্সিগুলো `uv.lock`-এ রিজলভ করা থাকে। Bandit ব্যর্থতা CI ব্যর্থ করে এবং সীমাবদ্ধ Atheris ফাজিং নেটওয়ার্ক অ্যাক্সেস ছাড়াই SSH, MySQL, HTTP, সার্টিফিকেট এবং SNMPv3 BER পার্সারগুলো পরীক্ষা করে।

Scorecard ঐতিহাসিক পর্যালোচনা কার্যক্রম, অবদানকারীর বৈচিত্র্য এবং রিলিজের উৎসও পরিমাপ করে। ওই স্কোরগুলো প্রকৃত প্রমাণ প্রতিফলিত করে; সেগুলো এমন কোনো দাবি নয় যে প্রতিটি গভর্ন্যান্স বা ঐতিহাসিক-রিলিজ পরীক্ষা পূরণ হয়েছে। [SECURITY.md](../../../SECURITY.md) এবং [রিলিজের উৎস তথ্য](../../../docs/releasing.md) দেখুন।

## লোকালাইজেশন

CLI বার্তা এবং টার্মিনাল সারসংক্ষেপ/diff টেবিলগুলো কোনো অতিরিক্ত রানটাইম ডিপেন্ডেন্সি ছাড়াই 45টি লোকেল (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) সমর্থন করে। রেজোলিউশন `--lang`, তারপর `LC_ALL`, `LC_MESSAGES` এবং `LANG` অনুসরণ করে, এবং শেষে `en`-এ ফিরে আসে। JSON স্কিমা, CSV কলাম এবং এক্সপোর্ট স্ক্রিপ্টগুলো সমস্ত লোকেলে অপরিবর্তিত থাকে।

```bash
hostcensus --lang de version
LANG=ja_JP.UTF-8 hostcensus scan 192.0.2.0/28
```
