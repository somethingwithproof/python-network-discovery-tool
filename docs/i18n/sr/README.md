hostcensus је Python CLI алат за поновљиву инвентаризацију сервиса на мрежама којима управљате. Бележи шта уређаји излажу, пореди запажања кроз време и генерише скрипте за увоз у Kadupul. Подразумевани позадински механизам користи asyncio сокете без root овлашћења; опционо откривање преко алата Nmap може да идентификује хостове и изван конфигурисаних портова сервиса.

## Зашто hostcensus

Једнократни извештај о портовима не објашњава да ли се следеће запажање променило или је једноставно пропало. hostcensus обједињује експлицитна стања сервиса, ограничене провере, вишекратно употребљиве профиле скенирања и локалну историју. Оператери могу поновити исти опсег, испитати грешке и разликовати несигурна запажања од потврђених промена.

- **Докази о сервисима:** SSH идентификација, MySQL поздравне поруке, HTTP заглавља, опажања TLS сертификата и SNMP откривање или ауторизовани упити за system-MIB.
- **Поновљив опсег:** именовани TOML профили, адитивна изузећа, подесиви сервиси, ограничења броја хостова и провера, као и ограничен број радника.
- **Провере пре саобраћаја:** локална предпровера валидира циљеве, алате, приступ одредиштима, шему историје и конфигурисане TLS CA пакете.
- **Историја инвентара:** трансакцијски SQLite снимци задржавају сва запажања; поређења чувају видљивим грешке скенера и непозната стања.
- **Интероперабилан излаз:** приказ у терминалу, JSON и CSV извештаји, верзионисани снимци у датотекама и скрипте за увоз у Kadupul.

CI покрива Python 3.12, 3.13 и 3.14 на системима Linux и macOS, уз контролисану Compose интеграциону лабораторију. Код користи савремене алијасе типова, типизиране резултате предпровере, слотоване профиле са параметрима само по кључној речи и структурирано асинхроно чишћење уз задржавање подршке за те верзије извршног окружења. Погледајте [Верзионисање и издања](../../../docs/releasing.md) за уговор о SemVer компатибилности и процес објављивања на GitHub-у. Значка издања описује објављене артефакте, а не радну копију: последња објављена ознака тренутно је `v0.3.0`, док ова радна копија користи верзију пакета `3.0.0`. Инсталирајте из радне копије да бисте користили овде документоване могућности инвентаризације.

Почните од [инсталације](#инсталација), затим пређите на [профиле и историју](#профили-инвентара-предпровера-и-локална-историја). За детаље интеграције погледајте [отиске сервиса](#отисци-сервиса), [поређење датотека](#поређење-инвентара) и [извоз за Kadupul](#извоз-за-kadupul).

## Инсталација

Потребан је Python 3.12 или новији; тестирана матрица покрива Python 3.12-3.14. Из ове радне копије инсталирајте закључане зависности за извршавање:

```bash
uv sync --locked
uv run hostcensus --help
uv run hostcensus --version
uv run hostcensus preflight 127.0.0.1
uv run hostcensus scan 127.0.0.1 --services ssh -o loopback.json
```

За опционо Nmap откривање хостова инсталирајте извршну датотеку Nmap преко менаџера пакета ваше платформе; додатни Python пакет није потребан. XML излаз алата Nmap парсира се библиотеком defusedxml, која је основна зависност, тако да се проширивање ентитета одбија. hostcensus покреће `nmap` пронађен на путањи `PATH` директно са фиксном листом аргумената, крајњим роком који расте са величином префикса и ограничењем излаза од 64 MiB. Nmap није потребан за подразумевани позадински механизам.

## Миграција са netprobe

hostcensus је ново име за netprobe, објављено у верзији 3.0.0. Пројекат никада није био објављен на PyPI ни под једним именом, па су инсталације долазиле из радне копије или GitHub издања. GitHub репозиторијум задржава своје постојеће име.

| Раније | Сада | Компатибилност |
| --- | --- | --- |
| Дистрибуција `netprobe` | `hostcensus` | Поново инсталирајте из радне копије; пакет под старим именом не постоји. |
| Команда `netprobe` | `hostcensus` | `netprobe` и даље ради и исписује један ред упозорења о застарелости на stderr. Излазни кодови и stdout остају непромењени. Биће уклоњено у наредном великом издању. |
| Променљиве окружења `NETPROBE_*` | `HOSTCENSUS_*` | Променљива `NETPROBE_*` користи се када њен парњак `HOSTCENSUS_*` није постављен, уз једно упозорење на stderr које наводи имена променљивих, а никада њихове вредности. `HOSTCENSUS_*` има предност када су обе постављене. Биће уклоњено у наредном великом издању. |
| `import netprobe`, `python -m netprobe` | `import hostcensus`, `python -m hostcensus` | **Некомпатибилна промена.** Није инсталиран заменски модул за увоз; ажурирајте увозе. |
| Ознака Docker слике `network-discovery:test` (само CI) и корисник контејнера `netprobe` | `hostcensus:test`, корисник `hostcensus` | Ниједна слика никада није објављена у регистру. Поново изградите слику и користите улазну тачку `hostcensus`. |
| `netprobe.toml`, `netprobe-history.sqlite3` | `hostcensus.toml`, `hostcensus-history.sqlite3` | Постојећа датотека са старим подразумеваним именом и даље се користи уз упозорење док ново име не постоји. Експлицитне путање `--config` и `--history` остају нетакнуте. |
| Извештаји и снимци са `"format": "netprobe-report"` или `"netprobe-snapshot"` и пољем `netprobe_version` | `hostcensus-report`, `hostcensus-snapshot`, `hostcensus_version` | `diff` и `export` и даље учитавају датотеке уписане под старим именом, а објављене JSON шеме прихватају оба облика. Нове датотеке користе нова имена. SQLite базе историје остају непромењене и учитавају се као раније. |
| Kadupul скрипте из `netprobe export` | Скрипте из `hostcensus export` | Старе скрипте настављају да раде и приликом покретања и даље читају `NETPROBE_SNMP_*`. Нове скрипте читају `HOSTCENSUS_SNMP_*`. |

## Брзи пример

Покренуто из тестног контејнера интеграционе лабораторије описане у одељку Развој; излаз је скраћен:

```console
$ hostcensus scan 172.30.57.8/29 --services ssh,http,snmp --save-snapshot after.json
┃ IP Address   ┃ Hostname       ┃ SSH ┃ SNMP ┃ MySQL ┃ Open services  ┃ Status ┃
│ 172.30.57.10 │ hostcensus-it-s… │ ✅  │  ❌  │  ❌   │ ssh:22         │ UP     │
│              │                │     │      │       │ OpenSSH_10.0   │        │
│ 172.30.57.13 │ hostcensus-it-w… │ ❌  │  ❌  │  ❌   │ http:80        │ UP     │
│              │                │     │      │       │ nginx/1.28.3   │        │

$ hostcensus diff before.json after.json; echo "exit=$?"
Warning: targets differ: 172.30.57.10 vs 172.30.57.8/29
│ new host │ 172.30.57.13 │ http:80/tcp  │ hostcensus-it-web-1.hostcensus-it_lab   │

$ hostcensus export after.json -o kadupul-import.sh --template 1
$ grep 57.13 kadupul-import.sh
add --description=hostcensus-it-web-1.hostcensus-it_lab --ip=172.30.57.13 --template=1 --version=0 --avail=ping --ping_method=tcp --ping_port=80 '--notes=hostcensus: http:80/tcp nginx/1.28.3'
```

## Излазни кодови

| Команда | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| `scan` | запажања или извештај уписани | неуспела предпровера/позадински механизам, историја или упис извештаја/снимка | неисправан циљ, опције, конфигурација или ограничења | - | достигнут `--deadline`; уписан непотпун извештај, историја и снимак прескочени |
| `preflight` | провере прошле | локална провера није успела | неисправан циљ/конфигурација или сукобљена одредишта | - | - |
| `profiles` | приказани валидирани профили | - | нечитљива/неисправна конфигурација или избор | - | - |
| `history` | приказани резимеи | недостајућа, неисправна или неподржана историја | неисправне CLI опције | - | - |
| `compare` | поређење генерисано, укључујући случај када постоје промене | нечитљива историја, некомпатибилан опсег/редослед или грешка при упису | неисправне CLI опције | - | - |
| `diff` | нема промена | датотека `-o` није могла бити уписана | недостајући, нечитљив или неподржан улаз или непотпуно скенирање без `--allow-partial` | пронађене промене, непотврђена запажања или непотпуно скенирање | - |
| `export` | скрипта уписана | скрипта није могла бити уписана | нечитљив улаз, непотпуно скенирање без `--allow-partial` или подаци који се не могу безбедно извести | - | - |

## Структура

| Модул | Одговорност |
| --- | --- |
| `cli.py` | Опције команди, разрешавање профила, предпровера, скенирање и извештавање |
| `scanner.py`, `probes.py` | Проширивање циљева, ограничени радници, откривање хостова и опажање сервиса |
| `config.py`, `profiles.py` | Дефиниције сервиса и валидирани профили инвентара |
| `models.py`, `output.py` | Типови резултата и испис за терминал, JSON и CSV |
| `history.py`, `diff.py` | SQLite историја и поређење верзионисаних снимака из датотека |
| `preflight.py` | Локалне провере и временски ограничено очитавање верзије алата Nmap |
| `export.py` | Валидиране и безбедно цитиране скрипте за увоз у Kadupul |

Свако опажање сервиса бележи његово стање одвојено од оглашеног идентитета. Читања и крајњи рокови су ограничени; изузеци при проверама остају забележени у грешкама хоста. SQLite историја користи трансакције, експлицитно затварање веза и путање само за читање приликом листања и поређења. SNMP тајне улазе искључиво преко променљивих окружења или датотека са тајнама; историја инвентара чува стварна подешавања без тајни. Погледајте [Архитектуру](../../../docs/architecture.md) за цевовод скенирања, његова ограничења и границе поверења, као и [SECURITY.md](../../../SECURITY.md#authorized-use) за овлашћену употребу.

## Употреба

Скенирајте искључиво мреже којима управљате.

```bash
hostcensus scan 192.168.1.0/24              # table of alive hosts
hostcensus scan 192.168.1.1 -o results.json # JSON report
hostcensus scan 10.0.0.0/24 -o report.csv   # CSV report
hostcensus scan 10.0.0.0/24 -q -o out.json  # no table, file only
hostcensus scan 10.0.0.0/24 --format json | jq '.devices[]'  # JSON report on stdout
```

| Опција | Значење |
| --- | --- |
| `NETWORK` | CIDR, IP или име хоста; опционо уз `--profile`. Идентификатори IPv6 опсега се одбијају. |
| `-o, --output PATH` | Уписује извештај у датотеку. Формат прати екстензију (`.json`, `.csv`); остале екстензије користе JSON. |
| `-f, --format json\|csv\|kadupul\|auto` | Форсира формат извештаја. Нема ефекта без `--output`. `.sh` бира `kadupul`. |
| `-v, --verbose` | Детаљно бележење за отклањање грешака. |
| `-q, --quiet` | Потискује резултате, напредак и информативне записе; упозорења и грешке се и даље приказују на stderr. |
| `--backend asyncio\|nmap` | Откривање хостова. `asyncio` (подразумевано) директно проверава портове сервиса; `nmap` најпре покреће nmap ping претрагу и захтева извршну датотеку `nmap` у `PATH`. |
| `--timeout SECONDS` | Време чекања за провере које не постављају сопствени буџет (подразумевано 1.0). Уграђене провере повезивања користе 0,3 s осим ако табела сервиса не зада `timeout`. |
| `--concurrency N` | Број истовремених провера у току (подразумевано 256). |
| `--deadline SECONDS` | Зауставља цело скенирање, укључујући nmap претрагу, након задатог времена (подразумевано 3600, највише 604800; променљива окружења `HOSTCENSUS_DEADLINE`). Обрађени хостови се уписују у извештај са `"complete": false`, историја и снимак се не уписују, а `scan` излази са кодом 4. |
| `--config PATH` | TOML датотека са дефиницијама сервиса и опционим именованим `[profiles]` подешавањима. |
| `--profile NAME` | Користи именовани профил; подразумевано користи `hostcensus.toml` када је `--config` изостављен. |
| `--exclude IP/CIDR` | Додаје изузеће; понављајте по потреби. Изузети IPv4 хост такође изузима IPv6 адресе које воде до њега: IPv4-мапиране (`::ffff:a.b.c.d`), NAT64 (`64:ff9b::/96`) и 6to4. IPv4-мапирани циљеви и изузећа третирају се као IPv4 адресе које представљају. |
| `--max-hosts N` | Ограничење броја адреса које се проверава пре изузећа (подразумевани и тврди максимум 65.536). |
| `--history PATH` | Бележи завршено скенирање у опциону SQLite базу историје. |
| `--services NAMES` | Листа назива сервиса одвојена зарезима за проверу тим редоследом (подразумевано: сви). |
| `--ports SPEC` | Листа одвојена зарезима облика `NAME=PORT` (премешта сервис) или `PORT` (додаје обичну TCP проверу под називом `tcp-PORT`). |
| `--snmp-community-file PATH` | Датотека која садржи SNMPv2c community ниску за упит system MIB. Променљиве окружења: `HOSTCENSUS_SNMP_COMMUNITY` (вредност) или `HOSTCENSUS_SNMP_COMMUNITY_FILE` (путања). |
| `--snmp-user` | SNMPv3 корисник. Променљива окружења: `HOSTCENSUS_SNMP_USER`. |
| `--snmp-auth-protocol`, `--snmp-auth-key-file PATH` | `MD5`, `SHA` (подразумевано), `SHA224`, `SHA256`, `SHA384`, `SHA512` и датотека са лозинком. Променљиве окружења: `HOSTCENSUS_SNMP_AUTH_PROTOCOL`, `HOSTCENSUS_SNMP_AUTH_KEY` или `HOSTCENSUS_SNMP_AUTH_KEY_FILE`. |
| `--snmp-priv-protocol`, `--snmp-priv-key-file PATH` | `DES`, `AES` (подразумевано), `AES128`, `AES192`, `AES192C`, `AES256`, `AES256C` и датотека са лозинком. Променљиве окружења: `HOSTCENSUS_SNMP_PRIV_PROTOCOL`, `HOSTCENSUS_SNMP_PRIV_KEY` или `HOSTCENSUS_SNMP_PRIV_KEY_FILE`. |
| `--save-snapshot PATH` | Додатно уписује верзионисани снимак за `hostcensus diff`. |
| `--tls-ca-file PATH` | Проверава HTTPS сертификате према овом PEM пакету уместо системског складишта. Променљива окружења: `HOSTCENSUS_TLS_CA_FILE`. |

Подразумевано се сваки хост проверава на SSH (TCP 22), SNMP (UDP 161), MySQL (TCP 3306), HTTP (TCP 80) и HTTPS (TCP 443). TCP портови се тестирају потпуним повезивањем. SNMP се тестира захтевом за откривање SNMPv3 механизма, на који сваки SNMPv3 агент мора да одговори без акредитива; агенти који говоре само v1/v2c неће бити откривени овом провером. Са позадинским механизмом asyncio хост се сматра активним када било која провера добије одговор, укључујући одбијену везу, па хост који одбацује све провере има `alive=false` и грешку "Host is down"; то не доказује да је рачунар физички искључен. Са `--backend nmap`, nmap одлучује који су хостови активни (ICMP као root, иначе TCP 80/443).

### Отисци сервиса

Сваки отворени сервис добија отисак на основу онога што пошаље пре било какве пријаве. Ништа се не аутентификује осим SNMP упита, и то само када доставите акредитиве.

| Провера | Чита | `version` | Кључеви у `details` |
| --- | --- | --- | --- |
| `ssh` | RFC 4253 идентификациони ред | софтвер, нпр. `OpenSSH_10.0` | `protocol`, `software`, `comments` |
| `mysql` | почетно руковање за MySQL/MariaDB | верзија сервера | `server_version`, `flavor`, `auth_plugin` или `error_code`/`error` |
| `http` | одговор на `HEAD /` | заглавље `Server` | `status`, `server` |
| `https` | TLS руковање, сертификат, `HEAD /` | заглавље `Server` | `tls_version`, `cert_verified`, `cert_verify_error`, `cert_subject`, `cert_issuer`, `cert_sans`, `cert_not_before`, `cert_not_after` (UTC ISO 8601), `cert_self_signed`, `status`, `server` |
| `snmp` | SNMPv3 откривање; уз акредитиве GET за sysDescr, sysObjectID, sysName | sysDescr | `engine_id`; уз акредитиве `snmp_version`, `sys_descr`, `sys_object_id`, `sys_name` или `snmp_error` |

Циљно име хоста разрешава се једном по хосту и свака провера се повезује на ту адресу, забележену као `address` у резултатима; име се користи само за TLS SNI, верификацију сертификата и HTTP заглавље `Host`. Име које се не може разрешити даје стања `unknown` и грешку `Cannot resolve`. Обрнути DNS називи се задржавају само када садрже знакове ваљаног имена хоста, а највише 16 упита ради истовремено. HTTPS користи верификацију сертификата и имена хоста према системском складишту или `--tls-ca-file`. Складиште поверења учитава се једном за скенирање и поново користи за сваку HTTPS проверу. TCP повезивање и TLS руковање мере се засебно, па је порт који прихвати везу али застане у руковању `open` са `tls_error`, а не `filtered`. Ако верификација не успе, резултат бележи `cert_verified: false` и `cert_verify_error`; не покушава поново са слабијим подешавањима нити шаље HTTP захтев. Детаљи сертификата и HTTP заглавља прикупљају се тек након успешне верификације. Доставите одговарајући CA пакет за сервисе са приватним CA. Старији извештаји могу садржати `cert_read_unverified`, што тренутне провере више не производе.

SNMP тајне се читају искључиво из променљивих окружења или датотека (`--snmp-*-file` или одговарајућа променљива `HOSTCENSUS_SNMP_*_FILE`), никада из вредности на командној линији које други локални корисници могу видети у листи процеса. `--snmp-community`, `--snmp-auth-key` и `--snmp-priv-key` са вредношћу завршавају излазним кодом 2 и наводе замену. Датотека са тајном мора бити непразан UTF-8 текст од највише 4096 бајтова; један завршни знак новог реда се занемарује, а постављање и променљиве и датотеке за исту тајну је грешка. Грешке наводе име датотеке, али никада не исписују њен садржај. Извештаји скенирања и историја намерно не укључују вредности акредитива. Извозник има засебну, експлицитну опцију `--include-credentials` описану у наставку. Community бира SNMPv2c; корисник бира SNMPv3, уз аутентификацију када је дат кључ аутентификације и приватност када су дата оба кључа (`snmp_security_level` бележи одабрани ниво). hostcensus одбија, уз излазни код 2, комбиновање community ниске са v3 корисником, коришћење кључа приватности без кључа аутентификације или коришћење кључева без корисника, и никада не понавља неуспели v3 упит са v2c или нижим нивоом безбедности. Агенти који говоре само v1/v2c занемарују v3 откривање без акредитива, па се приказују као отворени тек када се наведе community.

Текст банера се своди на исписиве знакове и ограничава на 256 знакова пре чувања или приказа. Читања су такође ограничена: 4 KiB по линији, 4 KiB за MySQL поздрав, 16 KiB за HTTP заглавља. SNMP engine ID дужи од 32 октета скраћује се пре чувања. HTTP и HTTPS шаљу заглавље Host са IPv6 адресом у угластим заградама и са портом када није 80 или 443. CSV ћелије које почињу окидачем формула за табеларне прорачуне добијају префикс како би ћелија остала текст.

### Ограничења

Једно покретање прихвата највише 65.536 адреса, 64 сервиса и 524.288 провера (хостови помножени са сервисима); већи захтеви излазе са кодом 2 пре слања било каквог саобраћаја. `--concurrency` је ограничен на 4096 сокета. Свака провера има тврди крајњи рок једнак четвороструком сопственом буџету. Провере повезивања (`tcp`, `ssh`, `mysql`, `http`) користе 0,3 секунде осим ако тај сервис не постави `timeout`. SNMP и HTTPS користе `--timeout` (подразумевано 1.0) када немају сопствени. Провера која достигне крајњи рок пријављује се као `unknown` са поруком "probe timed out" у `errors`. Локалне грешке сокета (на пример нестанак описника датотека) такође су `unknown` уз забележену грешку; никада се не рачунају као филтриран порт или недоступан хост. Пре провера, hostcensus подиже меко ограничење отворених датотека према тврдом ограничењу како би стало `--concurrency` плус 64 описника; када то није могуће, предпровера `open files` не успева и `scan` излази са кодом 1 пре слања саобраћаја. Nmap откривање користи временско ограничење од 30 секунди по хосту. Префикс се прослеђује алату nmap у CIDR облику, а претрага не успева са кодом 1 када nmap врати мање адреса него што му је дато (на пример име које не може да разреши), уместо да хостове означи недоступним. Циљно име хоста разрешава се једном и nmap добија ту адресу, тако да откривање и провере долазе до истог рачунара. Пун префикс је један nmap процес чији је рок подпроцеса 35 секунди за сваких 256 адреса, заокружено навише. Претраге са изузећима користе пакете од по 256 хостова и рок од 35 секунди по пакету. Креирање радника је ограничено независно од величине опсега. Обрнути DNS и разрешавање имена хостова имају засебан рок од две секунде; позив разрешивача који се никада не врати напушта се на сопственој нити, тако да не може задржати hostcensus преко ових граница. Истовремено ради највише 16 упита, а напуштени позив задржава своје место док се не врати, па број заглављених нити остаје ограничен; ако се свих 16 заглави, каснији упити чекају у реду изван двосекундног рока (који почиње тек када се место ослободи) док `--deadline` не заустави скенирање. `NetworkScanner` коришћен као библиотека без параметра `deadline` може чекати такво место неограничено дуго. `--deadline` (подразумевано један сат) ограничава цело покретање поврх свега наведеног.

### Конфигурисање сервиса

Сервиси се могу мењати путем TOML датотеке:

```toml
[services.ssh]          # same name as a built-in: replaces it
port = 2222
timeout = 0.5

[services.admin-ui]     # a new service, probed like HTTPS
port = 8443
probe = "https"
```

`probe` је један од `tcp`, `ssh`, `mysql`, `http`, `https` или `snmp` и подразумевано узима назив сервиса када је то врста провере, иначе `tcp`. Само `snmp` користи UDP. Називи сервиса састоје се од малих слова, цифара, `-` и `_`. Два сервиса не могу делити исти порт и протокол; историја бележи једно стање за тај пар. `timeout` је опцион, у секундама, и износи најмање 0,05. Провере засноване на повезивању (`tcp`, `ssh`, `mysql`, `http`) подразумевано користе 0,3 секунде. `snmp` и `https` користе `--timeout` скенирања када сервис не постави `timeout`. `--timeout` не замењује буџет који сервис већ има.

JSON извештаји су верзионисани документи (`"format": "hostcensus-report"`, `"version": 1`) који бележе циљ, проверене сервисе и подешавања поред поља `devices`; `--format json` без `-o` исписује извештај на stdout уместо табеле. Сваки JSON излаз има објављену шему; погледајте [JSON излаз](../../../docs/json-output.md). Уређаји задржавају изворна поља `ip`, `alive`, `ssh`, `snmp`, `mysql`, `hostname` и `errors` и додају листу `services` са пољима сваке провере: `name`, `port`, `protocol`, `state` (`open`, `closed`, `filtered` или `unknown` када је провера локално пала или достигла крајњи рок), `version` и `details`. CSV излаз добија завршне колоне `services` и `versions` за отворене сервисе. Логичке вредности `ssh`, `snmp` и `mysql` прате сервисе са тачно тим називима.

## Профили инвентара, предпровера и локална историја

Именовани профили деле TOML датотеку са постојећим дефиницијама `[services]`. Копирајте [hostcensus.example.toml](../../../hostcensus.example.toml) у `hostcensus.toml` и поставите мреже којима управљате:

```toml
[profiles.office]
network = "192.168.1.0/24"
exclusions = ["192.168.1.1"]
services = "ssh,http,https,mysql"
concurrency = 32
timeout = 1.0
max_hosts = 256
backend = "asyncio"
```

```bash
hostcensus profiles --config hostcensus.toml
hostcensus preflight --profile office --config hostcensus.toml
hostcensus scan --profile office --config hostcensus.toml -o report.json
```

`preflight` разрешава опције и профиле потпуно исто као `scan`, укључујући `--concurrency` за проверу отворених датотека, тако да успешна предпровера значи да ће `scan` кренути са истим планом.

Профили прихватају `network`, `exclusions`, `services`, `ports`, `backend`, `timeout`, `concurrency` и `max_hosts`. `services` и `ports` користе постојећу синтаксу листе одвојене зарезима. Експлицитне CLI опције надјачавају подешавања профила; поновљене опције `--exclude` додају се изузећима профила. Експлицитна мрежа уз `--profile` мора бити садржана у IP/CIDR опсегу тог профила. Имена хостова остају подржана за директна скенирања, али се не могу комбиновати са IP изузећима. Ограничења хостова примењују се пре изузећа; укупно ограничење провера и даље важи након њих. Изузети хостови се изостављају и из провера сервиса и из опционог Nmap откривања.

Свако скенирање обавља локалне предпровере пре циљаног саобраћаја: ограничења циљева/провера, приступ одредиштима, доступност опционе извршне датотеке или омотача за Nmap, шему историје и конфигурисани TLS CA пакет. `preflight` исписује JSON и не скенира циљеве нити креира базу историје. Привремено уписује суседну датотеку ради провере приступа одредишту без измене постојећег садржаја. Подразумевани asyncio механизам и даље не захтева ни Nmap ни root. Путање одредишта морају се разликовати једна од друге и од улазне конфигурације, укључујући тврде везе; симболичке везе на одредишту се одбијају. Неуспеле провере враћају 1; неисправан опсег/конфигурација враћа 2.

Упис извештаја и извозних датотека захтева подршку за `O_NOFOLLOW`. На платформама без ње, укључујући Windows, овакви уписи не успевају без отварања или скраћивања одредишта. Нови извештаји и скрипте за извоз креирају се само за власника (режим 0600); замена постојеће датотеке чува њене дозволе. Упис у именовану цев без читача одмах не успева уместо да чека. Нова база `--history` такође се креира само за власника; постојећа задржава свој режим. Записници увек иду на stderr, па stdout носи само резултате. Извози који садрже акредитиве увек форсирају режим 0600.

Историја је опциона и допуњује постојеће JSON снимке и команду `diff`:

```bash
mkdir -p output
hostcensus scan --profile office --history output/inventory.sqlite3
# Repeat later with the same targets and service selection.
hostcensus scan --profile office --history output/inventory.sqlite3
hostcensus history --history output/inventory.sqlite3 --limit 20
hostcensus compare 1 2 --history output/inventory.sqlite3
hostcensus compare 1 2 --history output/inventory.sqlite3 -o output/changes.json
```

Користите ID-ове из команде `history`; пример претпоставља нову базу података. Снимци се чувају трансакцијски са UTC временима почетка/завршетка, верзијом пакета, стварним подешавањима без тајни, резимеима и свим опажањима хостова/сервиса, укључујући грешке по хосту. Непотпуна опажања хостова се задржавају. Отказана покретања се не чувају. Постојећи уговори за извештаје, снимке, извоз и излазне кодове скенирања остају очувани.

`history` исписује JSON резимее без читања свих историјских података о уређајима. `compare` чита два сачувана скенирања, захтева идентичне циљеве и одабране портове и извештава о променама одзива, статуса и стања портова. ID ранијег скенирања мора претходити каснијем ID-у. Када оба скенирања имају забележен `timeout` или `backend` и те се вредности разликују, извештај наводи упозорење али ипак пореди запажања. Другачије време чекања може учинити да филтрирани порт изгледа отворен. Грешке скенера и непозната стања портова означавају се као несигурна уместо да се третирају као потврђен нестанак или затварање: хостови са грешкама појављују се у `uncertain_hosts`, а сваки прелаз порта који укључује `unknown` (укључујући unknown у оба скенирања) наводи се у `unconfirmed_ports` уместо у `port_changes`, осим порта који је отворен у каснијем скенирању, што представља промену порта. `compare` и `diff` класификују портове по истом правилу. `no_longer_responding` значи изостанак одговора, а не доказ уклањања уређаја. Излазни код 0 при скенирању не гарантује да је сваки хост одговорио: проверите грешке по хосту. Успешно поређење враћа 0 без обзира има ли промена; постојећа датотечна команда `diff` задржава свој уговор излазног кода 3. Неподржана или оштећена историја враћа 1.

Историја чува податке о инвентару, па одаберите одговарајуће заштићен локални директоријум. Датотеке профила и сачувана подешавања не садрже SNMP акредитиве; руковање акредитивима остаје путем постојећих опција при покретању и окружења.

## Поређење инвентара

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot monday.json
hostcensus scan 10.0.0.0/24 -q --save-snapshot tuesday.json
hostcensus diff monday.json tuesday.json             # table
hostcensus diff monday.json tuesday.json -f json     # JSON on stdout
```

Снимак је JSON са `format: "hostcensus-snapshot"`, `version: 1`, верзијом алата hostcensus, UTC временом настанка, циљем, `timeout` и `backend` подешавањима скенирања када их је скенирање забележило, провереним сервисима и активним хостовима у истом облику као `-o` извештај. Недоступни хостови се изостављају. `diff` такође прихвата обичне JSON извештаје из `scan -o`, укључујући оне настале пре постојања поља `services`.

`diff` пријављује нове и нестале хостове, портове који су се отворили или затворили на хостовима присутним у оба снимка и сервисе чија се `version` променила. Портови проверени само у једном од два скенирања се не пореде, уз одговарајуће упозорење. Неуспела опажања никада се не тумаче као "нема промена": порт са стањем `unknown` у било ком скенирању који није отворен у каснијем наводи се под `unconfirmed`, а не под `closed`, са `before` вредношћу `open`, `unknown` или `not-open` (проверен и затворен или филтриран) и `after` вредношћу `unknown` или `not-open`; порт који је сада отворен пријављује се под `opened` чак и ако је ранија провера пала. Хост чије су све провере пале без одговора у било ком скенирању наводи се под `unsettled_hosts` (са `before`/`after` вредношћу `up`, `uncertain` или `absent`, укључујући случај када је пао у оба скенирања или недостаје у другој датотеци) уместо под `vanished_hosts`; ако одговори у каснијем скенирању, пријављује се и као нови хост са својим отвореним портовима. Снимци задржавају такве неуспеле хостове управо из тог разлога. Упозорење се такође приказује када се циљеви разликују и када обе датотеке бележе timeout или backend и те се вредности разликују. `-o PATH` такође уписује JSON облик у датотеку.

Извештај из скенирања заустављеног опцијом `--deadline` (`"complete": false`) наводи само хостове до којих је скенирање стигло, па га `diff` и `export` одбијају са излазним кодом 2. `--allow-partial` га прихвата уз упозорење на stderr: `diff` тада хостове које непотпуно скенирање уопште није навело ставља у `unsettled_hosts` као `unscanned` уместо као нестале (хост наведен као недоступан и даље је нестали), поставља `partial` на true и никада не пријављује одсуство промена, док `export` уписује упозорење у заглавље скрипте.

Излазни кодови за `diff`: `0` нема промена, `3` пронађене промене, запажања која се нису могла потврдити или непотпун улаз (`changed` је true кад год је било која листа, укључујући `unsettled_hosts` и `unconfirmed`, непразна или је `partial` true), `2` датотека недостаје, нечитљива је, није подржан снимак или је непотпуна без `--allow-partial`, `1` датотека `-o` није могла бити уписана.

## Извоз за Kadupul

[Kadupul](https://github.com/kadupulhq/kadupul) (форк система Cacti 1.2.31) нема масовни увоз уређаја из датотеке. Његов подржани начин додавања уређаја из скрипте јесте `cli/add_device.php`, један уређај по позиву, са аргументима `--option=value`. `hostcensus export` уписује POSIX `sh` скрипту таквих позива:

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot inventory.json
hostcensus export inventory.json -o kadupul-import.sh --template 1
# or in one step, with template 0: hostcensus scan 10.0.0.0/24 -q -o kadupul-import.sh

# on the Kadupul server, as the user that owns the install:
export HOSTCENSUS_SNMP_COMMUNITY=...        # only if the script asks for it
KADUPUL_ROOT=/var/www/html/kadupul sh kadupul-import.sh
```

Сваки активни хост постаје `php "$KADUPUL_ROOT/cli/add_device.php" --description=... --ip=... --template=N ...`:

- Хостови код којих је SNMP упит током скенирања успео добијају `--version=2 --community=...` или `--version=3 --username=... --authproto=... --password=...` (плус `--privproto`/`--privpass` за authPriv), `--port` и `--avail=snmp`. SNMPv3 извоз захтева `--snmp-user`, а noAuthNoPriv се одбија јер `add_device.php` захтева v3 лозинку.
- Остали хостови добијају `--version=0 --avail=ping`, са `--ping_method=tcp --ping_port=` постављеним на први отворени TCP порт или ICMP ако нема ниједног.
- `--notes` наводи отворене сервисе и верзије. `--description` је обрнути DNS назив када је једноставан (слова, цифре, `.`, `_`, `-`), иначе IP адреса, и чини се јединственим јер `add_device.php` постојећи опис третира као ажурирање тог уређаја.

Свака вредност се валидира и цитира за љуску помоћу `shlex.quote`. Подразумевано се не уписује ниједна SNMP тајна: скрипта при извршавању проширује `HOSTCENSUS_SNMP_COMMUNITY`, `HOSTCENSUS_SNMP_AUTH_KEY` или `HOSTCENSUS_SNMP_PRIV_KEY` и стаје ако нека није постављена. `--include-credentials` уместо тога уписује вредности тих променљивих окружења у скрипту, креира је са режимом 0600 и бележи упозорење. Сам `add_device.php` исписује community и прима тајне као аргументе, који су видљиви у листи процеса Kadupul сервера док се сваки позив извршава.

`add_device.php` излази са кодом 1 за дупликате и грешке; скрипта наставља, броји неуспехе и излази са кодом 1 ако било који уређај није додат. ID-ови шаблона добијају се путем `php cli/add_device.php --list-host-templates`. Излазни кодови за `export`: `0` уписано, `2` нечитљив улаз, непотпуно скенирање без `--allow-partial` или подаци који се не могу безбедно извести, `1` скрипта није могла бити уписана.

## Верзионисање и процес објављивања

hostcensus прати [Семантичко верзионисање](https://semver.org/spec/v2.0.0.html): компатибилне исправке повећавају patch верзију, компатибилне могућности и ознаке застарелости повећавају minor верзију, а некомпатибилне промене повећавају major верзију. Команде и опције, излазни кодови и JSON шеме представљају јавни уговор; застарело понашање наставља да ради до наредног великог издања, осим ако безбедносна исправка не захтева ранију измену (тада дневник промена објашњава разлог).

release-please отвара PR за издање из наслова Conventional Commit порука на грани `main`, ажурирајући `pyproject.toml`, `uv.lock` и `CHANGES.md`. Спајање тог PR-а креира ознаку `vMAJOR.MINOR.PATCH` и нацрт GitHub издања на који CI прилаже тестирани wheel, изворну дистрибуцију и контролне суме; GitHub чува атестације изградње за те датотеке преко свог API-ја за атестације. Одржавалац прегледа и објављује нацрт након прилагања датотека. Издања се никада не замењују.

Поуздано објављивање на PyPI је опционо и захтева власништво над пројектом, поузданог издавача и окружење `pypi`. Објављује исте проверене артефакте издања без поновне изградње и без чувања API токена. Означена издања у овом јавном репозиторијуму генеришу GitHub атестације артефаката; приватни форкови захтевају подржан план и експлицитно укључивање. Погледајте [потпуни водич за издања](../../../docs/releasing.md) за подешавање, тачне команде и поновне покушаје.

## Развој

```bash
uv sync --locked                 # runtime plus the default `dev` group
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=hostcensus
uv build --no-build-isolation
uv run twine check --strict dist/*.whl dist/*.tar.gz
```

Развојни алати налазе се у [PEP 735](https://peps.python.org/pep-0735/) групама зависности у датотеци `pyproject.toml` (`dev`, `fuzz`, `build`), па се никада не појављују у објављеним метаподацима пакета. `uv.lock` је једина lock датотека; CI инсталира командом `uv sync --locked` и пада када је lock датотека застарела. Одаберите интерпретер преко `uv python`, mise (`mise exec python@3.14 -- uv sync --locked`) или било ког Python-а 3.12+.

CI намеће праг покривености пакета тестовима од 90%. Јединични тестови укључују контролисане loopback сервере и ванмрежне случајеве за профиле, историју и валидацију издања; Compose лабораторија покреће OpenSSH, MariaDB, nginx и net-snmp на изолованом мосту. Покрените је командом `make test-integration`. Погледајте [CONTRIBUTING.md](../../../CONTRIBUTING.md) и [алате за издања](../../../scripts/README.md).

Контејнер за извршавање ради под UID/GID 10001 без кућног директоријума, без пријаве у љуску и без алата pip, а може да пише у `/app/output`. Дајте том кориснику право писања у сваки монтирани излазни директоријум. Не захтева никакве додатне способности и ради са коренским системом датотека само за читање, па се може покренути овако:

```sh
docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp -v "$PWD/out:/app/output" IMAGE scan 192.0.2.0/28 -o /app/output/report.json
```

Nmap у овом контејнеру користи своје непривилеговано TCP откривање. CI руши изградњу слике ако Trivy пријави било коју поправљиву рањивост нивоа HIGH или CRITICAL.

[OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/somethingwithproof/python-network-discovery-tool) извршава се на грани main и недељно, објављује свој стварни резултат и учитава налазе у GitHub скенирање кода. Акције и основне слике контејнера фиксиране су непроменљивим хешевима; Python зависности разрешене су у `uv.lock`. Грешке алата Bandit руше CI, а ограничени Atheris fuzzing испитује SSH, MySQL, HTTP, сертификат и SNMPv3 BER парсере без мрежног приступа.

Scorecard такође мери историјску активност прегледа, разноликост сарадника и порекло издања. Ти резултати одражавају стварне доказе; они нису тврдња да је свака провера управљања или историјских издања испуњена.
