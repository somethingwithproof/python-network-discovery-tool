நீங்கள் நிர்வகிக்கும் பிணையங்களில் மீண்டும் மீண்டும் செயல்படுத்தக்கூடிய சேவைப் பட்டியலிடலுக்கான ஒரு Python CLI கருவி hostcensus ஆகும். சாதனங்கள் எவற்றை வெளிப்படுத்துகின்றன என்பதை இது பதிவு செய்கிறது, காலப்போக்கில் எடுக்கப்பட்ட ஆய்வுகளை ஒப்பிடுகிறது, மேலும் Kadupul இறக்குமதி ஸ்கிரிப்டுகளை உருவாக்குகிறது. இயல்புநிலை பின்புலம் root அனுமதி இல்லாமல் asyncio சாக்கெட்டுகளைப் பயன்படுத்துகிறது; விருப்பத்தேர்வான Nmap கண்டறிதல் கட்டமைக்கப்பட்ட சேவை போர்ட்டுகளுக்கு அப்பாலும் உள்ள ஹோஸ்ட்களை அடையாளம் காண முடியும்.

## ஏன் hostcensus

ஒருமுறை மட்டுமே எடுக்கும் போர்ட் அறிக்கை, அடுத்த ஆய்வில் மாற்றம் ஏற்பட்டதா அல்லது அது தோல்வியடைந்ததா என்பதை விளக்காது. hostcensus தெளிவான சேவை நிலைகள், வரையறுக்கப்பட்ட ஆய்வுகள், மீண்டும் பயன்படுத்தக்கூடிய ஸ்கேன் சுயவிவரங்கள் மற்றும் உள்ளூர் வரலாறு ஆகியவற்றை ஒருங்கிணைக்கிறது. இயக்குநர்கள் ஒரே வரம்பை மீண்டும் இயக்கலாம், பிழைகளை ஆராயலாம், மேலும் உறுதிப்படுத்தப்படாத ஆய்வுகளையும் உறுதிப்படுத்தப்பட்ட மாற்றங்களையும் வேறுபடுத்தி அறியலாம்.

- **சேவைச் சான்றுகள்:** SSH அடையாளப்படுத்தல், MySQL வரவேற்புச் செய்திகள், HTTP தலைப்புகள், TLS சான்றிதழ் ஆய்வுகள் மற்றும் SNMP கண்டறிதல் அல்லது சான்றுகளுடன் கூடிய system-MIB வினவல்கள்.
- **மீண்டும் பயன்படுத்தக்கூடிய வரம்பு:** பெயரிடப்பட்ட TOML சுயவிவரங்கள், சேர்க்கை விலக்குகள், கட்டமைக்கக்கூடிய சேவைகள், ஹோஸ்ட்/ஆய்வு வரம்புகள் மற்றும் வரையறுக்கப்பட்ட பணியாளர்கள்.
- **போக்குவரத்திற்கு முன் சரிபார்ப்புகள்:** உள்ளூர் முன்-சரிபார்ப்பு இலக்குகள், கருவிகள், சேருமிட அணுகல், வரலாற்றுத் திட்டம் மற்றும் கட்டமைக்கப்பட்ட TLS CA தொகுப்புகளைச் சரிபார்க்கிறது.
- **பட்டியல் வரலாறு:** பரிவர்த்தனை அடிப்படையிலான SQLite ஸ்னாப்ஷாட்கள் அனைத்து ஆய்வுகளையும் தக்கவைக்கின்றன; ஒப்பீடுகள் ஸ்கேனர் பிழைகள் மற்றும் அறியப்படாத நிலைகளைத் தெளிவாகக் காட்டுகின்றன.
- **இடைசெயல்பாட்டு வெளியீடு:** முனையம், JSON மற்றும் CSV அறிக்கைகள், பதிப்பிடப்பட்ட கோப்பு ஸ்னாப்ஷாட்கள் மற்றும் Kadupul இறக்குமதி ஸ்கிரிப்டுகள்.

CI சோதனையானது Linux மற்றும் macOS-இல் Python 3.12, 3.13 மற்றும் 3.14 ஆகியவற்றையும், கட்டுப்படுத்தப்பட்ட Compose ஒருங்கிணைப்பு ஆய்வகத்தையும் உள்ளடக்கியது. இந்த இயக்க நேரப் பதிப்புகளைத் தக்கவைத்துக் கொண்டே, நவீன வகை மாற்றுப் பெயர்கள், வகைப்படுத்தப்பட்ட முன்-சரிபார்ப்பு முடிவுகள், திறவுச்சொல்-மட்டும் கொண்ட ஸ்லாட் சுயவிவரங்கள் மற்றும் கட்டமைக்கப்பட்ட async சுத்திகரிப்பு ஆகியவற்றை இக்குறியீடு பயன்படுத்துகிறது. SemVer இணக்க ஒப்பந்தம் மற்றும் GitHub வெளியீட்டு செயல்முறைக்கு [பதிப்பிடல் மற்றும் வெளியீடுகள்](../../../docs/releasing.md) என்பதைப் பார்க்கவும். வெளியீட்டுப் பேட்ஜ் வெளியிடப்பட்ட கலைப்பொருட்களை விவரிக்கிறது, தற்போதைய செக்அவுட்டை அல்ல: தற்போது சமீபத்திய வெளியிடப்பட்ட குறிச்சொல் `v0.3.0` ஆகும், அதே சமயம் இந்த செக்அவுட் `3.0.0` என்ற தொகுப்புப் பதிப்பைப் பயன்படுத்துகிறது. இங்கே ஆவணப்படுத்தப்பட்டுள்ள பட்டியலிடல் அம்சங்களைப் பயன்படுத்த செக்அவுட்டிலிருந்து நிறுவவும்.

[நிறுவல்](#install) உடன் தொடங்கவும், பின்னர் [சுயவிவரங்கள் மற்றும் வரலாறு](#inventory-profiles-preflight-and-local-history) பகுதியைப் பார்க்கவும். ஒருங்கிணைப்பு விவரங்களுக்கு, [சேவை கைரேகைகள்](#fingerprints), [கோப்பு ஒப்பீடுகள்](#inventory-diff) மற்றும் [Kadupul ஏற்றுமதி](#kadupul-export) ஆகியவற்றைப் பார்க்கவும்.

## நிறுவல்

Python 3.12 அல்லது அதற்குப் பிந்தைய பதிப்பு தேவை; Python 3.12-3.14 என்பது சோதிக்கப்பட்ட பதிப்பு வரிசையாகும். இந்த செக்அவுட்டிலிருந்து, பூட்டப்பட்ட இயக்க நேரச் சார்புகளை நிறுவவும்:

```bash
uv sync --locked
uv run hostcensus --help
uv run hostcensus --version
uv run hostcensus preflight 127.0.0.1
uv run hostcensus scan 127.0.0.1 --services ssh -o loopback.json
```

விருப்பத்தேர்வான Nmap ஹோஸ்ட் கண்டறிதலுக்கு, உங்கள் தளத்தின் தொகுப்பு மேலாளரைப் பயன்படுத்தி Nmap இயங்கக்கூடிய கோப்பை நிறுவவும்; கூடுதல் Python தொகுப்பு எதுவும் தேவையில்லை. Nmap-இன் XML வெளியீடு ஒரு முக்கியச் சார்பான defusedxml மூலம் பாகுபடுத்தப்படுகிறது, எனவே entity expansion மறுக்கப்படுகிறது. hostcensus ஆனது `PATH`-இல் காணப்படும் `nmap`-ஐ நிலையான தருமதிப்புப் பட்டியல், prefix அளவுக்கேற்ப வளரும் காலக்கெடு மற்றும் 64 MiB வெளியீட்டு வரம்புடன் நேரடியாக இயக்குகிறது. இயல்புநிலை பின்புலத்திற்கு Nmap தேவையில்லை.

## netprobe-இலிருந்து இடம்பெயர்தல்

3.0.0 பதிப்பில் வெளியிடப்பட்ட netprobe-இன் புதிய பெயர்தான் hostcensus ஆகும். இத்திட்டம் இரண்டு பெயர்களிலும் PyPI-இல் வெளியிடப்படவில்லை, எனவே நிறுவல்கள் செக்அவுட் அல்லது GitHub வெளியீட்டிலிருந்து வந்தன. GitHub களஞ்சியம் அதன் பழைய பெயரையே தக்கவைத்துள்ளது.

## விரைவு எடுத்துக்காட்டு

மேம்பாடு பிரிவின் கீழ் விவரிக்கப்பட்டுள்ள ஒருங்கிணைப்பு ஆய்வகத்தின் சோதனையாளர் கொள்கலனிலிருந்து இயக்கவும்; வெளியீடு சுருக்கப்பட்டுள்ளது:

```console
$ hostcensus scan 172.30.57.8/29 --services ssh,http,snmp --save-snapshot after.json

│ 172.30.57.10 │ hostcensus-it-s… │ ✅  │  ❌  │  ❌   │ ssh:22         │ UP     │
│              │                │     │      │       │ OpenSSH_10.0   │        │
│ 172.30.57.13 │ hostcensus-it-w… │ ❌  │  ❌  │  ❌   │ http:80        │ UP     │
│              │                │     │      │       │ nginx/1.28.3   │        │

$ hostcensus diff before.json after.json; echo "exit=$?"
Warning: targets differ: 172.30.57.10 vs 172.30.57.8/29
│ new host │ 172.30.57.13 │ http:80/tcp  │ hostcensus-it-web-1.hostcensus-it_lab   │
exit=3

$ hostcensus export after.json -o kadupul-import.sh --template 1
$ grep 57.13 kadupul-import.sh
add --description=hostcensus-it-web-1.hostcensus-it_lab --ip=172.30.57.13 --template=1 --version=0 --avail=ping --ping_method=tcp --ping_port=80 '--notes=hostcensus: http:80/tcp nginx/1.28.3'
```

| தொகுதி | பொறுப்பு |
| --- | --- |

| `scanner.py`, `probes.py` | இலக்கு விரிவாக்கம், வரையறுக்கப்பட்ட பணியாளர்கள், ஹோஸ்ட் கண்டறிதல் மற்றும் சேவை ஆய்வுகள் |
| `config.py`, `profiles.py` | சேவை வரையறைகள் மற்றும் சரிபார்க்கப்பட்ட பட்டியல் சுயவிவரங்கள் |

ஒவ்வொரு சேவை ஆய்வும் அதன் நிலையை, அது விளம்பரப்படுத்தும் அடையாளத்திலிருந்து தனித்தனியாகப் பதிவு செய்கிறது. வாசிப்புகள் மற்றும் காலக்கெடுகள் வரையறுக்கப்பட்டுள்ளன; ஆய்வு விதிவிலக்குகள் ஹோஸ்ட் பிழைகளில் இருக்கும். SQLite வரலாறு பரிவர்த்தனைகள், வெளிப்படையான இணைப்பு சுத்திகரிப்பு மற்றும் படிக்க-மட்டும் பட்டியலிடல் மற்றும் ஒப்பீட்டுப் பாதைகளைப் பயன்படுத்துகிறது. SNMP ரகசியங்கள் சூழல் மாறிகள் அல்லது ரகசியக் கோப்புகள் வழியாக மட்டுமே உள்ளிடப்படுகின்றன; பட்டியல் வரலாறு பயனுள்ள ரகசியமற்ற அமைப்புகளைச் சேமிக்கிறது. ஸ்கேன் குழாய், அதன் வரம்புகள் மற்றும் நம்பிக்கை எல்லைகளுக்கு [கட்டமைப்பு](../../../docs/architecture.md) என்பதையும், அங்கீகரிக்கப்பட்ட பயன்பாட்டிற்கு [SECURITY.md](../../../SECURITY.md#authorized-use) என்பதையும் பார்க்கவும்.


## பயன்பாடு

நீங்கள் நிர்வகிக்கும் பிணையங்களை மட்டுமே ஸ்கேன் செய்யவும்.

```bash
hostcensus scan 192.168.1.0/24              # table of alive hosts
hostcensus scan 192.168.1.1 -o results.json # JSON report
hostcensus scan 10.0.0.0/24 -o report.csv   # CSV report
hostcensus scan 10.0.0.0/24 -q -o out.json  # no table, file only
hostcensus scan 10.0.0.0/24 --format json | jq '.devices[]'  # JSON report on stdout
```

| விருப்பத்தேர்வு | பொருள் |
| --- | --- |
| `NETWORK` | CIDR, IP அல்லது ஹோஸ்ட்பெயர்; `--profile` உடன் விருப்பத்தேர்வானது. IPv6 வரம்பு அடையாளங்காட்டிகள் நிராகரிக்கப்படும். |

| `-f, --format json\|csv\|kadupul\|auto` | அறிக்கை வடிவத்தைக் கட்டாயப்படுத்துகிறது. `--output` இல்லாமல் எந்த விளைவும் இல்லை. `.sh` என்பது `kadupul`-ஐத் தேர்ந்தெடுக்கும். |

| `--backend asyncio\|nmap` | ஹோஸ்ட் கண்டறிதல். `asyncio` (இயல்புநிலை) சேவை போர்ட்டுகளை நேரடியாக ஆய்வு செய்கிறது; `nmap` முதலில் ஒரு nmap ping sweep-ஐ இயக்கும் மற்றும் `PATH`-இல் `nmap` இயங்கக்கூடிய கோப்பு தேவை. |

| `--profile NAME` | பெயரிடப்பட்ட சுயவிவரத்தைப் பயன்படுத்துகிறது; `--config` தவிர்க்கப்படும்போது `hostcensus.toml`-ஐ இயல்புநிலையாகப் பயன்படுத்தும். |
| `--exclude IP/CIDR` | விலக்கு ஒன்றைச் சேர்க்கிறது; தேவைக்கேற்ப மீண்டும் பயன்படுத்தவும். விலக்கப்பட்ட ஒரு IPv4 ஹோஸ்ட், அதை அடையும் IPv6 முகவரிகளையும் விலக்குகிறது: IPv4-mapped (`::ffff:a.b.c.d`), NAT64 (`64:ff9b::/96`) மற்றும் 6to4. IPv4-mapped இலக்குகள் மற்றும் விலக்குகள் அவை குறிக்கும் IPv4 முகவரிகளாகவே கருதப்படுகின்றன. |
| `--max-hosts N` | விலக்குகளுக்கு முன் சரிபார்க்கப்படும் முகவரி வரம்பு (இயல்புநிலை/உச்ச வரம்பு 65,536). |
| `--history PATH` | முடிக்கப்பட்ட ஸ்கேனை விருப்பத்தேர்வான SQLite வரலாற்றுத் தரவுத்தளத்தில் பதிவு செய்கிறது. |
| `--services NAMES` | சரிபார்க்க வேண்டிய சேவைப் பெயர்களின் காற்புள்ளிப் பட்டியல், அந்த வரிசையில் (இயல்புநிலை: அனைத்தும்). |
| `--ports SPEC` | `NAME=PORT` (ஒரு சேவையை நகர்த்த) அல்லது `PORT` (`tcp-PORT` என்ற சாதாரண TCP சரிபார்ப்பைச் சேர்க்க) ஆகியவற்றின் காற்புள்ளிப் பட்டியல். |
| `--snmp-community-file PATH` | system MIB வினவலுக்கான SNMPv2c community-ஐக் கொண்ட கோப்பு. சூழல் மாறி: `HOSTCENSUS_SNMP_COMMUNITY` (மதிப்பு) அல்லது `HOSTCENSUS_SNMP_COMMUNITY_FILE` (பாதை). |
| `--snmp-user` | SNMPv3 பயனர். சூழல் மாறி: `HOSTCENSUS_SNMP_USER`. |
| `--snmp-auth-protocol`, `--snmp-auth-key-file PATH` | `MD5`, `SHA` (இயல்புநிலை), `SHA224`, `SHA256`, `SHA384`, `SHA512` மற்றும் கடவுச்சொற்றொடரைக் கொண்ட கோப்பு. சூழல் மாறி: `HOSTCENSUS_SNMP_AUTH_PROTOCOL`, `HOSTCENSUS_SNMP_AUTH_KEY` அல்லது `HOSTCENSUS_SNMP_AUTH_KEY_FILE`. |
| `--snmp-priv-protocol`, `--snmp-priv-key-file PATH` | `DES`, `AES` (இயல்புநிலை), `AES128`, `AES192`, `AES192C`, `AES256`, `AES256C` மற்றும் கடவுச்சொற்றொடரைக் கொண்ட கோப்பு. சூழல் மாறி: `HOSTCENSUS_SNMP_PRIV_PROTOCOL`, `HOSTCENSUS_SNMP_PRIV_KEY` அல்லது `HOSTCENSUS_SNMP_PRIV_KEY_FILE`. |
| `--save-snapshot PATH` | `hostcensus diff`-க்காகப் பதிப்பிடப்பட்ட ஸ்னாப்ஷாட்டையும் எழுதுகிறது. |
| `--tls-ca-file PATH` | கணினிச் சேமிப்பகத்திற்குப் பதிலாக இந்த PEM தொகுப்பிற்கு எதிராக HTTPS சான்றிதழ்களைச் சரிபார்க்கிறது. சூழல் மாறி: `HOSTCENSUS_TLS_CA_FILE`. |

இயல்புநிலையாக ஒவ்வொரு ஹோஸ்டும் SSH (TCP 22), SNMP (UDP 161), MySQL (TCP 3306), HTTP (TCP 80) மற்றும் HTTPS (TCP 443) ஆகியவற்றிற்காகச் சரிபார்க்கப்படுகிறது. TCP போர்ட்டுகள் முழு connect மூலம் சோதிக்கப்படுகின்றன. SNMP ஆனது SNMPv3 engine-discovery கோரிக்கையுடன் சோதிக்கப்படுகிறது, இதற்கு எந்தவொரு SNMPv3 முகவராலும் சான்றுகள் இல்லாமல் பதிலளிக்க வேண்டும்; v1/v2c மட்டும் பேசும் முகவர்கள் இந்த ஆய்வால் கண்டறியப்படமாட்டார்கள். asyncio பின்புலத்துடன், மறுக்கப்பட்ட இணைப்பு உட்பட எந்தவொரு ஆய்வும் பதில் பெற்றால் ஒரு ஹோஸ்ட் உயிருடன் இருப்பதாகக் கணக்கிடப்படும்; எனவே ஒவ்வொரு ஆய்வையும் கைவிடும் ஒரு ஹோஸ்ட் `alive=false` மற்றும் "Host is down" என்ற பிழையைப் பெறும்; இது அது இயற்பியல் ரீதியாக முடங்கியுள்ளது என்பதை நிரூபிக்காது. `--backend nmap` உடன், எந்த ஹோஸ்ட்கள் உயிருடன் உள்ளன என்பதை nmap தீர்மானிக்கிறது (root ஆக ICMP, இல்லையெனில் TCP 80/443).

### கைரேகைகள்

திறந்திருக்கும் ஒவ்வொரு சேவையும் உள்நுழைவதற்கு முன்பு அது அனுப்புவதிலிருந்து கைரேகை எடுக்கப்படுகிறது. SNMP வினவலைத் தவிர வேறு எதுவும் அங்கீகாரம் செய்வதில்லை, அதுவும் நீங்கள் சான்றுகளை வழங்கும்போது மட்டுமே.

| ஆய்வு | படிப்பது | `version` | `details` திறவுகோல்கள் |
| --- | --- | --- | --- |
| `ssh` | RFC 4253 அடையாள வரி | மென்பொருள், எ.கா. `OpenSSH_10.0` | `protocol`, `software`, `comments` |
| `mysql` | MySQL/MariaDB ஆரம்ப கைகுலுக்கல் | சேவையகப் பதிப்பு | `server_version`, `flavor`, `auth_plugin`, அல்லது `error_code`/`error` |
| `http` | `HEAD /` பதில் | `Server` தலைப்பு | `status`, `server` |
| `https` | TLS கைகுலுக்கல், சான்றிதழ், `HEAD /` | `Server` தலைப்பு | `tls_version`, `cert_verified`, `cert_verify_error`, `cert_subject`, `cert_issuer`, `cert_sans`, `cert_not_before`, `cert_not_after` (UTC ISO 8601), `cert_self_signed`, `status`, `server` |
| `snmp` | SNMPv3 கண்டறிதல்; சான்றுகளுடன், sysDescr, sysObjectID, sysName-இன் GET | sysDescr | `engine_id`; சான்றுகளுடன் `snmp_version`, `sys_descr`, `sys_object_id`, `sys_name`, அல்லது `snmp_error` |

ஒரு ஹோஸ்ட்பெயர் இலக்கு ஒவ்வொரு ஹோஸ்டுக்கும் ஒருமுறை தீர்க்கப்பட்டு, ஒவ்வொரு ஆய்வும் அந்த முகவரியுடன் இணைகிறது, இது முடிவுகளில் `address` எனப் பதிவு செய்யப்படுகிறது; பெயர் TLS SNI, சான்றிதழ் சரிபார்ப்பு மற்றும் HTTP `Host` தலைப்பு ஆகியவற்றிற்கு மட்டுமே பயன்படுத்தப்படுகிறது. தீர்க்க முடியாத ஒரு பெயர் `unknown` நிலைகளையும் `Cannot resolve` பிழையையும் தரும். தலைகீழ் DNS பெயர்கள் ஹோஸ்ட்பெயர் எழுத்துக்களைக் கொண்டிருக்கும்போது மட்டுமே தக்கவைக்கப்படும், மேலும் ஒரே நேரத்தில் அதிகபட்சம் 16 தேடல்கள் மட்டுமே இயங்கும். HTTPS ஆனது கணினிச் சேமிப்பகம் அல்லது `--tls-ca-file` ஆகியவற்றிற்கு எதிராகச் சான்றிதழ் மற்றும் ஹோஸ்ட்பெயர் சரிபார்ப்பைப் பயன்படுத்துகிறது. ஸ்கேனுக்காக நம்பிக்கைச் சேமிப்பகம் ஒருமுறை ஏற்றப்பட்டு ஒவ்வொரு HTTPS ஆய்வுக்கும் மீண்டும் பயன்படுத்தப்படுகிறது. TCP இணைப்பு மற்றும் TLS கைகுலுக்கல் ஆகியவை தனித்தனியாக நேர வரம்பிட்டு அளவிடப்படுகின்றன, எனவே இணைப்புகளை ஏற்றுக்கொண்டு கைகுலுக்கலைத் தாமதப்படுத்தும் ஒரு போர்ட் `filtered` என அல்லாமல் `tls_error` உடன் `open` எனக் குறிக்கப்படும். சரிபார்ப்பு தோல்வியடைந்தால், முடிவு `cert_verified: false` மற்றும் `cert_verify_error` ஆகியவற்றைப் பதிவு செய்கிறது; அது பலவீனமான அமைப்புகளுடன் மீண்டும் முயற்சிக்காது அல்லது HTTP கோரிக்கையை அனுப்பாது. சான்றிதழ் விவரங்கள் மற்றும் HTTP தலைப்புகள் சரிபார்ப்பு வெற்றியடைந்த பிறகே சேகரிக்கப்படுகின்றன. தனியார்-CA சேவைகளுக்குச் சரியான CA தொகுப்பை வழங்கவும். பழைய அறிக்கைகளில் `cert_read_unverified` இருக்கலாம், அதைத் தற்போதைய ஆய்வுகள் இனி உருவாக்குவதில்லை.

SNMP ரகசியங்கள் சூழல் மாறிகள் அல்லது கோப்புகளிலிருந்து (`--snmp-*-file`, அல்லது பொருந்தக்கூடிய `HOSTCENSUS_SNMP_*_FILE` மாறி) மட்டுமே படிக்கப்படுகின்றன, செயல்முறைப் பட்டியலில் பிற உள்ளூர் பயனர்கள் பார்க்கக்கூடிய கட்டளை-வரி மதிப்புகளிலிருந்து ஒருபோதும் படிக்கப்படுவதில்லை. மதிப்புடன் கூடிய `--snmp-community`, `--snmp-auth-key` மற்றும் `--snmp-priv-key` ஆகியவை குறியீடு 2 உடன் வெளியேறி மாற்று வழிமுறையைப் பெயரிடுகின்றன. ஒரு ரகசியக் கோப்பு அதிகபட்சம் 4096 பைட்டுகள் கொண்ட வெறுமையற்ற UTF-8 ஆக இருக்க வேண்டும்; இறுதியில் உள்ள ஒரு புதிய வரி புறக்கணிக்கப்படும், மேலும் ஒரே ரகசியத்திற்கு ஒரு மாறி மற்றும் ஒரு கோப்பு இரண்டையும் அமைப்பது பிழையாகும். பிழைகள் கோப்பின் பெயரைக் குறிப்பிடும் ஆனால் அதன் உள்ளடக்கத்தை ஒருபோதும் அச்சிடாது. ஸ்கேன் அறிக்கைகள் மற்றும் வரலாறு வேண்டுமென்றே சான்று மதிப்புகளை உள்ளடக்குவதில்லை. ஏற்றுமதியாளர் கீழே விவரிக்கப்பட்டுள்ளபடி தனி, வெளிப்படையான `--include-credentials` விருப்பத்தேர்வைக் கொண்டுள்ளது. ஒரு community ஆனது SNMPv2c-ஐத் தேர்ந்தெடுக்கிறது; ஒரு பயனர் SNMPv3-ஐத் தேர்ந்தெடுக்கிறார், auth திறவுகோல் கொடுக்கப்படும்போது அங்கீகாரத்துடனும் இரண்டு திறவுகோல்களும் கொடுக்கப்படும்போது தனியுரிமையுடனும் இருக்கும் (`snmp_security_level` எது என்பதைப் பதிவு செய்கிறது). hostcensus ஆனது வெளியேறு குறியீடு 2 உடன் ஒரு community-ஐ v3 பயனருடன் இணைக்க, auth திறவுகோல் இல்லாமல் தனியுரிமைத் திறவுகோலைப் பயன்படுத்த, அல்லது பயனர் இல்லாமல் திறவுகோல்களைப் பயன்படுத்த மறுக்கிறது, மேலும் தோல்வியுற்ற v3 வினவலை v2c அல்லது குறைந்த பாதுகாப்பு நிலையுடன் ஒருபோதும் மீண்டும் முயற்சிக்காது. v1/v2c மட்டும் பேசும் முகவர்கள் சான்று-இல்லாத v3 கண்டறிதலைப் புறக்கணிக்கின்றன, எனவே ஒரு community வழங்கப்படும்போது மட்டுமே அவை open எனக் காண்பிக்கப்படும்.

பேனர் உரை சேமிக்கப்படுவதற்கு அல்லது காட்டப்படுவதற்கு முன்பு அச்சிடக்கூடிய எழுத்துக்களாகக் குறைக்கப்பட்டு 256 எழுத்துக்களுக்குள் வரையறுக்கப்படுகிறது. வாசிப்புகளும் வரையறுக்கப்பட்டுள்ளன: ஒரு வரிக்கு 4 KiB, MySQL வரவேற்புச் செய்திக்கு 4 KiB, HTTP தலைப்புகளுக்கு 16 KiB. 32 ஆக்டெட்டுகளுக்கு மேல் உள்ள SNMP engine ID சேமிக்கப்படுவதற்கு முன்பு துண்டிக்கப்படுகிறது. HTTP மற்றும் HTTPS ஆகியவை IPv6 முகவரியை அடைப்புக்குறிகளுக்குள்ளும், 80 அல்லது 443 அல்லாதபோது போர்ட்டுடனும் ஒரு Host தலைப்பை அனுப்புகின்றன. விரிதாள் சூத்திரத் தூண்டுதலுடன் தொடங்கும் CSV செல்கள் உரையாகவே இருக்க முன்னொட்டு சேர்க்கப்படுகின்றன.

### வரம்புகள்

ஒரு இயக்கம் அதிகபட்சம் 65,536 முகவரிகள், 64 சேவைகள் மற்றும் 524,288 ஆய்வுகளை (ஹோஸ்ட்கள் பெருக்கல் சேவைகள்) ஏற்றுக்கொள்கிறது; பெரிய கோரிக்கைகள் எதுவும் அனுப்பப்படுவதற்கு முன்பே வெளியேறு குறியீடு 2 உடன் வெளியேறும். `--concurrency` ஆனது 4096 சாக்கெட்டுகளுக்குள் வரையறுக்கப்பட்டுள்ளது. ஒவ்வொரு ஆய்வுக்கும் அதன் சொந்த வரம்பை விட நான்கு மடங்கு கடினமான காலக்கெடு உள்ளது. அந்தச் சேவை `timeout` அமைக்காவிட்டால் Connect ஆய்வுகள் (`tcp`, `ssh`, `mysql`, `http`) 0.3 வினாடிகளைப் பயன்படுத்தும். SNMP மற்றும் HTTPS ஆகியவை அமைக்காதபோது `--timeout` (இயல்புநிலை 1.0) பயன்படுத்துகின்றன. காலக்கெடுவை எட்டும் ஒரு ஆய்வு `errors`-இல் "probe timed out" உடன் `unknown` எனப் புகாரளிக்கப்படுகிறது. உள்ளூர் சாக்கெட் தோல்விகளும் (எடுத்துக்காட்டாக கோப்பு விவரிப்பான்கள் தீர்ந்துபோதல்) பிழை பதிவு செய்யப்பட்டு `unknown` ஆகும்; அவை ஒருபோதும் வடிகட்டப்பட்ட போர்ட்டாகவோ அல்லது முடங்கிய ஹோஸ்டாகவோ கணக்கிடப்படாது. ஆய்வு செய்வதற்கு முன்பு, `--concurrency` மற்றும் 64 விவரிப்பான்களுக்குப் பொருந்துமாறு திறந்த-கோப்பு மென் வரம்பை கடின வரம்பை நோக்கி hostcensus உயர்த்துகிறது; அவ்வாறு செய்ய முடியாதபோது, `open files` முன்-சரிபார்ப்பு தோல்வியடைந்து போக்குவரத்தை அனுப்புவதற்கு முன்பு `scan` குறியீடு 1 உடன் வெளியேறுகிறது. Nmap கண்டறிதல் 30-வினாடி ஹோஸ்ட் காலக்கெடுவைப் பயன்படுத்துகிறது. ஒரு prefix ஆனது CIDR வடிவத்தில் nmap-க்கு அனுப்பப்படுகிறது, மேலும் ஹோஸ்ட்களை முடங்கியதாகக் குறிப்பதற்குப் பதிலாக nmap தனக்குக் கொடுக்கப்பட்டதை விடக் குறைவான முகவரிகளைப் புகாரளிக்கும்போது (எடுத்துக்காட்டாக அதனால் தீர்க்க முடியாத ஒரு பெயர்) ஒரு sweep வெளியேறு குறியீடு 1 உடன் தோல்வியடைகிறது. ஒரு ஹோஸ்ட்பெயர் இலக்கு ஒருமுறை தீர்க்கப்பட்டு nmap-க்கு அந்த முகவரி கொடுக்கப்படுகிறது, எனவே கண்டறிதலும் ஆய்வுகளும் ஒரே இயந்திரத்தை அடைகின்றன. ஒரு முழு prefix என்பது ஒரு nmap செயல்முறையாகும், அதன் துணைச்செயல்முறை காலக்கெடு ஒவ்வொரு 256 முகவரிகளுக்கும் 35 வினாடிகள், முழுமையாக்கப்பட்டது. விலக்குகளுடன் கூடிய sweep-கள் 256 ஹோஸ்ட்கள் கொண்ட தொகுப்புகளையும் ஒவ்வொரு தொகுப்புக்கும் 35-வினாடி காலக்கெடுவையும் பயன்படுத்துகின்றன. வரம்பு அளவைச் சாராமல் பணியாளர் உருவாக்கம் வரையறுக்கப்பட்டுள்ளது. தலைகீழ் DNS மற்றும் ஹோஸ்ட்பெயர் தீர்வு ஆகியவை தனி இரண்டு-வினாடி காலக்கெடுவைக் கொண்டுள்ளன; ஒருபோதும் திரும்பாத ஒரு தீர்வு அழைப்பு அதன் சொந்தத் திரியில் கைவிடப்படுகிறது, எனவே அது இந்த வரம்புகளுக்கு அப்பால் hostcensus இயங்குவதைத் தக்கவைக்க முடியாது. ஒரே நேரத்தில் அதிகபட்சம் 16 தேடல்கள் இயங்கும், மேலும் கைவிடப்பட்ட ஒரு அழைப்பு அது திரும்பும் வரை அதன் இடத்தைத் தக்கவைத்துக் கொள்ளும், எனவே சிக்கிய திரிகளின் எண்ணிக்கை வரையறுக்கப்பட்டே இருக்கும்; அனைத்து 16-உம் தொங்கினால், `--deadline` ஸ்கேனை நிறுத்தும் வரை பிந்தைய தேடல்கள் இரண்டு-வினாடி காலக்கெடுவுக்கு வெளியே (ஒரு இடம் காலியானதும் தொடங்கும்) ஒரு இடத்திற்காக வரிசையில் காத்திருக்கும். `deadline` இல்லாமல் ஒரு நூலகமாகப் பயன்படுத்தப்படும் `NetworkScanner` அத்தகைய இடத்திற்காகக் காலவரையின்றி காத்திருக்கக்கூடும். இவற்றிற்கு மேல் `--deadline` (இயல்புநிலை ஒரு மணி நேரம்) முழு இயக்கத்தையும் வரையறுக்கிறது.

### சேவைகளைக் கட்டமைத்தல்

TOML கோப்பு மூலம் சேவைகளை மாற்றலாம்:

```toml
[services.ssh]          # same name as a built-in: replaces it
port = 2222
timeout = 0.5

[services.admin-ui]     # a new service, probed like HTTPS
port = 8443
probe = "https"
```

`probe` என்பது `tcp`, `ssh`, `mysql`, `http`, `https` அல்லது `snmp` ஆகியவற்றில் ஒன்றாகும், மேலும் சேவைப் பெயர் ஒரு ஆய்வாக இருக்கும்போது அதுவே இயல்புநிலையாகும், இல்லையெனில் `tcp` ஆகும். `snmp` மட்டுமே UDP-ஐப் பயன்படுத்துகிறது. சேவைப் பெயர்கள் சிறிய எழுத்துக்கள், இலக்கங்கள், `-` மற்றும் `_` ஆகியவற்றைக் கொண்டிருக்கும். இரண்டு சேவைகள் ஒரே போர்ட் மற்றும் நெறிமுறையைப் பகிர முடியாது; வரலாறு அந்த இணைக்கு ஒரு நிலையைப் பதிவு செய்கிறது. `timeout` விருப்பத்தேர்வானது, வினாடிகளில் இருக்கும், மேலும் குறைந்தது 0.05 ஆக இருக்க வேண்டும். Connect-பாணி ஆய்வுகள் (`tcp`, `ssh`, `mysql`, `http`) இயல்புநிலையாக 0.3 வினாடிகள் ஆகும். சேவை `timeout` அமைக்காதபோது `snmp` மற்றும் `https` ஆகியவை ஸ்கேன் `--timeout`-ஐப் பயன்படுத்துகின்றன. சேவையில் ஏற்கனவே உள்ள வரம்பை `--timeout` மாற்றாது.

JSON அறிக்கைகள் என்பவை `devices`-க்கு அடுத்து இலக்கு, ஆய்வு செய்யப்பட்ட சேவைகள் மற்றும் அமைப்புகளைப் பதிவு செய்யும் பதிப்பிடப்பட்ட ஆவணங்கள் (`"format": "hostcensus-report"`, `"version": 1`) ஆகும்; `-o` இல்லாத `--format json` அட்டவணைக்குப் பதிலாக stdout-இல் அறிக்கையை எழுதுகிறது. ஒவ்வொரு JSON வெளியீட்டிற்கும் வெளியிடப்பட்ட திட்டம் உள்ளது; [JSON வெளியீடு](../../../docs/json-output.md) என்பதைப் பார்க்கவும். சாதனங்கள் அசல் `ip`, `alive`, `ssh`, `snmp`, `mysql`, `hostname` மற்றும் `errors` புலங்களைத் தக்கவைத்து, ஒவ்வொரு ஆய்வின் `name`, `port`, `protocol`, `state` (`open`, `closed`, `filtered`, அல்லது ஆய்வு உள்ளூரில் தோல்வியடைந்தாலோ அதன் காலக்கெடுவை எட்டினாலோ `unknown`), `version` மற்றும் `details` ஆகியவற்றைக் கொண்ட `services` பட்டியலைச் சேர்க்கின்றன. CSV வெளியீடு திறந்தவற்றிற்கான பின் இணைப்பு `services` மற்றும் `versions` நெடுவரிசைகளைப் பெறுகிறது. `ssh`, `snmp` மற்றும் `mysql` பூலியன்கள் அதே பெயர்களைக் கொண்ட சேவைகளைப் பின்பற்றுகின்றன.


## பட்டியல் சுயவிவரங்கள், முன்-சரிபார்ப்பு மற்றும் உள்ளூர் வரலாறு

பெயரிடப்பட்ட சுயவிவரங்கள் தற்போதுள்ள `[services]` வரையறைகளுடன் ஒரு TOML கோப்பைப் பகிர்கின்றன. [hostcensus.example.toml](../../../hostcensus.example.toml)-ஐ `hostcensus.toml` என நகலெடுத்து, நீங்கள் நிர்வகிக்கும் பிணையங்களை அமைக்கவும்:

```toml
[profiles.office]
network = "192.168.1.0/24"
exclusions = ["192.168.1.1"]
services = "ssh,http,https,mysql"
concurrency = 32
timeout = 1.0
max_hosts = 256
backend = "asyncio"
```

```bash
hostcensus profiles --config hostcensus.toml
hostcensus preflight --profile office --config hostcensus.toml
hostcensus scan --profile office --config hostcensus.toml -o report.json
```

`scan` போலவே `preflight`-உம் திறந்த-கோப்புச் சரிபார்ப்புக்கான `--concurrency` உட்பட விருப்பத்தேர்வுகள் மற்றும் சுயவிவரங்களைத் துல்லியமாகத் தீர்க்கிறது, எனவே தேர்ச்சி பெற்ற முன்-சரிபார்ப்பு என்பது `scan` அதே திட்டத்துடன் தொடங்கும் என்பதைக் குறிக்கிறது.

சுயவிவரங்கள் `network`, `exclusions`, `services`, `ports`, `backend`, `timeout`, `concurrency` மற்றும் `max_hosts` ஆகியவற்றை ஏற்கின்றன. `services` மற்றும் `ports` ஆகியவை தற்போதுள்ள காற்புள்ளி-பட்டியல் தொடரியலைப் பயன்படுத்துகின்றன. வெளிப்படையான CLI விருப்பத்தேர்வுகள் சுயவிவர அமைப்புகளை மேலெழுதுகின்றன; மீண்டும் மீண்டும் வரும் `--exclude` விருப்பத்தேர்வுகள் சுயவிவர விலக்குகளுடன் சேர்க்கப்படுகின்றன. `--profile` உடன் கூடிய வெளிப்படையான பிணையம் அந்த சுயவிவரத்தின் IP/CIDR வரம்பிற்குள் இருக்க வேண்டும். நேரடி ஸ்கேன்களுக்கு ஹோஸ்ட்பெயர்கள் தொடர்ந்து ஆதரிக்கப்படுகின்றன, ஆனால் IP விலக்குகளுடன் இணைக்க முடியாது. ஹோஸ்ட் வரம்புகள் விலக்குகளுக்கு முன் பொருந்தும்; மொத்த ஆய்வு வரம்பு அதன் பிறகும் பொருந்தும். விலக்கப்பட்ட ஹோஸ்ட்கள் சேவை சரிபார்ப்புகள் மற்றும் விருப்பத்தேர்வான Nmap கண்டறிதல் ஆகிய இரண்டிலிருந்தும் தவிர்க்கப்படுகின்றன.

ஒவ்வொரு ஸ்கேனும் இலக்குப் போக்குவரத்திற்கு முன்பு உள்ளூர் முன்-சரிபார்ப்புகளைச் செய்கிறது: இலக்கு/ஆய்வு வரம்புகள், சேருமிட அணுகல், விருப்பத்தேர்வான Nmap இயங்கக்கூடிய கோப்பு/உறை கிடைக்கும்தன்மை, வரலாற்றுத் திட்டம் மற்றும் கட்டமைக்கப்பட்ட TLS CA தொகுப்பு. `preflight` JSON-ஐப் புகாரளிக்கிறது மற்றும் இலக்குகளை ஸ்கேன் செய்யாது அல்லது வரலாற்றுத் தரவுத்தளத்தை உருவாக்காது. இது தற்போதுள்ள உள்ளடக்கங்களை மாற்றாமல் சேருமிட அணுகலைச் சோதிக்கத் தற்காலிகமாக ஒரு உடன்பிறப்புக் கோப்பை எழுதுகிறது. இயல்புநிலை asyncio பின்புலத்திற்கு இன்னும் Nmap-ஓ root-ஓ தேவையில்லை. சேருமிடப் பாதைகள் ஹார்ட் இணைப்புகள் உட்பட ஒன்றிலிருந்தும் உள்ளீட்டுக் கட்டமைப்பிலிருந்தும் தனித்தனியாக இருக்க வேண்டும்; சேருமிடக் குறியீட்டு இணைப்புகள் நிராகரிக்கப்படும். தோல்வியுற்ற சரிபார்ப்புகள் 1-ஐத் திருப்பும்; தவறான வரம்பு/கட்டமைப்பு 2-ஐத் திருப்பும்.

அறிக்கை மற்றும் ஏற்றுமதி எழுதுதல்களுக்கு `O_NOFOLLOW` ஆதரவு தேவை. Windows உட்பட அது இல்லாத தளங்களில், சேருமிடத்தைத் திறக்காமல் அல்லது துண்டிக்காமல் இந்த எழுதுதல்கள் தோல்வியடையும். புதிய அறிக்கைகள் மற்றும் ஏற்றுமதி ஸ்கிரிப்டுகள் உரிமையாளர்-மட்டுமானவை (mode 0600); ஏற்கனவே உள்ள கோப்பை மாற்றுவது அதன் அனுமதிகளைப் பாதுகாக்கிறது. வாசிப்பாளர் இல்லாத பெயரிடப்பட்ட குழாயில் எழுதுவது காத்திருக்காமல் உடனடியாகத் தோல்வியடையும். ஒரு புதிய `--history` தரவுத்தளமும் உரிமையாளர்-மட்டுமானதாக உருவாக்கப்படுகிறது; ஏற்கனவே உள்ள ஒன்று அதன் பயன்முறையைத் தக்கவைக்கிறது. பதிவுச் செய்திகள் எப்போதும் stderr-க்குச் செல்கின்றன, எனவே stdout முடிவுகளை மட்டுமே கொண்டு செல்கிறது. சான்றுகளைக் கொண்ட ஏற்றுமதிகள் எப்போதும் mode 0600-ஐக் கட்டாயப்படுத்துகின்றன.

வரலாறு விருப்பத்தேர்வானது மற்றும் தற்போதுள்ள JSON ஸ்னாப்ஷாட்கள் மற்றும் `diff` கட்டளைக்குத் துணையாக உள்ளது:

```bash
mkdir -p output
hostcensus scan --profile office --history output/inventory.sqlite3
# Repeat later with the same targets and service selection.
hostcensus scan --profile office --history output/inventory.sqlite3
hostcensus history --history output/inventory.sqlite3 --limit 20
hostcensus compare 1 2 --history output/inventory.sqlite3
hostcensus compare 1 2 --history output/inventory.sqlite3 -o output/changes.json
```

`history`-இலிருந்து ID-களைப் பயன்படுத்தவும்; எடுத்துக்காட்டு ஒரு புதிய தரவுத்தளத்தைக் கருதுகிறது. ஸ்னாப்ஷாட்கள் UTC தொடக்க/முடிவு நேரங்கள், தொகுப்புப் பதிப்பு, பயனுள்ள ரகசியமற்ற அமைப்புகள், சுருக்கங்கள் மற்றும் ஒவ்வொரு ஹோஸ்டுக்கான பிழைகள் உட்பட அனைத்து ஹோஸ்ட்/சேவை ஆய்வுகளுடன் பரிவர்த்தனை முறையில் சேமிக்கப்படுகின்றன. முழுமையற்ற ஹோஸ்ட் ஆய்வுகள் தக்கவைக்கப்படுகின்றன. ரத்து செய்யப்பட்ட இயக்கங்கள் சேமிக்கப்படுவதில்லை. தற்போதுள்ள அறிக்கை, ஸ்னாப்ஷாட், ஏற்றுமதி மற்றும் ஸ்கேன் வெளியேறு-குறியீடு ஒப்பந்தங்கள் பாதுகாக்கப்படுகின்றன.

`history` அனைத்து வரலாற்றுச் சாதனப் பொதிகளையும் படிக்காமல் JSON சுருக்கங்களைப் பட்டியலிடுகிறது. `compare` சேமிக்கப்பட்ட இரண்டு ஸ்கேன்களைப் படிக்கிறது, ஒத்த இலக்கு அடையாளங்கள் மற்றும் தேர்ந்தெடுக்கப்பட்ட போர்ட்டுகளைக் கோருகிறது, மேலும் பதிலளிக்கும் தன்மை, நிலை மற்றும் போர்ட்-நிலை மாற்றங்களைப் புகாரளிக்கிறது. முந்தைய ஸ்கேன் ID பிந்தைய ID-க்கு முன்பு இருக்க வேண்டும். இரண்டு ஸ்கேன்களும் `timeout` அல்லது `backend`-ஐப் பதிவு செய்து அந்த மதிப்புகள் வேறுபடும்போது, அறிக்கை ஒரு எச்சரிக்கையைப் பட்டியலிட்டு ஆய்வுகளைத் தொடர்ந்து ஒப்பிடுகிறது. வேறுபட்ட காத்திருப்பு நேரம் ஒரு வடிகட்டப்பட்ட போர்ட்டைத் திறந்ததாகக் காட்டக்கூடும். ஸ்கேனர் பிழைகள் மற்றும் அறியப்படாத போர்ட் ஆய்வுகள் உறுதிப்படுத்தப்பட்ட மறைவு அல்லது மூடலாகக் கருதப்படாமல் நிச்சயமற்றவையாகக் கொடியிடப்படுகின்றன: பிழைகள் உள்ள ஹோஸ்ட்கள் `uncertain_hosts`-இல் தோன்றும், மேலும் `unknown`-ஐ உள்ளடக்கிய ஒவ்வொரு போர்ட் மாற்றமும் (இரண்டு ஸ்கேன்களிலும் unknown உட்பட) `port_changes`-க்குப் பதிலாக `unconfirmed_ports`-இல் பட்டியலிடப்படும், பிந்தைய ஸ்கேனில் திறந்திருக்கும் ஒரு போர்ட் தவிர, அது ஒரு போர்ட் மாற்றமாகும். `compare` மற்றும் `diff` ஆகியவை ஒரே விதியுடன் போர்ட்டுகளை வகைப்படுத்துகின்றன. `no_longer_responding` என்பது பதில் இல்லாமையைக் குறிக்கிறது, சாதனம் அகற்றப்பட்டதற்கான ஆதாரம் அல்ல. ஸ்கேன் வெளியேறு குறியீடு 0 என்பது ஒவ்வொரு ஹோஸ்டும் பதிலளித்தது என்பதை உறுதிப்படுத்தாது: ஹோஸ்ட்-வாரி பிழைகளை ஆராயவும். மாற்றங்கள் இருந்தாலும் இல்லாவிட்டாலும் ஒப்பீட்டு வெற்றி 0-ஐத் திருப்பும்; தற்போதுள்ள கோப்பு `diff` அதன் வெளியேறு குறியீடு 3 ஒப்பந்தத்தைத் தக்கவைக்கிறது. ஆதரிக்கப்படாத அல்லது சிதைந்த வரலாறு 1-ஐத் திருப்பும்.

வரலாறு பட்டியல் தகவலைச் சேமிக்கிறது, எனவே சரியான முறையில் பாதுகாக்கப்பட்ட உள்ளூர் கோப்பகத்தைத் தேர்ந்தெடுக்கவும். சுயவிவரக் கோப்புகள் மற்றும் சேமிக்கப்பட்ட அமைப்புகளில் SNMP சான்றுகள் இல்லை; சான்று கையாளுதல் தற்போதுள்ள இயக்க நேர விருப்பத்தேர்வுகள்/சூழல் வழியாகத் தொடர்கிறது.

## பட்டியல் வேறுபாடு

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot monday.json
hostcensus scan 10.0.0.0/24 -q --save-snapshot tuesday.json
hostcensus diff monday.json tuesday.json             # table
hostcensus diff monday.json tuesday.json -f json     # JSON on stdout
```

ஒரு ஸ்னாப்ஷாட் என்பது `format: "hostcensus-snapshot"`, `version: 1`, hostcensus பதிப்பு, UTC உருவாக்க நேரம், இலக்கு, ஸ்கேன் அவற்றைப் பதிவு செய்திருந்தால் ஸ்கேன் `timeout` மற்றும் `backend`, ஆய்வு செய்யப்பட்ட சேவைகள் மற்றும் `-o` அறிக்கையின் அதே வடிவத்தில் உயிருடன் உள்ள ஹோஸ்ட்கள் ஆகியவற்றைக் கொண்ட JSON ஆகும். முடங்கிய ஹோஸ்ட்கள் தவிர்க்கப்படுகின்றன. `services` புலம் உருவாவதற்கு முன்பிருந்தவை உட்பட சாதாரண `scan -o` JSON அறிக்கைகளையும் `diff` ஏற்கிறது.

`diff` புதிய மற்றும் மறைந்த ஹோஸ்ட்கள், இரண்டிலும் உள்ள ஹோஸ்ட்களில் திறந்த அல்லது மூடிய போர்ட்டுகள் மற்றும் `version` மாறிய சேவைகள் ஆகியவற்றைப் புகாரளிக்கிறது. இரண்டு ஸ்கேன்களில் ஒன்றில் மட்டுமே ஆய்வு செய்யப்பட்ட போர்ட்டுகள் ஒப்பிடப்படுவதில்லை, மேலும் ஒரு எச்சரிக்கை அவ்வாறு கூறுகிறது. தோல்வியுற்ற ஆய்வுகள் ஒருபோதும் "மாற்றம் இல்லை" எனப் படிக்கப்படுவதில்லை: இரண்டு ஸ்கேன்களில் ஒன்றில் `unknown` ஆக இருந்து பிந்தையதில் திறக்கப்படாத ஒரு போர்ட், `closed`-க்குப் பதிலாக `unconfirmed`-இன் கீழ் `open`, `unknown` அல்லது `not-open` (ஆய்வு செய்யப்பட்டு மூடப்பட்டது அல்லது வடிகட்டப்பட்டது) என்ற `before` மற்றும் `unknown` அல்லது `not-open` என்ற `after` உடன் பட்டியலிடப்படுகிறது; முந்தைய ஆய்வு தோல்வியடைந்திருந்தாலும் இப்போது திறந்திருக்கும் ஒரு போர்ட் `opened`-இன் கீழ் புகாரளிக்கப்படுகிறது. இரண்டு ஸ்கேன்களில் ஒன்றில் அனைத்து ஆய்வுகளும் பதிலின்றித் தோல்வியடைந்த ஒரு ஹோஸ்ட், `vanished_hosts`-க்குப் பதிலாக `unsettled_hosts`-இன் கீழ் (`up`, `uncertain` அல்லது `absent` என்ற `before`/`after` உடன், இரண்டு ஸ்கேன்களிலும் தோல்வியடைந்தாலோ அல்லது மற்ற கோப்பில் இல்லாதபோதோ உட்பட) பட்டியலிடப்படுகிறது; அது பிந்தைய ஸ்கேனில் பதிலளித்தால் அதன் திறந்த போர்ட்டுகளுடன் ஒரு புதிய ஹோஸ்டாகவும் புகாரளிக்கப்படுகிறது. இதனாலேயே ஸ்னாப்ஷாட்கள் அந்தத் தோல்வியுற்ற ஹோஸ்ட்களைத் தக்கவைக்கின்றன. இலக்குகள் வேறுபடும்போதும், இரண்டு கோப்புகளும் timeout அல்லது backend-ஐப் பதிவு செய்து அந்த மதிப்புகள் வேறுபடும்போதும் ஒரு எச்சரிக்கையும் தோன்றும். `-o PATH` ஒரு கோப்பிலும் JSON வடிவத்தை எழுதுகிறது.

`--deadline` மூலம் நிறுத்தப்பட்ட ஸ்கேனிலிருந்து (`"complete": false`) பெறப்பட்ட அறிக்கை அது அடைந்த ஹோஸ்ட்களை மட்டுமே பட்டியலிடுகிறது, எனவே `diff` மற்றும் `export` அதை வெளியேறு குறியீடு 2 உடன் நிராகரிக்கின்றன. `--allow-partial` அதை stderr-இல் ஒரு எச்சரிக்கையுடன் ஏற்கிறது: `diff` அப்போது முழுமையற்ற ஸ்கேன் பட்டியலிடாத ஹோஸ்ட்களை vanished என்பதற்குப் பதிலாக `unsettled_hosts`-இன் கீழ் `unscanned` எனப் பட்டியலிடுகிறது (அது முடங்கியதாகப் பட்டியலிட்டுள்ள ஹோஸ்ட் இன்னும் vanished ஆகவே இருக்கும்), `partial` என்பதை true என அமைக்கிறது மற்றும் ஒருபோதும் மாற்றம் இல்லை எனப் புகாரளிக்காது, மேலும் `export` ஸ்கிரிப்ட் தலைப்பில் ஒரு எச்சரிக்கையை எழுதுகிறது.

`diff` வெளியேறு குறியீடுகள்: `0` மாற்றங்கள் இல்லை, `3` மாற்றங்கள் கண்டறியப்பட்டன, உறுதிப்படுத்த முடியாத ஆய்வுகள், அல்லது முழுமையற்ற உள்ளீடு (`unsettled_hosts` மற்றும் `unconfirmed` உட்பட எந்தப் பட்டியலும் வெறுமையாக இல்லாமல் இருந்தால் அல்லது `partial` true ஆக இருந்தால் `changed` true ஆகும்), `2` ஒரு கோப்பு காணவில்லை, படிக்க முடியவில்லை, ஆதரிக்கப்படும் ஸ்னாப்ஷாட் அல்ல, அல்லது `--allow-partial` இல்லாமல் முழுமையற்றது, `1` `-o` கோப்பை எழுத முடியவில்லை.

## Kadupul ஏற்றுமதி

[Kadupul](https://github.com/kadupulhq/kadupul) (Cacti 1.2.31-இன் ஒரு கிளை) மொத்த சாதனக் கோப்பு இறக்குமதியைக் கொண்டிருக்கவில்லை. ஒரு ஸ்கிரிப்டிலிருந்து சாதனங்களைச் சேர்ப்பதற்கான அதன் ஆதரிக்கப்பட்ட வழி `cli/add_device.php` ஆகும், ஒரு அழைப்புக்கு ஒரு சாதனம், `--option=value` தருமதிப்புகளுடன். `hostcensus export` அந்த அழைப்புகளின் POSIX `sh` ஸ்கிரிப்டை எழுதுகிறது:

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot inventory.json
hostcensus export inventory.json -o kadupul-import.sh --template 1
# or in one step, with template 0: hostcensus scan 10.0.0.0/24 -q -o kadupul-import.sh

# on the Kadupul server, as the user that owns the install:
export HOSTCENSUS_SNMP_COMMUNITY=...        # only if the script asks for it
KADUPUL_ROOT=/var/www/html/kadupul sh kadupul-import.sh
```

உயிருடன் உள்ள ஒவ்வொரு ஹோஸ்டும் `php "$KADUPUL_ROOT/cli/add_device.php" --description=... --ip=... --template=N ...` என மாறும்:

- ஸ்கேனின் SNMP வினவல் வெற்றியடைந்த ஹோஸ்ட்கள் `--version=2 --community=...` அல்லது `--version=3 --username=... --authproto=... --password=...` (கூடுதலாக authPriv-க்கு `--privproto`/`--privpass`), `--port` மற்றும் `--avail=snmp` ஆகியவற்றைப் பெறுகின்றன. SNMPv3 ஏற்றுமதிக்கு `--snmp-user` தேவை, மேலும் `add_device.php`-க்கு v3 கடவுச்சொல் தேவை என்பதால் noAuthNoPriv மறுக்கப்படுகிறது.
- பிற ஹோஸ்ட்கள் `--version=0 --avail=ping` உடன், `--ping_method=tcp --ping_port=` முதல் திறந்த TCP போர்ட்டையும், எதுவும் இல்லையென்றால் ICMP-ஐயும் பெறுகின்றன.
- `--notes` திறந்த சேவைகளையும் பதிப்புகளையும் பட்டியலிடுகிறது. `--description` என்பது சாதாரணமாக இருக்கும்போது (எழுத்துக்கள், இலக்கங்கள், `.`, `_`, `-`) தலைகீழ்-DNS பெயராகவும், இல்லையெனில் IP ஆகவும் இருக்கும், மேலும் தனித்துவமாக்கப்படுகிறது, ஏனெனில் `add_device.php` ஏற்கனவே உள்ள விளக்கத்தை அந்தச் சாதனத்திற்கான புதுப்பிப்பாகக் கருதுகிறது.

ஒவ்வொரு மதிப்பும் சரிபார்க்கப்பட்டு `shlex.quote` உடன் shell-மேற்கோளிடப்படுகிறது. இயல்புநிலையாக எந்த SNMP ரகசியமும் எழுதப்படுவதில்லை: ஸ்கிரிப்ட் இயக்க நேரத்தில் `HOSTCENSUS_SNMP_COMMUNITY`, `HOSTCENSUS_SNMP_AUTH_KEY` அல்லது `HOSTCENSUS_SNMP_PRIV_KEY` ஆகியவற்றை விரிவாக்குகிறது மற்றும் ஒன்று அமைக்கப்படாவிட்டால் நின்றுவிடுகிறது. `--include-credentials` அதற்குப் பதிலாக அந்தச் சூழல் மாறிகளிலிருந்து மதிப்புகளை ஸ்கிரிப்டில் எழுதுகிறது, அதை mode 0600 உடன் உருவாக்குகிறது, மேலும் ஒரு எச்சரிக்கையைப் பதிவு செய்கிறது. `add_device.php` தானே community-ஐ அச்சிடுகிறது மற்றும் ரகசியங்களைத் தருமதிப்புகளாகப் பெறுகிறது, அவை ஒவ்வொரு அழைப்பும் இயங்கும்போது Kadupul சேவையகத்தின் செயல்முறைப் பட்டியலில் தெரியும்.

`add_device.php` நகல்கள் மற்றும் பிழைகளுக்கு 1 என வெளியேறுகிறது; ஸ்கிரிப்ட் தொடர்கிறது, தோல்விகளைக் கணக்கிடுகிறது, மேலும் எந்தவொரு சாதனமும் சேர்க்கப்படவில்லை எனில் 1 என வெளியேறுகிறது. வார்ப்புரு அடையாள எண்கள் `php cli/add_device.php --list-host-templates` என்பதிலிருந்து வருகின்றன. `export` வெளியேறு குறியீடுகள்: `0` எழுதப்பட்டது, `2` படிக்க முடியாத உள்ளீடு, `--allow-partial` இல்லாத முழுமையற்ற ஸ்கேன், அல்லது பாதுகாப்பாக ஏற்றுமதி செய்ய முடியாத தரவு, `1` ஸ்கிரிப்டை எழுத முடியவில்லை.

## பதிப்பிடல் மற்றும் வெளியீட்டு செயல்முறை

hostcensus [Semantic Versioning](https://semver.org/spec/v2.0.0.html)-ஐப் பின்பற்றுகிறது: இணக்கமான திருத்தங்கள் patch பதிப்பை அதிகரிக்கின்றன, இணக்கமான அம்சங்கள்/வழக்கொழிவுகள் minor பதிப்பை அதிகரிக்கின்றன, மேலும் இணக்கத்தை முறிக்கும் மாற்றங்கள் major பதிப்பை அதிகரிக்கின்றன. கட்டளைகள் மற்றும் விருப்பத்தேர்வுகள், வெளியேறு குறியீடுகள் மற்றும் JSON திட்டங்கள் ஆகியவை பொது ஒப்பந்தமாகும்; பாதுகாப்புத் திருத்தம் முன்கூட்டியே மாற்றக் கோரினால் தவிர (அப்போது மாற்றப் பதிவு காரணத்தைக் கூறும்) வழக்கொழிந்த நடத்தை அடுத்த முக்கிய வெளியீடு வரை தொடர்ந்து வேலை செய்யும்.

release-please ஆனது `main`-இல் உள்ள Conventional Commit தலைப்புகளிலிருந்து ஒரு வெளியீட்டு PR-ஐத் திறந்து, `pyproject.toml`, `uv.lock` மற்றும் `CHANGES.md` ஆகியவற்றை உயர்த்துகிறது. அதை இணைப்பதன் மூலம் `vMAJOR.MINOR.PATCH` குறிச்சொல்லும் ஒரு வரைவு GitHub வெளியீடும் உருவாக்கப்படுகின்றன, அதனுடன் CI சோதிக்கப்பட்ட wheel, மூல விநியோகம் மற்றும் செக்சம்களை இணைக்கிறது; GitHub அதன் attestations API வழியாக அந்தக் கோப்புகளுக்கான உருவாக்கச் சான்றளிப்புகளைச் சேமிக்கிறது. கோப்புகள் இணைக்கப்பட்டதும் ஒரு பராமரிப்பாளர் வரைவை மதிப்பாய்வு செய்து வெளியிடுகிறார். வெளியீடுகள் ஒருபோதும் மாற்றப்படுவதில்லை.

PyPI நம்பகமான வெளியீடு விருப்பத்தேர்வானது மற்றும் திட்ட உரிமை, நம்பகமான வெளியீட்டாளர் மற்றும் `pypi` சூழல் ஆகியவற்றைக் கோருகிறது. இது மீண்டும் உருவாக்காமல் அல்லது API டோக்கனைச் சேமிக்காமல் அதே சரிபார்க்கப்பட்ட வெளியீட்டுக் கலைப்பொருட்களை வெளியிடுகிறது. இந்தப் பொதுக் களஞ்சியத்தில் குறிச்சொல்லிடப்பட்ட வெளியீடுகள் GitHub கலைப்பொருள் சான்றளிப்புகளை உருவாக்குகின்றன; தனிப்பட்ட கிளைகளுக்கு ஆதரிக்கப்படும் திட்டம் மற்றும் வெளிப்படையான விருப்பத்தேர்வு தேவை. அமைப்பு, சரியான கட்டளைகள் மற்றும் மறுமுயற்சிகளுக்கு [முழு வெளியீட்டு வழிகாட்டி](../../../docs/releasing.md) என்பதைப் பார்க்கவும்.

## மேம்பாடு

```bash
uv sync --locked                 # runtime plus the default `dev` group
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=hostcensus
uv build --no-build-isolation
uv run twine check --strict dist/*.whl dist/*.tar.gz
```

மேம்பாட்டுக் கருவிகள் `pyproject.toml`-இல் உள்ள [PEP 735](https://peps.python.org/pep-0735/) சார்புக் குழுக்களில் (`dev`, `fuzz`, `build`) உள்ளன, எனவே அவை வெளியிடப்பட்ட தொகுப்பு மெட்டாடேட்டாவில் ஒருபோதும் தோன்றாது. `uv.lock` என்பது ஒற்றைப் பூட்டுக் கோப்பாகும்; CI `uv sync --locked` உடன் நிறுவுகிறது மற்றும் பூட்டுக் கோப்பு பழையதாகும்போது தோல்வியடைகிறது. `uv python`, mise (`mise exec python@3.14 -- uv sync --locked`), அல்லது எந்தவொரு Python 3.12+ உடனும் மொழிபெயர்ப்பியைத் தேர்ந்தெடுக்கவும்.

CI ஆனது 90% தொகுப்பு சோதனைக் கவரேஜ் வரம்பைச் செயல்படுத்துகிறது. அலகு சோதனைகளில் கட்டுப்படுத்தப்பட்ட loopback சேவையகங்கள் மற்றும் ஆஃப்லைன் சுயவிவரம்/வரலாறு/வெளியீட்டு-சரிபார்ப்பி நிகழ்வுகள் அடங்கும்; Compose ஆய்வகம் தனிமைப்படுத்தப்பட்ட bridge-இல் OpenSSH, MariaDB, nginx மற்றும் net-snmp ஆகியவற்றை இயக்குகிறது. அதை `make test-integration` உடன் இயக்கவும். [CONTRIBUTING.md](../../../CONTRIBUTING.md) மற்றும் [வெளியீட்டுக் கருவிகள்](../../../scripts/README.md) ஆகியவற்றைப் பார்க்கவும்.

இயக்க நேரக் கொள்கலன் முகப்புக் கோப்பகம் இல்லாமல், shell உள்நுழைவு இல்லாமல் மற்றும் pip இல்லாமல் UID/GID 10001 ஆக இயங்குகிறது, மேலும் `/app/output`-இல் எழுத முடியும். இணைக்கப்பட்ட எந்த வெளியீட்டுக் கோப்பகத்திற்கும் அந்தப் பயனருக்கு எழுதுவதற்கான அணுகலை வழங்கவும். இதற்கு எந்தத் திறன்களும் தேவையில்லை மற்றும் படிக்க-மட்டும் root கோப்பு முறைமையுடன் வேலை செய்கிறது, எனவே இதை இவ்வாறு இயக்கலாம்:

```sh
docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp -v "$PWD/out:/app/output" IMAGE scan 192.0.2.0/28 -o /app/output/report.json
```

இந்தக் கொள்கலனில் Nmap அதன் சலுகையற்ற TCP கண்டறிதல் நடத்தையைப் பயன்படுத்துகிறது. Trivy புகாரளிக்கும் சரிசெய்யக்கூடிய HIGH அல்லது CRITICAL பாதிப்பு ஏதேனும் இருந்தால் CI பட உருவாக்கத்தைத் தோல்வியடையச் செய்யும்.

## உள்ளூர்மயமாக்கல்

CLI செய்திகள் மற்றும் முனையச் சுருக்கம்/வேறுபாடு அட்டவணைகள் பூஜ்ஜிய கூடுதல் இயக்க நேரச் சார்புகளுடன் 45 மொழிப்பகுதிகளை (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) ஆதரிக்கின்றன. தீர்மானம் `--lang`, பின்னர் `LC_ALL`, `LC_MESSAGES`, மற்றும் `LANG` ஆகியவற்றை மதித்து, `en`-க்குத் திரும்புகிறது. JSON திட்டங்கள், CSV நெடுவரிசைகள் மற்றும் ஏற்றுமதி ஸ்கிரிப்டுகள் அனைத்து மொழிப்பகுதிகளிலும் மாறாமல் இருக்கும்.

```bash
hostcensus --lang de version
LANG=ja_JP.UTF-8 hostcensus scan 192.0.2.0/28
```
