hostcensus เป็น Python CLI สำหรับการจัดทำรายการบริการแบบทำซ้ำได้บนเครือข่ายที่คุณดูแล โดยจะบันทึกสิ่งที่อุปกรณ์เปิดเผย เปรียบเทียบผลสังเกตการณ์ตามช่วงเวลา และสร้างสคริปต์นำเข้าสำหรับ Kadupul แบ็กเอนด์เริ่มต้นใช้ asyncio socket โดยไม่จำเป็นต้องใช้สิทธิ์ root ส่วนการค้นหาโฮสต์ด้วย Nmap ที่เลือกใช้เพิ่มเติมได้นั้นสามารถระบุโฮสต์ที่อยู่นอกเหนือจากพอร์ตบริการที่กำหนดค่าไว้

## ทำไมต้องใช้ hostcensus

รายงานพอร์ตแบบครั้งเดียวไม่สามารถอธิบายได้ว่าการสังเกตการณ์ครั้งถัดไปมีการเปลี่ยนแปลงหรือเพียงแค่ล้มเหลว hostcensus ผสานสถานะบริการที่ชัดเจน การตรวจสอบที่มีขอบเขตชัดเจน โปรไฟล์การสแกนที่นำกลับมาใช้ซ้ำได้ และประวัติในเครื่อง ผู้ดูแลระบบสามารถทำซ้ำในขอบเขตเดิม ตรวจสอบข้อผิดพลาด และแยกแยะผลสังเกตการณ์ที่ไม่แน่นอนออกจากการเปลี่ยนแปลงที่ยืนยันแล้วได้

- **หลักฐานของบริการ:** การระบุตัวตนของ SSH, ข้อความทักทายของ MySQL, ส่วนหัว HTTP, ผลสังเกตการณ์ใบรับรอง TLS และการค้นหา SNMP หรือการคิวรี system-MIB แบบใช้ข้อมูลรับรอง
- **ขอบเขตที่ทำซ้ำได้:** โปรไฟล์ TOML แบบตั้งชื่อ การยกเว้นแบบเพิ่มเติมได้ บริการที่กำหนดค่าได้ การจำกัดจำนวนโฮสต์และการตรวจสอบ และ worker ที่มีขอบเขตจำกัด
- **ตรวจสอบก่อนส่งทราฟฟิก:** การตรวจสอบเบื้องต้นในเครื่อง (preflight) จะตรวจสอบเป้าหมาย เครื่องมือ สิทธิ์การเข้าถึงปลายทาง สคีมาประวัติ และชุดใบรับรอง TLS CA ที่กำหนดค่าไว้
- **ประวัติรายการบริการ:** สแนปช็อต SQLite แบบมีทรานแซกชันจะเก็บผลสังเกตการณ์ทั้งหมด การเปรียบเทียบยังคงแสดงความล้มเหลวของตัวสแกนและสถานะที่ไม่ทราบค่าให้เห็นได้
- **เอาต์พุตที่ทำงานร่วมกันได้:** รายงานบนเทอร์มินัล, JSON และ CSV, สแนปช็อตไฟล์แบบมีเวอร์ชัน และสคริปต์นำเข้าสำหรับ Kadupul

CI ครอบคลุม Python 3.12, 3.13 และ 3.14 บน Linux และ macOS รวมถึงแล็บทดสอบการรวมระบบแบบควบคุมด้วย Compose โค้ดใช้ type alias สมัยใหม่ ผลลัพธ์ preflight แบบกำหนดชนิด โปรไฟล์แบบสล็อตที่รับเฉพาะอาร์กิวเมนต์แบบคีย์เวิร์ด และการคืนทรัพยากรแบบอะซิงโครนัสที่มีโครงสร้าง โดยยังคงรองรับรันไทม์เวอร์ชันเหล่านั้น ดู [การกำหนดเวอร์ชันและการเผยแพร่](../../../docs/releasing.md) สำหรับข้อตกลงความเข้ากันได้แบบ SemVer และกระบวนการเผยแพร่บน GitHub ป้ายแสดงเวอร์ชันที่เผยแพร่นั้นอธิบายถึงอาร์ติแฟกต์ที่เผยแพร่แล้ว ไม่ใช่โค้ดชุดที่ checkout มา โดยแท็กล่าสุดที่เผยแพร่ในปัจจุบันคือ `v0.3.0` ขณะที่โค้ดชุดนี้ใช้เวอร์ชันแพ็กเกจ `3.0.0` ให้ติดตั้งจากโค้ดชุดที่ checkout นี้เพื่อใช้งานฟีเจอร์รายการบริการที่อธิบายไว้ในเอกสารนี้

เริ่มต้นที่ [การติดตั้ง](#install) จากนั้นดูที่ [โปรไฟล์และประวัติ](#inventory-profiles-preflight-and-local-history) สำหรับรายละเอียดการผสานรวม ดูที่ [ลายนิ้วมือบริการ](#fingerprints), [การเปรียบเทียบไฟล์](#inventory-diff) และ [การส่งออกไปยัง Kadupul](#kadupul-export)

## การติดตั้ง

ต้องใช้ Python 3.12 ขึ้นไป โดยเมทริกซ์ที่ทดสอบคือ Python 3.12–3.14 จากโค้ดชุดที่ checkout นี้ ให้ติดตั้งส่วนพึ่งพารันไทม์ที่ล็อกเวอร์ชันไว้:

```bash
uv sync --locked
uv run hostcensus --help
uv run hostcensus --version
uv run hostcensus preflight 127.0.0.1
uv run hostcensus scan 127.0.0.1 --services ssh -o loopback.json
```

สำหรับการค้นหาโฮสต์ด้วย Nmap ซึ่งเป็นตัวเลือกเสริม ให้ติดตั้งโปรแกรม Nmap ด้วยตัวจัดการแพ็กเกจของแพลตฟอร์มคุณ โดยไม่จำเป็นต้องติดตั้งแพ็กเกจ Python เพิ่มเติม เอาต์พุต XML ของ Nmap จะถูกแยกวิเคราะห์ด้วย defusedxml ซึ่งเป็นส่วนพึ่งพาหลัก ดังนั้นจึงปฏิเสธการขยายเอนทิตี (entity expansion) hostcensus จะรัน `nmap` ที่พบใน `PATH` โดยตรงด้วยรายการอาร์กิวเมนต์ที่กำหนดตายตัว กำหนดเวลาที่เพิ่มขึ้นตามขนาดพรีฟิกซ์ และขีดจำกัดเอาต์พุตที่ 64 MiB แบ็กเอนด์เริ่มต้นไม่จำเป็นต้องใช้ Nmap

## การย้ายจาก netprobe

hostcensus เป็นชื่อใหม่ของ netprobe ซึ่งเผยแพร่ในเวอร์ชัน 3.0.0 โปรเจกต์นี้ไม่เคยถูกเผยแพร่ไปยัง PyPI ภายใต้ชื่อใดชื่อหนึ่ง ดังนั้นการติดตั้งจึงมาจากการ checkout หรือการเผยแพร่บน GitHub ทั้งนี้รีพอสิทอรีบน GitHub ยังคงใช้ชื่อเดิม

| เดิม | ปัจจุบัน | ความเข้ากันได้ |
| --- | --- | --- |
| แพ็กเกจการแจกจ่าย `netprobe` | `hostcensus` | ติดตั้งใหม่จากโค้ดที่ checkout ไม่มีแพ็กเกจในชื่อเดิมอีกต่อไป |
| คำสั่ง `netprobe` | `hostcensus` | `netprobe` ยังคงรันได้และพิมพ์ข้อความแจ้งเตือนการเลิกใช้งานหนึ่งบรรทัดไปยัง stderr รหัสออกและ stdout ยังคงเหมือนเดิม และจะถูกนำออกในเวอร์ชันหลักถัดไป |
| ตัวแปรสภาพแวดล้อม `NETPROBE_*` | `HOSTCENSUS_*` | ระบบจะใช้ตัวแปร `NETPROBE_*` เมื่อตัวแปรคู่กัน `HOSTCENSUS_*` ไม่ได้ถูกตั้งค่า พร้อมคำเตือนทาง stderr หนึ่งบรรทัดที่ระบุชื่อตัวแปรแต่ไม่แสดงค่า หากตั้งค่าทั้งคู่ `HOSTCENSUS_*` จะมีผลเหนือกว่า และจะถูกนำออกในเวอร์ชันหลักถัดไป |
| `import netprobe`, `python -m netprobe` | `import hostcensus`, `python -m hostcensus` | **มีการเปลี่ยนแปลงที่เข้ากันไม่ได้ (Breaking)** ไม่มีการติดตั้งตัวเชื่อมความเข้ากันได้สำหรับ import ให้ปรับปรุงคำสั่ง import |
| แท็กอิมเมจ Docker `network-discovery:test` (ใช้เฉพาะใน CI) และผู้ใช้คอนเทนเนอร์ `netprobe` | `hostcensus:test`, ผู้ใช้ `hostcensus` | ไม่เคยมีการเผยแพร่อิมเมจไปยัง registry มาก่อน ให้สร้างอิมเมจใหม่และใช้ entrypoint `hostcensus` |
| `netprobe.toml`, `netprobe-history.sqlite3` | `hostcensus.toml`, `hostcensus-history.sqlite3` | ไฟล์ที่มีอยู่เดิมในชื่อเริ่มต้นเก่ายังคงถูกใช้งานพร้อมคำเตือน ตราบใดที่ยังไม่มีไฟล์ชื่อใหม่ ส่วนพาธที่ระบุชัดเจนผ่าน `--config` และ `--history` จะไม่ถูกเปลี่ยนแปลง |
| รายงานและสแนปช็อตที่มี `"format": "netprobe-report"` หรือ `"netprobe-snapshot"` และฟิลด์ `netprobe_version` | `hostcensus-report`, `hostcensus-snapshot`, `hostcensus_version` | `diff` และ `export` ยังคงโหลดไฟล์ที่เขียนภายใต้ชื่อเดิมได้ และ JSON Schema ที่เผยแพร่รองรับการสะกดทั้งสองแบบ ไฟล์ใหม่จะใช้ชื่อใหม่ ส่วนฐานข้อมูลประวัติ SQLite ไม่เปลี่ยนแปลงและโหลดได้เหมือนเดิม |
| สคริปต์ Kadupul จาก `netprobe export` | สคริปต์จาก `hostcensus export` | สคริปต์เดิมยังคงใช้งานได้และยังคงอ่าน `NETPROBE_SNMP_*` เมื่อรัน ส่วนสคริปต์ใหม่จะอ่าน `HOSTCENSUS_SNMP_*` |

## ตัวอย่างการใช้งานอย่างรวดเร็ว

รันจากคอนเทนเนอร์ผู้ทดสอบของแล็บการรวมระบบที่อธิบายไว้ในหัวข้อการพัฒนา (ตัดทอนเอาต์พุตบางส่วน):

```console
$ hostcensus scan 172.30.57.8/29 --services ssh,http,snmp --save-snapshot after.json
┃ IP Address   ┃ Hostname       ┃ SSH ┃ SNMP ┃ MySQL ┃ Open services  ┃ Status ┃
│ 172.30.57.10 │ hostcensus-it-s… │ ✅  │  ❌  │  ❌   │ ssh:22         │ UP     │
│              │                │     │      │       │ OpenSSH_10.0   │        │
│ 172.30.57.13 │ hostcensus-it-w… │ ❌  │  ❌  │  ❌   │ http:80        │ UP     │
│              │                │     │      │       │ nginx/1.28.3   │        │

$ hostcensus diff before.json after.json; echo "exit=$?"
Warning: targets differ: 172.30.57.10 vs 172.30.57.8/29
│ new host │ 172.30.57.13 │ http:80/tcp  │ hostcensus-it-web-1.hostcensus-it_lab   │
exit=3

$ hostcensus export after.json -o kadupul-import.sh --template 1
$ grep 57.13 kadupul-import.sh
add --description=hostcensus-it-web-1.hostcensus-it_lab --ip=172.30.57.13 --template=1 --version=0 --avail=ping --ping_method=tcp --ping_port=80 '--notes=hostcensus: http:80/tcp nginx/1.28.3'
```

| `cli.py` | ตัวเลือกคำสั่ง การแปลงโปรไฟล์ การตรวจสอบเบื้องต้น การสแกน และการรายงาน |
| `scanner.py`, `probes.py` | การขยายเป้าหมาย worker ที่มีขอบเขตจำกัด การค้นหาโฮสต์ และการสังเกตการณ์บริการ |
| `config.py`, `profiles.py` | คำนิยามบริการและโปรไฟล์รายการบริการที่ตรวจสอบความถูกต้องแล้ว |
| `models.py`, `output.py` | ชนิดข้อมูลผลลัพธ์และการแสดงผลแบบเทอร์มินัล/JSON/CSV |
| `history.py`, `diff.py` | ประวัติ SQLite และการเปรียบเทียบสแนปช็อตไฟล์แบบมีเวอร์ชัน |
| `preflight.py` | การตรวจสอบในเครื่องและการค้นหาเวอร์ชัน Nmap แบบมีขอบเขต |
| `export.py` | สคริปต์นำเข้า Kadupul ที่ตรวจสอบความถูกต้องและใส่เครื่องหมายคำพูดอย่างปลอดภัยแล้ว |

ผลสังเกตการณ์ของแต่ละบริการจะบันทึกสถานะแยกจากข้อมูลระบุตัวตนที่บริการประกาศออกมา การอ่านข้อมูลและกำหนดเวลาล้วนมีขอบเขตจำกัด ข้อยกเว้นจากการตรวจสอบจะยังคงอยู่ในรายการข้อผิดพลาดของโฮสต์ ประวัติ SQLite ใช้ทรานแซกชัน การปิดการเชื่อมต่ออย่างชัดเจน และเส้นทางการแสดงรายการและการเปรียบเทียบแบบอ่านอย่างเดียว ข้อมูลลับของ SNMP จะรับเข้าผ่านตัวแปรสภาพแวดล้อมหรือไฟล์ข้อมูลลับเท่านั้น ประวัติรายการบริการจะจัดเก็บเฉพาะการตั้งค่าที่มีผลซึ่งไม่ใช่ข้อมูลลับ ดู [สถาปัตยกรรม](../../../docs/architecture.md) สำหรับไปป์ไลน์การสแกน ขีดจำกัด และขอบเขตความน่าเชื่อถือ และดู [SECURITY.md](../../../SECURITY.md#authorized-use) สำหรับการใช้งานที่ได้รับอนุญาต

## วิธีใช้งาน

สแกนเฉพาะเครือข่ายที่คุณเป็นผู้ดูแลเท่านั้น

```bash
hostcensus scan 192.168.1.0/24              # table of alive hosts
hostcensus scan 192.168.1.1 -o results.json # JSON report
hostcensus scan 10.0.0.0/24 -o report.csv   # CSV report
hostcensus scan 10.0.0.0/24 -q -o out.json  # no table, file only
hostcensus scan 10.0.0.0/24 --format json | jq '.devices[]'  # JSON report on stdout
```

| ตัวเลือก | ความหมาย |
| --- | --- |
| `NETWORK` | CIDR, IP หรือชื่อโฮสต์ ใช้แบบไม่ระบุได้เมื่อใช้ร่วมกับ `--profile` ตัวระบุขอบเขตของ IPv6 จะถูกปฏิเสธ |
| `-o, --output PATH` | เขียนรายงาน โดยรูปแบบจะอ้างอิงตามนามสกุลไฟล์ (`.json`, `.csv`) นามสกุลอื่นจะใช้ JSON เป็นค่าเริ่มต้น |
| `-f, --format json\|csv\|kadupul\|auto` | บังคับรูปแบบรายงาน ไม่มีผลหากไม่ระบุ `--output` นามสกุล `.sh` จะเลือก `kadupul` |
| `-v, --verbose` | แสดงบันทึกการดีบัก |
| `-q, --quiet` | ซ่อนผลลัพธ์ ความคืบหน้า และบันทึกข้อมูลทั่วไป โดยคำเตือนและข้อผิดพลาดยังคงแสดงทาง stderr |
| `--backend asyncio\|nmap` | วิธีการค้นหาโฮสต์ `asyncio` (ค่าเริ่มต้น) จะตรวจสอบพอร์ตบริการโดยตรง ส่วน `nmap` จะรันการสแกน ping ของ nmap ก่อนและต้องมีโปรแกรม `nmap` อยู่ใน `PATH` |
| `--timeout SECONDS` | เวลารอสำหรับการตรวจสอบที่ไม่ได้กำหนดงบประมาณเวลาของตนเอง (ค่าเริ่มต้น 1.0) การตรวจสอบการเชื่อมต่อในตัวใช้เวลา 0.3 วินาที เว้นแต่ตารางบริการจะกำหนด `timeout` ไว้ |
| `--concurrency N` | จำนวนการตรวจสอบที่ทำงานพร้อมกัน (ค่าเริ่มต้น 256) |
| `--deadline SECONDS` | หยุดการสแกนทั้งหมด รวมถึงการกวาดของ nmap หลังจากเวลานี้ (ค่าเริ่มต้น 3600 สูงสุด 604800; ตัวแปรสภาพแวดล้อม `HOSTCENSUS_DEADLINE`) โฮสต์ที่ตรวจสอบเสร็จแล้วจะถูกเขียนลงในรายงานพร้อม `"complete": false` โดยไม่เขียนประวัติหรือสแนปช็อต และ `scan` จะจบด้วยรหัสออก 4 |
| `--config PATH` | คำนิยามบริการในรูปแบบ TOML และการตั้งค่า `[profiles]` แบบตั้งชื่อที่เป็นตัวเลือกเสริม |
| `--profile NAME` | ใช้โปรไฟล์ตามชื่อ ค่าเริ่มต้นคือ `hostcensus.toml` เมื่อไม่ได้ระบุ `--config` |
| `--exclude IP/CIDR` | เพิ่มการยกเว้น สามารถระบุซ้ำได้ตามต้องการ โฮสต์ IPv4 ที่ถูกยกเว้นจะยกเว้นที่อยู่ IPv6 ที่เชื่อมต่อถึงมันด้วย ได้แก่ IPv4-mapped (`::ffff:a.b.c.d`), NAT64 (`64:ff9b::/96`) และ 6to4 เป้าหมายและการยกเว้นแบบ IPv4-mapped จะถูกปฏิบัติเสมือนเป็นที่อยู่ IPv4 ที่อ้างอิงถึง |
| `--max-hosts N` | ขีดจำกัดจำนวนที่อยู่ซึ่งตรวจสอบก่อนหักรายการยกเว้น (ค่าเริ่มต้นและค่าสูงสุดที่อนุญาตคือ 65,536) |
| `--history PATH` | บันทึกการสแกนที่เสร็จสมบูรณ์ลงในฐานข้อมูลประวัติ SQLite แบบเลือกเปิดใช้ |
| `--services NAMES` | รายชื่อบริการคั่นด้วยจุลภาคที่ต้องการตรวจสอบตามลำดับนั้น (ค่าเริ่มต้น: ทั้งหมด) |
| `--ports SPEC` | รายการคั่นด้วยจุลภาคในรูปแบบ `NAME=PORT` (ย้ายพอร์ตของบริการ) หรือ `PORT` (เพิ่มการตรวจสอบ TCP ธรรมดาชื่อ `tcp-PORT`) |
| `--snmp-community-file PATH` | ไฟล์ที่เก็บ community ของ SNMPv2c สำหรับการคิวรี system MIB ตัวแปรสภาพแวดล้อม: `HOSTCENSUS_SNMP_COMMUNITY` (ตัวค่า) หรือ `HOSTCENSUS_SNMP_COMMUNITY_FILE` (พาธไฟล์) |
| `--snmp-user` | ชื่อผู้ใช้ SNMPv3 ตัวแปรสภาพแวดล้อม: `HOSTCENSUS_SNMP_USER` |
| `--snmp-auth-protocol`, `--snmp-auth-key-file PATH` | `MD5`, `SHA` (ค่าเริ่มต้น), `SHA224`, `SHA256`, `SHA384`, `SHA512` และไฟล์ที่เก็บวลีรหัสผ่าน ตัวแปรสภาพแวดล้อม: `HOSTCENSUS_SNMP_AUTH_PROTOCOL`, `HOSTCENSUS_SNMP_AUTH_KEY` หรือ `HOSTCENSUS_SNMP_AUTH_KEY_FILE` |
| `--snmp-priv-protocol`, `--snmp-priv-key-file PATH` | `DES`, `AES` (ค่าเริ่มต้น), `AES128`, `AES192`, `AES192C`, `AES256`, `AES256C` และไฟล์ที่เก็บวลีรหัสผ่าน ตัวแปรสภาพแวดล้อม: `HOSTCENSUS_SNMP_PRIV_PROTOCOL`, `HOSTCENSUS_SNMP_PRIV_KEY` หรือ `HOSTCENSUS_SNMP_PRIV_KEY_FILE` |
| `--save-snapshot PATH` | เขียนไฟล์สแนปช็อตแบบมีเวอร์ชันเพิ่มเติมสำหรับใช้กับ `hostcensus diff` |
| `--tls-ca-file PATH` | ตรวจสอบใบรับรอง HTTPS เทียบกับชุด PEM นี้แทนคลังของระบบ ตัวแปรสภาพแวดล้อม: `HOSTCENSUS_TLS_CA_FILE` |

โดยค่าเริ่มต้นแต่ละโฮสต์จะถูกตรวจสอบสำหรับ SSH (TCP 22), SNMP (UDP 161), MySQL (TCP 3306), HTTP (TCP 80) และ HTTPS (TCP 443) พอร์ต TCP จะถูกทดสอบด้วยการเชื่อมต่อแบบเต็มรูปแบบ ส่วน SNMP จะทดสอบด้วยคำขอค้นหาเอนจิน SNMPv3 (engine-discovery) ซึ่งเอเจนต์ SNMPv3 ทุกตัวต้องตอบกลับโดยไม่ต้องใช้ข้อมูลรับรอง เอเจนต์ที่รองรับเฉพาะ v1/v2c จะไม่ถูกตรวจพบด้วยวิธีการนี้ เมื่อใช้แบ็กเอนด์ asyncio โฮสต์จะนับว่าทำงานอยู่เมื่อมีการตอบกลับจากการตรวจสอบใด ๆ รวมถึงการปฏิเสธการเชื่อมต่อ ดังนั้นโฮสต์ที่ทิ้งแพ็กเก็ตการตรวจสอบทั้งหมดจะมีค่า `alive=false` และข้อผิดพลาด "Host is down" ซึ่งไม่ได้พิสูจน์ว่าเครื่องปิดอยู่จริง เมื่อใช้ `--backend nmap` ตัว nmap จะเป็นผู้ตัดสินว่าโฮสต์ใดทำงานอยู่ (ใช้ ICMP เมื่อรันด้วยสิทธิ์ root และใช้ TCP 80/443 ในกรณีอื่น)

### ลายนิ้วมือบริการ (Fingerprints)

บริการที่เปิดอยู่แต่ละรายการจะถูกเก็บลายนิ้วมือจากข้อมูลที่ส่งมาก่อนมีการเข้าสู่ระบบ ไม่มีการยืนยันตัวตนใด ๆ ยกเว้นการคิวรี SNMP และจะทำเฉพาะเมื่อคุณระบุข้อมูลรับรองเท่านั้น

| ตัวตรวจสอบ | ข้อมูลที่อ่าน | `version` | คีย์ใน `details` |
| --- | --- | --- | --- |
| `ssh` | บรรทัดระบุตัวตนตาม RFC 4253 | ซอฟต์แวร์ เช่น `OpenSSH_10.0` | `protocol`, `software`, `comments` |
| `mysql` | การจับมือเริ่มต้นของ MySQL/MariaDB | เวอร์ชันเซิร์ฟเวอร์ | `server_version`, `flavor`, `auth_plugin` หรือ `error_code`/`error` |
| `http` | การตอบกลับ `HEAD /` | ส่วนหัว `Server` | `status`, `server` |
| `https` | การจับมือ TLS, ใบรับรอง, `HEAD /` | ส่วนหัว `Server` | `tls_version`, `cert_verified`, `cert_verify_error`, `cert_subject`, `cert_issuer`, `cert_sans`, `cert_not_before`, `cert_not_after` (UTC ISO 8601), `cert_self_signed`, `status`, `server` |
| `snmp` | การค้นหา SNMPv3; หากมีข้อมูลรับรองจะทำ GET สำหรับ sysDescr, sysObjectID, sysName | sysDescr | `engine_id`; หากมีข้อมูลรับรองจะได้ `snmp_version`, `sys_descr`, `sys_object_id`, `sys_name` หรือ `snmp_error` |

เป้าหมายที่เป็นชื่อโฮสต์จะถูกแปลงชื่อหนึ่งครั้งต่อโฮสต์ และการตรวจสอบทุกครั้งจะเชื่อมต่อไปยังที่อยู่นั้น โดยบันทึกเป็น `address` ในผลลัพธ์ ส่วนชื่อโฮสต์จะใช้เฉพาะสำหรับ TLS SNI การตรวจสอบใบรับรอง และส่วนหัว HTTP `Host` ชื่อที่ไม่สามารถแปลงได้จะได้สถานะ `unknown` และข้อผิดพลาด `Cannot resolve` ชื่อ Reverse DNS จะถูกเก็บไว้เฉพาะเมื่อมีอักขระของชื่อโฮสต์เท่านั้น และมีการค้นหาพร้อมกันได้สูงสุด 16 รายการ HTTPS ใช้การตรวจสอบใบรับรองและชื่อโฮสต์เทียบกับคลังของระบบหรือ `--tls-ca-file` คลังความน่าเชื่อถือจะถูกโหลดเพียงครั้งเดียวสำหรับการสแกนและนำกลับมาใช้ซ้ำกับทุกการตรวจสอบ HTTPS การเชื่อมต่อ TCP และการจับมือ TLS จะจับเวลาแยกกัน ดังนั้นพอร์ตที่รับการเชื่อมต่อแต่ค้างในขั้นตอนการจับมือจะเป็น `open` พร้อม `tls_error` ไม่ใช่ `filtered` หากการตรวจสอบล้มเหลว ผลลัพธ์จะบันทึก `cert_verified: false` และ `cert_verify_error` โดยจะไม่ลองใหม่ด้วยค่าที่ปลอดภัยน้อยกว่าและไม่ส่งคำขอ HTTP รายละเอียดใบรับรองและส่วนหัว HTTP จะถูกเก็บเฉพาะเมื่อการตรวจสอบผ่านแล้วเท่านั้น โปรดระบุชุด CA ที่ถูกต้องสำหรับบริการที่ใช้ CA ส่วนตัว รายงานรุ่นเก่าอาจมี `cert_read_unverified` ซึ่งตัวตรวจสอบปัจจุบันไม่ได้สร้างขึ้นแล้ว

ข้อมูลลับของ SNMP จะอ่านจากตัวแปรสภาพแวดล้อมหรือจากไฟล์ (`--snmp-*-file` หรือตัวแปร `HOSTCENSUS_SNMP_*_FILE` ที่ตรงกัน) เท่านั้น และจะไม่อ่านจากค่าบนบรรทัดคำสั่งซึ่งผู้ใช้อื่นในเครื่องอาจมองเห็นได้ในรายการโปรเซส การระบุ `--snmp-community`, `--snmp-auth-key` และ `--snmp-priv-key` พร้อมค่าจะจบการทำงานด้วยรหัสออก 2 และแจ้งตัวเลือกที่ใช้แทน ไฟล์ข้อมูลลับต้องเป็น UTF-8 ที่ไม่ว่างเปล่าและมีขนาดไม่เกิน 4096 ไบต์ โดยจะละเว้นการขึ้นบรรทัดใหม่ท้ายไฟล์หนึ่งตัว และการตั้งค่าทั้งตัวแปรและไฟล์สำหรับข้อมูลลับเดียวกันถือเป็นข้อผิดพลาด ข้อความแสดงข้อผิดพลาดจะระบุชื่อไฟล์แต่ไม่แสดงเนื้อหาในไฟล์ รายงานการสแกนและประวัติจะไม่รวมค่าข้อมูลรับรองโดยตั้งใจ ส่วนตัวส่งออกจะมีตัวเลือก `--include-credentials` แยกต่างหากตามที่อธิบายด้านล่าง การระบุ community จะเลือกใช้ SNMPv2c ส่วนการระบุ user จะเลือกใช้ SNMPv3 โดยใช้การยืนยันตัวตนเมื่อมีคีย์ auth และใช้การเข้ารหัสความเป็นส่วนตัวเมื่อมีทั้งสองคีย์ (`snmp_security_level` จะบันทึกระดับที่ใช้) hostcensus จะปฏิเสธด้วยรหัสออก 2 หากมีการใช้ community ร่วมกับผู้ใช้ v3 ใช้คีย์ privacy โดยไม่มีคีย์ auth หรือใช้คีย์โดยไม่ระบุ user และจะไม่ลองคิวรี v3 ที่ล้มเหลวซ้ำด้วย v2c หรือระดับความปลอดภัยที่ต่ำกว่า เอเจนต์ที่รองรับเฉพาะ v1/v2c จะเพิกเฉยต่อการค้นหา v3 แบบไม่มีข้อมูลรับรอง ดังนั้นจึงแสดงสถานะ open เฉพาะเมื่อมีการระบุ community เท่านั้น

ข้อความแบนเนอร์จะถูกกรองให้เหลือเฉพาะอักขระที่พิมพ์ได้และจำกัดความยาวไว้ที่ 256 อักขระก่อนจัดเก็บหรือแสดงผล การอ่านข้อมูลก็มีขอบเขตเช่นกัน: 4 KiB ต่อบรรทัด, 4 KiB สำหรับข้อความทักทายของ MySQL และ 16 KiB สำหรับส่วนหัว HTTP รหัส SNMP engine ID ที่ยาวเกิน 32 octet จะถูกตัดทอนก่อนจัดเก็บ HTTP และ HTTPS จะส่งส่วนหัว Host โดยมีที่อยู่ IPv6 อยู่ในวงเล็บเหลี่ยมและระบุพอร์ตเมื่อไม่ใช่ 80 หรือ 443 เซลล์ CSV ที่ขึ้นต้นด้วยอักขระทริกเกอร์สูตรสเปรดชีตจะถูกเติมคำนำหน้าเพื่อให้เซลล์ยังคงเป็นข้อความธรรมดา

### ขีดจำกัด

การรันหนึ่งครั้งรองรับได้สูงสุด 65,536 ที่อยู่, 64 บริการ และ 524,288 การตรวจสอบ (จำนวนโฮสต์คูณจำนวนบริการ) คำขอที่ใหญ่กว่านี้จะจบการทำงานด้วยรหัสออก 2 ก่อนที่จะส่งข้อมูลใด ๆ ออกไป `--concurrency` จำกัดไว้สูงสุดที่ 4096 socket การตรวจสอบแต่ละครั้งมีกำหนดเวลาตายตัวอยู่ที่สี่เท่าของงบประมาณเวลาของตัวเอง การตรวจสอบแบบเชื่อมต่อ (`tcp`, `ssh`, `mysql`, `http`) ใช้เวลา 0.3 วินาที เว้นแต่บริการนั้นจะกำหนด `timeout` ไว้ ส่วน SNMP และ HTTPS จะใช้ `--timeout` (ค่าเริ่มต้น 1.0) เมื่อไม่ได้กำหนดไว้ การตรวจสอบที่เกินกำหนดเวลาจะถูกรายงานเป็น `unknown` พร้อมข้อความ "probe timed out" ใน `errors` ความล้มเหลวของ socket ในเครื่อง (เช่น file descriptor หมด) จะเป็น `unknown` พร้อมบันทึกข้อผิดพลาดเช่นกัน และจะไม่ถูกนับเป็นพอร์ตที่ถูกกรองหรือโฮสต์ที่ปิดอยู่ ก่อนเริ่มตรวจสอบ hostcensus จะเพิ่มขีดจำกัดแบบ soft limit ของจำนวนไฟล์ที่เปิดได้เข้าหา hard limit เพื่อให้รองรับ `--concurrency` บวก 64 descriptor หากไม่สามารถทำได้ การตรวจสอบเบื้องต้น `open files` จะล้มเหลวและ `scan` จะจบด้วยรหัสออก 1 ก่อนส่งทราฟฟิก การค้นหาด้วย Nmap ใช้เวลารอต่อโฮสต์ 30 วินาที พรีฟิกซ์จะถูกส่งให้ nmap ในรูปแบบ CIDR และการกวาดจะล้มเหลวด้วยรหัสออก 1 เมื่อ nmap รายงานจำนวนที่อยู่น้อยกว่าที่ได้รับไป (เช่น ชื่อที่ไม่สามารถแปลงได้) แทนที่จะทำเครื่องหมายว่าโฮสต์ปิดอยู่ เป้าหมายที่เป็นชื่อโฮสต์จะถูกแปลงหนึ่งครั้งและส่งที่อยู่นั้นให้ nmap เพื่อให้การค้นหาและการตรวจสอบเข้าถึงเครื่องเดียวกัน พรีฟิกซ์เต็มหนึ่งชุดจะใช้หนึ่งโปรเซสของ nmap ที่มีกำหนดเวลาโปรเซสย่อย 35 วินาทีต่อทุก 256 ที่อยู่ (ปัดเศษขึ้น) การกวาดที่มีรายการยกเว้นจะแบ่งทำเป็นชุดละ 256 โฮสต์ โดยมีกำหนดเวลา 35 วินาทีต่อชุด การสร้าง worker จะมีขอบเขตจำกัดแยกอิสระจากขนาดช่วงเครือข่าย การแปลง Reverse DNS และชื่อโฮสต์มีกำหนดเวลาแยกต่างหาก 2 วินาที การเรียกตัวแปลงชื่อที่ไม่ตอบกลับจะถูกปล่อยทิ้งไว้ในเธรดของตัวเอง จึงไม่สามารถทำให้ hostcensus ทำงานค้างเกินขีดจำกัดเหล่านี้ได้ การค้นหาชื่อสามารถทำงานพร้อมกันได้สูงสุด 16 รายการ และการเรียกที่ถูกปล่อยทิ้งไว้จะยังคงครองสล็อตของตนจนกว่าจะคืนค่า ดังนั้นจำนวนเธรดที่ค้างอยู่จึงถูกจำกัดไว้ หากทั้ง 16 สล็อตค้างทั้งหมด การค้นหาถัดไปจะเข้าคิวรอสล็อตโดยอยู่นอกกำหนดเวลา 2 วินาที (ซึ่งจะเริ่มนับเมื่อมีสล็อตว่าง) จนกว่า `--deadline` จะหยุดการสแกน การใช้ `NetworkScanner` เป็นไลบรารีโดยไม่มี `deadline` อาจรอสล็อตดังกล่าวไปเรื่อย ๆ โดยไม่มีกำหนด `--deadline` (ค่าเริ่มต้น 1 ชั่วโมง) จะครอบคลุมขอบเขตเวลาของการรันทั้งหมดอีกชั้นหนึ่ง

### การกำหนดค่าบริการ

สามารถปรับเปลี่ยนบริการได้ด้วยไฟล์ TOML:

```toml
[services.ssh]          # same name as a built-in: replaces it
port = 2222
timeout = 0.5

[services.admin-ui]     # a new service, probed like HTTPS
port = 8443
probe = "https"
```

`probe` มีค่าเป็น `tcp`, `ssh`, `mysql`, `http`, `https` หรือ `snmp` และจะใช้ชื่อบริการเป็นค่าเริ่มต้นหากชื่อนั้นเป็นชนิดของตัวตรวจสอบ มิฉะนั้นจะใช้ `tcp` มีเพียง `snmp` เท่านั้นที่ใช้ UDP ชื่อบริการต้องเป็นตัวอักษรพิมพ์เล็ก ตัวเลข `-` และ `_` บริการสองรายการไม่สามารถใช้พอร์ตและโปรโตคอลร่วมกันได้ เนื่องจากประวัติจะบันทึกเพียงหนึ่งสถานะสำหรับคู่นั้น `timeout` เป็นตัวเลือกเสริม มีหน่วยเป็นวินาที และต้องมีค่าอย่างน้อย 0.05 ตัวตรวจสอบแบบเชื่อมต่อ (`tcp`, `ssh`, `mysql`, `http`) มีค่าเริ่มต้นที่ 0.3 วินาที ส่วน `snmp` และ `https` จะใช้ `--timeout` ของการสแกนเมื่อบริการไม่ได้ตั้งค่า `timeout` ไว้ ทั้งนี้ `--timeout` จะไม่แทนที่งบประมาณเวลาที่บริการกำหนดไว้แล้ว

รายงาน JSON เป็นเอกสารที่มีการระบุเวอร์ชัน (`"format": "hostcensus-report"`, `"version": 1`) ซึ่งบันทึกเป้าหมาย บริการที่ตรวจสอบ และการตั้งค่าไว้คู่กับ `devices`; การใช้ `--format json` โดยไม่ระบุ `-o` จะเขียนรายงานไปยัง stdout แทนตาราง เอาต์พุต JSON ทุกแบบมีสคีมาที่เผยแพร่อยู่ ดู [เอาต์พุต JSON](../../../docs/json-output.md) รายการอุปกรณ์ยังคงฟิลด์ `ip`, `alive`, `ssh`, `snmp`, `mysql`, `hostname` และ `errors` เดิมไว้ และเพิ่มรายการ `services` ที่ระบุ `name`, `port`, `protocol`, `state` (`open`, `closed`, `filtered` หรือ `unknown` เมื่อตัวตรวจสอบล้มเหลวในเครื่องหรือเกินกำหนดเวลา), `version` และ `details` ของแต่ละการตรวจสอบ เอาต์พุต CSV จะเพิ่มคอลัมน์ `services` และ `versions` ต่อท้ายสำหรับบริการที่เปิดอยู่ ค่าบูลีน `ssh`, `snmp` และ `mysql` จะอ้างอิงตามบริการที่มีชื่อตรงกันทุกประการ

## โปรไฟล์รายการบริการ การตรวจสอบเบื้องต้น และประวัติในเครื่อง

โปรไฟล์แบบตั้งชื่อใช้ไฟล์ TOML ร่วมกับคำนิยาม `[services]` ที่มีอยู่ ให้คัดลอก [hostcensus.example.toml](../../../hostcensus.example.toml) ไปยัง `hostcensus.toml` และกำหนดเครือข่ายที่คุณดูแล:

```toml
[profiles.office]
network = "192.168.1.0/24"
exclusions = ["192.168.1.1"]
services = "ssh,http,https,mysql"
concurrency = 32
timeout = 1.0
max_hosts = 256
backend = "asyncio"
```

```bash
hostcensus profiles --config hostcensus.toml
hostcensus preflight --profile office --config hostcensus.toml
hostcensus scan --profile office --config hostcensus.toml -o report.json
```

`preflight` จะแปลงค่าตัวเลือกและโปรไฟล์ในลักษณะเดียวกับ `scan` ทุกประการ รวมถึง `--concurrency` สำหรับการตรวจสอบจำนวนไฟล์ที่เปิดได้ ดังนั้นหาก preflight ผ่าน ก็หมายความว่า `scan` จะเริ่มต้นด้วยแผนการทำงานเดียวกัน

โปรไฟล์รองรับ `network`, `exclusions`, `services`, `ports`, `backend`, `timeout`, `concurrency` และ `max_hosts` โดย `services` และ `ports` ใช้รูปแบบรายการคั่นด้วยจุลภาคที่มีอยู่ ตัวเลือก CLI ที่ระบุชัดเจนจะเขียนทับการตั้งค่าของโปรไฟล์ และตัวเลือก `--exclude` ที่ระบุซ้ำจะเพิ่มเข้าไปในรายการยกเว้นของโปรไฟล์ เครือข่ายที่ระบุชัดเจนพร้อมกับ `--profile` ต้องอยู่ภายในขอบเขต IP/CIDR ของโปรไฟล์นั้น ชื่อโฮสต์ยังคงรองรับสำหรับการสแกนโดยตรง แต่ไม่สามารถใช้ร่วมกับการยกเว้น IP ได้ ขีดจำกัดโฮสต์จะถูกนำไปใช้ก่อนหักรายการยกเว้น ส่วนขีดจำกัดจำนวนการตรวจสอบรวมยังคงมีผลหลังจากนั้น โฮสต์ที่ถูกยกเว้นจะถูกข้ามทั้งในการตรวจสอบบริการและการค้นหาด้วย Nmap ที่เลือกใช้เพิ่มเติม

การสแกนทุกครั้งจะทำการตรวจสอบเบื้องต้นในเครื่องก่อนส่งทราฟฟิกไปยังเป้าหมาย ได้แก่ ขีดจำกัดเป้าหมาย/การตรวจสอบ สิทธิ์การเข้าถึงปลายทาง ความพร้อมใช้งานของโปรแกรม/wrapper Nmap (หากเลือกใช้) สคีมาประวัติ และชุดใบรับรอง TLS CA ที่กำหนดค่าไว้ `preflight` จะรายงานผลเป็น JSON โดยไม่สแกนเป้าหมายหรือสร้างฐานข้อมูลประวัติ ระบบจะเขียนไฟล์ข้างเคียงชั่วคราวเพื่อทดสอบสิทธิ์การเข้าถึงปลายทางโดยไม่แก้ไขเนื้อหาที่มีอยู่ แบ็กเอนด์ asyncio เริ่มต้นยังคงไม่ต้องการทั้ง Nmap และสิทธิ์ root พาธปลายทางต้องแยกต่างหากจากกันและแยกจากไฟล์กำหนดค่าอินพุต รวมถึงกรณี hard link ด้วย และลิงก์สัญลักษณ์ (symlink) ของปลายทางจะถูกปฏิเสธ การตรวจสอบที่ล้มเหลวจะคืนรหัส 1 ส่วนขอบเขตหรือการกำหนดค่าที่ไม่ถูกต้องจะคืนรหัส 2

การเขียนรายงานและการส่งออกต้องรองรับ `O_NOFOLLOW` บนแพลตฟอร์มที่ไม่รองรับ รวมถึง Windows การเขียนเหล่านี้จะล้มเหลวโดยไม่เปิดหรือตัดทอนไฟล์ปลายทาง รายงานและสคริปต์ส่งออกที่สร้างใหม่จะให้สิทธิ์เฉพาะเจ้าของไฟล์เท่านั้น (โหมด 0600) ส่วนการเขียนทับไฟล์เดิมจะคงสิทธิ์เดิมไว้ การเขียนไปยัง named pipe ที่ไม่มีตัวอ่านจะล้มเหลวทันทีแทนที่จะรอ ฐานข้อมูล `--history` ที่สร้างใหม่จะถูกสร้างให้เข้าถึงได้เฉพาะเจ้าของเช่นกัน ส่วนฐานข้อมูลที่มีอยู่เดิมจะคงโหมดสิทธิ์เดิมไว้ ข้อความบันทึกจะส่งไปยัง stderr เสมอ เพื่อให้ stdout มีเฉพาะผลลัพธ์ การส่งออกที่มีข้อมูลรับรองจะบังคับใช้โหมด 0600 เสมอ

การจัดเก็บประวัติเป็นแบบเลือกเปิดใช้ และช่วยเสริมสแนปช็อต JSON และคำสั่ง `diff` ที่มีอยู่:

```bash
mkdir -p output
hostcensus scan --profile office --history output/inventory.sqlite3
# Repeat later with the same targets and service selection.
hostcensus scan --profile office --history output/inventory.sqlite3
hostcensus history --history output/inventory.sqlite3 --limit 20
hostcensus compare 1 2 --history output/inventory.sqlite3
hostcensus compare 1 2 --history output/inventory.sqlite3 -o output/changes.json
```

ใช้ ID จาก `history` โดยตัวอย่างนี้สมมติว่าใช้ฐานข้อมูลใหม่ สแนปช็อตจะถูกจัดเก็บแบบมีทรานแซกชันพร้อมเวลาเริ่มต้น/สิ้นสุดแบบ UTC เวอร์ชันแพ็กเกจ การตั้งค่าที่มีผลซึ่งไม่ใช่ข้อมูลลับ ข้อมูลสรุป และผลสังเกตการณ์ของโฮสต์/บริการทั้งหมด รวมถึงข้อผิดพลาดรายโฮสต์ ผลสังเกตการณ์ของโฮสต์ที่ไม่สมบูรณ์จะถูกเก็บไว้ การรันที่ถูกยกเลิกจะไม่ถูกบันทึก ข้อตกลงของรายงาน สแนปช็อต การส่งออก และรหัสออกของการสแกนที่มีอยู่เดิมยังคงเดิมทั้งหมด

`history` แสดงรายการสรุปแบบ JSON โดยไม่ต้องอ่านข้อมูลอุปกรณ์ในอดีตทั้งหมด `compare` จะอ่านการสแกนที่บันทึกไว้สองครั้ง โดยต้องมีข้อมูลระบุเป้าหมายและพอร์ตที่เลือกตรงกัน และรายงานการเปลี่ยนแปลงของการตอบสนอง สถานะ และสถานะพอร์ต ID ของการสแกนก่อนหน้าต้องมาก่อน ID ของการสแกนครั้งหลัง เมื่อการสแกนทั้งสองบันทึก `timeout` หรือ `backend` ไว้และค่าเหล่านั้นต่างกัน รายงานจะแสดงคำเตือนแต่ยังคงเปรียบเทียบผลสังเกตการณ์ต่อไป เวลารอที่ต่างกันอาจทำให้พอร์ตที่ถูกกรองดูเหมือนเปิดอยู่ได้ ข้อผิดพลาดของตัวสแกนและผลสังเกตการณ์พอร์ตที่เป็น `unknown` จะถูกทำเครื่องหมายว่าไม่แน่นอน แทนที่จะถือว่าหายไปหรือปิดอย่างยืนยันแล้ว: โฮสต์ที่มีข้อผิดพลาดจะปรากฏใน `uncertain_hosts` และทุกการเปลี่ยนสถานะของพอร์ตที่เกี่ยวข้องกับ `unknown` (รวมถึงกรณีที่เป็น `unknown` ทั้งสองครั้ง) จะอยู่ใน `unconfirmed_ports` แทนที่จะอยู่ใน `port_changes` ยกเว้นพอร์ตที่เปิดอยู่ในการสแกนครั้งหลัง ซึ่งจะนับเป็นการเปลี่ยนแปลงของพอร์ต `compare` และ `diff` ใช้กฎเดียวกันในการจำแนกพอร์ต `no_longer_responding` หมายถึงไม่มีการตอบสนอง ไม่ได้พิสูจน์ว่าอุปกรณ์ถูกถอดออก รหัสออก 0 ของการสแกนไม่ได้รับประกันว่าทุกโฮสต์ตอบกลับ ให้ตรวจสอบข้อผิดพลาดรายโฮสต์ด้วย การเปรียบเทียบที่สำเร็จจะคืนค่า 0 ไม่ว่าจะมีการเปลี่ยนแปลงหรือไม่ก็ตาม ส่วนคำสั่ง `diff` สำหรับไฟล์ยังคงข้อตกลงรหัสออก 3 ไว้ ประวัติที่ไม่รองรับหรือเสียหายจะคืนค่า 1

ประวัติจะจัดเก็บข้อมูลรายการบริการ ดังนั้นควรเลือกไดเรกทอรีในเครื่องที่มีการป้องกันอย่างเหมาะสม ไฟล์โปรไฟล์และการตั้งค่าที่จัดเก็บไว้จะไม่มีข้อมูลรับรอง SNMP การจัดการข้อมูลรับรองยังคงทำผ่านตัวเลือกขณะรันและตัวแปรสภาพแวดล้อมที่มีอยู่

## การเปรียบเทียบรายการบริการ (Inventory diff)

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot monday.json
hostcensus scan 10.0.0.0/24 -q --save-snapshot tuesday.json
hostcensus diff monday.json tuesday.json             # table
hostcensus diff monday.json tuesday.json -f json     # JSON on stdout
```

สแนปช็อตคือไฟล์ JSON ที่มี `format: "hostcensus-snapshot"`, `version: 1`, เวอร์ชันของ hostcensus, เวลาที่สร้างแบบ UTC, เป้าหมาย, ค่า `timeout` และ `backend` ของการสแกนเมื่อมีการบันทึกไว้, บริการที่ถูกตรวจสอบ และโฮสต์ที่ทำงานอยู่ในรูปแบบเดียวกับรายงาน `-o` โฮสต์ที่ปิดอยู่จะไม่ถูกรวมไว้ นอกจากนี้ `diff` ยังรองรับรายงาน JSON ปกติจาก `scan -o` รวมถึงรายงานจากรุ่นก่อนที่จะมีฟิลด์ `services` ด้วย

`diff` จะรายงานโฮสต์ที่เพิ่มเข้ามาใหม่และโฮสต์ที่หายไป พอร์ตที่เปิดหรือปิดบนโฮสต์ที่ปรากฏอยู่ทั้งสองครั้ง และบริการที่ `version` เปลี่ยนแปลงไป พอร์ตที่ถูกตรวจสอบเพียงครั้งเดียวจากสองการสแกนจะไม่ถูกนำมาเปรียบเทียบ และจะมีคำเตือนแจ้งให้ทราบ ผลสังเกตการณ์ที่ล้มเหลวจะไม่ถูกตีความว่า "ไม่มีการเปลี่ยนแปลง": พอร์ตที่เป็น `unknown` ในการสแกนใดสแกนหนึ่งและไม่ได้เปิดอยู่ในการสแกนครั้งหลังจะถูกจัดไว้ใน `unconfirmed` ไม่ใช่ `closed` โดยมีค่า `before` เป็น `open`, `unknown` หรือ `not-open` (ตรวจสอบแล้วพบว่าปิดหรือถูกกรอง) และค่า `after` เป็น `unknown` หรือ `not-open` ส่วนพอร์ตที่เปิดอยู่ในปัจจุบันจะถูกรายงานใน `opened` แม้ว่าการตรวจสอบก่อนหน้าจะล้มเหลวก็ตาม โฮสต์ที่การตรวจสอบทั้งหมดล้มเหลวโดยไม่มีการตอบกลับในการสแกนใดสแกนหนึ่งจะถูกจัดไว้ใน `unsettled_hosts` (โดยมี `before`/`after` เป็น `up`, `uncertain` หรือ `absent` รวมถึงกรณีที่ล้มเหลวทั้งสองครั้งหรือไม่มีอยู่ในอีกไฟล์หนึ่ง) แทนที่จะอยู่ใน `vanished_hosts` และหากโฮสต์นั้นตอบกลับในการสแกนครั้งหลัง ก็จะถูกรายงานเป็นโฮสต์ใหม่พร้อมพอร์ตที่เปิดอยู่ด้วย สแนปช็อตเก็บโฮสต์ที่ล้มเหลวเหล่านั้นไว้ด้วยเหตุผลนี้ คำเตือนจะปรากฏขึ้นด้วยเมื่อเป้าหมายแตกต่างกัน และเมื่อไฟล์ทั้งสองบันทึกค่า timeout หรือ backend ไว้แตกต่างกัน `-o PATH` จะเขียนผลลัพธ์รูปแบบ JSON ลงในไฟล์ด้วยเช่นกัน

รายงานจากการสแกนที่ถูกหยุดโดย `--deadline` (`"complete": false`) จะแสดงเฉพาะโฮสต์ที่สแกนไปถึงเท่านั้น ดังนั้น `diff` และ `export` จึงปฏิเสธรายงานดังกล่าวด้วยรหัสออก 2 ตัวเลือก `--allow-partial` จะยอมรับรายงานนี้พร้อมแสดงคำเตือนทาง stderr: จากนั้น `diff` จะจัดโฮสต์ที่การสแกนไม่สมบูรณ์ไม่ได้ระบุไว้เลยให้อยู่ภายใต้ `unsettled_hosts` ในสถานะ `unscanned` แทนที่จะเป็นโฮสต์ที่หายไป (โฮสต์ที่ระบุว่าปิดอยู่จะยังคงเป็นโฮสต์ที่หายไป) ตั้งค่า `partial` เป็น true และจะไม่รายงานว่าไม่มีการเปลี่ยนแปลง ส่วน `export` จะเขียนคำเตือนไว้ในส่วนหัวของสคริปต์

รหัสออกของ `diff`: `0` ไม่มีการเปลี่ยนแปลง, `3` พบการเปลี่ยนแปลง ผลสังเกตการณ์ที่ไม่สามารถยืนยันได้ หรืออินพุตไม่สมบูรณ์ (`changed` จะเป็น true เมื่อใดก็ตามที่รายการใด ๆ รวมถึง `unsettled_hosts` และ `unconfirmed` ไม่ว่างเปล่า หรือ `partial` เป็น true), `2` ไฟล์ขาดหาย อ่านไม่ได้ ไม่ใช่สแนปช็อตที่รองรับ หรือไม่สมบูรณ์โดยไม่มี `--allow-partial`, `1` ไม่สามารถเขียนไฟล์ `-o` ได้

## การส่งออกไปยัง Kadupul

[Kadupul](https://github.com/kadupulhq/kadupul) (ซึ่งเป็น fork ของ Cacti 1.2.31) ไม่มีการนำเข้าไฟล์อุปกรณ์แบบเป็นชุด วิธีที่รองรับสำหรับการเพิ่มอุปกรณ์จากสคริปต์คือผ่าน `cli/add_device.php` หนึ่งอุปกรณ์ต่อการเรียกหนึ่งครั้ง พร้อมอาร์กิวเมนต์ `--option=value` คำสั่ง `hostcensus export` จะเขียนสคริปต์ POSIX `sh` ของการเรียกเหล่านั้น:

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot inventory.json
hostcensus export inventory.json -o kadupul-import.sh --template 1
# or in one step, with template 0: hostcensus scan 10.0.0.0/24 -q -o kadupul-import.sh

# on the Kadupul server, as the user that owns the install:
export HOSTCENSUS_SNMP_COMMUNITY=...        # only if the script asks for it
KADUPUL_ROOT=/var/www/html/kadupul sh kadupul-import.sh
```

โฮสต์ที่ทำงานอยู่แต่ละเครื่องจะถูกแปลงเป็น `php "$KADUPUL_ROOT/cli/add_device.php" --description=... --ip=... --template=N ...`:

- โฮสต์ที่การคิวรี SNMP จากการสแกนสำเร็จจะได้ `--version=2 --community=...` หรือ `--version=3 --username=... --authproto=... --password=...` (พร้อม `--privproto`/`--privpass` สำหรับ authPriv), `--port` และ `--avail=snmp` การส่งออก SNMPv3 ต้องระบุ `--snmp-user` และระบบจะปฏิเสธ noAuthNoPriv เนื่องจาก `add_device.php` ต้องใช้รหัสผ่าน v3
- โฮสต์อื่น ๆ จะได้ `--version=0 --avail=ping` พร้อม `--ping_method=tcp --ping_port=` ที่ระบุพอร์ต TCP แรกที่เปิดอยู่ หรือใช้ ICMP หากไม่มีพอร์ตเปิด
- `--notes` จะระบุรายการบริการและเวอร์ชันที่เปิดอยู่ `--description` จะใช้ชื่อ reverse-DNS เมื่อเป็นชื่อธรรมดา (ตัวอักษร ตัวเลข `.`, `_`, `-`) มิฉะนั้นจะใช้ IP และจะถูกทำให้ไม่ซ้ำกัน เนื่องจาก `add_device.php` ถือว่า description ที่มีอยู่แล้วเป็นการอัปเดตอุปกรณ์นั้น

ทุกค่าจะถูกตรวจสอบความถูกต้องและใส่เครื่องหมายคำพูดสำหรับ shell ด้วย `shlex.quote` โดยค่าเริ่มต้นจะไม่มีการเขียนข้อมูลลับ SNMP ลงไป: สคริปต์จะขยายค่า `HOSTCENSUS_SNMP_COMMUNITY`, `HOSTCENSUS_SNMP_AUTH_KEY` หรือ `HOSTCENSUS_SNMP_PRIV_KEY` ขณะรันและหยุดทำงานหากตัวแปรใดไม่ได้ตั้งค่าไว้ ตัวเลือก `--include-credentials` จะเขียนค่าจากตัวแปรสภาพแวดล้อมเหล่านั้นลงในสคริปต์แทน โดยสร้างไฟล์ด้วยโหมด 0600 และบันทึกคำเตือนไว้ ทั้งนี้ตัว `add_device.php` เองจะพิมพ์ค่า community และรับข้อมูลลับเป็นอาร์กิวเมนต์ ซึ่งอาจมองเห็นได้ในรายการโปรเซสของเซิร์ฟเวอร์ Kadupul ขณะที่แต่ละคำสั่งกำลังทำงาน

`add_device.php` จะจบการทำงานด้วยรหัส 1 เมื่อพบข้อมูลซ้ำหรือข้อผิดพลาด สคริปต์จะทำงานต่อไป นับจำนวนความล้มเหลว และจบด้วยรหัส 1 หากมีอุปกรณ์ใดที่ไม่ได้ถูกเพิ่ม รหัสเทมเพลตได้มาจาก `php cli/add_device.php --list-host-templates` รหัสออกของ `export`: `0` เขียนสำเร็จ, `2` อินพุตอ่านไม่ได้ การสแกนไม่สมบูรณ์โดยไม่มี `--allow-partial` หรือข้อมูลไม่สามารถส่งออกได้อย่างปลอดภัย, `1` ไม่สามารถเขียนสคริปต์ได้

## การกำหนดเวอร์ชันและกระบวนการเผยแพร่

hostcensus ยึดตาม [Semantic Versioning](https://semver.org/spec/v2.0.0.html): การแก้ไขที่เข้ากันได้จะเพิ่มเลขเวอร์ชัน patch ฟีเจอร์ที่เข้ากันได้หรือการประกาศเลิกใช้งานจะเพิ่มเลขเวอร์ชัน minor และการเปลี่ยนแปลงที่ทำให้เข้ากันไม่ได้จะเพิ่มเลขเวอร์ชัน major คำสั่งและตัวเลือก รหัสออก และ JSON schema ถือเป็นข้อตกลงสาธารณะ พฤติกรรมที่ประกาศเลิกใช้จะยังคงทำงานได้จนถึงการเผยแพร่เวอร์ชันหลักถัดไป เว้นแต่การแก้ไขด้านความปลอดภัยจำเป็นต้องเปลี่ยนเร็วกว่านั้น (ซึ่งบันทึกการเปลี่ยนแปลงจะอธิบายเหตุผลไว้)

release-please จะเปิด PR สำหรับการเผยแพร่จากหัวข้อ Conventional Commit บน `main` เพื่อปรับเวอร์ชันใน `pyproject.toml`, `uv.lock` และ `CHANGES.md` การผสาน PR ดังกล่าวจะสร้างแท็ก `vMAJOR.MINOR.PATCH` และร่างการเผยแพร่บน GitHub ซึ่ง CI จะแนบไฟล์ wheel ที่ทดสอบแล้ว แพ็กเกจซอร์สโค้ด และค่าตรวจสอบความถูกต้อง (checksum) เข้าไปด้วย โดย GitHub จะจัดเก็บหลักฐานการรับรองการสร้าง (build attestations) สำหรับไฟล์เหล่านั้นผ่าน API การรับรอง ผู้ดูแลโปรเจกต์จะตรวจสอบและเผยแพร่ร่างเมื่อไฟล์แนบครบถ้วนแล้ว การเผยแพร่ที่ออกไปแล้วจะไม่ถูกเขียนทับ

การเผยแพร่แบบเชื่อถือได้บน PyPI (trusted publishing) เป็นแบบเลือกเปิดใช้ และต้องมีการเป็นเจ้าของโปรเจกต์ ผู้เผยแพร่ที่เชื่อถือได้ และสภาพแวดล้อม `pypi` ซึ่งจะเผยแพร่อาร์ติแฟกต์ของการเผยแพร่ชุดเดิมที่ผ่านการตรวจสอบแล้วโดยไม่ต้องสร้างใหม่หรือจัดเก็บโทเค็น API การเผยแพร่แบบติดแท็กในรีพอสิทอรีสาธารณะนี้จะสร้างหลักฐานรับรองอาร์ติแฟกต์ของ GitHub ส่วน fork ส่วนตัวต้องใช้แผนบริการที่รองรับและเปิดใช้ด้วยตนเอง ดู [คู่มือการเผยแพร่ฉบับสมบูรณ์](../../../docs/releasing.md) สำหรับการตั้งค่า คำสั่งที่แน่นอน และการลองใหม่

## การพัฒนา

```bash
uv sync --locked                 # runtime plus the default `dev` group
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=hostcensus
uv build --no-build-isolation
uv run twine check --strict dist/*.whl dist/*.tar.gz
```

เครื่องมือสำหรับการพัฒนาอยู่ในกลุ่มส่วนพึ่งพา [PEP 735](https://peps.python.org/pep-0735/) ใน `pyproject.toml` (`dev`, `fuzz`, `build`) จึงไม่ปรากฏในข้อมูลเมตาของแพ็กเกจที่เผยแพร่ `uv.lock` เป็น lockfile เพียงไฟล์เดียว CI จะติดตั้งด้วย `uv sync --locked` และจะล้มเหลวหาก lockfile ล้าสมัย สามารถเลือกตัวแปลภาษาได้ด้วย `uv python`, mise (`mise exec python@3.14 -- uv sync --locked`) หรือ Python 3.12+ ใด ๆ

CI บังคับเกณฑ์ขั้นต่ำของการครอบคลุมโค้ด (coverage) ของแพ็กเกจไว้ที่ 90% การทดสอบระดับยูนิตประกอบด้วยเซิร์ฟเวอร์ loopback แบบควบคุมและกรณีทดสอบออฟไลน์สำหรับโปรไฟล์/ประวัติ/ตัวตรวจสอบการเผยแพร่ ส่วนแล็บ Compose จะรัน OpenSSH, MariaDB, nginx และ net-snmp บนบริดจ์ที่แยกออกมาต่างหาก รันได้ด้วย `make test-integration` ดูเพิ่มเติมที่ [CONTRIBUTING.md](../../../CONTRIBUTING.md) และ [เครื่องมือการเผยแพร่](../../../scripts/README.md)

คอนเทนเนอร์รันไทม์ทำงานด้วย UID/GID 10001 โดยไม่มีไดเรกทอรี home ไม่มีการเข้าสู่ระบบ shell และไม่มี pip และสามารถเขียนลงใน `/app/output` ได้ โปรดให้สิทธิ์การเขียนแก่ผู้ใช้ดังกล่าวในไดเรกทอรีเอาต์พุตที่เมาต์เข้าไป คอนเทนเนอร์นี้ไม่ต้องการ Linux capabilities ใด ๆ และทำงานได้กับระบบไฟล์รูทแบบอ่านอย่างเดียว จึงสามารถรันได้ดังนี้:

```sh
docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp -v "$PWD/out:/app/output" IMAGE scan 192.0.2.0/28 -o /app/output/report.json
```

Nmap จะใช้พฤติกรรมการค้นหาแบบ TCP ที่ไม่ใช้สิทธิ์พิเศษในคอนเทนเนอร์นี้ CI จะทำให้การสร้างอิมเมจล้มเหลวหากพบช่องโหว่ระดับ HIGH หรือ CRITICAL ที่แก้ไขได้ที่ Trivy รายงาน

## การตรวจสอบซัพพลายเชน

[OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/somethingwithproof/python-network-discovery-tool) จะทำงานบน main และเป็นรายสัปดาห์ เผยแพร่คะแนนจริง และอัปโหลดผลที่พบไปยัง GitHub code scanning ทั้ง Actions และอิมเมจพื้นฐานของคอนเทนเนอร์ถูกปักหมุดด้วยแฮชที่ไม่เปลี่ยนแปลง ส่วนพึ่งพาของ Python ถูกแก้ไขเวอร์ชันใน `uv.lock` ความล้มเหลวของ Bandit จะทำให้ CI ล้มเหลว และการทำ fuzzing แบบมีขอบเขตด้วย Atheris จะทดสอบตัวแยกวิเคราะห์ SSH, MySQL, HTTP, ใบรับรอง และ SNMPv3 BER โดยไม่เข้าถึงเครือข่าย

Scorecard ยังวัดกิจกรรมการรีวิวในอดีต ความหลากหลายของผู้ร่วมพัฒนา และที่มาของการเผยแพร่ (release provenance) ด้วย คะแนนเหล่านั้นสะท้อนจากหลักฐานจริง ไม่ได้เป็นการอ้างว่าผ่านการตรวจสอบด้านธรรมาภิบาลหรือการเผยแพร่ในอดีตทุกข้อ ดูเพิ่มเติมที่ [SECURITY.md](../../../SECURITY.md) และ [ที่มาของการเผยแพร่](../../../docs/releasing.md)

## การรองรับภาษาท้องถิ่น

ข้อความ CLI และตารางสรุป/การเปรียบเทียบ (diff) บนเทอร์มินัลรองรับ 45 ภาษาท้องถิ่น (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) โดยไม่ต้องเพิ่มส่วนพึ่งพารันไทม์ใด ๆ การเลือกลำดับภาษาจะใช้ `--lang` ตามด้วย `LC_ALL`, `LC_MESSAGES` และ `LANG` และย้อนกลับไปใช้ `en` เป็นค่าเริ่มต้น ส่วน JSON schema คอลัมน์ CSV และสคริปต์ส่งออกยังคงเหมือนเดิมในทุกภาษาท้องถิ่น

```bash
hostcensus --lang de version
LANG=ja_JP.UTF-8 hostcensus scan 192.0.2.0/28
```
