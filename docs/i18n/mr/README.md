hostcensus ही तुम्ही व्यवस्थापित करत असलेल्या नेटवर्क्सवर पुनरावृत्ती करण्यायोग्य सर्व्हिस इन्व्हेंटरीसाठी एक Python CLI आहे. ती डिव्हाइसेस काय उघड करतात याची नोंद करते, वेळेनुसार निरीक्षणांची तुलना करते आणि Kadupul आयात स्क्रिप्ट्स तयार करते. डीफॉल्ट बॅकएंड root शिवाय asyncio सॉकेट्स वापरतो; पर्यायी Nmap डिस्कव्हरी कॉन्फिगर केलेल्या सर्व्हिस पोर्ट्सपलीकडील होस्ट्स ओळखू शकते.

## hostcensus का वापरावे

एकवेळचा पोर्ट अहवाल पुढील निरीक्षणात बदल झाला आहे की ते केवळ अयशस्वी झाले आहे हे स्पष्ट करत नाही. hostcensus मध्ये स्पष्ट सर्व्हिस स्थिती, मर्यादित प्रोब्स, पुनर्वापर करण्यायोग्य स्कॅन प्रोफाइल्स आणि स्थानिक इतिहास एकत्र केले आहेत. ऑपरेटर्स तीच व्याप्ती पुन्हा तपासू शकतात, त्रुटी पाहू शकतात आणि अनिश्चित निरीक्षणे तसेच निश्चित झालेले बदल यांतील फरक ओळखू शकतात.

- **सर्व्हिस पुरावे:** SSH ओळख, MySQL ग्रीटिंग्ज, HTTP हेडर्स, TLS प्रमाणपत्र निरीक्षणे आणि SNMP डिस्कव्हरी किंवा क्रेडेंशियलसह system-MIB क्वेरीज.
- **पुनरावृत्ती करण्यायोग्य व्याप्ती:** नाव दिलेले TOML प्रोफाइल्स, जोडता येणारे वगळणे (additive exclusions), कॉन्फिगर करण्यायोग्य सर्व्हिसेस, होस्ट/प्रोब मर्यादा आणि मर्यादित वर्कर्स.
- **ट्रॅफिकपूर्वी तपासण्या:** स्थानिक प्रीफ्लाइट लक्ष्ये, साधने, गंतव्य प्रवेश, इतिहास स्कीमा आणि कॉन्फिगर केलेले TLS CA बंडल्स वैध आहेत का हे तपासते.
- **इन्व्हेंटरी इतिहास:** व्यवहारिक (transactional) SQLite स्नॅपशॉट्स सर्व निरीक्षणे जतन करतात; तुलनांमध्ये स्कॅनर त्रुटी आणि अज्ञात स्थिती दृश्यमान ठेवल्या जातात.
- **परस्पर-सुसंगत आउटपुट:** टर्मिनल, JSON आणि CSV अहवाल, आवृत्तीकृत फाइल स्नॅपशॉट्स आणि Kadupul आयात स्क्रिप्ट्स.

CI मध्ये Linux आणि macOS वर Python 3.12, 3.13 आणि 3.14, तसेच नियंत्रित Compose एकत्रीकरण लॅब समाविष्ट आहे. कोड त्या रनटाइम आवृत्त्या कायम ठेवत आधुनिक टाइप एलियासेस, टाइप्ड प्रीफ्लाइट परिणाम, कीवर्ड-ओन्ली स्लॉटेड प्रोफाइल्स आणि संरचित async क्लीनअप वापरतो. SemVer सुसंगतता करार आणि GitHub प्रकाशन प्रक्रियेसाठी [आवृत्तीकरण आणि प्रकाशन](../../../docs/releasing.md) पहा. प्रकाशन बॅज प्रकाशित आर्टिफॅक्ट्स दर्शवतो, सध्याच्या चेकआउटचे नव्हे: सध्याचा नवीनतम प्रकाशित टॅग `v0.3.0` आहे, तर हा चेकआउट पॅकेज आवृत्ती `3.0.0` वापरतो. येथे दस्तऐवजीकरण केलेली इन्व्हेंटरी वैशिष्ट्ये वापरण्यासाठी चेकआउटवरून स्थापना करा.

[स्थापना](#install) पासून सुरुवात करा, त्यानंतर [प्रोफाइल्स आणि इतिहास](#inventory-profiles-preflight-and-local-history) पहा. एकत्रीकरण तपशिलांसाठी, [सर्व्हिस फिंगरप्रिंट्स](#fingerprints), [फाइल तुलना](#inventory-diff) आणि [Kadupul निर्यात](#kadupul-export) पहा.

## स्थापना

Python 3.12 किंवा त्यापुढील आवृत्ती आवश्यक आहे; Python 3.12 ते 3.14 ही तपासलेली श्रेणी आहे. या चेकआउटवरून लॉक केलेल्या रनटाइम अवलंबनांची स्थापना करा:

```bash
uv sync --locked
uv run hostcensus --help
uv run hostcensus --version
uv run hostcensus preflight 127.0.0.1
uv run hostcensus scan 127.0.0.1 --services ssh -o loopback.json
```

पर्यायी Nmap होस्ट डिस्कव्हरीसाठी, तुमच्या प्लॅटफॉर्मच्या पॅकेज व्यवस्थापकाचा वापर करून Nmap एक्झिक्युटेबल स्थापित करा; कोणत्याही अतिरिक्त Python पॅकेजची आवश्यकता नाही. Nmap चे XML आउटपुट मुख्य अवलंबन असलेल्या defusedxml द्वारे पार्स केले जाते, त्यामुळे एंटिटी विस्तार नाकारला जातो. hostcensus थेट `PATH` वर सापडलेला `nmap` एका निश्चित आर्ग्युमेंट सूचीसह, प्रीफिक्स आकारासोबत वाढणाऱ्या वेळमर्यादेसह आणि 64 MiB आउटपुट मर्यादेसह चालवते. डीफॉल्ट बॅकएंडसाठी Nmap आवश्यक नाही.

## netprobe वरून स्थलांतर

3.0.0 मध्ये प्रकाशित झालेले hostcensus हे netprobe चे नवीन नाव आहे. हा प्रकल्प कोणत्याही नावाखाली कधीही PyPI वर प्रकाशित केला गेला नव्हता, त्यामुळे स्थापना चेकआउट किंवा GitHub प्रकाशनावरून केली गेली होती. GitHub रेपॉझिटरीचे नाव तसेच राहते.

| पूर्वी | आता | सुसंगतता |
| --- | --- | --- |
| वितरण `netprobe` | `hostcensus` | चेकआउटवरून पुन्हा स्थापना करा; जुन्या नावाचे पॅकेज उपलब्ध नाही. |
| `netprobe` कमांड | `hostcensus` | `netprobe` अजूनही चालते आणि stderr वर एक डेप्रिकेशन ओळ प्रिंट करते. एक्झिट कोड्स आणि stdout बदललेले नाहीत. पुढील मुख्य प्रकाशनात काढून टाकले जाईल. |
| `NETPROBE_*` पर्यावरण चले | `HOSTCENSUS_*` | जेव्हा संबंधित `HOSTCENSUS_*` चल सेट केलेले नसेल तेव्हा `NETPROBE_*` चल वापरले जाते, आणि stderr वर चलांची नावे सांगणारी एक चेतावणी येते पण त्यांची मूल्ये कधीही प्रिंट केली जात नाहीत. दोन्ही सेट केल्यास `HOSTCENSUS_*` ला प्राधान्य मिळते. पुढील मुख्य प्रकाशनात काढून टाकले जाईल. |
| `import netprobe`, `python -m netprobe` | `import hostcensus`, `python -m hostcensus` | **ब्रेकिंग बदल.** कोणतेही इम्पोर्ट शिम स्थापित केलेले नाही; इम्पोर्ट्स अद्यतनित करा. |
| Docker इमेज टॅग `network-discovery:test` (फक्त CI) आणि कंटेनर वापरकर्ता `netprobe` | `hostcensus:test`, वापरकर्ता `hostcensus` | कोणतीही रजिस्ट्री इमेज कधीही प्रकाशित केली गेली नव्हती. इमेज पुन्हा तयार करा आणि `hostcensus` एंट्रीपॉइंट वापरा. |
| `netprobe.toml`, `netprobe-history.sqlite3` | `hostcensus.toml`, `hostcensus-history.sqlite3` | नवीन नाव अस्तित्वात नसताना जुन्या डीफॉल्ट नावाची विद्यमान फाइल चेतावणीसह अजूनही वापरली जाते. स्पष्ट `--config` आणि `--history` पाथ्सना हात लावला जात नाही. |
| `"format": "netprobe-report"` किंवा `"netprobe-snapshot"` आणि `netprobe_version` फील्ड असलेले अहवाल आणि स्नॅपशॉट्स | `hostcensus-report`, `hostcensus-snapshot`, `hostcensus_version` | `diff` आणि `export` अजूनही जुन्या नावाने लिहिलेल्या फाइल्स लोड करतात आणि प्रकाशित JSON Schemas दोन्ही नावे स्वीकारतात. नवीन फाइल्स नवीन नावे वापरतात. SQLite इतिहास डेटाबेस अपरिवर्तित आहेत आणि पूर्वीप्रमाणेच लोड होतात. |
| `netprobe export` मधील Kadupul स्क्रिप्ट्स | `hostcensus export` मधील स्क्रिप्ट्स | जुन्या स्क्रिप्ट्स काम करत राहतात आणि चालताना अजूनही `NETPROBE_SNMP_*` वाचतात. नवीन स्क्रिप्ट्स `HOSTCENSUS_SNMP_*` वाचतात. |

## झटपट उदाहरण

विकास विभागाखाली वर्णन केलेल्या एकत्रीकरण लॅबच्या tester कंटेनरमधून चालवा; आउटपुट संक्षिप्त केले आहे:

```console
$ hostcensus scan 172.30.57.8/29 --services ssh,http,snmp --save-snapshot after.json
┃ IP Address   ┃ Hostname       ┃ SSH ┃ SNMP ┃ MySQL ┃ Open services  ┃ Status ┃
│ 172.30.57.10 │ hostcensus-it-s… │ ✅  │  ❌  │  ❌   │ ssh:22         │ UP     │
│              │                │     │      │       │ OpenSSH_10.0   │        │
│ 172.30.57.13 │ hostcensus-it-w… │ ❌  │  ❌  │  ❌   │ http:80        │ UP     │
│              │                │     │      │       │ nginx/1.28.3   │        │

$ hostcensus diff before.json after.json; echo "exit=$?"
Warning: targets differ: 172.30.57.10 vs 172.30.57.8/29
│ new host │ 172.30.57.13 │ http:80/tcp  │ hostcensus-it-web-1.hostcensus-it_lab   │
exit=3

$ hostcensus export after.json -o kadupul-import.sh --template 1
$ grep 57.13 kadupul-import.sh
add --description=hostcensus-it-web-1.hostcensus-it_lab --ip=172.30.57.13 --template=1 --version=0 --avail=ping --ping_method=tcp --ping_port=80 '--notes=hostcensus: http:80/tcp nginx/1.28.3'
```

| `history` | सारांश सूचीबद्ध | गहाळ, अवैध किंवा असमर्थित इतिहास | अवैध CLI पर्याय | - | - |

| `export` | स्क्रिप्ट लिहिली | स्क्रिप्ट लिहिता आली नाही | वाचता न येणारे इनपुट, `--allow-partial` शिवाय अपूर्ण स्कॅन, किंवा सुरक्षितपणे निर्यात न करता येणारा डेटा | - | - |

| `export.py` | वैध आणि कोटेड Kadupul आयात स्क्रिप्ट्स |

प्रत्येक सर्व्हिस निरीक्षण त्याची स्थिती आणि जाहीर केलेली ओळख स्वतंत्रपणे नोंदवते. वाचन आणि अंतिम मुदती मर्यादित असतात; प्रोब अपवाद होस्ट त्रुटींमध्ये राहतात. SQLite इतिहास व्यवहार (transactions), स्पष्ट कनेक्शन क्लीनअप आणि केवळ-वाचन सूची तसेच तुलना मार्ग वापरतो. SNMP गुपिते फक्त पर्यावरण चले किंवा सिक्रेट फाइल्सद्वारेच दिली जातात; इन्व्हेंटरी इतिहास प्रभावी गोपनीय-नसलेली सेटिंग्ज संग्रहित करतो. स्कॅन पाइपलाइन, त्याच्या मर्यादा आणि विश्वास सीमांसाठी [आर्किटेक्चर](../../../docs/architecture.md), आणि अधिकृत वापरासाठी [SECURITY.md](../../../SECURITY.md#authorized-use) पहा.


## वापर

फक्त तुम्ही व्यवस्थापित करत असलेले नेटवर्क्सच स्कॅन करा.

```bash
hostcensus scan 192.168.1.0/24              # table of alive hosts
hostcensus scan 192.168.1.1 -o results.json # JSON report
hostcensus scan 10.0.0.0/24 -o report.csv   # CSV report
hostcensus scan 10.0.0.0/24 -q -o out.json  # no table, file only
hostcensus scan 10.0.0.0/24 --format json | jq '.devices[]'  # JSON report on stdout
```

| पर्याय | अर्थ |
| --- | --- |
| `NETWORK` | CIDR, IP, किंवा होस्टनाव; `--profile` सोबत ऐच्छिक. IPv6 स्कोप अभिज्ञापक नाकारले जातात. |
| `-o, --output PATH` | अहवाल लिहा. स्वरूप एक्स्टेंशननुसार ठरते (`.json`, `.csv`); इतर एक्स्टेंशन्ससाठी डीफॉल्ट JSON वापरले जाते. |
| `-f, --format json\|csv\|kadupul\|auto` | अहवालाचे स्वरूप निश्चित करा. `--output` शिवाय याचा कोणताही परिणाम होत नाही. `.sh` मुळे `kadupul` निवडले जाते. |
| `-v, --verbose` | डीबग लॉगिंग. |
| `-q, --quiet` | परिणाम, प्रगती आणि माहितीपूर्ण लॉग्स दडपते; चेतावण्या आणि त्रुटी अजूनही stderr वर दिसतात. |
| `--backend asyncio\|nmap` | होस्ट डिस्कव्हरी. `asyncio` (डीफॉल्ट) थेट सर्व्हिस पोर्ट्स तपासतो; `nmap` आधी nmap पिंग स्वीप चालवतो आणि त्यासाठी `PATH` वर `nmap` एक्झिक्युटेबल आवश्यक असते. |
| `--timeout SECONDS` | स्वतःचे बजेट सेट न केलेल्या प्रोब्ससाठी प्रतीक्षा वेळ (डीफॉल्ट 1.0). सर्व्हिस टेबलने `timeout` सेट न केल्यास अंगभूत कनेक्ट प्रोब्स 0.3s वापरतात. |
| `--concurrency N` | एकाच वेळी चालणारे प्रोब्स (डीफॉल्ट 256). |
| `--deadline SECONDS` | nmap स्वीपसह संपूर्ण स्कॅन इतक्या वेळानंतर थांबवा (डीफॉल्ट 3600, कमाल 604800; env `HOSTCENSUS_DEADLINE`). पूर्ण झालेले होस्ट्स `"complete": false` सह अहवालात लिहिले जातात, कोणताही इतिहास किंवा स्नॅपशॉट लिहिला जात नाही आणि `scan` 4 कोडसह बाहेर पडते. |

| `--profile NAME` | नाव दिलेले प्रोफाइल वापरा; `--config` वगळल्यास डीफॉल्ट `hostcensus.toml` वापरते. |

| `--max-hosts N` | वगळण्यापूर्वी तपासली जाणारी पत्ता मर्यादा (डीफॉल्ट/कठोर कमाल 65,536). |
| `--history PATH` | पूर्ण झालेला स्कॅन ऐच्छिक SQLite इतिहास डेटाबेसमध्ये नोंदवा. |
| `--services NAMES` | तपासण्यासाठी सर्व्हिस नावांची स्वल्पविराम सूची, त्याच क्रमाने (डीफॉल्ट: सर्व). |
| `--ports SPEC` | `NAME=PORT` (सर्व्हिस हलवणे) किंवा `PORT` (`tcp-PORT` नावाची साधी TCP तपासणी जोडणे) यांची स्वल्पविराम सूची. |
| `--snmp-community-file PATH` | सिस्टम MIB क्वेरीसाठी SNMPv2c कम्युनिटी असलेली फाइल. Env: `HOSTCENSUS_SNMP_COMMUNITY` (मूल्य) किंवा `HOSTCENSUS_SNMP_COMMUNITY_FILE` (पाथ). |
| `--snmp-user` | SNMPv3 वापरकर्ता. Env: `HOSTCENSUS_SNMP_USER`. |
| `--snmp-auth-protocol`, `--snmp-auth-key-file PATH` | `MD5`, `SHA` (डीफॉल्ट), `SHA224`, `SHA256`, `SHA384`, `SHA512` आणि पासफ्रेज असलेली फाइल. Env: `HOSTCENSUS_SNMP_AUTH_PROTOCOL`, `HOSTCENSUS_SNMP_AUTH_KEY` किंवा `HOSTCENSUS_SNMP_AUTH_KEY_FILE`. |
| `--snmp-priv-protocol`, `--snmp-priv-key-file PATH` | `DES`, `AES` (डीफॉल्ट), `AES128`, `AES192`, `AES192C`, `AES256`, `AES256C` आणि पासफ्रेज असलेली फाइल. Env: `HOSTCENSUS_SNMP_PRIV_PROTOCOL`, `HOSTCENSUS_SNMP_PRIV_KEY` किंवा `HOSTCENSUS_SNMP_PRIV_KEY_FILE`. |
| `--save-snapshot PATH` | `hostcensus diff` साठी आवृत्तीकृत स्नॅपशॉट देखील लिहा. |
| `--tls-ca-file PATH` | सिस्टम स्टोअरऐवजी या PEM बंडलविरुद्ध HTTPS प्रमाणपत्रे तपासा. Env: `HOSTCENSUS_TLS_CA_FILE`. |

डीफॉल्टनुसार प्रत्येक होस्टची SSH (TCP 22), SNMP (UDP 161), MySQL (TCP 3306), HTTP (TCP 80) आणि HTTPS (TCP 443) साठी तपासणी केली जाते. TCP पोर्ट्सची तपासणी पूर्ण कनेक्टसह केली जाते. SNMP ची तपासणी SNMPv3 इंजिन-डिस्कव्हरी विनंतीद्वारे केली जाते, ज्याला कोणत्याही SNMPv3 एजंटने क्रेडेंशियल्सशिवाय उत्तर देणे आवश्यक असते; केवळ v1/v2c बोलणारे एजंट्स या प्रोबद्वारे आढळणार नाहीत. asyncio बॅकएंडसह, नाकारलेल्या कनेक्शनसह कोणत्याही प्रोबला उत्तर मिळाल्यास होस्ट जिवंत (alive) मानला जातो, त्यामुळे प्रत्येक प्रोब ड्रॉप करणाऱ्या होस्टमध्ये `alive=false` आणि `"Host is down"` त्रुटी येते; यावरून तो प्रत्यक्ष बंद आहे हे सिद्ध होत नाही. `--backend nmap` सह, कोणते होस्ट्स जिवंत आहेत हे nmap ठरवते (root म्हणून ICMP, अन्यथा TCP 80/443).

### फिंगरप्रिंट्स

प्रत्येक खुल्या सर्व्हिसचे फिंगरप्रिंटिंग ती कोणत्याही लॉगिनपूर्वी जे पाठवते त्यावरून केले जाते. SNMP क्वेरीशिवाय काहीही प्रमाणित केले जात नाही, आणि तेही फक्त तुम्ही क्रेडेंशियल्स दिल्यावरच.

| प्रोब | वाचते | `version` | `details` कीज |
| --- | --- | --- | --- |
| `ssh` | RFC 4253 ओळख ओळ | सॉफ्टवेअर, उदा. `OpenSSH_10.0` | `protocol`, `software`, `comments` |
| `mysql` | MySQL/MariaDB प्रारंभिक हँडशेक | सर्व्हर आवृत्ती | `server_version`, `flavor`, `auth_plugin`, किंवा `error_code`/`error` |
| `http` | `HEAD /` प्रतिसाद | `Server` हेडर | `status`, `server` |
| `https` | TLS हँडशेक, प्रमाणपत्र, `HEAD /` | `Server` हेडर | `tls_version`, `cert_verified`, `cert_verify_error`, `cert_subject`, `cert_issuer`, `cert_sans`, `cert_not_before`, `cert_not_after` (UTC ISO 8601), `cert_self_signed`, `status`, `server` |
| `snmp` | SNMPv3 डिस्कव्हरी; क्रेडेंशियल्ससह sysDescr, sysObjectID, sysName चा GET | sysDescr | `engine_id`; क्रेडेंशियल्ससह `snmp_version`, `sys_descr`, `sys_object_id`, `sys_name`, किंवा `snmp_error` |

होस्टनाव लक्ष्य प्रति होस्ट एकदाच रिझॉल्व्ह केले जाते आणि प्रत्येक प्रोब त्या पत्त्याशी कनेक्ट होतो, जो परिणामांमध्ये `address` म्हणून नोंदवला जातो; हे नाव फक्त TLS SNI, प्रमाणपत्र पडताळणी आणि HTTP `Host` हेडरसाठी वापरले जाते. रिझॉल्व्ह न होणारे नाव `unknown` स्थिती आणि `Cannot resolve` त्रुटी देते. रिव्हर्स DNS नावे फक्त तेव्हाच जतन केली जातात जेव्हा त्यांमध्ये होस्टनाव वर्णे असतात, आणि एकाच वेळी जास्तीत जास्त 16 लुकअप्स चालतात. HTTPS सिस्टम स्टोअर किंवा `--tls-ca-file` विरुद्ध प्रमाणपत्र आणि होस्टनाव पडताळणी वापरते. ट्रस्ट स्टोअर स्कॅनसाठी एकदा लोड केले जाते आणि प्रत्येक HTTPS प्रोबसाठी पुन्हा वापरले जाते. TCP कनेक्ट आणि TLS हँडशेक यांना स्वतंत्रपणे वेळ दिला जातो, त्यामुळे कनेक्शन स्वीकारणारा पण हँडशेक अडवणारा पोर्ट `filtered` ऐवजी `tls_error` सह `open` असतो. पडताळणी अयशस्वी झाल्यास, परिणामात `cert_verified: false` आणि `cert_verify_error` नोंदवले जातात; ते कमकुवत सेटिंग्जसह पुन्हा प्रयत्न करत नाही किंवा HTTP विनंती पाठवत नाही. पडताळणी यशस्वी झाल्यानंतरच प्रमाणपत्र तपशील आणि HTTP हेडर्स गोळा केले जातात. खाजगी-CA सर्व्हिसेससाठी योग्य CA बंडल पुरवा. जुन्या अहवालांमध्ये `cert_read_unverified` असू शकते, जे सध्याचे प्रोब्स आता तयार करत नाहीत.

SNMP गुपिते फक्त पर्यावरण चले किंवा फाइल्समधून (`--snmp-*-file`, किंवा संबंधित `HOSTCENSUS_SNMP_*_FILE` चल) वाचली जातात, कमांड-लाइन मूल्यांमधून कधीही नाही, कारण प्रक्रिया सूचीमध्ये इतर स्थानिक वापरकर्ते ती पाहू शकतात. `--snmp-community`, `--snmp-auth-key` आणि `--snmp-priv-key` मूल्यासह दिल्यास कोड 2 सह बाहेर पडतात आणि बदली पर्यायाचे नाव सांगतात. सिक्रेट फाइल रिकामी नसलेली आणि जास्तीत जास्त 4096 बाइट्सची UTF-8 असणे आवश्यक आहे; शेवटची एक न्यूलाइन दुर्लक्षित केली जाते आणि एकाच गुपितासाठी चल आणि फाइल दोन्ही सेट करणे ही त्रुटी आहे. त्रुटींमध्ये फाइलचे नाव दिले जाते पण तिचा मजकूर कधीही प्रिंट केला जात नाही. स्कॅन अहवाल आणि इतिहासात जाणीवपूर्वक क्रेडेंशियल मूल्ये समाविष्ट केली जात नाहीत. एक्सपोर्टरमध्ये खाली वर्णन केलेला एक स्वतंत्र, स्पष्ट `--include-credentials` पर्याय आहे. कम्युनिटी SNMPv2c निवडते; वापरकर्ता SNMPv3 निवडतो, ज्यात ऑथ की दिल्यास प्रमाणीकरण आणि दोन्ही की दिल्यास गोपनीयता वापरली जाते (`snmp_security_level` कोणती पातळी आहे ते नोंदवते). hostcensus कोड 2 सह कम्युनिटीला v3 वापरकर्त्यासोबत एकत्र करणे, ऑथ की शिवाय प्रायव्हसी की वापरणे किंवा वापरकर्त्याशिवाय की वापरणे नाकारते आणि अयशस्वी झालेल्या v3 क्वेरीचा v2c किंवा कमी सुरक्षा पातळीसह कधीही पुन्हा प्रयत्न करत नाही. केवळ v1/v2c बोलणारे एजंट्स क्रेडेंशियल-मुक्त v3 डिस्कव्हरीकडे दुर्लक्ष करतात, त्यामुळे ते फक्त कम्युनिटी पुरवल्यावरच खुले दिसतात.

बॅनर मजकूर संग्रहित किंवा प्रदर्शित करण्यापूर्वी प्रिंट करण्यायोग्य वर्णांपुरता मर्यादित केला जातो आणि 256 वर्णांवर मर्यादित केला जातो. वाचन देखील मर्यादित असते: प्रति ओळ 4 KiB, MySQL ग्रीटिंगसाठी 4 KiB, HTTP हेडर्ससाठी 16 KiB. 32 ऑक्टेट्सपेक्षा मोठा SNMP इंजिन आयडी संग्रहित करण्यापूर्वी कापला जातो. HTTP आणि HTTPS कंसात IPv6 पत्त्यासह आणि 80 किंवा 443 नसलेल्या पोर्टसह Host हेडर पाठवतात. स्प्रेडशीट फॉर्म्युला ट्रिगरने सुरू होणाऱ्या CSV सेल्सना प्रीफिक्स जोडला जातो जेणेकरून सेल मजकूर म्हणूनच राहील.

### मर्यादा

एक रन जास्तीत जास्त 65,536 पत्ते, 64 सर्व्हिसेस आणि 524,288 प्रोब्स (होस्ट्स गुणिले सर्व्हिसेस) स्वीकारतो; मोठ्या विनंत्या काहीही पाठवण्यापूर्वी कोड 2 सह बाहेर पडतात. `--concurrency` 4096 सॉकेट्सवर मर्यादित आहे. प्रत्येक प्रोबला त्याच्या स्वतःच्या बजेटच्या चार पट कठोर अंतिम मुदत असते. संबंधित सर्व्हिसने `timeout` सेट न केल्यास कनेक्ट प्रोब्स (`tcp`, `ssh`, `mysql`, `http`) 0.3 सेकंद वापरतात. SNMP आणि HTTPS जेव्हा स्वतःचा वेळ सेट करत नाहीत तेव्हा `--timeout` (डीफॉल्ट 1.0) वापरतात. अंतिम मुदतीवर पोहोचलेला प्रोब `errors` मध्ये "probe timed out" सह `unknown` म्हणून नोंदवला जातो. स्थानिक सॉकेट अपयश (उदाहरणार्थ फाइल डिस्क्रिप्टर्स संपणे) देखील त्रुटी नोंदवून `unknown` होतात; ते कधीही फिल्टर केलेला पोर्ट किंवा बंद होस्ट म्हणून मोजले जात नाहीत. प्रोबिंगपूर्वी, hostcensus `--concurrency` अधिक 64 डिस्क्रिप्टर्स बसवण्यासाठी ओपन-फाइल सॉफ्ट मर्यादा हार्ड मर्यादेकडे वाढवते; जेव्हा ते शक्य नसते, तेव्हा `open files` प्रीफ्लाइट तपासणी अयशस्वी होते आणि ट्रॅफिक पाठवण्यापूर्वी `scan` 1 सह बाहेर पडते. Nmap डिस्कव्हरी 30-सेकंदाचा होस्ट टाइमआउट वापरते. प्रीफिक्स CIDR स्वरूपात nmap ला दिले जाते, आणि जेव्हा nmap त्याला दिलेल्या पत्त्यांपेक्षा कमी पत्ते नोंदवते (उदाहरणार्थ रिझॉल्व्ह न होणारे नाव) तेव्हा होस्ट्स बंद दाखवण्याऐवजी स्वीप एक्झिट 1 सह अयशस्वी होतो. होस्टनाव लक्ष्य एकदा रिझॉल्व्ह केले जाते आणि nmap ला तोच पत्ता दिला जातो, ज्यामुळे डिस्कव्हरी आणि प्रोब्स एकाच मशीनपर्यंत पोहोचतात. पूर्ण प्रीफिक्स ही एक nmap प्रक्रिया असते जिची सबप्रोसेस अंतिम मुदत प्रत्येक 256 पत्त्यांसाठी 35 सेकंद (वरच्या दिशेने पूर्णांकित) असते. वगळण्यांसह असलेले स्वीप्स 256 होस्ट्सचे बॅच आणि प्रत्येक बॅचसाठी 35-सेकंदाची अंतिम मुदत वापरतात. वर्कर निर्मिती श्रेणीच्या आकारापासून स्वतंत्रपणे मर्यादित असते. रिव्हर्स DNS आणि होस्टनाव रिझोल्यूशनला स्वतंत्र दोन-सेकंदाची अंतिम मुदत असते; कधीही परत न येणारा रिझॉल्व्हर कॉल त्याच्या स्वतःच्या थ्रेडवर सोडून दिला जातो, त्यामुळे तो hostcensus ला या मर्यादांपलीकडे चालू ठेवू शकत नाही. एकाच वेळी जास्तीत जास्त 16 लुकअप्स चालतात, आणि सोडून दिलेला कॉल परत येईपर्यंत त्याचा स्लॉट राखून ठेवतो, त्यामुळे अडकलेल्या थ्रेड्सची संख्या मर्यादित राहते; जर सर्व 16 अडकले, तर `--deadline` स्कॅन थांबवेपर्यंत नंतरचे लुकअप्स दोन-सेकंदाच्या अंतिम मुदतीबाहेर (जी स्लॉट मोकळा झाल्यावर सुरू होते) स्लॉटसाठी रांगेत थांबतात. `deadline` शिवाय लायब्ररी म्हणून वापरलेले `NetworkScanner` अशा स्लॉटसाठी अनिश्चित काळापर्यंत प्रतीक्षा करू शकते. या सर्वांच्या वर `--deadline` (डीफॉल्ट एक तास) संपूर्ण रनवर मर्यादा घालते.

### सर्व्हिसेस कॉन्फिगर करणे

TOML फाइलसह सर्व्हिसेस बदलता येतात:

```toml
[services.ssh]          # same name as a built-in: replaces it
port = 2222
timeout = 0.5

[services.admin-ui]     # a new service, probed like HTTPS
port = 8443
probe = "https"
```

`probe` हे `tcp`, `ssh`, `mysql`, `http`, `https` किंवा `snmp` पैकी एक असते आणि जेव्हा ते प्रोब असते तेव्हा डीफॉल्टनुसार सर्व्हिस नाव वापरते, अन्यथा `tcp` वापरते. फक्त `snmp` UDP वापरते. सर्व्हिस नावे लहान अक्षरे, अंक, `-` आणि `_` असतात. दोन सर्व्हिसेस एकच पोर्ट आणि प्रोटोकॉल शेअर करू शकत नाहीत; इतिहास त्या जोडीसाठी एकच स्थिती नोंदवतो. `timeout` ऐच्छिक आहे, सेकंदांमध्ये आहे आणि किमान 0.05 असावा लागतो. कनेक्ट-शैलीतील प्रोब्स (`tcp`, `ssh`, `mysql`, `http`) डीफॉल्टनुसार 0.3 सेकंद घेतात. सर्व्हिसने `timeout` सेट न केल्यास `snmp` आणि `https` स्कॅनचा `--timeout` वापरतात. `--timeout` सर्व्हिसकडे आधीच असलेले बजेट बदलत नाही.

JSON अहवाल हे आवृत्तीकृत दस्तऐवज (`"format": "hostcensus-report"`, `"version": 1`) आहेत जे `devices` च्या बाजूला लक्ष्य, तपासलेल्या सर्व्हिसेस आणि सेटिंग्ज नोंदवतात; `-o` शिवाय `--format json` टेबलऐवजी stdout वर अहवाल लिहितो. प्रत्येक JSON आउटपुटमध्ये एक प्रकाशित स्कीमा आहे; [JSON आउटपुट](../../../docs/json-output.md) पहा. डिव्हाइसेस मूळ `ip`, `alive`, `ssh`, `snmp`, `mysql`, `hostname` आणि `errors` फील्ड्स कायम ठेवतात आणि प्रत्येक प्रोबचे `name`, `port`, `protocol`, `state` (`open`, `closed`, `filtered`, किंवा जेव्हा प्रोब स्थानिक पातळीवर अयशस्वी झाला किंवा अंतिम मुदतीवर पोहोचला तेव्हा `unknown`), `version` आणि `details` असलेली `services` सूची जोडतात. CSV आउटपुटमध्ये खुल्या सर्व्हिसेससाठी शेवटी `services` आणि `versions` स्तंभ जोडले जातात. `ssh`, `snmp` आणि `mysql` बुलियन मूल्ये तंतोतंत त्याच नावांच्या सर्व्हिसेसचे अनुसरण करतात.

## इन्व्हेंटरी प्रोफाइल्स, प्रीफ्लाइट आणि स्थानिक इतिहास

नाव दिलेले प्रोफाइल्स विद्यमान `[services]` व्याख्यांसह एक TOML फाइल शेअर करतात. [hostcensus.example.toml](../../../hostcensus.example.toml) ला `hostcensus.toml` वर कॉपी करा आणि तुम्ही व्यवस्थापित करत असलेले नेटवर्क्स सेट करा:

```toml
[profiles.office]
network = "192.168.1.0/24"
exclusions = ["192.168.1.1"]
services = "ssh,http,https,mysql"
concurrency = 32
timeout = 1.0
max_hosts = 256
backend = "asyncio"
```

```bash
hostcensus profiles --config hostcensus.toml
hostcensus preflight --profile office --config hostcensus.toml
hostcensus scan --profile office --config hostcensus.toml -o report.json
```

`preflight` पर्याय आणि प्रोफाइल्स तंतोतंत `scan` प्रमाणेच सोडवते, ज्यात ओपन-फाइल तपासणीसाठी `--concurrency` चा समावेश आहे, त्यामुळे उत्तीर्ण झालेले प्रीफ्लाइट म्हणजे `scan` त्याच योजनेने सुरू होईल.

प्रोफाइल्स `network`, `exclusions`, `services`, `ports`, `backend`, `timeout`, `concurrency` आणि `max_hosts` स्वीकारतात. `services` आणि `ports` विद्यमान स्वल्पविराम-सूची वाक्यरचना वापरतात. स्पष्ट CLI पर्याय प्रोफाइल सेटिंग्जना ओव्हरराइड करतात; वारंवार दिलेले `--exclude` पर्याय प्रोफाइल वगळण्यांमध्ये जोडले जातात. `--profile` सह स्पष्टपणे दिलेले नेटवर्क त्या प्रोफाइलच्या IP/CIDR व्याप्तीमध्ये समाविष्ट असणे आवश्यक आहे. थेट स्कॅनसाठी होस्टनावे समर्थित राहतात, परंतु ती IP वगळण्यांसह एकत्र करता येत नाहीत. होस्ट मर्यादा वगळण्यापूर्वी लागू होतात; एकूण प्रोब मर्यादा नंतरही लागू होते. वगळलेले होस्ट्स सर्व्हिस तपासण्या आणि पर्यायी Nmap डिस्कव्हरी या दोन्हीमधून वगळले जातात.

प्रत्येक स्कॅन लक्ष्य ट्रॅफिकपूर्वी स्थानिक प्रीफ्लाइट तपासण्या करतो: लक्ष्य/प्रोब मर्यादा, गंतव्य प्रवेश, पर्यायी Nmap एक्झिक्युटेबल/रॅपर उपलब्धता, इतिहास स्कीमा आणि कॉन्फिगर केलेले TLS CA बंडल. `preflight` JSON अहवाल देते आणि लक्ष्ये स्कॅन करत नाही किंवा इतिहास डेटाबेस तयार करत नाही. विद्यमान मजकूर न बदलता गंतव्य प्रवेश तपासण्यासाठी ते तात्पुरती एक सहचर फाइल लिहिते. डीफॉल्ट asyncio बॅकएंडला अजूनही Nmap किंवा root ची आवश्यकता नाही. हार्ड लिंक्ससह, गंतव्य पाथ्स एकमेकांपासून आणि इनपुट कॉन्फिगरेशनपासून वेगळे असणे आवश्यक आहे; गंतव्य सिमलिंक्स नाकारले जातात. अयशस्वी तपासण्या 1 परत करतात; अवैध व्याप्ती/कॉन्फिगरेशन 2 परत करते.

अहवाल आणि निर्यात लेखनासाठी `O_NOFOLLOW` समर्थन आवश्यक आहे. Windows सह ज्या प्लॅटफॉर्मवर ते नाही, तिथे ही लेखने गंतव्य न उघडता किंवा रिकामे न करता अयशस्वी होतात. नवीन अहवाल आणि निर्यात स्क्रिप्ट्स केवळ-मालक (मोड 0600) असतात; विद्यमान फाइल बदलताना तिचे परवानगे जतन केल्या जातात. वाचक नसलेल्या नेम केलेल्या पाइपवर लिहिणे प्रतीक्षा करण्याऐवजी ताबडतोब अयशस्वी होते. नवीन `--history` डेटाबेस देखील केवळ-मालक म्हणून तयार केला जातो; विद्यमान डेटाबेस त्याचा मोड कायम ठेवतो. लॉग संदेश नेहमी stderr वर जातात, त्यामुळे stdout वर फक्त परिणाम येतात. क्रेडेंशियल्स असलेली निर्याती नेहमी मोड 0600 लागू करतात.

इतिहास ऐच्छिक आहे आणि विद्यमान JSON स्नॅपशॉट्स तसेच `diff` कमांडला पूरक आहे:

```bash
mkdir -p output
hostcensus scan --profile office --history output/inventory.sqlite3
# Repeat later with the same targets and service selection.
hostcensus scan --profile office --history output/inventory.sqlite3
hostcensus history --history output/inventory.sqlite3 --limit 20
hostcensus compare 1 2 --history output/inventory.sqlite3
hostcensus compare 1 2 --history output/inventory.sqlite3 -o output/changes.json
```

`history` मधील आयडी वापरा; उदाहरण नवीन डेटाबेस गृहीत धरते. स्नॅपशॉट्स UTC प्रारंभ/समाप्ती वेळा, पॅकेज आवृत्ती, प्रभावी गोपनीय-नसलेली सेटिंग्ज, सारांश आणि प्रति-होस्ट त्रुटींसह सर्व होस्ट/सर्व्हिस निरीक्षणांसह व्यवहारिकरित्या (transactionally) संग्रहित केले जातात. अपूर्ण होस्ट निरीक्षणे जतन केली जातात. रद्द केलेले रन्स जतन केले जात नाहीत. विद्यमान अहवाल, स्नॅपशॉट, निर्यात आणि स्कॅन एक्झिट-कोड करार जतन केले जातात.

`history` सर्व ऐतिहासिक डिव्हाइस पेलोड्स न वाचता JSON सारांश सूचीबद्ध करते. `compare` दोन जतन केलेले स्कॅन्स वाचते, समान लक्ष्य ओळख आणि निवडलेले पोर्ट्स आवश्यक मानतो आणि प्रतिसादक्षमता, स्थिती आणि पोर्ट-स्थिती बदल नोंदवतो. आधीचा स्कॅन आयडी नंतरच्या आयडीच्या आधी असणे आवश्यक आहे. जेव्हा दोन्ही स्कॅन्सनी `timeout` किंवा `backend` नोंदवले असेल आणि ती मूल्ये भिन्न असतील, तेव्हा अहवाल एक चेतावणी सूचीबद्ध करतो आणि तरीही निरीक्षणांची तुलना करतो. वेगळ्या प्रतीक्षा वेळेमुळे फिल्टर केलेला पोर्ट खुला दिसू शकतो. स्कॅनर त्रुटी आणि अज्ञात पोर्ट निरीक्षणे निश्चित गायब होणे किंवा बंद होणे मानण्याऐवजी अनिश्चित म्हणून चिन्हांकित केली जातात: त्रुटी असलेले होस्ट्स `uncertain_hosts` मध्ये दिसतात, आणि नंतरच्या स्कॅनमध्ये खुला असलेला पोर्ट (जो पोर्ट बदल आहे) वगळता `unknown` समाविष्ट असलेला प्रत्येक पोर्ट बदल (दोन्ही स्कॅन्समध्ये अज्ञात असण्यासह) `port_changes` ऐवजी `unconfirmed_ports` मध्ये सूचीबद्ध केला जातो. `compare` आणि `diff` समान नियमाने पोर्ट्सचे वर्गीकरण करतात. `no_longer_responding` चा अर्थ प्रतिसादाचा अभाव असा होतो, डिव्हाइस काढून टाकल्याचा पुरावा नाही. स्कॅन एक्झिट कोड 0 प्रत्येक होस्टने प्रतिसाद दिल्याची हमी देत नाही: प्रति-होस्ट त्रुटी तपासा. तुलना यशस्वी झाल्यास बदल असोत वा नसोत 0 परत करते; विद्यमान फाइल `diff` तिचा एक्झिट कोड 3 करार कायम ठेवते. असमर्थित किंवा खराब झालेला इतिहास 1 परत करतो.

इतिहास इन्व्हेंटरी माहिती संग्रहित करतो, त्यामुळे योग्यरित्या संरक्षित केलेली स्थानिक डिरेक्टरी निवडा. प्रोफाइल फाइल्स आणि संग्रहित सेटिंग्जमध्ये SNMP क्रेडेंशियल्स नसतात; क्रेडेंशियल हाताळणी विद्यमान रनटाइम पर्याय/पर्यावरणाद्वारे सुरू राहते.

## इन्व्हेंटरी diff

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot monday.json
hostcensus scan 10.0.0.0/24 -q --save-snapshot tuesday.json
hostcensus diff monday.json tuesday.json             # table
hostcensus diff monday.json tuesday.json -f json     # JSON on stdout
```

स्नॅपशॉट हा `format: "hostcensus-snapshot"`, `version: 1`, hostcensus आवृत्ती, UTC निर्मिती वेळ, लक्ष्य, स्कॅनने नोंदवले असल्यास स्कॅन `timeout` आणि `backend`, तपासलेल्या सर्व्हिसेस आणि `-o` अहवालाच्या स्वरूपात जिवंत होस्ट्स असलेला JSON असतो. बंद होस्ट्स वगळले जातात. `diff` साधे `scan -o` JSON अहवाल देखील स्वीकारतो, ज्यात `services` फील्ड अस्तित्वात येण्यापूर्वीच्या अहवालांचाही समावेश आहे.

`diff` नवीन आणि गायब झालेले होस्ट्स, दोन्हीमध्ये उपस्थित असलेल्या होस्ट्सवर उघडलेले किंवा बंद झालेले पोर्ट्स आणि ज्यांची `version` बदलली आहे अशा सर्व्हिसेस नोंदवतो. दोनपैकी फक्त एका स्कॅनमध्ये तपासलेल्या पोर्ट्सची तुलना केली जात नाही आणि एक चेतावणी तसे सांगते. अयशस्वी निरीक्षणे कधीही "कोणताही बदल नाही" अशी वाचली जात नाहीत: दोन्हीपैकी कोणत्याही स्कॅनमध्ये `unknown` असलेला आणि नंतरच्या स्कॅनमध्ये खुला नसलेला पोर्ट `closed` ऐवजी `unconfirmed` अंतर्गत सूचीबद्ध केला जातो, ज्यामध्ये `before` म्हणून `open`, `unknown` किंवा `not-open` (तपासलेले आणि बंद किंवा फिल्टर केलेले) आणि `after` म्हणून `unknown` किंवा `not-open` असते; जरी आधीचा प्रोब अयशस्वी झाला असला तरीही आता खुला असलेला पोर्ट `opened` अंतर्गत नोंदवला जातो. ज्या होस्टचे सर्व प्रोब्स दोन्हीपैकी कोणत्याही स्कॅनमध्ये उत्तराशिवाय अयशस्वी झाले असतील तो `vanished_hosts` ऐवजी `unsettled_hosts` अंतर्गत सूचीबद्ध केला जातो (ज्यामध्ये `before`/`after` म्हणून `up`, `uncertain` किंवा `absent` असते, ज्यात तो दोन्ही स्कॅन्समध्ये अयशस्वी झाला किंवा दुसऱ्या फाइलमधून गहाळ आहे याचाही समावेश आहे); नंतरच्या स्कॅनमध्ये त्याने उत्तर दिल्यास तो त्याच्या खुल्या पोर्ट्ससह नवीन होस्ट म्हणूनही नोंदवला जातो. स्नॅपशॉट्स या कारणासाठी ते अयशस्वी होस्ट्स जतन करतात. जेव्हा लक्ष्ये भिन्न असतात आणि जेव्हा दोन्ही फाइल्सनी टाइमआउट किंवा बॅकएंड नोंदवले असेल आणि ती मूल्ये भिन्न असतील तेव्हा देखील एक चेतावणी दिसते. `-o PATH` JSON स्वरूप फाइलमध्ये देखील लिहिते.

`--deadline` द्वारे थांबवलेल्या स्कॅनमधील अहवाल (`"complete": false`) फक्त तो पोहोचलेल्या होस्ट्सचीच सूची देतो, त्यामुळे `diff` आणि `export` एक्झिट कोड 2 सह तो नाकारतात. `--allow-partial` stderr वर चेतावणीसह तो स्वीकारतो: त्यानंतर `diff` अपूर्ण स्कॅनने अजिबात सूचीबद्ध न केलेल्या होस्ट्सना गायब होण्याऐवजी `unsettled_hosts` अंतर्गत `unscanned` म्हणून सूचीबद्ध करतो (त्याने बंद म्हणून सूचीबद्ध केलेला होस्ट अजूनही गायब असतो), `partial` ला true सेट करतो आणि कधीही कोणताही बदल नाही असे नोंदवत नाही, आणि `export` स्क्रिप्ट हेडरमध्ये एक चेतावणी लिहिते.

`diff` एक्झिट कोड्स: `0` कोणतेही बदल नाहीत, `3` बदल आढळले, पुष्टी करता न आलेली निरीक्षणे किंवा अपूर्ण इनपुट (`unsettled_hosts` आणि `unconfirmed` सह कोणतीही सूची रिकामी नसल्यास किंवा `partial` true असल्यास `changed` true असते), `2` फाइल गहाळ आहे, वाचता येत नाही, समर्थित स्नॅपशॉट नाही किंवा `--allow-partial` शिवाय अपूर्ण आहे, `1` `-o` फाइल लिहिता आली नाही.

## Kadupul निर्यात

[Kadupul](https://github.com/kadupulhq/kadupul) (Cacti 1.2.31 चा एक फोर्क) मध्ये बल्क डिव्हाइस फाइल इम्पोर्ट नाही. स्क्रिप्टमधून डिव्हाइसेस जोडण्याचा त्याचा समर्थित मार्ग म्हणजे `cli/add_device.php`, प्रति कॉल एक डिव्हाइस, `--option=value` आर्ग्युमेंट्ससह. `hostcensus export` त्या कॉल्सची एक POSIX `sh` स्क्रिप्ट लिहिते:

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot inventory.json
hostcensus export inventory.json -o kadupul-import.sh --template 1
# or in one step, with template 0: hostcensus scan 10.0.0.0/24 -q -o kadupul-import.sh

# on the Kadupul server, as the user that owns the install:
export HOSTCENSUS_SNMP_COMMUNITY=...        # only if the script asks for it
KADUPUL_ROOT=/var/www/html/kadupul sh kadupul-import.sh
```

प्रत्येक जिवंत होस्ट `php "$KADUPUL_ROOT/cli/add_device.php" --description=... --ip=... --template=N ...` बनतो:

- ज्या होस्ट्सवर स्कॅनची SNMP क्वेरी यशस्वी झाली त्यांना `--version=2 --community=...` किंवा `--version=3 --username=... --authproto=... --password=...` (तसेच authPriv साठी `--privproto`/`--privpass`), `--port` आणि `--avail=snmp` मिळतात. SNMPv3 निर्यातीसाठी `--snmp-user` आवश्यक आहे, आणि noAuthNoPriv नाकारले जाते कारण `add_device.php` ला v3 पासवर्ड आवश्यक असतो.
- इतर होस्ट्सना `--version=0 --avail=ping` मिळते, ज्यात `--ping_method=tcp --ping_port=` पहिला खुला TCP पोर्ट असतो, किंवा कोणताही नसल्यास ICMP असतो.
- `--notes` खुल्या सर्व्हिसेस आणि आवृत्त्यांची सूची देतो. `--description` साधे असल्यास (अक्षरे, अंक, `.`, `_`, `-`) रिव्हर्स-DNS नाव असते, अन्यथा IP असते आणि ते युनिक केले जाते, कारण `add_device.php` विद्यमान वर्णनाला त्या डिव्हाइसचे अद्यतन मानतो.

प्रत्येक मूल्य प्रमाणित केले जाते आणि `shlex.quote` सह शेल-कोट केले जाते. डीफॉल्टनुसार कोणतेही SNMP गुपित लिहिले जात नाही: स्क्रिप्ट रन टाइमला `HOSTCENSUS_SNMP_COMMUNITY`, `HOSTCENSUS_SNMP_AUTH_KEY` किंवा `HOSTCENSUS_SNMP_PRIV_KEY` विस्तारित करते आणि एक सेट नसल्यास थांबते. `--include-credentials` त्याऐवजी त्या पर्यावरण चलांमधील मूल्ये स्क्रिप्टमध्ये लिहिते, ती मोड 0600 सह तयार करते आणि एक चेतावणी लॉग करते. `add_device.php` स्वतः कम्युनिटी प्रिंट करते आणि गुपिते आर्ग्युमेंट्स म्हणून स्वीकारते, जी प्रत्येक कॉल चालू असताना Kadupul सर्व्हरच्या प्रक्रिया सूचीमध्ये दृश्यमान असतात.

`add_device.php` डुप्लिकेट्स आणि त्रुटींसाठी 1 कोडसह बाहेर पडते; स्क्रिप्ट सुरू राहते, अपयश मोजते आणि कोणतेही डिव्हाइस जोडले न गेल्यास 1 कोडसह बाहेर पडते. टेम्पलेट आयडी `php cli/add_device.php --list-host-templates` मधून येतात. `export` एक्झिट कोड्स: `0` लिहिले, `2` वाचता न येणारे इनपुट, `--allow-partial` शिवाय अपूर्ण स्कॅन किंवा सुरक्षितपणे निर्यात न करता येणारा डेटा, `1` स्क्रिप्ट लिहिता आली नाही.

## आवृत्तीकरण आणि प्रकाशन प्रक्रिया

hostcensus [Semantic Versioning](https://semver.org/spec/v2.0.0.html) चे अनुसरण करते: सुसंगत दुरुस्त्या पॅच आवृत्ती वाढवतात, सुसंगत वैशिष्ट्ये/डेप्रिकेशन्स मायनर आवृत्ती वाढवतात आणि ब्रेकिंग सुसंगतता बदल मेजर आवृत्ती वाढवतात. कमांड्स आणि पर्याय, एक्झिट कोड्स आणि JSON स्कीमा हा सार्वजनिक करार आहे; सुरक्षा दुरुस्तीसाठी लवकर बदलणे आवश्यक नसल्यास (चेंजलॉग तेव्हा का ते सांगतो) डेप्रिकेटेड वर्तन पुढील मुख्य प्रकाशनापर्यंत कार्य करत राहते.

release-please `main` वरील Conventional Commit शीर्षकांवरून एक प्रकाशन PR उघडते, ज्यामुळे `pyproject.toml`, `uv.lock` आणि `CHANGES.md` अद्यतनित होतात. ते मर्ज केल्याने `vMAJOR.MINOR.PATCH` टॅग आणि एक ड्राफ्ट GitHub प्रकाशन तयार होते, ज्याला CI एक तपासलेले wheel, सोर्स वितरण आणि चेकसम जोडते; GitHub त्याच्या attestations API द्वारे त्या फाइल्ससाठी बिल्ड प्रमाणपत्रे संग्रहित करते. एकदा फाइल्स जोडल्या गेल्यानंतर मेंटेनर ड्राफ्टचे पुनरावलोकन करतो आणि प्रकाशित करतो. प्रकाशने कधीही बदलली जात नाहीत.

PyPI विश्वसनीय प्रकाशन ऐच्छिक आहे आणि त्यासाठी प्रकल्प मालकी, विश्वसनीय प्रकाशक आणि `pypi` पर्यावरण आवश्यक आहे. ते API टोकन पुन्हा तयार न करता किंवा संग्रहित न करता तीच तपासलेली प्रकाशन आर्टिफॅक्ट्स प्रकाशित करते. या सार्वजनिक रेपॉझिटरीमधील टॅग केलेली प्रकाशने GitHub आर्टिफॅक्ट प्रमाणपत्रे तयार करतात; खाजगी फोर्क्सना समर्थित योजना आणि स्पष्ट निवड आवश्यक असते. सेटअप, अचूक कमांड्स आणि पुन्हा प्रयत्नांसाठी [संपूर्ण प्रकाशन मार्गदर्शक](../../../docs/releasing.md) पहा.

## विकास

```bash
uv sync --locked                 # runtime plus the default `dev` group
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=hostcensus
uv build --no-build-isolation
uv run twine check --strict dist/*.whl dist/*.tar.gz
```

विकास साधने `pyproject.toml` (`dev`, `fuzz`, `build`) मधील [PEP 735](https://peps.python.org/pep-0735/) अवलंबन गटांमध्ये राहतात, त्यामुळे ती कधीही प्रकाशित पॅकेज मेटाडेटा मध्ये दिसत नाहीत. `uv.lock` ही एकमेव लॉकफाइल आहे; CI `uv sync --locked` सह स्थापना करते आणि लॉकफाइल जुनी असल्यास अयशस्वी होते. `uv python`, mise (`mise exec python@3.14 -- uv sync --locked`) किंवा कोणत्याही Python 3.12+ सह इंटरप्रिटर निवडा.

CI 90% पॅकेज कव्हरेज मर्यादा लागू करते. युनिट चाचण्यांमध्ये नियंत्रित लूपबॅक सर्व्हर्स आणि ऑफलाइन प्रोफाइल/इतिहास/रिलीज-व्हॅलिडेटर केसेस समाविष्ट आहेत; Compose लॅब एका अलग ब्रिजवर OpenSSH, MariaDB, nginx आणि net-snmp चालवते. ती `make test-integration` सह चालवा. [CONTRIBUTING.md](../../../CONTRIBUTING.md) आणि [प्रकाशन साधने](../../../scripts/README.md) पहा.

रनटाइम कंटेनर होम डिरेक्टरीशिवाय, शेल लॉगिनशिवाय आणि pip शिवाय UID/GID 10001 म्हणून चालतो आणि `/app/output` वर लिहू शकतो. त्या वापरकर्त्याला कोणत्याही माउंट केलेल्या आउटपुट डिरेक्टरीमध्ये लेखन प्रवेश द्या. त्याला कोणत्याही क्षमतांची आवश्यकता नाही आणि तो केवळ-वाचन रूट फाइलसिस्टमसह कार्य करतो, त्यामुळे तो खालीलप्रमाणे चालू शकतो:

```sh
docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp -v "$PWD/out:/app/output" IMAGE scan 192.0.2.0/28 -o /app/output/report.json
```

Nmap या कंटेनरमध्ये त्याचे विशेषाधिकार नसलेले TCP डिस्कव्हरी वर्तन वापरते. Trivy नोंदवत असलेल्या कोणत्याही दुरुस्त करण्यायोग्य HIGH किंवा CRITICAL असुरक्षिततेवर CI इमेज बिल्ड अयशस्वी करते.

## स्थानिकीकरण

CLI संदेश आणि टर्मिनल सारांश/diff टेबल्स कोणत्याही अतिरिक्त रनटाइम अवलंबनाशिवाय 45 लोकेल्सना (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) समर्थन देतात. रिझोल्यूशन `--lang`, नंतर `LC_ALL`, `LC_MESSAGES` आणि `LANG` ला प्राधान्य देते, आणि शेवटी `en` वर येते. JSON स्कीमा, CSV स्तंभ आणि निर्यात स्क्रिप्ट्स सर्व लोकेल्समध्ये अपरिवर्तित राहतात.

```bash
hostcensus --lang de version
LANG=ja_JP.UTF-8 hostcensus scan 192.0.2.0/28
```
