hostcensus అనేది మీరు నిర్వహించే నెట్‌వర్క్‌లపై పునరావృత సర్వీస్ ఇన్వెంటరీ కోసం ఉద్దేశించిన Python CLI సాధనం. పరికరాలు ఏ సర్వీసులను అందిస్తున్నాయో ఇది నమోదు చేస్తుంది, కాలక్రమేణా జరిగిన పరిశీలనలను పోలుస్తుంది, మరియు Kadupul దిగుమతి స్క్రిప్ట్‌లను రూపొందిస్తుంది. డిఫాల్ట్ బ్యాకెండ్ root అధికారాలు లేకుండా asyncio సాకెట్లను ఉపయోగిస్తుంది; ఐచ్ఛిక Nmap డిస్కవరీ కాన్ఫిగర్ చేసిన సర్వీస్ పోర్ట్‌లకు మించి ఉన్న హోస్ట్‌లను గుర్తించగలదు.

## hostcensus ఎందుకు

ఒకసారి చేసే పోర్ట్ నివేదిక, తదుపరి పరిశీలనలో మార్పు జరిగిందా లేక అది కేవలం విఫలమైందా అనేది వివరించదు. hostcensus స్పష్టమైన సర్వీస్ స్థితులు, పరిమిత ప్రోబ్‌లు, పునర్వినియోగించదగిన స్కాన్ ప్రొఫైల్‌లు, మరియు స్థానిక చరిత్రను అనుసంధానిస్తుంది. నిర్వాహకులు ఒకే పరిధిని మళ్లీ అమలు చేయవచ్చు, లోపాలను పరిశీలించవచ్చు, మరియు అనిశ్చిత పరిశీలనలను నిర్ధారిత మార్పుల నుండి వేరు చేయవచ్చు.

- **సర్వీస్ ఆధారాలు:** SSH గుర్తింపు, MySQL గ్రీటింగ్‌లు, HTTP హెడర్‌లు, TLS సర్టిఫికేట్ పరిశీలనలు, మరియు SNMP డిస్కవరీ లేదా క్రెడెన్షియల్స్‌తో కూడిన system-MIB ప్రశ్నలు.
- **పునరావృత పరిధి:** పేరు పెట్టిన TOML ప్రొఫైల్‌లు, సంకలన మినహాయింపులు, కాన్ఫిగర్ చేయదగిన సర్వీసులు, హోస్ట్/ప్రోబ్ పరిమితులు, మరియు పరిమిత వర్కర్లు.
- **ట్రాఫిక్ పంపే ముందు తనిఖీలు:** స్థానిక preflight లక్ష్యాలు, సాధనాలు, గమ్యస్థాన యాక్సెస్, చరిత్ర స్కీమా, మరియు కాన్ఫిగర్ చేసిన TLS CA బండిల్‌లను ధృవీకరిస్తుంది.
- **ఇన్వెంటరీ చరిత్ర:** లావాదేవీల ఆధారిత SQLite స్నాప్‌షాట్‌లు అన్ని పరిశీలనలను భద్రపరుస్తాయి; పోలికలు స్కానర్ వైఫల్యాలు మరియు తెలియని స్థితులను స్పష్టంగా చూపిస్తాయి.
- **పరస్పర వినియోగ అవుట్‌పుట్:** టెర్మినల్, JSON మరియు CSV నివేదికలు, వెర్షన్ చేయబడిన ఫైల్ స్నాప్‌షాట్‌లు, మరియు Kadupul దిగుమతి స్క్రిప్ట్‌లు.

CI అనేది Linux మరియు macOS లపై Python 3.12, 3.13 మరియు 3.14 లతో పాటు నియంత్రిత Compose ఇంటిగ్రేషన్ ల్యాబ్‌ను కూడా కవర్ చేస్తుంది. ఆ రన్‌టైమ్ వెర్షన్‌లను కొనసాగిస్తూనే, కోడ్ ఆధునిక టైప్ అలియాస్‌లు, టైప్ చేసిన preflight ఫలితాలు, కీవర్డ్-మాత్రమే slotted ప్రొఫైల్‌లు మరియు నిర్మాణాత్మక async శుభ్రతను ఉపయోగిస్తుంది. SemVer అనుకూలత ఒప్పందం మరియు GitHub విడుదల ప్రక్రియ కోసం [వెర్షనింగ్ మరియు విడుదలలు](../../../docs/releasing.md) చూడండి. విడుదల బ్యాడ్జ్ చెక్‌అవుట్‌ను కాకుండా ప్రచురించబడిన ఆర్టిఫ్యాక్ట్‌లను వివరిస్తుంది: ప్రస్తుతం తాజాగా ప్రచురించిన ట్యాగ్ `v0.3.0`, కాగా ఈ చెక్‌అవుట్ ప్యాకేజీ వెర్షన్ `3.0.0` ను ఉపయోగిస్తుంది. ఇక్కడ డాక్యుమెంట్ చేసిన ఇన్వెంటరీ ఫీచర్లను ఉపయోగించడానికి చెక్‌అవుట్ నుండి ఇన్‌స్టాల్ చేయండి.

[ఇన్‌స్టాలేషన్](#install) తో ప్రారంభించండి, ఆపై [ప్రొఫైల్‌లు మరియు చరిత్ర](#inventory-profiles-preflight-and-local-history) చూడండి. ఇంటిగ్రేషన్ వివరాల కోసం, [సర్వీస్ ఫింగర్‌ప్రింట్లు](#fingerprints), [ఫైల్ పోలికలు](#inventory-diff), మరియు [Kadupul ఎగుమతి](#kadupul-export) చూడండి.

## ఇన్‌స్టాల్

Python 3.12 లేదా కొత్త వెర్షన్ అవసరం; Python 3.12–3.14 పరీక్షించబడిన మాతృక. ఈ చెక్‌అవుట్ నుండి, లాక్ చేసిన రన్‌టైమ్ డిపెండెన్సీలను ఇన్‌స్టాల్ చేయండి:

```bash
uv sync --locked
uv run hostcensus --help
uv run hostcensus --version
uv run hostcensus preflight 127.0.0.1
uv run hostcensus scan 127.0.0.1 --services ssh -o loopback.json
```

ఐచ్ఛిక Nmap హోస్ట్ డిస్కవరీ కోసం, మీ ప్లాట్‌ఫారమ్ ప్యాకేజీ మేనేజర్ ద్వారా Nmap ఎగ్జిక్యూటబుల్‌ను ఇన్‌స్టాల్ చేయండి; అదనపు Python ప్యాకేజీ అవసరం లేదు. Nmap యొక్క XML అవుట్‌పుట్ ప్రధాన డిపెండెన్సీ అయిన defusedxml ద్వారా పార్స్ చేయబడుతుంది, కాబట్టి entity expansion తిరస్కరించబడుతుంది. hostcensus స్థిరమైన ఆర్గ్యుమెంట్ జాబితా, ప్రిఫిక్స్ పరిమాణంతో పెరిగే గడువు, మరియు 64 MiB అవుట్‌పుట్ పరిమితితో `PATH` లో ఉన్న `nmap` ను నేరుగా అమలు చేస్తుంది. డిఫాల్ట్ బ్యాకెండ్ కోసం Nmap అవసరం లేదు.

## netprobe నుండి మైగ్రేషన్

hostcensus అనేది 3.0.0 లో విడుదలైన netprobe యొక్క కొత్త పేరు. ఈ ప్రాజెక్ట్ ఏ పేరుతోనూ PyPI లో ప్రచురించబడలేదు, కాబట్టి ఇన్‌స్టాలేషన్‌లు చెక్‌అవుట్ లేదా GitHub విడుదల నుండి వచ్చాయి. GitHub రిపోజిటరీ తన పాత పేరునే ఉంచుకుంటుంది.

| `"format": "netprobe-report"` లేదా `"netprobe-snapshot"` మరియు `netprobe_version` ఫీల్డ్ ఉన్న నివేదికలు, స్నాప్‌షాట్‌లు | `hostcensus-report`, `hostcensus-snapshot`, `hostcensus_version` | `diff` మరియు `export` పాత పేరుతో వ్రాసిన ఫైళ్లను ఇప్పటికీ లోడ్ చేస్తాయి, మరియు ప్రచురించబడిన JSON Schemas రెండు స్పెల్లింగ్‌లను అంగీకరిస్తాయి. కొత్త ఫైళ్లు కొత్త పేర్లను ఉపయోగిస్తాయి. SQLite చరిత్ర డేటాబేస్‌లు మారలేదు మరియు మునుపటిలాగే లోడ్ అవుతాయి. |
| `netprobe export` నుండి Kadupul స్క్రిప్ట్‌లు | `hostcensus export` నుండి స్క్రిప్ట్‌లు | పాత స్క్రిప్ట్‌లు పనిచేస్తూనే ఉంటాయి మరియు అమలయ్యేటప్పుడు `NETPROBE_SNMP_*` ను చదువుతాయి. కొత్త స్క్రిప్ట్‌లు `HOSTCENSUS_SNMP_*` ను చదువుతాయి. |

## నిర్మాణం

| మాడ్యూల్ | బాధ్యత |
| --- | --- |
| `cli.py` | కమాండ్ ఎంపికలు, ప్రొఫైల్ రిజల్యూషన్, preflight, స్కానింగ్ మరియు నివేదికలు |
| `scanner.py`, `probes.py` | లక్ష్య విస్తరణ, పరిమిత వర్కర్లు, హోస్ట్ డిస్కవరీ మరియు సర్వీస్ పరిశీలనలు |
| `config.py`, `profiles.py` | సర్వీస్ నిర్వచనాలు మరియు ధృవీకరించబడిన ఇన్వెంటరీ ప్రొఫైల్‌లు |
| `models.py`, `output.py` | ఫలిత రకాలు మరియు టెర్మినల్/JSON/CSV రెండరింగ్ |
| `history.py`, `diff.py` | SQLite చరిత్ర మరియు వెర్షన్ చేయబడిన ఫైల్-స్నాప్‌షాట్ పోలికలు |
| `preflight.py` | స్థానిక తనిఖీలు మరియు పరిమిత Nmap వెర్షన్ శోధన |
| `export.py` | ధృవీకరించబడిన మరియు కోట్ చేయబడిన Kadupul దిగుమతి స్క్రిప్ట్‌లు |

ప్రతి సర్వీస్ పరిశీలన తన స్థితిని అది ప్రకటించిన గుర్తింపు నుండి వేరుగా నమోదు చేస్తుంది. రీడ్‌లు మరియు గడువులు పరిమితం చేయబడ్డాయి; ప్రోబ్ మినహాయింపులు హోస్ట్ లోపాలలో ఉంటాయి. SQLite చరిత్ర లావాదేవీలు, స్పష్టమైన కనెక్షన్ శుభ్రత, మరియు రీడ్-ఓన్లీ జాబితా మరియు పోలిక మార్గాలను ఉపయోగిస్తుంది. SNMP రహస్యాలు కేవలం ఎన్విరాన్‌మెంట్ వేరియబుల్స్ లేదా రహస్య ఫైళ్ల ద్వారా మాత్రమే ప్రవేశిస్తాయి; ఇన్వెంటరీ చరిత్ర రహస్యేతర ప్రభావవంతమైన సెట్టింగ్‌లను నిల్వ చేస్తుంది. స్కాన్ పైప్‌లైన్, దాని పరిమితులు మరియు విశ్వాస సరిహద్దుల కోసం [ఆర్కిటెక్చర్](../../../docs/architecture.md), మరియు అధికారిత వినియోగం కోసం [SECURITY.md](../../../SECURITY.md#authorized-use) చూడండి.


## వినియోగం

మీరు నిర్వహించే నెట్‌వర్క్‌లను మాత్రమే స్కాన్ చేయండి.

```bash
hostcensus scan 192.168.1.0/24              # table of alive hosts
hostcensus scan 192.168.1.1 -o results.json # JSON report
hostcensus scan 10.0.0.0/24 -o report.csv   # CSV report
hostcensus scan 10.0.0.0/24 -q -o out.json  # no table, file only
hostcensus scan 10.0.0.0/24 --format json | jq '.devices[]'  # JSON report on stdout
```

| ఎంపిక | అర్థం |
| --- | --- |
| `NETWORK` | CIDR, IP, లేదా హోస్ట్ పేరు; `--profile` తో ఐచ్ఛికం. IPv6 స్కోప్ ఐడెంటిఫైయర్‌లు తిరస్కరించబడతాయి. |
| `-o, --output PATH` | నివేదికను వ్రాయండి. ఫార్మాట్ పొడిగింపును (`.json`, `.csv`) అనుసరిస్తుంది; ఇతర పొడిగింపులు JSON కు వెళ్తాయి. |
| `-f, --format json\|csv\|kadupul\|auto` | నివేదిక ఫార్మాట్‌ను బలవంతంగా నిర్దేశించండి. `-o` లేకుండా ప్రభావం ఉండదు. `.sh` అనేది `kadupul` ను ఎంచుకుంటుంది. |
| `-v, --verbose` | డీబగ్ లాగింగ్. |
| `-q, --quiet` | ఫలితాలు, పురోగతి మరియు సమాచార లాగ్‌లను దాచండి; హెచ్చరికలు మరియు లోపాలు ఇప్పటికీ stderr లో కనిపిస్తాయి. |
| `--backend asyncio\|nmap` | హోస్ట్ డిస్కవరీ. `asyncio` (డిఫాల్ట్) సర్వీస్ పోర్ట్‌లను నేరుగా ప్రోబ్ చేస్తుంది; `nmap` ముందుగా nmap ping స్వీప్‌ను అమలు చేస్తుంది మరియు `PATH` లో `nmap` ఎగ్జిక్యూటబుల్ అవసరం. |
| `--timeout SECONDS` | స్వంత బడ్జెట్‌ను సెట్ చేయని ప్రోబ్‌ల కోసం వేచి ఉండే సమయం (డిఫాల్ట్ 1.0). సర్వీస్ పట్టిక `timeout` సెట్ చేయకపోతే అంతర్నిర్మిత కనెక్ట్ ప్రోబ్‌లు 0.3s ఉపయోగిస్తాయి. |
| `--concurrency N` | ఒకేసారి జరిగే ప్రోబ్‌లు (డిఫాల్ట్ 256). |
| `--deadline SECONDS` | nmap స్వీప్‌తో సహా మొత్తం స్కాన్‌ను ఇంత సమయం తర్వాత ఆపివేయండి (డిఫాల్ట్ 3600, గరిష్ఠంగా 604800; ఎన్విరాన్‌మెంట్ `HOSTCENSUS_DEADLINE`). పూర్తయిన హోస్ట్‌లు `"complete": false` తో నివేదికలో వ్రాయబడతాయి, చరిత్ర లేదా స్నాప్‌షాట్ వ్రాయబడదు, మరియు `scan` 4 కోడ్‌తో నిష్క్రమిస్తుంది. |
| `--config PATH` | TOML సర్వీస్ నిర్వచనాలు మరియు ఐచ్ఛికంగా పేరు పెట్టిన `[profiles]` సెట్టింగ్‌లు. |
| `--profile NAME` | పేరు పెట్టిన ప్రొఫైల్‌ను ఉపయోగించండి; `--config` వదిలివేసినప్పుడు డిఫాల్ట్‌గా `hostcensus.toml` కు వెళ్తుంది. |
| `--exclude IP/CIDR` | మినహాయింపును జోడించండి; అవసరమైనంతవరకు పునరావృతం చేయండి. మినహాయించబడిన IPv4 హోస్ట్ దానిని చేరుకునే IPv6 చిరునామాలను కూడా మినహాయిస్తుంది: IPv4-mapped (`::ffff:a.b.c.d`), NAT64 (`64:ff9b::/96`) మరియు 6to4. IPv4-mapped లక్ష్యాలు మరియు మినహాయింపులు అవి సూచించే IPv4 చిరునామాలుగానే పరిగణించబడతాయి. |
| `--max-hosts N` | మినహాయింపులకు ముందు తనిఖీ చేసే చిరునామా పరిమితి (డిఫాల్ట్/గరిష్ఠ పరిమితి 65,536). |
| `--history PATH` | పూర్తయిన స్కాన్‌ను ఆప్ట్-ఇన్ SQLite చరిత్ర డేటాబేస్‌లో నమోదు చేయండి. |
| `--services NAMES` | తనిఖీ చేయవలసిన సర్వీస్ పేర్ల కామా-వేరు జాబితా, అదే క్రమంలో (డిఫాల్ట్: అన్నీ). |
| `--ports SPEC` | `NAME=PORT` (ఒక సర్వీస్‌ను మార్చడం) లేదా `PORT` (`tcp-PORT` పేరుతో సాధారణ TCP తనిఖీని జోడించడం) యొక్క కామా-వేరు జాబితా. |
| `--snmp-community-file PATH` | system MIB ప్రశ్న కోసం SNMPv2c కమ్యూనిటీని కలిగి ఉన్న ఫైల్. ఎన్విరాన్‌మెంట్: `HOSTCENSUS_SNMP_COMMUNITY` (విలువ) లేదా `HOSTCENSUS_SNMP_COMMUNITY_FILE` (పాత్). |
| `--snmp-user` | SNMPv3 యూజర్. ఎన్విరాన్‌మెంట్: `HOSTCENSUS_SNMP_USER`. |
| `--snmp-auth-protocol`, `--snmp-auth-key-file PATH` | `MD5`, `SHA` (డిఫాల్ట్), `SHA224`, `SHA256`, `SHA384`, `SHA512` మరియు పాస్‌ఫ్రేజ్‌ను కలిగి ఉన్న ఫైల్. ఎన్విరాన్‌మెంట్: `HOSTCENSUS_SNMP_AUTH_PROTOCOL`, `HOSTCENSUS_SNMP_AUTH_KEY` లేదా `HOSTCENSUS_SNMP_AUTH_KEY_FILE`. |
| `--snmp-priv-protocol`, `--snmp-priv-key-file PATH` | `DES`, `AES` (డిఫాల్ట్), `AES128`, `AES192`, `AES192C`, `AES256`, `AES256C` మరియు పాస్‌ఫ్రేజ్‌ను కలిగి ఉన్న ఫైల్. ఎన్విరాన్‌మెంట్: `HOSTCENSUS_SNMP_PRIV_PROTOCOL`, `HOSTCENSUS_SNMP_PRIV_KEY` లేదా `HOSTCENSUS_SNMP_PRIV_KEY_FILE`. |
| `--save-snapshot PATH` | `hostcensus diff` కోసం వెర్షన్ చేయబడిన స్నాప్‌షాట్‌ను కూడా వ్రాయండి. |
| `--tls-ca-file PATH` | సిస్టమ్ స్టోర్‌కు బదులుగా ఈ PEM బండిల్‌తో HTTPS సర్టిఫికేట్లను ధృవీకరించండి. ఎన్విరాన్‌మెంట్: `HOSTCENSUS_TLS_CA_FILE`. |

డిఫాల్ట్‌గా ప్రతి హోస్ట్ SSH (TCP 22), SNMP (UDP 161), MySQL (TCP 3306), HTTP (TCP 80) మరియు HTTPS (TCP 443) కోసం తనిఖీ చేయబడుతుంది. TCP పోర్ట్‌లు పూర్తి connect ద్వారా పరీక్షించబడతాయి. SNMP ఒక SNMPv3 engine-discovery అభ్యర్థనతో పరీక్షించబడుతుంది, దీనికి ఏ SNMPv3 ఏజెంట్ అయినా క్రెడెన్షియల్స్ లేకుండా సమాధానం ఇవ్వాలి; కేవలం v1/v2c మాత్రమే మాట్లాడే ఏజెంట్లు ఈ ప్రోబ్ ద్వారా గుర్తించబడవు. asyncio బ్యాకెండ్‌తో, తిరస్కరించబడిన కనెక్షన్‌తో సహా ఏ ప్రోబ్‌కైనా సమాధానం వస్తే ఆ హోస్ట్ సజీవంగా ఉన్నట్లు లెక్కించబడుతుంది, కాబట్టి ప్రతి ప్రోబ్‌ను డ్రాప్ చేసే హోస్ట్‌కు `alive=false` మరియు `"Host is down"` లోపం ఉంటుంది; ఇది భౌతికంగా ఆఫ్‌లో ఉందని రుజువు కాదు. `--backend nmap` తో, ఏ హోస్ట్‌లు సజీవంగా ఉన్నాయో nmap నిర్ణయిస్తుంది (root గా ICMP, లేకుంటే TCP 80/443).

### ఫింగర్‌ప్రింట్లు

తెరిచి ఉన్న ప్రతి సర్వీస్ ఏదైనా లాగిన్ కంటే ముందు అది పంపే సమాచారం నుండి ఫింగర్‌ప్రింట్ చేయబడుతుంది. SNMP ప్రశ్న తప్ప మరేదీ ప్రామాణీకరించదు, అది కూడా మీరు క్రెడెన్షియల్స్ అందించినప్పుడు మాత్రమే.

| ప్రోబ్ | చదివేది | `version` | `details` కీలు |
| --- | --- | --- | --- |
| `ssh` | RFC 4253 గుర్తింపు లైన్ | సాఫ్ట్‌వేర్, ఉదా. `OpenSSH_10.0` | `protocol`, `software`, `comments` |
| `mysql` | MySQL/MariaDB ప్రారంభ హ్యాండ్‌షేక్ | సర్వర్ వెర్షన్ | `server_version`, `flavor`, `auth_plugin`, లేదా `error_code`/`error` |
| `http` | `HEAD /` ప్రతిస్పందన | `Server` హెడర్ | `status`, `server` |
| `https` | TLS హ్యాండ్‌షేక్, సర్టిఫికేట్, `HEAD /` | `Server` హెడర్ | `tls_version`, `cert_verified`, `cert_verify_error`, `cert_subject`, `cert_issuer`, `cert_sans`, `cert_not_before`, `cert_not_after` (UTC ISO 8601), `cert_self_signed`, `status`, `server` |
| `snmp` | SNMPv3 డిస్కవరీ; క్రెడెన్షియల్స్‌తో, sysDescr, sysObjectID, sysName ల GET | sysDescr | `engine_id`; క్రెడెన్షియల్స్‌తో `snmp_version`, `sys_descr`, `sys_object_id`, `sys_name`, లేదా `snmp_error` |

హోస్ట్ పేరు లక్ష్యం ప్రతి హోస్ట్‌కు ఒకసారి రిజాల్వ్ చేయబడుతుంది మరియు ప్రతి ప్రోబ్ ఆ చిరునామాకే కనెక్ట్ అవుతుంది, ఇది ఫలితాలలో `address` గా నమోదవుతుంది; ఆ పేరు కేవలం TLS SNI, సర్టిఫికేట్ ధృవీకరణ మరియు HTTP `Host` హెడర్ కోసం మాత్రమే ఉపయోగించబడుతుంది. రిజాల్వ్ కాని పేరు `unknown` స్థితులను మరియు `Cannot resolve` లోపాన్ని ఇస్తుంది. రివర్స్ DNS పేర్లు కేవలం హోస్ట్ పేరు అక్షరాలను కలిగి ఉన్నప్పుడు మాత్రమే ఉంచబడతాయి, మరియు ఒకేసారి గరిష్ఠంగా 16 శోధనలు నడుస్తాయి. HTTPS సిస్టమ్ స్టోర్ లేదా `--tls-ca-file` కు వ్యతిరేకంగా సర్టిఫికేట్ మరియు హోస్ట్ పేరు ధృవీకరణను ఉపయోగిస్తుంది. స్కాన్ కోసం ట్రస్ట్ స్టోర్ ఒకసారి లోడ్ చేయబడి ప్రతి HTTPS ప్రోబ్‌కు పునర్వినియోగించబడుతుంది. TCP కనెక్ట్ మరియు TLS హ్యాండ్‌షేక్ విడివిడిగా సమయ నిర్ధారణ చేయబడతాయి, కాబట్టి కనెక్షన్లను అంగీకరించి హ్యాండ్‌షేక్‌ను నిలిపివేసే పోర్ట్ `filtered` గా కాకుండా `tls_error` తో `open` గా ఉంటుంది. ధృవీకరణ విఫలమైతే, ఫలితం `cert_verified: false` మరియు `cert_verify_error` ను నమోదు చేస్తుంది; బలహీనమైన సెట్టింగ్‌లతో మళ్లీ ప్రయత్నించదు లేదా HTTP అభ్యర్థనను పంపదు. సర్టిఫికేట్ వివరాలు మరియు HTTP హెడర్‌లు ధృవీకరణ విజయవంతమైన తర్వాత మాత్రమే సేకరించబడతాయి. ప్రైవేట్-CA సర్వీసుల కోసం సరైన CA బండిల్‌ను అందించండి. పాత నివేదికలలో `cert_read_unverified` ఉండవచ్చు, దీనిని ప్రస్తుత ప్రోబ్‌లు ఇకపై ఉత్పత్తి చేయవు.

SNMP రహస్యాలు కేవలం ఎన్విరాన్‌మెంట్ వేరియబుల్స్ లేదా ఫైళ్ల (`--snmp-*-file`, లేదా సరిపోయే `HOSTCENSUS_SNMP_*_FILE` వేరియబుల్) నుండి మాత్రమే చదవబడతాయి, ప్రాసెస్ జాబితాలో ఇతర స్థానిక వినియోగదారులకు కనిపించే కమాండ్-లైన్ విలువల నుండి ఎప్పుడూ చదవబడవు. విలువతో కూడిన `--snmp-community`, `--snmp-auth-key` మరియు `--snmp-priv-key` కోడ్ 2 తో నిష్క్రమిస్తాయి మరియు ప్రత్యామ్నాయాన్ని పేర్కొంటాయి. రహస్య ఫైల్ ఖాళీగా లేని గరిష్ఠంగా 4096 బైట్ల UTF-8 అయి ఉండాలి; చివరిలో ఉన్న ఒక newline విస్మరించబడుతుంది, మరియు ఒకే రహస్యం కోసం వేరియబుల్ మరియు ఫైల్ రెండింటినీ సెట్ చేయడం లోపం అవుతుంది. లోపాలు ఫైల్ పేరును పేర్కొంటాయి కానీ దానిలోని విషయాలను ఎప్పుడూ ప్రింట్ చేయవు. స్కాన్ నివేదికలు మరియు చరిత్ర ఉద్దేశపూర్వకంగా క్రెడెన్షియల్ విలువలను చేర్చవు. దిగువ వివరించిన ప్రత్యేక, స్పష్టమైన `--include-credentials` ఎంపిక ఎగుమతిదారు వద్ద ఉంది. కమ్యూనిటీ SNMPv2c ను ఎంచుకుంటుంది; యూజర్ SNMPv3 ను ఎంచుకుంటుంది, auth key ఇచ్చినప్పుడు ప్రామాణీకరణతో మరియు రెండు కీలు ఇచ్చినప్పుడు గోప్యతతో (`snmp_security_level` ఏది అనేది నమోదు చేస్తుంది). కమ్యూనిటీని v3 యూజర్‌తో కలపడానికి, auth key లేకుండా privacy key ని ఉపయోగించడానికి, లేదా యూజర్ లేకుండా కీలను ఉపయోగించడానికి hostcensus నిష్క్రమణ కోడ్ 2 తో నిరాకరిస్తుంది, మరియు విఫలమైన v3 ప్రశ్నను v2c తో లేదా తక్కువ భద్రతా స్థాయితో ఎప్పుడూ మళ్లీ ప్రయత్నించదు. కేవలం v1/v2c మాత్రమే మాట్లాడే ఏజెంట్లు క్రెడెన్షియల్స్ లేని v3 డిస్కవరీని విస్మరిస్తాయి, కాబట్టి కమ్యూనిటీని అందించినప్పుడు మాత్రమే అవి open గా కనిపిస్తాయి.

బ్యానర్ టెక్స్ట్ నిల్వ చేయబడటానికి లేదా చూపబడటానికి ముందు ముద్రించదగిన అక్షరాలకు తగ్గించబడుతుంది మరియు 256 అక్షరాలకు పరిమితం చేయబడుతుంది. రీడ్‌లు కూడా పరిమితం చేయబడ్డాయి: లైన్‌కు 4 KiB, MySQL గ్రీటింగ్ కోసం 4 KiB, HTTP హెడర్‌లకు 16 KiB. 32 ఆక్టెట్‌ల కంటే పొడవైన SNMP engine ID నిల్వ చేయబడటానికి ముందు కత్తిరించబడుతుంది. HTTP మరియు HTTPS బ్రాకెట్లలో ఉన్న IPv6 చిరునామాతో మరియు 80 లేదా 443 కానప్పుడు పోర్ట్‌తో Host హెడర్‌ను పంపుతాయి. స్ప్రెడ్‌షీట్ ఫార్ములా ట్రిగ్గర్‌తో ప్రారంభమయ్యే CSV సెల్‌లు టెక్స్ట్‌గానే ఉండేలా ప్రిఫిక్స్ చేయబడతాయి.

### పరిమితులు

ఒక రన్ గరిష్ఠంగా 65,536 చిరునామాలు, 64 సర్వీసులు, మరియు 524,288 ప్రోబ్‌లను (హోస్ట్‌లు గుణకం సర్వీసులు) అంగీకరిస్తుంది; పెద్ద అభ్యర్థనలు ఏమీ పంపడానికి ముందే కోడ్ 2 తో నిష్క్రమిస్తాయి. `--concurrency` గరిష్ఠంగా 4096 సాకెట్లకు పరిమితం చేయబడింది. ప్రతి ప్రోబ్‌కు దాని స్వంత బడ్జెట్‌కు నాలుగు రెట్ల కఠిన గడువు ఉంటుంది. కనెక్ట్ ప్రోబ్‌లు (`tcp`, `ssh`, `mysql`, `http`) ఆ సర్వీస్ `timeout` సెట్ చేయకపోతే 0.3 సెకన్లు ఉపయోగిస్తాయి. SNMP మరియు HTTPS ఒకదాన్ని సెట్ చేయనప్పుడు `--timeout` (డిఫాల్ట్ 1.0) ను ఉపయోగిస్తాయి. గడువును తాకిన ప్రోబ్ `errors` లో `"probe timed out"` తో `unknown` గా నివేదించబడుతుంది. స్థానిక సాకెట్ వైఫల్యాలు (ఉదాహరణకు ఫైల్ డిస్క్రిప్టర్లు అయిపోవడం) కూడా లోపం నమోదై `unknown` గా ఉంటాయి; అవి ఎప్పుడూ ఫిల్టర్ చేసిన పోర్ట్‌గా లేదా డౌన్ హోస్ట్‌గా లెక్కించబడవు. ప్రోబ్ చేయడానికి ముందు, hostcensus `--concurrency` ప్లస్ 64 డిస్క్రిప్టర్లకు సరిపోయేలా open-file soft limit ను hard limit వైపు పెంచుతుంది; అలా చేయలేనప్పుడు, `open files` preflight తనిఖీ విఫలమై ట్రాఫిక్ పంపడానికి ముందే `scan` 1 తో నిష్క్రమిస్తుంది. Nmap డిస్కవరీ 30-సెకన్ల హోస్ట్ గడువును ఉపయోగిస్తుంది. ఒక ప్రిఫిక్స్ CIDR రూపంలో nmap కు పంపబడుతుంది, మరియు nmap తనకు ఇచ్చిన వాటి కంటే తక్కువ చిరునామాలను నివేదించినప్పుడు (ఉదాహరణకు అది రిజాల్వ్ చేయలేని పేరు) హోస్ట్‌లను డౌన్ అని గుర్తించకుండా స్వీప్ ఎగ్జిట్ 1 తో విఫలమవుతుంది. హోస్ట్ పేరు లక్ష్యం ఒకసారి రిజాల్వ్ చేయబడి nmap కు ఆ చిరునామా ఇవ్వబడుతుంది, కాబట్టి డిస్కవరీ మరియు ప్రోబ్‌లు ఒకే యంత్రానికి చేరుకుంటాయి. పూర్తి ప్రిఫిక్స్ అనేది ఒక nmap ప్రాసెస్, దీని సబ్‌ప్రాసెస్ గడువు ప్రతి 256 చిరునామాలకు 35 సెకన్లు (పైకి రౌండ్ చేయబడింది). మినహాయింపులతో కూడిన స్వీప్‌లు 256 హోస్ట్‌ల బ్యాచ్‌లను మరియు ప్రతి బ్యాచ్‌కు 35-సెకన్ల గడువును ఉపయోగిస్తాయి. వర్కర్ సృష్టి రేంజ్ పరిమాణంతో సంబంధం లేకుండా పరిమితం చేయబడింది. రివర్స్ DNS మరియు హోస్ట్ పేరు రిజల్యూషన్‌కు వేరుగా రెండు-సెకన్ల గడువు ఉంటుంది; ఎప్పటికీ తిరిగి రాని రిజాల్వర్ కాల్ దాని స్వంత థ్రెడ్‌లో వదిలివేయబడుతుంది, కాబట్టి అది hostcensus ను ఈ పరిమితులకు మించి నడిపించదు. ఒకేసారి గరిష్ఠంగా 16 శోధనలు నడుస్తాయి, మరియు వదిలివేయబడిన కాల్ తిరిగి వచ్చే వరకు తన స్లాట్‌ను ఉంచుకుంటుంది, కాబట్టి చిక్కుకున్న థ్రెడ్‌ల సంఖ్య పరిమితంగా ఉంటుంది; మొత్తం 16 వేలాడిపోతే, `--deadline` స్కాన్‌ను ఆపే వరకు తదుపరి శోధనలు రెండు-సెకన్ల గడువుకు వెలుపల (స్లాట్ ఖాళీ అయిన తర్వాత ఇది ప్రారంభమవుతుంది) స్లాట్ కోసం క్యూలో ఉంటాయి. `deadline` లేకుండా లైబ్రరీగా ఉపయోగించే `NetworkScanner` అటువంటి స్లాట్ కోసం నిరవధికంగా వేచి ఉండగలదు. `--deadline` (డిఫాల్ట్ ఒక గంట) వీటన్నింటిపై మొత్తం రన్‌ను పరిమితం చేస్తుంది.

### సర్వీసులను కాన్ఫిగర్ చేయడం

సర్వీసులను TOML ఫైల్‌తో మార్చవచ్చు:

```toml
[services.ssh]          # same name as a built-in: replaces it
port = 2222
timeout = 0.5

[services.admin-ui]     # a new service, probed like HTTPS
port = 8443
probe = "https"
```

`probe` అనేది `tcp`, `ssh`, `mysql`, `http`, `https` లేదా `snmp` లలో ఒకటి మరియు సర్వీస్ పేరు ఒక ప్రోబ్ అయినప్పుడు దానికే డిఫాల్ట్ అవుతుంది, లేకపోతే `tcp` అవుతుంది. కేవలం `snmp` మాత్రమే UDP ను ఉపయోగిస్తుంది. సర్వీస్ పేర్లు చిన్న అక్షరాలు, అంకెలు, `-` మరియు `_` లతో ఉంటాయి. రెండు సర్వీసులు ఒకే పోర్ట్ మరియు ప్రోటోకాల్‌ను పంచుకోలేవు; చరిత్ర ఆ జత కోసం ఒకే స్థితిని నమోదు చేస్తుంది. `timeout` ఐచ్ఛికం, సెకన్లలో ఉంటుంది, మరియు కనీసం 0.05. కనెక్ట్-శైలి ప్రోబ్‌లు (`tcp`, `ssh`, `mysql`, `http`) డిఫాల్ట్‌గా 0.3 సెకన్లు ఉంటాయి. సర్వీస్ `timeout` సెట్ చేయనప్పుడు `snmp` మరియు `https` స్కాన్ `--timeout` ను ఉపయోగిస్తాయి. సర్వీస్‌కు ఇప్పటికే ఉన్న బడ్జెట్‌ను `--timeout` భర్తీ చేయదు.

JSON నివేదికలు వెర్షన్ చేయబడిన పత్రాలు (`"format": "hostcensus-report"`, `"version": 1`), ఇవి `devices` పక్కన లక్ష్యం, ప్రోబ్ చేసిన సర్వీసులు మరియు సెట్టింగ్‌లను నమోదు చేస్తాయి; `-o` లేకుండా `--format json` టేబుల్‌కు బదులుగా stdout కు నివేదికను వ్రాస్తుంది. ప్రతి JSON అవుట్‌పుట్‌కు ప్రచురించబడిన స్కీమా ఉంటుంది; [JSON అవుట్‌పుట్](../../../docs/json-output.md) చూడండి. పరికరాలు అసలైన `ip`, `alive`, `ssh`, `snmp`, `mysql`, `hostname` మరియు `errors` ఫీల్డ్‌లను ఉంచుతాయి మరియు ప్రతి ప్రోబ్ యొక్క `name`, `port`, `protocol`, `state` (`open`, `closed`, `filtered`, లేదా ప్రోబ్ స్థానికంగా విఫలమైనప్పుడు లేదా గడువును తాకినప్పుడు `unknown`), `version` మరియు `details` లతో ఒక `services` జాబితాను జోడిస్తాయి. CSV అవుట్‌పుట్ తెరిచి ఉన్న వాటి కోసం చివరిలో `services` మరియు `versions` నిలువు వరుసలను పొందుతుంది. `ssh`, `snmp` మరియు `mysql` బూలియన్‌లు ఖచ్చితంగా ఆ పేర్లతో ఉన్న సర్వీసులను అనుసరిస్తాయి.

## ఇన్వెంటరీ ప్రొఫైల్‌లు, preflight, మరియు స్థానిక చరిత్ర

పేరు పెట్టిన ప్రొఫైల్‌లు ఇప్పటికే ఉన్న `[services]` నిర్వచనాలతో TOML ఫైల్‌ను పంచుకుంటాయి. [hostcensus.example.toml](../../../hostcensus.example.toml) ను `hostcensus.toml` కు కాపీ చేసి మీరు నిర్వహించే నెట్‌వర్క్‌లను సెట్ చేయండి:

```toml
[profiles.office]
network = "192.168.1.0/24"
exclusions = ["192.168.1.1"]
services = "ssh,http,https,mysql"
concurrency = 32
timeout = 1.0
max_hosts = 256
backend = "asyncio"
```

```bash
hostcensus profiles --config hostcensus.toml
hostcensus preflight --profile office --config hostcensus.toml
hostcensus scan --profile office --config hostcensus.toml -o report.json
```

`preflight` open-file తనిఖీ కోసం `--concurrency` తో సహా `scan` మాదిరిగానే ఎంపికలను మరియు ప్రొఫైల్‌లను రిజాల్వ్ చేస్తుంది, కాబట్టి ఉత్తీర్ణమైన preflight అంటే `scan` అదే ప్రణాళికతో ప్రారంభమవుతుందని అర్థం.

ప్రొఫైల్‌లు `network`, `exclusions`, `services`, `ports`, `backend`, `timeout`, `concurrency`, మరియు `max_hosts` లను అంగీకరిస్తాయి. `services` మరియు `ports` ఇప్పటికే ఉన్న కామా-జాబితా సింటాక్స్‌ను ఉపయోగిస్తాయి. స్పష్టమైన CLI ఎంపికలు ప్రొఫైల్ సెట్టింగ్‌లను అధిగమిస్తాయి; పునరావృత `--exclude` ఎంపికలు ప్రొఫైల్ మినహాయింపులకు జోడించబడతాయి. `--profile` తో ఉన్న స్పష్టమైన నెట్‌వర్క్ తప్పనిసరిగా ఆ ప్రొఫైల్ యొక్క IP/CIDR పరిధిలో ఉండాలి. ప్రత్యక్ష స్కాన్‌ల కోసం హోస్ట్ పేర్లు ఇప్పటికీ మద్దతు ఇవ్వబడతాయి, కానీ వాటిని IP మినహాయింపులతో కలపలేము. హోస్ట్ పరిమితులు మినహాయింపులకు ముందు వర్తిస్తాయి; మొత్తం ప్రోబ్ పరిమితి ఆ తర్వాత కూడా వర్తిస్తుంది. మినహాయించబడిన హోస్ట్‌లు సర్వీస్ తనిఖీలు మరియు ఐచ్ఛిక Nmap డిస్కవరీ రెండింటి నుండీ వదిలివేయబడతాయి.

ప్రతి స్కాన్ టార్గెట్ ట్రాఫిక్‌కు ముందు స్థానిక preflight తనిఖీలను నిర్వహిస్తుంది: లక్ష్యం/ప్రోబ్ పరిమితులు, గమ్యస్థాన యాక్సెస్, ఐచ్ఛిక Nmap ఎగ్జిక్యూటబుల్/ర్యాపర్ లభ్యత, చరిత్ర స్కీమా, మరియు కాన్ఫిగర్ చేసిన TLS CA బండిల్. `preflight` JSON ను నివేదిస్తుంది మరియు లక్ష్యాలను స్కాన్ చేయదు లేదా చరిత్ర డేటాబేస్‌ను సృష్టించదు. ఇది ప్రస్తుత విషయాలను మార్చకుండా గమ్యస్థాన యాక్సెస్‌ను పరీక్షించడానికి తాత్కాలికంగా ఒక సోదర ఫైల్‌ను వ్రాస్తుంది. డిఫాల్ట్ asyncio బ్యాకెండ్‌కు ఇప్పటికీ Nmap గానీ root గానీ అవసరం లేదు. హార్డ్ లింక్‌లతో సహా గమ్యస్థాన పాత్‌లు ఒకదానికొకటి మరియు ఇన్‌పుట్ కాన్ఫిగరేషన్ నుండి విభిన్నంగా ఉండాలి; గమ్యస్థాన సిమ్‌లింక్‌లు తిరస్కరించబడతాయి. విఫలమైన తనిఖీలు 1 ని తిరిగి ఇస్తాయి; చెల్లని పరిధి/కాన్ఫిగరేషన్ 2 ను తిరిగి ఇస్తుంది.

నివేదిక మరియు ఎగుమతి వ్రాతలకు `O_NOFOLLOW` మద్దతు అవసరం. Windows తో సహా ఇది లేని ప్లాట్‌ఫారమ్‌లపై, ఈ వ్రాతలు గమ్యస్థానాన్ని తెరవకుండా లేదా కత్తిరించకుండానే విఫలమవుతాయి. కొత్త నివేదికలు మరియు ఎగుమతి స్క్రిప్ట్‌లు యజమానికి మాత్రమే పరిమితమై ఉంటాయి (మోడ్ 0600); ఇప్పటికే ఉన్న ఫైల్‌ను భర్తీ చేయడం దాని అనుమతులను భద్రపరుస్తుంది. రీడర్ లేని నేమ్డ్ పైప్‌కు వ్రాయడం వేచి ఉండకుండా వెంటనే విఫలమవుతుంది. కొత్త `--history` డేటాబేస్ కూడా యజమానికి మాత్రమే సృష్టించబడుతుంది; ఇప్పటికే ఉన్నది దాని మోడ్‌ను ఉంచుకుంటుంది. లాగ్ సందేశాలు ఎల్లప్పుడూ stderr కు వెళ్తాయి, కాబట్టి stdout కేవలం ఫలితాలను మాత్రమే తీసుకువెళ్తుంది. క్రెడెన్షియల్స్ ఉన్న ఎగుమతులు ఎల్లప్పుడూ మోడ్ 0600 ను బలవంతంగా అమలు చేస్తాయి.

చరిత్ర ఆప్ట్-ఇన్ మరియు ఇప్పటికే ఉన్న JSON స్నాప్‌షాట్‌లు మరియు `diff` కమాండ్‌కు అనుబంధంగా ఉంటుంది:

```bash
mkdir -p output
hostcensus scan --profile office --history output/inventory.sqlite3
# Repeat later with the same targets and service selection.
hostcensus scan --profile office --history output/inventory.sqlite3
hostcensus history --history output/inventory.sqlite3 --limit 20
hostcensus compare 1 2 --history output/inventory.sqlite3
hostcensus compare 1 2 --history output/inventory.sqlite3 -o output/changes.json
```

`history` నుండి ID లను ఉపయోగించండి; ఉదాహరణ కొత్త డేటాబేస్‌ను ఊహిస్తుంది. స్నాప్‌షాట్‌లు UTC ప్రారంభ/ముగింపు సమయాలు, ప్యాకేజీ వెర్షన్, ప్రభావవంతమైన రహస్యేతర సెట్టింగ్‌లు, సారాంశాలు, మరియు ప్రతి-హోస్ట్ లోపాలతో సహా అన్ని హోస్ట్/సర్వీస్ పరిశీలనలతో లావాదేవీల ద్వారా నిల్వ చేయబడతాయి. అసంపూర్ణ హోస్ట్ పరిశీలనలు ఉంచబడతాయి. రద్దు చేయబడిన రన్‌లు సేవ్ చేయబడవు. ప్రస్తుత నివేదిక, స్నాప్‌షాట్, ఎగుమతి, మరియు స్కాన్ నిష్క్రమణ కోడ్ ఒప్పందాలు భద్రపరచబడతాయి.

`history` అన్ని చారిత్రక పరికర పేలోడ్‌లను చదవకుండానే JSON సారాంశాలను జాబితా చేస్తుంది. `compare` సేవ్ చేసిన రెండు స్కాన్‌లను చదువుతుంది, ఒకేలాంటి లక్ష్య గుర్తింపులు మరియు ఎంచుకున్న పోర్ట్‌లను కోరుతుంది, మరియు ప్రతిస్పందన, స్థితి, మరియు పోర్ట్-స్థితి మార్పులను నివేదిస్తుంది. ముందస్తు స్కాన్ ID తప్పనిసరిగా తరువాతి ID కంటే ముందుండాలి. రెండు స్కాన్‌లు `timeout` లేదా `backend` ను నమోదు చేసి ఆ విలువలు భిన్నంగా ఉన్నప్పుడు, నివేదిక ఒక హెచ్చరికను జాబితా చేస్తుంది మరియు పరిశీలనలను ఇప్పటికీ పోలుస్తుంది. వేరే వేచి ఉండే సమయం ఫిల్టర్ చేసిన పోర్ట్‌ను తెరిచినట్లుగా చూపించవచ్చు. స్కానర్ లోపాలు మరియు తెలియని పోర్ట్ పరిశీలనలు నిర్ధారిత అదృశ్యం లేదా మూసివేతగా పరిగణించబడటానికి బదులుగా అనిశ్చితమైనవిగా గుర్తించబడతాయి: లోపాలు ఉన్న హోస్ట్‌లు `uncertain_hosts` లో కనిపిస్తాయి, మరియు `unknown` తో కూడిన ప్రతి పోర్ట్ మార్పు (రెండు స్కాన్‌లలోనూ unknown తో సహా) `port_changes` కు బదులుగా `unconfirmed_ports` లో జాబితా చేయబడుతుంది, తరువాతి స్కాన్‌లో తెరిచి ఉన్న పోర్ట్ తప్ప, అది పోర్ట్ మార్పు అవుతుంది. `compare` మరియు `diff` ఒకే నియమంతో పోర్ట్‌లను వర్గీకరిస్తాయి. `no_longer_responding` అంటే ప్రతిస్పందన లేకపోవడం అని అర్థం, పరికరాన్ని తీసివేసినట్లు రుజువు కాదు. స్కాన్ నిష్క్రమణ కోడ్ 0 ప్రతి హోస్ట్ ప్రతిస్పందించిందని హామీ ఇవ్వదు: ప్రతి-హోస్ట్ లోపాలను పరిశీలించండి. మార్పులు ఉన్నా లేకపోయినా పోలిక విజయం 0 ను తిరిగి ఇస్తుంది; ఇప్పటికే ఉన్న ఫైల్ `diff` దాని నిష్క్రమణ కోడ్ 3 ఒప్పందాన్ని ఉంచుకుంటుంది. మద్దతు లేని లేదా పాడైన చరిత్ర 1 ని తిరిగి ఇస్తుంది.

చరిత్ర ఇన్వెంటరీ సమాచారాన్ని నిల్వ చేస్తుంది, కాబట్టి తగిన రక్షణ ఉన్న స్థానిక డైరెక్టరీని ఎంచుకోండి. ప్రొఫైల్ ఫైళ్లు మరియు నిల్వ చేసిన సెట్టింగ్‌లలో SNMP క్రెడెన్షియల్స్ ఉండవు; క్రెడెన్షియల్ నిర్వహణ ప్రస్తుత రన్‌టైమ్ ఎంపికలు/ఎన్విరాన్‌మెంట్ ద్వారా కొనసాగుతుంది.

## ఇన్వెంటరీ diff

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot monday.json
hostcensus scan 10.0.0.0/24 -q --save-snapshot tuesday.json
hostcensus diff monday.json tuesday.json             # table
hostcensus diff monday.json tuesday.json -f json     # JSON on stdout
```

స్నాప్‌షాట్ అనేది `format: "hostcensus-snapshot"`, `version: 1`, hostcensus వెర్షన్, UTC సృష్టి సమయం, లక్ష్యం, స్కాన్ వాటిని నమోదు చేసినప్పుడు స్కాన్ `timeout` మరియు `backend`, ప్రోబ్ చేసిన సర్వీసులు, మరియు `-o` నివేదిక ఆకారంలోనే సజీవ హోస్ట్‌లతో కూడిన JSON. డౌన్ హోస్ట్‌లు వదిలివేయబడతాయి. `services` ఫీల్డ్ ఉనికిలో లేని మునుపటి వాటితో సహా సాధారణ `scan -o` JSON నివేదికలను కూడా `diff` అంగీకరిస్తుంది.

`diff` కొత్త మరియు అదృశ్యమైన హోస్ట్‌లను, రెండింటిలోనూ ఉన్న హోస్ట్‌లపై తెరిచిన లేదా మూసిన పోర్ట్‌లను, మరియు `version` మారిన సర్వీసులను నివేదిస్తుంది. రెండు స్కాన్‌లలో ఒకదానిలో మాత్రమే ప్రోబ్ చేసిన పోర్ట్‌లు పోల్చబడవు, మరియు ఒక హెచ్చరిక అలా చెబుతుంది. విఫలమైన పరిశీలనలు ఎప్పుడూ "మార్పు లేదు" అని చూపవు: రెండు స్కాన్‌లలో ఏదో ఒకదానిలో `unknown` గా ఉండి తరువాతి దానిలో తెరిచి లేని పోర్ట్ `closed` క్రింద కాకుండా `unconfirmed` క్రింద జాబితా చేయబడుతుంది, దీనికి `before` గా `open`, `unknown` లేదా `not-open` (ప్రోబ్ చేయబడి మూసివేయబడినది లేదా ఫిల్టర్ చేయబడినది) మరియు `after` గా `unknown` లేదా `not-open` ఉంటాయి; మునుపటి ప్రోబ్ విఫలమైనప్పటికీ ఇప్పుడు తెరిచి ఉన్న పోర్ట్ `opened` క్రింద నివేదించబడుతుంది. రెండు స్కాన్‌లలో ఏదో ఒకదానిలో సమాధానం లేకుండా అన్ని ప్రోబ్‌లు విఫలమైన హోస్ట్ `vanished_hosts` కు బదులుగా `unsettled_hosts` క్రింద జాబితా చేయబడుతుంది (రెండు స్కాన్‌లలోనూ విఫలమైనప్పుడు లేదా ఇతర ఫైల్ నుండి లేనప్పుడు కూడా, `up`, `uncertain` లేదా `absent` అనే `before`/`after` తో); అది తరువాతి స్కాన్‌లో సమాధానం ఇస్తే దాని తెరిచిన పోర్ట్‌లతో కొత్త హోస్ట్‌గా కూడా నివేదించబడుతుంది. ఈ కారణంగానే స్నాప్‌షాట్‌లు ఆ విఫలమైన హోస్ట్‌లను ఉంచుతాయి. లక్ష్యాలు భిన్నంగా ఉన్నప్పుడు, మరియు రెండు ఫైళ్లు timeout లేదా backend ను నమోదు చేసి ఆ విలువలు భిన్నంగా ఉన్నప్పుడు కూడా ఒక హెచ్చరిక కనిపిస్తుంది. `-o PATH` JSON రూపాన్ని ఒక ఫైల్‌కు కూడా వ్రాస్తుంది.

`--deadline` (`"complete": false`) ద్వారా ఆపబడిన స్కాన్ నుండి వచ్చిన నివేదిక అది చేరుకున్న హోస్ట్‌లను మాత్రమే జాబితా చేస్తుంది, కాబట్టి `diff` మరియు `export` దానిని నిష్క్రమణ కోడ్ 2 తో తిరస్కరిస్తాయి. `--allow-partial` stderr పై హెచ్చరికతో దానిని అంగీకరిస్తుంది: అప్పుడు `diff` అసంపూర్ణ స్కాన్ అస్సలు జాబితా చేయని హోస్ట్‌లను vanished కు బదులుగా `unsettled_hosts` క్రింద `unscanned` గా జాబితా చేస్తుంది (అది డౌన్ అని జాబితా చేసిన హోస్ట్ ఇప్పటికీ vanished గానే ఉంటుంది), `partial` ను true గా సెట్ చేస్తుంది మరియు ఎప్పుడూ మార్పు లేదని నివేదించదు, మరియు `export` స్క్రిప్ట్ హెడర్‌లో ఒక హెచ్చరికను వ్రాస్తుంది.

`diff` నిష్క్రమణ కోడ్‌లు: `0` మార్పులు లేవు, `3` మార్పులు కనుగొనబడ్డాయి, నిర్ధారించలేని పరిశీలనలు, లేదా అసంపూర్ణ ఇన్‌పుట్ (`unsettled_hosts` మరియు `unconfirmed` తో సహా ఏ జాబితా అయినా ఖాళీగా లేనప్పుడు, లేదా `partial` true అయినప్పుడు `changed` true అవుతుంది), `2` ఒక ఫైల్ లేదు, చదవలేనిది, మద్దతు ఉన్న స్నాప్‌షాట్ కాదు, లేదా `--allow-partial` లేకుండా అసంపూర్ణంగా ఉంది, `1` `-o` ఫైల్ వ్రాయబడలేదు.

## Kadupul ఎగుమతి

[Kadupul](https://github.com/kadupulhq/kadupul) (Cacti 1.2.31 యొక్క ఫోర్క్) లో బల్క్ పరికర ఫైల్ దిగుమతి లేదు. స్క్రిప్ట్ నుండి పరికరాలను జోడించడానికి దాని మద్దతు ఉన్న మార్గం `--option=value` ఆర్గ్యుమెంట్లతో ప్రతి కాల్‌కు ఒక పరికరం చొప్పున `cli/add_device.php`. `hostcensus export` ఆ కాల్‌ల POSIX `sh` స్క్రిప్ట్‌ను వ్రాస్తుంది:

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot inventory.json
hostcensus export inventory.json -o kadupul-import.sh --template 1
# or in one step, with template 0: hostcensus scan 10.0.0.0/24 -q -o kadupul-import.sh

# on the Kadupul server, as the user that owns the install:
export HOSTCENSUS_SNMP_COMMUNITY=...        # only if the script asks for it
KADUPUL_ROOT=/var/www/html/kadupul sh kadupul-import.sh
```

ప్రతి సజీవ హోస్ట్ `php "$KADUPUL_ROOT/cli/add_device.php" --description=... --ip=... --template=N ...` అవుతుంది:

- స్కాన్ యొక్క SNMP ప్రశ్న విజయవంతమైన హోస్ట్‌లు `--version=2 --community=...` లేదా `--version=3 --username=... --authproto=... --password=...` (ప్లస్ authPriv కోసం `--privproto`/`--privpass`), `--port` మరియు `--avail=snmp` పొందుతాయి. SNMPv3 ఎగుమతికి `--snmp-user` అవసరం, మరియు `add_device.php` కు v3 పాస్‌వర్డ్ అవసరం కాబట్టి noAuthNoPriv తిరస్కరించబడుతుంది.
- ఇతర హోస్ట్‌లు `--version=0 --avail=ping` పొందుతాయి, మొదటి తెరిచిన TCP పోర్ట్‌తో `--ping_method=tcp --ping_port=` లేదా ఏదీ లేకుంటే ICMP.
- `--notes` తెరిచి ఉన్న సర్వీసులు మరియు వెర్షన్లను జాబితా చేస్తుంది. `--description` సాదాగా (అక్షరాలు, అంకెలు, `.`, `_`, `-`) ఉన్నప్పుడు రివర్స్-DNS పేరు అవుతుంది, లేదంటే IP అవుతుంది, మరియు దానిని ప్రత్యేకంగా చేస్తారు, ఎందుకంటే `add_device.php` ఇప్పటికే ఉన్న వివరణను ఆ పరికరానికి నవీకరణగా పరిగణిస్తుంది.

ప్రతి విలువ ధృవీకరించబడుతుంది మరియు `shlex.quote` తో షెల్-కోట్ చేయబడుతుంది. డిఫాల్ట్‌గా ఏ SNMP రహస్యం వ్రాయబడదు: స్క్రిప్ట్ రన్ టైమ్‌లో `HOSTCENSUS_SNMP_COMMUNITY`, `HOSTCENSUS_SNMP_AUTH_KEY` లేదా `HOSTCENSUS_SNMP_PRIV_KEY` ను విస్తరిస్తుంది మరియు ఒకటి సెట్ చేయకపోతే ఆగిపోతుంది. `--include-credentials` బదులుగా ఆ ఎన్విరాన్‌మెంట్ వేరియబుల్స్ నుండి విలువలను స్క్రిప్ట్‌లోకి వ్రాస్తుంది, మోడ్ 0600 తో సృష్టిస్తుంది, మరియు ఒక హెచ్చరికను లాగ్ చేస్తుంది. `add_device.php` స్వయంగా కమ్యూనిటీని ప్రింట్ చేస్తుంది మరియు రహస్యాలను ఆర్గ్యుమెంట్లుగా స్వీకరిస్తుంది, ఇవి ప్రతి కాల్ నడుస్తున్నప్పుడు Kadupul సర్వర్ యొక్క ప్రాసెస్ జాబితాలో కనిపిస్తాయి.

నకిలీలు మరియు లోపాల కోసం `add_device.php` 1 తో నిష్క్రమిస్తుంది; స్క్రిప్ట్ కొనసాగుతుంది, వైఫల్యాలను లెక్కిస్తుంది, మరియు ఏదైనా పరికరం జోడించబడకపోతే 1 తో నిష్క్రమిస్తుంది. టెంప్లేట్ ID లు `php cli/add_device.php --list-host-templates` నుండి వస్తాయి. `export` నిష్క్రమణ కోడ్‌లు: `0` వ్రాయబడింది, `2` చదవలేని ఇన్‌పుట్, `--allow-partial` లేని అసంపూర్ణ స్కాన్, లేదా సురక్షితంగా ఎగుమతి చేయలేని డేటా, `1` స్క్రిప్ట్ వ్రాయబడలేదు.

## వెర్షనింగ్ మరియు విడుదల ప్రక్రియ

hostcensus [Semantic Versioning](https://semver.org/spec/v2.0.0.html) ను అనుసరిస్తుంది: అనుకూలమైన పరిష్కారాలు patch వెర్షన్‌ను పెంచుతాయి, అనుకూలమైన ఫీచర్లు/డిప్రికేషన్లు minor వెర్షన్‌ను పెంచుతాయి, మరియు బ్రేకింగ్ అనుకూలత మార్పులు major వెర్షన్‌ను పెంచుతాయి. కమాండ్లు మరియు ఎంపికలు, నిష్క్రమణ కోడ్‌లు మరియు JSON స్కీమాలు పబ్లిక్ ఒప్పందం; భద్రతా పరిష్కారం ముందుగానే మార్చాల్సిన అవసరం లేకుంటే తప్ప, తదుపరి ప్రధాన విడుదల వరకు deprecated ప్రవర్తన పనిచేస్తూనే ఉంటుంది (అప్పుడు changelog ఎందుకు అని చెబుతుంది).

release-please `main` లోని Conventional Commit శీర్షికల నుండి విడుదల PR ను తెరుస్తుంది, `pyproject.toml`, `uv.lock` మరియు `CHANGES.md` లను అప్‌డేట్ చేస్తుంది. దానిని విలీనం చేయడం ద్వారా `vMAJOR.MINOR.PATCH` ట్యాగ్ మరియు ఒక డ్రాఫ్ట్ GitHub విడుదల సృష్టించబడతాయి, దీనికి CI పరీక్షించిన wheel, సోర్స్ డిస్ట్రిబ్యూషన్ మరియు చెక్‌సమ్‌లను జతచేస్తుంది; GitHub దాని attestations API ద్వారా ఆ ఫైళ్ల కోసం బిల్డ్ అటెస్టేషన్లను నిల్వ చేస్తుంది. ఫైళ్లు జతచేయబడిన తర్వాత ఒక మెయింటెయినర్ డ్రాఫ్ట్‌ను సమీక్షించి ప్రచురిస్తారు. విడుదలలు ఎప్పుడూ భర్తీ చేయబడవు.

PyPI విశ్వసనీయ ప్రచురణ ఆప్ట్-ఇన్ మరియు ప్రాజెక్ట్ యాజమాన్యం, విశ్వసనీయ ప్రచురణకర్త మరియు `pypi` ఎన్విరాన్‌మెంట్ అవసరం. ఇది API టోకెన్‌ను పునర్నిర్మించకుండా లేదా నిల్వ చేయకుండా అదే తనిఖీ చేసిన విడుదల ఆర్టిఫ్యాక్ట్‌లను ప్రచురిస్తుంది. ఈ పబ్లిక్ రిపోజిటరీలో ట్యాగ్ చేసిన విడుదలలు GitHub ఆర్టిఫ్యాక్ట్ అటెస్టేషన్లను ఉత్పత్తి చేస్తాయి; ప్రైవేట్ ఫోర్క్‌లకు మద్దతు ఉన్న ప్లాన్ మరియు స్పష్టమైన ఆప్ట్-ఇన్ అవసరం. సెటప్, ఖచ్చితమైన కమాండ్లు మరియు పునఃప్రయత్నాల కోసం [పూర్తి విడుదల గైడ్](../../../docs/releasing.md) చూడండి.

```bash
uv build --no-build-isolation
uv run twine check --strict dist/*.whl dist/*.tar.gz
```

అభివృద్ధి సాధనాలు `pyproject.toml` (`dev`, `fuzz`, `build`) లోని [PEP 735](https://peps.python.org/pep-0735/) డిపెండెన్సీ సమూహాలలో ఉంటాయి, కాబట్టి అవి ప్రచురించబడిన ప్యాకేజీ మెటాడేటాలో ఎప్పుడూ కనిపించవు. `uv.lock` అనేది ఏకైక లాక్‌ఫైల్; CI `uv sync --locked` తో ఇన్‌స్టాల్ చేస్తుంది మరియు లాక్‌ఫైల్ పాతదైనప్పుడు విఫలమవుతుంది. `uv python`, mise (`mise exec python@3.14 -- uv sync --locked`), లేదా ఏదైనా Python 3.12+ తో ఇంటర్‌ప్రెటర్‌ను ఎంచుకోండి.

CI 90% ప్యాకేజీ కవరేజ్ కనిష్ఠ పరిమితిని అమలు చేస్తుంది. యూనిట్ పరీక్షలలో నియంత్రిత లూప్‌బ్యాక్ సర్వర్లు మరియు ఆఫ్‌లైన్ ప్రొఫైల్/చరిత్ర/విడుదల-వాలిడేటర్ కేసులు ఉంటాయి; Compose ల్యాబ్ ఒక ఐసోలేటెడ్ బ్రిడ్జ్‌పై OpenSSH, MariaDB, nginx మరియు net-snmp లను నడుపుతుంది. దీనిని `make test-integration` తో అమలు చేయండి. [CONTRIBUTING.md](../../../CONTRIBUTING.md) మరియు [విడుదల సాధనాలు](../../../scripts/README.md) చూడండి.

రన్‌టైమ్ కంటైనర్ హోమ్ డైరెక్టరీ లేకుండా, షెల్ లాగిన్ లేకుండా మరియు pip లేకుండా UID/GID 10001 గా నడుస్తుంది, మరియు `/app/output` కు వ్రాయగలదు. మౌంట్ చేసిన ఏదైనా అవుట్‌పుట్ డైరెక్టరీకి ఆ యూజర్‌కు వ్రాసే యాక్సెస్ ఇవ్వండి. దీనికి ఎటువంటి capabilities అవసరం లేదు మరియు read-only root ఫైల్‌సిస్టమ్‌తో పనిచేస్తుంది, కాబట్టి దీనిని ఇలా అమలు చేయవచ్చు:

```sh
docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp -v "$PWD/out:/app/output" IMAGE scan 192.0.2.0/28 -o /app/output/report.json
```

ఈ కంటైనర్‌లో Nmap తన unprivileged TCP డిస్కవరీ ప్రవర్తనను ఉపయోగిస్తుంది. Trivy నివేదించే ఏదైనా పరిష్కరించదగిన HIGH లేదా CRITICAL దుర్బలత్వంపై CI ఇమేజ్ బిల్డ్‌ను విఫలం చేస్తుంది.

## స్థానికీకరణ

CLI సందేశాలు మరియు టెర్మినల్ సారాంశం/diff పట్టికలు సున్నా అదనపు రన్‌టైమ్ డిపెండెన్సీలతో 45 లోకేల్‌లకు (`en`, `de`, `es`, `fr`, `it`, `pt-BR`, `nl`, `ru`, `uk`, `ja`, `ko`, `zh-CN`, `zh-TW`, `ar`, `hi`, `pl`, `tr`, `sv`, `vi`, `id`, `af-ZA`, `am-ET`, `ar-EG`, `ar-MA`, `fr-MA`, `fr-SN`, `ha-NG`, `ig-NG`, `mg-MG`, `rw-RW`, `so-SO`, `sw-KE`, `xh-ZA`, `yo-NG`, `zu-ZA`, `bn`, `fa`, `he`, `mr`, `ta`, `te`, `th`, `ur`, `ms`, `fil`) మద్దతు ఇస్తాయి. రిజల్యూషన్ `--lang`, ఆపై `LC_ALL`, `LC_MESSAGES`, మరియు `LANG` ను గౌరవిస్తుంది, చివరగా `en` కు వెళ్తుంది. JSON స్కీమాలు, CSV నిలువు వరుసలు, మరియు ఎగుమతి స్క్రిప్ట్‌లు అన్ని లోకేల్‌లలోనూ మారవు.

```bash
hostcensus --lang de version
LANG=ja_JP.UTF-8 hostcensus scan 192.0.2.0/28
```
