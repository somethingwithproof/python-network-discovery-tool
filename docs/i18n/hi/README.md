hostcensus आपके द्वारा प्रशासित नेटवर्क पर दोहराई जा सकने वाली सेवा इन्वेंटरी के लिए एक Python CLI है।
यह रिकॉर्ड करता है कि डिवाइस क्या प्रदर्शित करते हैं, समय के साथ अवलोकनों की तुलना करता है, और Kadupul
आयात स्क्रिप्ट तैयार करता है। डिफ़ॉल्ट बैकएंड बिना root के asyncio सॉकेट का उपयोग करता है;
वैकल्पिक Nmap खोज कॉन्फ़िगर किए गए सेवा पोर्ट से परे भी होस्ट की पहचान कर सकती है।

## hostcensus क्यों

एक बार की पोर्ट रिपोर्ट यह नहीं बताती कि अगला अवलोकन बदला है या बस विफल हो गया।
hostcensus स्पष्ट सेवा अवस्थाओं, सीमित प्रॉब, पुनः उपयोग योग्य स्कैन प्रोफ़ाइल और स्थानीय
इतिहास को जोड़ता है। ऑपरेटर एक ही दायरे को दोहरा सकते हैं, त्रुटियों की जाँच कर सकते हैं,
और अनिश्चित अवलोकनों को पुष्ट परिवर्तनों से अलग कर सकते हैं।

- **सेवा प्रमाण:** SSH पहचान, MySQL ग्रीटिंग, HTTP हेडर, TLS प्रमाणपत्र अवलोकन,
  और SNMP खोज या क्रेडेंशियल-आधारित system-MIB क्वेरी।
- **दोहराने योग्य दायरा:** नामित TOML प्रोफ़ाइल, योगात्मक बहिष्करण, कॉन्फ़िगर करने योग्य
  सेवाएँ, होस्ट/प्रॉब सीमाएँ, और सीमित वर्कर।
- **ट्रैफ़िक से पहले जाँच:** स्थानीय प्रीफ़्लाइट लक्ष्यों, टूल, गंतव्य पहुँच,
  इतिहास स्कीमा, और कॉन्फ़िगर किए गए TLS CA बंडल को सत्यापित करता है।
- **इन्वेंटरी इतिहास:** लेनदेन-आधारित SQLite स्नैपशॉट सभी अवलोकनों को सहेजते हैं;
  तुलनाएँ स्कैनर विफलताओं और अज्ञात अवस्थाओं को दृश्यमान रखती हैं।
- **अंतर-संचालनीय आउटपुट:** टर्मिनल, JSON और CSV रिपोर्ट, संस्करणित फ़ाइल स्नैपशॉट,
  और Kadupul आयात स्क्रिप्ट।

CI, Linux और macOS पर Python 3.12, 3.13 और 3.14 को कवर करता है, साथ ही एक नियंत्रित Compose
एकीकरण लैब भी चलाता है। कोड उन रनटाइम संस्करणों को बनाए रखते हुए आधुनिक टाइप उपनामों,
टाइप्ड प्रीफ़्लाइट परिणामों, कीवर्ड-ओनली स्लॉटेड प्रोफ़ाइल और संरचित async क्लीनअप का उपयोग करता है।
SemVer संगतता अनुबंध और GitHub रिलीज़ प्रक्रिया के लिए [संस्करण और रिलीज़](../../../docs/releasing.md) देखें।
रिलीज़ बैज प्रकाशित आर्टिफैक्ट्स को दर्शाता है, चेकआउट को नहीं: नवीनतम प्रकाशित टैग वर्तमान में
`v0.3.0` है, जबकि यह चेकआउट पैकेज संस्करण `3.0.0` का उपयोग करता है। यहाँ प्रलेखित इन्वेंटरी
सुविधाओं का उपयोग करने के लिए चेकआउट से इंस्टॉल करें।

[इंस्टॉलेशन](#install) से शुरुआत करें, फिर [प्रोफ़ाइल और इतिहास](#inventory-profiles-preflight-and-local-history) देखें।
एकीकरण विवरण के लिए, [सेवा फ़िंगरप्रिंट](#fingerprints),
[फ़ाइल तुलनाएँ](#inventory-diff), और [Kadupul निर्यात](#kadupul-export) देखें।

## इंस्टॉल

Python 3.12 या उससे नया संस्करण आवश्यक है; Python 3.12–3.14 परीक्षित मैट्रिक्स है। इस
चेकआउट से, लॉक की गई रनटाइम निर्भरताएँ इंस्टॉल करें:

```bash
uv sync --locked
uv run hostcensus --help
uv run hostcensus --version
uv run hostcensus preflight 127.0.0.1
uv run hostcensus scan 127.0.0.1 --services ssh -o loopback.json
```

वैकल्पिक Nmap होस्ट खोज के लिए, अपने प्लेटफ़ॉर्म के पैकेज प्रबंधक का उपयोग करके Nmap
निष्पादन योग्य फ़ाइल इंस्टॉल करें; किसी अतिरिक्त Python पैकेज की आवश्यकता नहीं है। Nmap के XML आउटपुट को
defusedxml (एक कोर निर्भरता) के साथ पार्स किया जाता है, इसलिए एंटिटी विस्तार को अस्वीकार किया जाता है। hostcensus
`PATH` पर मिलने वाले `nmap` को सीधे एक निश्चित तर्क सूची, प्रीफ़िक्स आकार के साथ बढ़ने वाली समय-सीमा,
और 64 MiB आउटपुट सीमा के साथ चलाता है। डिफ़ॉल्ट बैकएंड के लिए Nmap की आवश्यकता नहीं है।

## netprobe से माइग्रेशन

hostcensus, netprobe का नया नाम है, जिसे 3.0.0 में रिलीज़ किया गया है। यह प्रोजेक्ट कभी भी
किसी भी नाम से PyPI पर प्रकाशित नहीं हुआ था, इसलिए इंस्टॉलेशन चेकआउट या GitHub
रिलीज़ से आते थे। GitHub रिपॉजिटरी अपना नाम बनाए रखती है।

| पहले | अब | संगतता |
| --- | --- | --- |
| वितरण `netprobe` | `hostcensus` | चेकआउट से पुनः इंस्टॉल करें; पुराने नाम का कोई पैकेज नहीं है। |
| `netprobe` कमांड | `hostcensus` | `netprobe` अभी भी चलता है और stderr पर एक अवमूल्यन पंक्ति प्रिंट करता है। निकास कोड और stdout अपरिवर्तित हैं। अगले प्रमुख रिलीज़ में हटा दिया जाएगा। |
| `NETPROBE_*` पर्यावरण चर | `HOSTCENSUS_*` | जब उसका `HOSTCENSUS_*` समकक्ष सेट नहीं होता है, तब `NETPROBE_*` चर का उपयोग किया जाता है, और stderr पर एक चेतावनी दिखती है जो चरों का नाम बताती है, उनके मान कभी नहीं। दोनों सेट होने पर `HOSTCENSUS_*` प्रभावी होता है। अगले प्रमुख रिलीज़ में हटा दिया जाएगा। |
| `import netprobe`, `python -m netprobe` | `import hostcensus`, `python -m hostcensus` | **ब्रेकिंग परिवर्तन।** कोई इम्पोर्ट शिम इंस्टॉल नहीं है; इम्पोर्ट अपडेट करें। |
| Docker इमेज टैग `network-discovery:test` (केवल CI) और कंटेनर उपयोगकर्ता `netprobe` | `hostcensus:test`, उपयोगकर्ता `hostcensus` | कोई रजिस्ट्री इमेज कभी प्रकाशित नहीं हुई थी। इमेज को फिर से बिल्ड करें और `hostcensus` एंट्रीपॉइंट का उपयोग करें। |
| `netprobe.toml`, `netprobe-history.sqlite3` | `hostcensus.toml`, `hostcensus-history.sqlite3` | जब नया नाम मौजूद न हो, तब पुराने डिफ़ॉल्ट नाम वाली मौजूदा फ़ाइल का उपयोग अभी भी चेतावनी के साथ किया जाता है। स्पष्ट `--config` और `--history` पथ अपरिवर्तित रहते हैं। |
| `"format": "netprobe-report"` या `"netprobe-snapshot"`, और `netprobe_version` फ़ील्ड वाली रिपोर्ट और स्नैपशॉट | `hostcensus-report`, `hostcensus-snapshot`, `hostcensus_version` | `diff` और `export` अभी भी पुराने नाम से लिखी गई फ़ाइलों को लोड करते हैं, और प्रकाशित JSON स्कीमा दोनों वर्तनी स्वीकार करते हैं। नई फ़ाइलें नए नामों का उपयोग करती हैं। SQLite इतिहास डेटाबेस अपरिवर्तित हैं और पहले की तरह लोड होते हैं। |
| `netprobe export` से Kadupul स्क्रिप्ट | `hostcensus export` से स्क्रिप्ट | पुरानी स्क्रिप्ट काम करती रहती हैं और चलने पर अभी भी `NETPROBE_SNMP_*` पढ़ती हैं। नई स्क्रिप्ट `HOSTCENSUS_SNMP_*` पढ़ती हैं। |

## त्वरित उदाहरण

विकास अनुभाग के अंतर्गत वर्णित एकीकरण लैब के टेस्टर कंटेनर से चलाएँ; आउटपुट संक्षिप्त किया गया है:

```console
$ hostcensus scan 172.30.57.8/29 --services ssh,http,snmp --save-snapshot after.json
┃ IP Address   ┃ Hostname       ┃ SSH ┃ SNMP ┃ MySQL ┃ Open services  ┃ Status ┃
│ 172.30.57.10 │ hostcensus-it-s… │ ✅  │  ❌  │  ❌   │ ssh:22         │ UP     │
│              │                │     │      │       │ OpenSSH_10.0   │        │
│ 172.30.57.13 │ hostcensus-it-w… │ ❌  │  ❌  │  ❌   │ http:80        │ UP     │
│              │                │     │      │       │ nginx/1.28.3   │        │

$ hostcensus diff before.json after.json; echo "exit=$?"
Warning: targets differ: 172.30.57.10 vs 172.30.57.8/29
│ new host │ 172.30.57.13 │ http:80/tcp  │ hostcensus-it-web-1.hostcensus-it_lab   │
exit=3

$ hostcensus export after.json -o kadupul-import.sh --template 1
$ grep 57.13 kadupul-import.sh
add --description=hostcensus-it-web-1.hostcensus-it_lab --ip=172.30.57.13 --template=1 --version=0 --avail=ping --ping_method=tcp --ping_port=80 '--notes=hostcensus: http:80/tcp nginx/1.28.3'
```

## निकास कोड

| कमांड | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| `scan` | अवलोकन/रिपोर्ट रिकॉर्ड किए गए | प्रीफ़्लाइट/बैकएंड, इतिहास, या रिपोर्ट/स्नैपशॉट लेखन विफल | अमान्य लक्ष्य, विकल्प, कॉन्फ़िगरेशन, या सीमाएँ | - | `--deadline` समाप्त; आंशिक रिपोर्ट लिखी गई, इतिहास और स्नैपशॉट छोड़े गए |
| `preflight` | जाँच उत्तीर्ण | स्थानीय जाँच विफल | अमान्य लक्ष्य/कॉन्फ़िगरेशन या परस्पर विरोधी गंतव्य | - | - |
| `profiles` | मान्य प्रोफ़ाइल सूचीबद्ध | - | अपठनीय/अमान्य कॉन्फ़िगरेशन या चयन | - | - |
| `history` | सारांश सूचीबद्ध | गुम, अमान्य, या असमर्थित इतिहास | अमान्य CLI विकल्प | - | - |
| `compare` | तुलना तैयार, जिसमें परिवर्तन मौजूद होने की स्थिति भी शामिल है | अपठनीय इतिहास, असंगत दायरा/क्रम, या लेखन विफलता | अमान्य CLI विकल्प | - | - |
| `diff` | कोई परिवर्तन नहीं | `-o` फ़ाइल लिखी नहीं जा सकी | गुम, अपठनीय या असमर्थित इनपुट, या `--allow-partial` के बिना अधूरा स्कैन | परिवर्तन मिले, अपुष्ट अवलोकन, या अधूरा स्कैन | - |
| `export` | स्क्रिप्ट लिखी गई | स्क्रिप्ट लिखी नहीं जा सकी | अपठनीय इनपुट, `--allow-partial` के बिना अधूरा स्कैन, या ऐसा डेटा जिसे सुरक्षित रूप से निर्यात नहीं किया जा सकता | - | - |

## लेआउट

| मॉड्यूल | उत्तरदायित्व |
| --- | --- |
| `cli.py` | कमांड विकल्प, प्रोफ़ाइल समाधान, प्रीफ़्लाइट, स्कैनिंग और रिपोर्टिंग |
| `scanner.py`, `probes.py` | लक्ष्य विस्तार, सीमित वर्कर, होस्ट खोज और सेवा अवलोकन |
| `config.py`, `profiles.py` | सेवा परिभाषाएँ और मान्य इन्वेंटरी प्रोफ़ाइल |
| `models.py`, `output.py` | परिणाम प्रकार और टर्मिनल/JSON/CSV रेंडरिंग |
| `history.py`, `diff.py` | SQLite इतिहास और संस्करणित फ़ाइल-स्नैपशॉट तुलनाएँ |
| `preflight.py` | स्थानीय जाँच और सीमित Nmap संस्करण खोज |
| `export.py` | मान्य और उद्धृत Kadupul आयात स्क्रिप्ट |

प्रत्येक सेवा अवलोकन अपनी अवस्था को अपनी विज्ञापित पहचान से अलग रिकॉर्ड करता है।
पठन और समय-सीमाएँ सीमित हैं; प्रॉब अपवाद होस्ट त्रुटियों में रहते हैं। SQLite
इतिहास लेनदेन, स्पष्ट कनेक्शन क्लीनअप, और केवल-पठन सूचीकरण व तुलना पथों का
उपयोग करता है। SNMP रहस्य केवल पर्यावरण चरों या गुप्त फ़ाइलों के माध्यम से प्रवेश करते हैं;
इन्वेंटरी इतिहास प्रभावी गैर-गुप्त सेटिंग्स को संग्रहीत करता है। स्कैन पाइपलाइन, उसकी
सीमाओं और विश्वास सीमाओं के लिए [आर्किटेक्चर](../../../docs/architecture.md), और अधिकृत उपयोग के
लिए [SECURITY.md](../../../SECURITY.md#authorized-use) देखें।


## उपयोग

केवल उन्हीं नेटवर्क को स्कैन करें जिन्हें आप प्रशासित करते हैं।

```bash
hostcensus scan 192.168.1.0/24              # table of alive hosts
hostcensus scan 192.168.1.1 -o results.json # JSON report
hostcensus scan 10.0.0.0/24 -o report.csv   # CSV report
hostcensus scan 10.0.0.0/24 -q -o out.json  # no table, file only
hostcensus scan 10.0.0.0/24 --format json | jq '.devices[]'  # JSON report on stdout
```

| विकल्प | अर्थ |
| --- | --- |
| `NETWORK` | CIDR, IP, या होस्टनाम; `--profile` के साथ वैकल्पिक। IPv6 स्कोप पहचानकर्ता अस्वीकार किए जाते हैं। |
| `-o, --output PATH` | एक रिपोर्ट लिखें। फ़ॉर्मेट एक्सटेंशन (`.json`, `.csv`) का अनुसरण करता है; अन्य एक्सटेंशन JSON पर फ़ॉलबैक करते हैं। |
| `-f, --format json\|csv\|kadupul\|auto` | रिपोर्ट फ़ॉर्मेट बाध्य करें। `--output` के बिना कोई प्रभाव नहीं। `.sh` `kadupul` चुनता है। |
| `-v, --verbose` | डिबग लॉगिंग। |
| `-q, --quiet` | परिणाम, प्रगति और सूचनात्मक लॉग दबाएँ; चेतावनियाँ और त्रुटियाँ अभी भी stderr पर दिखाई देती हैं। |
| `--backend asyncio\|nmap` | होस्ट खोज। `asyncio` (डिफ़ॉल्ट) सीधे सेवा पोर्ट की जाँच करता है; `nmap` पहले एक nmap पिंग स्वीप चलाता है और इसके लिए `PATH` पर `nmap` निष्पादन योग्य फ़ाइल की आवश्यकता होती है। |
| `--timeout SECONDS` | उन प्रॉब की प्रतीक्षा करें जो अपना बजट सेट नहीं करते (डिफ़ॉल्ट 1.0)। बिल्ट-इन कनेक्ट प्रॉब 0.3s का उपयोग करते हैं जब तक सेवा तालिका `timeout` सेट न करे। |
| `--concurrency N` | एक साथ चल रहे प्रॉब की संख्या (डिफ़ॉल्ट 256)। |
| `--deadline SECONDS` | पूरे स्कैन को, nmap स्वीप सहित, इतने समय के बाद रोकें (डिफ़ॉल्ट 3600, अधिकतम 604800; पर्यावरण चर `HOSTCENSUS_DEADLINE`)। जो होस्ट पूरे हो गए हैं उन्हें `"complete": false` के साथ रिपोर्ट में लिखा जाता है, कोई इतिहास या स्नैपशॉट नहीं लिखा जाता है, और `scan` कोड 4 के साथ बाहर निकलता है। |
| `--config PATH` | TOML सेवा परिभाषाएँ और वैकल्पिक नामित `[profiles]` सेटिंग्स। |
| `--profile NAME` | नामित प्रोफ़ाइल का उपयोग करें; `--config` छोड़े जाने पर `hostcensus.toml` डिफ़ॉल्ट होता है। |
| `--exclude IP/CIDR` | एक बहिष्करण जोड़ें; आवश्यकतानुसार दोहराएँ। एक बहिष्कृत IPv4 होस्ट उन IPv6 पतों को भी बाहर करता है जो उस तक पहुँचते हैं: IPv4-मैप्ड (`::ffff:a.b.c.d`), NAT64 (`64:ff9b::/96`) और 6to4। IPv4-मैप्ड लक्ष्यों और बहिष्करणों को उन IPv4 पतों के रूप में माना जाता है जिन्हें वे दर्शाते हैं। |
| `--max-hosts N` | बहिष्करण से पहले जाँची जाने वाली पता सीमा (डिफ़ॉल्ट/कठोर अधिकतम 65,536)। |
| `--history PATH` | पूर्ण हुए स्कैन को एक ऑप्ट-इन SQLite इतिहास डेटाबेस में रिकॉर्ड करें। |
| `--services NAMES` | जाँचने के लिए सेवा नामों की अल्पविराम-पृथक सूची, उसी क्रम में (डिफ़ॉल्ट: सभी)। |
| `--ports SPEC` | `NAME=PORT` (किसी सेवा को स्थानांतरित करें) या `PORT` (`tcp-PORT` नाम की एक सादा TCP जाँच जोड़ें) की अल्पविराम-पृथक सूची। |
| `--snmp-community-file PATH` | सिस्टम MIB क्वेरी के लिए SNMPv2c कम्युनिटी रखने वाली फ़ाइल। पर्यावरण चर: `HOSTCENSUS_SNMP_COMMUNITY` (मान) या `HOSTCENSUS_SNMP_COMMUNITY_FILE` (पथ)। |
| `--snmp-user` | SNMPv3 उपयोगकर्ता। पर्यावरण चर: `HOSTCENSUS_SNMP_USER`। |
| `--snmp-auth-protocol`, `--snmp-auth-key-file PATH` | `MD5`, `SHA` (डिफ़ॉल्ट), `SHA224`, `SHA256`, `SHA384`, `SHA512` और पासफ़्रेज़ रखने वाली फ़ाइल। पर्यावरण चर: `HOSTCENSUS_SNMP_AUTH_PROTOCOL`, `HOSTCENSUS_SNMP_AUTH_KEY` या `HOSTCENSUS_SNMP_AUTH_KEY_FILE`। |
| `--snmp-priv-protocol`, `--snmp-priv-key-file PATH` | `DES`, `AES` (डिफ़ॉल्ट), `AES128`, `AES192`, `AES192C`, `AES256`, `AES256C` और पासफ़्रेज़ रखने वाली फ़ाइल। पर्यावरण चर: `HOSTCENSUS_SNMP_PRIV_PROTOCOL`, `HOSTCENSUS_SNMP_PRIV_KEY` या `HOSTCENSUS_SNMP_PRIV_KEY_FILE`। |
| `--save-snapshot PATH` | `hostcensus diff` के लिए एक संस्करणित स्नैपशॉट भी लिखें। |
| `--tls-ca-file PATH` | सिस्टम स्टोर के बजाय इस PEM बंडल के विरुद्ध HTTPS प्रमाणपत्रों को सत्यापित करें। पर्यावरण चर: `HOSTCENSUS_TLS_CA_FILE`। |

डिफ़ॉल्ट रूप से प्रत्येक होस्ट को SSH (TCP 22), SNMP (UDP 161), MySQL (TCP 3306), HTTP (TCP 80) और HTTPS (TCP 443) के लिए जाँचा जाता है। TCP पोर्ट का परीक्षण पूर्ण कनेक्ट के साथ किया जाता है। SNMP का परीक्षण SNMPv3 इंजन-डिस्कवरी अनुरोध के साथ किया जाता है, जिसका उत्तर किसी भी SNMPv3 एजेंट को बिना क्रेडेंशियल के देना होता है; केवल v1/v2c बोलने वाले एजेंट इस प्रॉब द्वारा पहचाने नहीं जाएँगे। asyncio बैकएंड के साथ कोई होस्ट तब जीवित माना जाता है जब किसी भी प्रॉब को उत्तर मिलता है, जिसमें अस्वीकृत कनेक्शन भी शामिल है, इसलिए जो होस्ट हर प्रॉब को ड्रॉप करता है उसका `alive=false` और त्रुटि "Host is down" होती है; यह प्रमाणित नहीं करता कि वह भौतिक रूप से बंद है। `--backend nmap` के साथ, nmap तय करता है कि कौन-से होस्ट जीवित हैं (root के रूप में ICMP, अन्यथा TCP 80/443)।

### फ़िंगरप्रिंट

प्रत्येक खुली सेवा का फ़िंगरप्रिंट किसी भी लॉगिन से पहले उसके द्वारा भेजे गए डेटा से तैयार किया जाता है। SNMP क्वेरी को छोड़कर कोई भी सेवा प्रमाणीकरण नहीं करती, और वह भी केवल तब जब आप क्रेडेंशियल प्रदान करते हैं।

| प्रॉब | पढ़ता है | `version` | `details` कुंजियाँ |
| --- | --- | --- | --- |
| `ssh` | RFC 4253 पहचान पंक्ति | सॉफ़्टवेयर, जैसे `OpenSSH_10.0` | `protocol`, `software`, `comments` |
| `mysql` | MySQL/MariaDB प्रारंभिक हैंडशेक | सर्वर संस्करण | `server_version`, `flavor`, `auth_plugin`, या `error_code`/`error` |
| `http` | `HEAD /` प्रतिक्रिया | `Server` हेडर | `status`, `server` |
| `https` | TLS हैंडशेक, प्रमाणपत्र, `HEAD /` | `Server` हेडर | `tls_version`, `cert_verified`, `cert_verify_error`, `cert_subject`, `cert_issuer`, `cert_sans`, `cert_not_before`, `cert_not_after` (UTC ISO 8601), `cert_self_signed`, `status`, `server` |
| `snmp` | SNMPv3 खोज; क्रेडेंशियल के साथ, sysDescr, sysObjectID, sysName का GET | sysDescr | `engine_id`; क्रेडेंशियल के साथ `snmp_version`, `sys_descr`, `sys_object_id`, `sys_name`, या `snmp_error` |

होस्टनाम लक्ष्य को प्रति होस्ट एक बार हल किया जाता है और प्रत्येक प्रॉब उसी पते से जुड़ता है, जिसे परिणामों में `address` के रूप में रिकॉर्ड किया जाता है; नाम का उपयोग केवल TLS SNI, प्रमाणपत्र सत्यापन और HTTP `Host` हेडर के लिए किया जाता है। जो नाम हल नहीं होता वह `unknown` अवस्थाएँ और `Cannot resolve` त्रुटि देता है। रिवर्स DNS नाम केवल तभी रखे जाते हैं जब उनमें होस्टनाम वर्ण हों, और एक बार में अधिकतम 16 लुकअप चलते हैं। HTTPS सिस्टम स्टोर या `--tls-ca-file` के विरुद्ध प्रमाणपत्र और होस्टनाम सत्यापन का उपयोग करता है। ट्रस्ट स्टोर को स्कैन के लिए एक बार लोड किया जाता है और प्रत्येक HTTPS प्रॉब के लिए पुनः उपयोग किया जाता है। TCP कनेक्ट और TLS हैंडशेक का समय अलग-अलग मापा जाता है, इसलिए जो पोर्ट कनेक्शन स्वीकार करता है लेकिन हैंडशेक को रोक देता है वह `filtered` नहीं बल्कि `tls_error` के साथ `open` होता है। यदि सत्यापन विफल होता है, तो परिणाम `cert_verified: false` और `cert_verify_error` रिकॉर्ड करता है; यह कमजोर सेटिंग्स के साथ पुनः प्रयास नहीं करता या HTTP अनुरोध नहीं भेजता। प्रमाणपत्र विवरण और HTTP हेडर केवल सत्यापन सफल होने के बाद एकत्र किए जाते हैं। निजी-CA सेवाओं के लिए सही CA बंडल प्रदान करें। पुरानी रिपोर्ट में `cert_read_unverified` हो सकता है, जिसे वर्तमान प्रॉब अब उत्पन्न नहीं करते।

SNMP रहस्य केवल पर्यावरण चरों या फ़ाइलों (`--snmp-*-file`, या संबंधित `HOSTCENSUS_SNMP_*_FILE` चर) से पढ़े जाते हैं, कमांड-लाइन मानों से कभी नहीं, जिन्हें अन्य स्थानीय उपयोगकर्ता प्रक्रिया सूची में देख सकते हैं। मान के साथ `--snmp-community`, `--snmp-auth-key` और `--snmp-priv-key` कोड 2 के साथ बाहर निकलते हैं और प्रतिस्थापन का नाम बताते हैं। एक गुप्त फ़ाइल गैर-रिक्त UTF-8 होनी चाहिए और अधिकतम 4096 बाइट्स की होनी चाहिए; एक अनुगामी नई पंक्ति को अनदेखा किया जाता है, और एक ही रहस्य के लिए चर और फ़ाइल दोनों सेट करना एक त्रुटि है। त्रुटियाँ फ़ाइल का नाम बताती हैं लेकिन कभी उसकी सामग्री प्रिंट नहीं करतीं। स्कैन रिपोर्ट और इतिहास में जानबूझकर क्रेडेंशियल मान शामिल नहीं किए जाते हैं। निर्यातक में नीचे वर्णित एक अलग, स्पष्ट `--include-credentials` विकल्प है। कम्युनिटी SNMPv2c चुनती है; उपयोगकर्ता SNMPv3 चुनता है, जिसमें auth कुंजी दिए जाने पर प्रमाणीकरण और दोनों कुंजियाँ दिए जाने पर गोपनीयता होती है (`snmp_security_level` यह रिकॉर्ड करता है कि कौन-सा उपयोग हुआ)। hostcensus निकास कोड 2 के साथ v3 उपयोगकर्ता के साथ कम्युनिटी को मिलाने, auth कुंजी के बिना गोपनीयता कुंजी का उपयोग करने, या उपयोगकर्ता के बिना कुंजियों का उपयोग करने से इनकार करता है, और वह कभी भी विफल v3 क्वेरी को v2c या निचले सुरक्षा स्तर के साथ पुनः प्रयास नहीं करता। केवल v1/v2c बोलने वाले एजेंट क्रेडेंशियल-मुक्त v3 खोज को अनदेखा करते हैं, इसलिए वे केवल तभी खुले दिखाई देते हैं जब कम्युनिटी प्रदान की जाती है।

बैनर टेक्स्ट को संग्रहीत करने या दिखाने से पहले मुद्रण योग्य वर्णों तक सीमित किया जाता है और अधिकतम 256 वर्णों तक छोटा किया जाता है। पठन भी सीमित हैं: प्रति पंक्ति 4 KiB, MySQL ग्रीटिंग के लिए 4 KiB, HTTP हेडर के लिए 16 KiB। 32 ऑक्टेट से अधिक लंबी SNMP इंजन ID को संग्रहीत करने से पहले छोटा कर दिया जाता है। HTTP और HTTPS ब्रैकेट में IPv6 पते के साथ और 80 या 443 न होने पर पोर्ट के साथ एक Host हेडर भेजते हैं। ऐसे CSV सेल जो स्प्रेडशीट फ़ॉर्मूला ट्रिगर से शुरू होते हैं, उन्हें प्रीफ़िक्स किया जाता है ताकि सेल टेक्स्ट ही बना रहे।

### सीमाएँ

एक रन अधिकतम 65,536 पतों, 64 सेवाओं और 524,288 प्रॉब (होस्ट गुणा सेवाएँ) को स्वीकार करता है; इससे बड़े अनुरोध कुछ भी भेजे जाने से पहले निकास कोड 2 के साथ बाहर निकल जाते हैं। `--concurrency` अधिकतम 4096 सॉकेट पर सीमित है। प्रत्येक प्रॉब की कठोर समय-सीमा उसके अपने बजट की चार गुना होती है। कनेक्ट प्रॉब (`tcp`, `ssh`, `mysql`, `http`) 0.3 सेकंड का उपयोग करते हैं जब तक वह सेवा `timeout` सेट न करे। जब सेवा `timeout` सेट नहीं करती, तब SNMP और HTTPS `--timeout` (डिफ़ॉल्ट 1.0) का उपयोग करते हैं। जो प्रॉब समय-सीमा तक पहुँच जाता है उसे `errors` में "probe timed out" के साथ `unknown` के रूप में रिपोर्ट किया जाता है। स्थानीय सॉकेट विफलताएँ (उदाहरण के लिए फ़ाइल डिस्क्रिप्टर समाप्त होना) भी दर्ज त्रुटि के साथ `unknown` होती हैं; वे कभी भी फ़िल्टर्ड पोर्ट या बंद होस्ट के रूप में नहीं गिनी जातीं। प्रॉबिंग से पहले, hostcensus `--concurrency` और 64 डिस्क्रिप्टर को समायोजित करने के लिए ओपन-फ़ाइल सॉफ्ट सीमा को हार्ड सीमा की ओर बढ़ाता है; जब वह ऐसा नहीं कर पाता, तो `open files` प्रीफ़्लाइट जाँच विफल हो जाती है और ट्रैफ़िक भेजने से पहले `scan` कोड 1 के साथ बाहर निकलता है। Nmap खोज 30-सेकंड के होस्ट टाइमआउट का उपयोग करती है। nmap को CIDR रूप में एक प्रीफ़िक्स दिया जाता है, और जब nmap दिए गए पतों से कम पते रिपोर्ट करता है (उदाहरण के लिए कोई ऐसा नाम जिसे वह हल नहीं कर सकता) तो होस्ट को बंद चिह्नित करने के बजाय स्वीप निकास 1 के साथ विफल हो जाता है। होस्टनाम लक्ष्य को एक बार हल किया जाता है और nmap को वही पता दिया जाता है, ताकि खोज और प्रॉब एक ही मशीन तक पहुँचें। एक पूर्ण प्रीफ़िक्स एक nmap प्रक्रिया है जिसकी उपप्रक्रिया समय-सीमा प्रत्येक 256 पतों (ऊपर की ओर पूर्णांकित) के लिए 35 सेकंड है। बहिष्करण वाले स्वीप 256 होस्ट के बैच और प्रत्येक बैच के लिए 35-सेकंड की समय-सीमा का उपयोग करते हैं। वर्कर निर्माण रेंज के आकार से स्वतंत्र रूप से सीमित है। रिवर्स DNS और होस्टनाम समाधान की एक अलग दो-सेकंड की समय-सीमा है; जो रिज़ॉल्वर कॉल कभी वापस नहीं लौटती उसे उसके अपने थ्रेड पर छोड़ दिया जाता है, ताकि वह hostcensus को इन सीमाओं से आगे चालू न रख सके। एक बार में अधिकतम 16 लुकअप चलते हैं, और छोड़ी गई कॉल लौटने तक अपना स्लॉट बनाए रखती है, इसलिए अटके हुए थ्रेड्स की संख्या सीमित रहती है; यदि सभी 16 लटक जाते हैं, तो बाद के लुकअप दो-सेकंड की समय-सीमा (जो स्लॉट खाली होने पर शुरू होती है) के बाहर एक स्लॉट के लिए कतार में लगते हैं जब तक `--deadline` स्कैन को रोक न दे। `deadline` के बिना लाइब्रेरी के रूप में उपयोग किया गया `NetworkScanner` ऐसे स्लॉट के लिए अनिश्चित काल तक प्रतीक्षा कर सकता है। इन सबके ऊपर `--deadline` (डिफ़ॉल्ट एक घंटा) पूरे रन को सीमित करता है।

### सेवाएँ कॉन्फ़िगर करना

TOML फ़ाइल के साथ सेवाओं को बदला जा सकता है:

```toml
[services.ssh]          # same name as a built-in: replaces it
port = 2222
timeout = 0.5

[services.admin-ui]     # a new service, probed like HTTPS
port = 8443
probe = "https"
```

`probe`, `tcp`, `ssh`, `mysql`, `http`, `https` या `snmp` में से एक है और जब सेवा का नाम स्वयं एक प्रॉब हो तो उसी पर डिफ़ॉल्ट होता है, अन्यथा `tcp` पर। केवल `snmp` UDP का उपयोग करता है। सेवा के नाम छोटे अक्षरों, अंकों, `-` और `_` से बने होते हैं। दो सेवाएँ एक पोर्ट और प्रोटोकॉल साझा नहीं कर सकतीं; इतिहास उस युग्म के लिए एक अवस्था रिकॉर्ड करता है। `timeout` वैकल्पिक है, सेकंड में है, और कम से कम 0.05 है। कनेक्ट-शैली के प्रॉब (`tcp`, `ssh`, `mysql`, `http`) डिफ़ॉल्ट रूप से 0.3 सेकंड के होते हैं। जब सेवा `timeout` सेट नहीं करती, तब `snmp` और `https` स्कैन `--timeout` का उपयोग करते हैं। `--timeout` उस बजट को प्रतिस्थापित नहीं करता जो सेवा के पास पहले से है।

JSON रिपोर्ट संस्करणित दस्तावेज़ (`"format": "hostcensus-report"`, `"version": 1`) हैं जो `devices` के साथ लक्ष्य, जाँची गई सेवाओं और सेटिंग्स को रिकॉर्ड करते हैं; `-o` के बिना `--format json` तालिका के बजाय stdout पर रिपोर्ट लिखता है। प्रत्येक JSON आउटपुट का एक प्रकाशित स्कीमा है; [JSON आउटपुट](../../../docs/json-output.md) देखें। डिवाइस मूल `ip`, `alive`, `ssh`, `snmp`, `mysql`, `hostname` और `errors` फ़ील्ड बनाए रखते हैं और प्रत्येक प्रॉब के `name`, `port`, `protocol`, `state` (`open`, `closed`, `filtered`, या जब प्रॉब स्थानीय रूप से विफल हुआ या अपनी समय-सीमा पर पहुँचा तब `unknown`), `version` और `details` के साथ एक `services` सूची जोड़ते हैं। CSV आउटपुट में खुली सेवाओं के लिए अनुगामी `services` और `versions` कॉलम जुड़ते हैं। `ssh`, `snmp` और `mysql` बूलियन ठीक उन्हीं नामों वाली सेवाओं का अनुसरण करते हैं।

## इन्वेंटरी प्रोफ़ाइल, प्रीफ़्लाइट और स्थानीय इतिहास

नामित प्रोफ़ाइल मौजूदा `[services]` परिभाषाओं के साथ एक TOML फ़ाइल साझा करती हैं।
[hostcensus.example.toml](../../../hostcensus.example.toml) को `hostcensus.toml` में कॉपी करें और वे नेटवर्क सेट करें
जिन्हें आप प्रशासित करते हैं:

```toml
[profiles.office]
network = "192.168.1.0/24"
exclusions = ["192.168.1.1"]
services = "ssh,http,https,mysql"
concurrency = 32
timeout = 1.0
max_hosts = 256
backend = "asyncio"
```

```bash
hostcensus profiles --config hostcensus.toml
hostcensus preflight --profile office --config hostcensus.toml
hostcensus scan --profile office --config hostcensus.toml -o report.json
```

`preflight` विकल्पों और प्रोफ़ाइलों को ठीक उसी तरह हल करता है जैसे `scan` करता है, जिसमें
ओपन-फ़ाइल जाँच के लिए `--concurrency` भी शामिल है, इसलिए सफल प्रीफ़्लाइट का अर्थ है कि `scan`
उसी योजना के साथ शुरू होगा।

प्रोफ़ाइल `network`, `exclusions`, `services`, `ports`, `backend`, `timeout`,
`concurrency`, और `max_hosts` स्वीकार करते हैं। `services` और `ports` मौजूदा अल्पविराम-सूची
सिंटैक्स का उपयोग करते हैं। स्पष्ट CLI विकल्प प्रोफ़ाइल सेटिंग्स को ओवरराइड करते हैं; दोहराए गए `--exclude`
विकल्प प्रोफ़ाइल बहिष्करण में जुड़ते हैं। `--profile` के साथ एक स्पष्ट नेटवर्क उस
प्रोफ़ाइल के IP/CIDR दायरे में समाहित होना चाहिए। प्रत्यक्ष स्कैन के लिए होस्टनाम समर्थित
रहते हैं, लेकिन उन्हें IP बहिष्करणों के साथ जोड़ा नहीं जा सकता। होस्ट सीमाएँ बहिष्करण से
पहले लागू होती हैं; कुल प्रॉब सीमा उसके बाद भी लागू होती है। बहिष्कृत होस्ट को
सेवा जाँच और वैकल्पिक Nmap खोज दोनों से बाहर रखा जाता है।

प्रत्येक स्कैन लक्ष्य ट्रैफ़िक से पहले स्थानीय प्रीफ़्लाइट जाँच करता है: लक्ष्य/प्रॉब
सीमाएँ, गंतव्य पहुँच, वैकल्पिक Nmap निष्पादन योग्य/रैपर उपलब्धता, इतिहास
स्कीमा, और कॉन्फ़िगर किया गया TLS CA बंडल। `preflight` JSON रिपोर्ट करता है और लक्ष्यों को स्कैन
नहीं करता या इतिहास डेटाबेस नहीं बनाता। यह मौजूदा सामग्री को बदले बिना गंतव्य पहुँच का
परीक्षण करने के लिए अस्थायी रूप से एक सहवर्ती फ़ाइल लिखता है। डिफ़ॉल्ट asyncio बैकएंड को
अभी भी न तो Nmap की आवश्यकता है और न ही root की। गंतव्य पथ एक-दूसरे से और इनपुट
कॉन्फ़िगरेशन से भिन्न होने चाहिए, जिसमें हार्ड लिंक भी शामिल हैं; गंतव्य सिमलिंक अस्वीकार
किए जाते हैं। विफल जाँच 1 लौटाती है; अमान्य दायरा/कॉन्फ़िगरेशन 2 लौटाता है।

रिपोर्ट और निर्यात लेखन के लिए `O_NOFOLLOW` समर्थन आवश्यक है। इसके बिना वाले प्लेटफ़ॉर्म पर,
जिनमें Windows भी शामिल है, ये लेखन गंतव्य को खोले या ट्रंकेट किए बिना विफल हो जाते हैं।
नई रिपोर्ट और निर्यात स्क्रिप्ट केवल-स्वामी (मोड 0600) होती हैं; मौजूदा फ़ाइल को प्रतिस्थापित करने पर
उसकी अनुमतियाँ सुरक्षित रहती हैं। बिना किसी रीडर वाले नेम्ड पाइप में लिखना प्रतीक्षा करने के बजाय तुरंत विफल हो जाता है। एक नया `--history` डेटाबेस भी केवल-स्वामी बनाया जाता है; मौजूदा डेटाबेस अपना मोड बनाए रखता है। लॉग संदेश हमेशा stderr पर जाते हैं, इसलिए stdout केवल परिणाम ले जाता है। क्रेडेंशियल वाले निर्यात हमेशा मोड 0600 लागू करते हैं।

इतिहास ऑप्ट-इन है और मौजूदा JSON स्नैपशॉट तथा `diff` कमांड का पूरक है:

```bash
mkdir -p output
hostcensus scan --profile office --history output/inventory.sqlite3
# Repeat later with the same targets and service selection.
hostcensus scan --profile office --history output/inventory.sqlite3
hostcensus history --history output/inventory.sqlite3 --limit 20
hostcensus compare 1 2 --history output/inventory.sqlite3
hostcensus compare 1 2 --history output/inventory.sqlite3 -o output/changes.json
```

`history` से ID का उपयोग करें; उदाहरण एक नया डेटाबेस मानता है। स्नैपशॉट UTC
प्रारंभ/समाप्ति समय, पैकेज संस्करण, प्रभावी गैर-गुप्त सेटिंग्स, सारांश और सभी होस्ट/सेवा
अवलोकनों (प्रति-होस्ट त्रुटियों सहित) के साथ लेनदेन-आधारित रूप से संग्रहीत किए जाते हैं।
अधूरे होस्ट अवलोकन रखे जाते हैं। रद्द किए गए रन सहेजे नहीं जाते। मौजूदा
रिपोर्ट, स्नैपशॉट, निर्यात और स्कैन निकास-कोड अनुबंध सुरक्षित रहते हैं।

`history` सभी ऐतिहासिक डिवाइस पेलोड पढ़े बिना JSON सारांश सूचीबद्ध करता है।
`compare` दो सहेजे गए स्कैन पढ़ता है, समान लक्ष्य पहचान और चयनित पोर्ट की
अपेक्षा करता है, और प्रतिक्रियाशीलता, स्थिति और पोर्ट-अवस्था परिवर्तनों की रिपोर्ट करता है। पहले का
स्कैन ID बाद के ID से पहले होना चाहिए। जब दोनों स्कैन ने `timeout` या `backend`
रिकॉर्ड किया हो और वे मान भिन्न हों, तो रिपोर्ट एक चेतावनी सूचीबद्ध करती है और फिर भी
अवलोकनों की तुलना करती है। भिन्न प्रतीक्षा समय एक फ़िल्टर किए गए पोर्ट को खुला दिखा सकता है। स्कैनर त्रुटियों
और अज्ञात पोर्ट अवलोकनों को पुष्ट विलोपन या समापन मानने के बजाय अनिश्चित के रूप में चिह्नित किया जाता है:
त्रुटियों वाले होस्ट `uncertain_hosts` में दिखाई देते हैं, और `unknown` से जुड़े प्रत्येक पोर्ट संक्रमण
(दोनों स्कैन में अज्ञात सहित) को `port_changes` के बजाय `unconfirmed_ports` में सूचीबद्ध किया जाता है,
सिवाय उस पोर्ट के जो बाद के स्कैन में खुला है, जो एक पोर्ट परिवर्तन है। `compare` और `diff` एक ही नियम से पोर्ट को वर्गीकृत करते हैं।
`no_longer_responding` का अर्थ प्रतिक्रिया की कमी है, डिवाइस हटाए जाने का प्रमाण नहीं।
स्कैन निकास कोड 0 यह गारंटी नहीं देता कि हर होस्ट ने उत्तर दिया: प्रति-होस्ट त्रुटियाँ जाँचें। तुलना सफल होने पर परिवर्तन हों या न हों, यह 0 लौटाता है; मौजूदा फ़ाइल `diff`
अपना निकास कोड 3 अनुबंध बनाए रखता है। असमर्थित या दूषित इतिहास 1 लौटाता है।

इतिहास इन्वेंटरी जानकारी संग्रहीत करता है, इसलिए उचित रूप से सुरक्षित स्थानीय निर्देशिका चुनें।
प्रोफ़ाइल फ़ाइलों और संग्रहीत सेटिंग्स में SNMP क्रेडेंशियल नहीं होते;
क्रेडेंशियल प्रबंधन मौजूदा रनटाइम विकल्पों/पर्यावरण के माध्यम से जारी रहता है।

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot monday.json
hostcensus scan 10.0.0.0/24 -q --save-snapshot tuesday.json
hostcensus diff monday.json tuesday.json             # table
hostcensus diff monday.json tuesday.json -f json     # JSON on stdout
```

एक स्नैपशॉट JSON है जिसमें `format: "hostcensus-snapshot"`, `version: 1`, hostcensus संस्करण, UTC निर्माण समय, लक्ष्य, जब स्कैन ने रिकॉर्ड किया हो तब स्कैन `timeout` और `backend`, जाँची गई सेवाएँ, और `-o` रिपोर्ट जैसे ही आकार में जीवित होस्ट होते हैं। बंद होस्ट को छोड़ दिया जाता है। `diff` सादा `scan -o` JSON रिपोर्ट भी स्वीकार करता है, जिनमें `services` फ़ील्ड के अस्तित्व से पहले की रिपोर्ट भी शामिल हैं।

`diff` नए और गायब हुए होस्ट, दोनों में मौजूद होस्ट पर खुले या बंद हुए पोर्ट, और वे सेवाएँ जिनका `version` बदला है, की रिपोर्ट करता है। वे पोर्ट जिनकी जाँच दोनों में से केवल एक स्कैन में हुई थी, उनकी तुलना नहीं की जाती, और एक चेतावनी ऐसा बताती है। विफल अवलोकन कभी भी "कोई परिवर्तन नहीं" के रूप में नहीं पढ़े जाते: जो पोर्ट दोनों में से किसी भी स्कैन में `unknown` हो और बाद वाले में खुला न हो, उसे `closed` के बजाय `unconfirmed` के अंतर्गत सूचीबद्ध किया जाता है, जिसमें `before` का मान `open`, `unknown` या `not-open` (जाँचा गया और बंद या फ़िल्टर्ड) और `after` का मान `unknown` या `not-open` होता है; जो पोर्ट अब खुला है उसे `opened` के अंतर्गत रिपोर्ट किया जाता है, भले ही पहले वाला प्रॉब विफल हुआ हो। जिस होस्ट के सभी प्रॉब किसी भी स्कैन में बिना उत्तर के विफल हुए हों, उसे `vanished_hosts` के बजाय `unsettled_hosts` के अंतर्गत सूचीबद्ध किया जाता है (जिसमें `before`/`after` का मान `up`, `uncertain` या `absent` होता है, जिसमें दोनों स्कैन में विफल होना या दूसरी फ़ाइल से अनुपस्थित होना भी शामिल है); यदि वह बाद के स्कैन में उत्तर देता है तो उसे उसके खुले पोर्ट के साथ एक नए होस्ट के रूप में भी रिपोर्ट किया जाता है। स्नैपशॉट इसी कारण उन विफल होस्ट को रखते हैं। जब लक्ष्य भिन्न हों, और जब दोनों फ़ाइलों ने timeout या backend रिकॉर्ड किया हो और वे मान भिन्न हों, तब भी चेतावनी दिखाई देती है। `-o PATH` JSON रूप को किसी फ़ाइल में भी लिखता है।

`--deadline` (`"complete": false`) द्वारा रोके गए स्कैन की रिपोर्ट केवल उन्हीं होस्ट को सूचीबद्ध करती है जिन तक वह पहुँचा, इसलिए `diff` और `export` निकास कोड 2 के साथ इसे अस्वीकार करते हैं। `--allow-partial` stderr पर चेतावनी के साथ इसे स्वीकार करता है: तब `diff` उन होस्ट को जिन्हें अधूरे स्कैन ने बिल्कुल सूचीबद्ध नहीं किया था, गायब के बजाय `unscanned` के रूप में `unsettled_hosts` के अंतर्गत सूचीबद्ध करता है (जिस होस्ट को उसने बंद के रूप में सूचीबद्ध किया वह अभी भी गायब है), `partial` को true सेट करता है और कभी कोई परिवर्तन नहीं रिपोर्ट नहीं करता, और `export` स्क्रिप्ट हेडर में एक चेतावनी लिखता है।

`diff` निकास कोड: `0` कोई परिवर्तन नहीं, `3` परिवर्तन मिले, ऐसे अवलोकन जिनकी पुष्टि नहीं हो सकी, या अधूरा इनपुट (जब भी कोई सूची, जिसमें `unsettled_hosts` और `unconfirmed` शामिल हैं, गैर-रिक्त हो, या `partial` true हो, तो `changed` true होता है), `2` कोई फ़ाइल गुम है, अपठनीय है, समर्थित स्नैपशॉट नहीं है, या `--allow-partial` के बिना अधूरी है, `1` `-o` फ़ाइल लिखी नहीं जा सकी।

## Kadupul निर्यात

[Kadupul](https://github.com/kadupulhq/kadupul) (Cacti 1.2.31 का एक फ़ॉर्क) में कोई बल्क डिवाइस फ़ाइल आयात नहीं है। स्क्रिप्ट से डिवाइस जोड़ने का इसका समर्थित तरीका `cli/add_device.php` है, प्रति कॉल एक डिवाइस, `--option=value` तर्कों के साथ। `hostcensus export` उन कॉल की एक POSIX `sh` स्क्रिप्ट लिखता है:

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot inventory.json
hostcensus export inventory.json -o kadupul-import.sh --template 1
# or in one step, with template 0: hostcensus scan 10.0.0.0/24 -q -o kadupul-import.sh

# on the Kadupul server, as the user that owns the install:
export HOSTCENSUS_SNMP_COMMUNITY=...        # only if the script asks for it
KADUPUL_ROOT=/var/www/html/kadupul sh kadupul-import.sh
```

प्रत्येक जीवित होस्ट `php "$KADUPUL_ROOT/cli/add_device.php" --description=... --ip=... --template=N ...` बन जाता है:

- जिन होस्ट पर स्कैन की SNMP क्वेरी सफल रही उन्हें `--version=2 --community=...` या `--version=3 --username=... --authproto=... --password=...` (authPriv के लिए साथ में `--privproto`/`--privpass`), `--port` और `--avail=snmp` मिलता है। SNMPv3 निर्यात के लिए `--snmp-user` आवश्यक है, और noAuthNoPriv को अस्वीकार किया जाता है क्योंकि `add_device.php` को v3 पासवर्ड की आवश्यकता होती है।
- अन्य होस्ट को `--version=0 --avail=ping` मिलता है, जिसमें `--ping_method=tcp --ping_port=` पहला खुला TCP पोर्ट होता है, या यदि कोई नहीं है तो ICMP।
- `--notes` खुली सेवाओं और संस्करणों को सूचीबद्ध करता है। `--description` तब रिवर्स-DNS नाम होता है जब वह सादा हो (अक्षर, अंक, `.`, `_`, `-`), अन्यथा IP होता है, और इसे अद्वितीय बनाया जाता है, क्योंकि `add_device.php` मौजूदा विवरण को उस डिवाइस के अपडेट के रूप में मानता है।

प्रत्येक मान को सत्यापित किया जाता है और `shlex.quote` के साथ शेल-उद्धृत किया जाता है। डिफ़ॉल्ट रूप से कोई SNMP रहस्य नहीं लिखा जाता: स्क्रिप्ट रन टाइम पर `HOSTCENSUS_SNMP_COMMUNITY`, `HOSTCENSUS_SNMP_AUTH_KEY` या `HOSTCENSUS_SNMP_PRIV_KEY` का विस्तार करती है और यदि कोई अनसेट हो तो रुक जाती है। इसके बजाय `--include-credentials` उन पर्यावरण चरों से मान स्क्रिप्ट में लिखता है, इसे मोड 0600 के साथ बनाता है, और एक चेतावनी लॉग करता है। `add_device.php` स्वयं कम्युनिटी को प्रिंट करता है और रहस्यों को तर्कों के रूप में प्राप्त करता है, जो प्रत्येक कॉल चलने के दौरान Kadupul सर्वर की प्रक्रिया सूची में दिखाई देते हैं।

`add_device.php` डुप्लिकेट और त्रुटियों के लिए 1 के साथ बाहर निकलता है; स्क्रिप्ट जारी रहती है, विफलताओं को गिनती है, और यदि कोई डिवाइस नहीं जोड़ा गया तो 1 के साथ बाहर निकलती है। टेम्पलेट ID `php cli/add_device.php --list-host-templates` से आती हैं। `export` निकास कोड: `0` लिखा गया, `2` अपठनीय इनपुट, `--allow-partial` के बिना अधूरा स्कैन, या ऐसा डेटा जिसे सुरक्षित रूप से निर्यात नहीं किया जा सकता, `1` स्क्रिप्ट लिखी नहीं जा सकी।

## संस्करण और रिलीज़ प्रक्रिया

hostcensus [Semantic Versioning](https://semver.org/spec/v2.0.0.html) का पालन करता है: संगत
सुधार पैच संस्करण बढ़ाते हैं, संगत सुविधाएँ/अवमूल्यन माइनर संस्करण बढ़ाते हैं,
और ब्रेकिंग संगतता परिवर्तन मेजर संस्करण बढ़ाते हैं। कमांड और विकल्प, निकास कोड और JSON स्कीमा
सार्वजनिक अनुबंध हैं; अवमूल्यित व्यवहार अगले मेजर रिलीज़ तक काम करता रहता है, जब तक कि किसी
सुरक्षा सुधार के लिए इसे पहले बदलना आवश्यक न हो (तब चेंजलॉग बताता है कि क्यों)।

release-please `main` पर Conventional Commit शीर्षकों से एक रिलीज़ PR खोलता है,
जो `pyproject.toml`, `uv.lock` और `CHANGES.md` को बढ़ाता है। इसे मर्ज करने पर
`vMAJOR.MINOR.PATCH` टैग और एक ड्राफ्ट GitHub रिलीज़ बनता है, जिससे CI एक परीक्षित व्हील,
स्रोत वितरण और चेकसम संलग्न करता है; GitHub अपने attestations API के माध्यम से उन फ़ाइलों के
लिए बिल्ड प्रमाणन संग्रहीत करता है। फ़ाइलें संलग्न होने के बाद एक मेंटेनर ड्राफ्ट की समीक्षा करता है
और उसे प्रकाशित करता है। रिलीज़ कभी प्रतिस्थापित नहीं किए जाते।

PyPI विश्वसनीय प्रकाशन ऑप्ट-इन है और इसके लिए प्रोजेक्ट स्वामित्व, एक विश्वसनीय प्रकाशक
और `pypi` वातावरण की आवश्यकता होती है। यह बिना पुनर्निर्माण किए या API टोकन संग्रहीत किए
उन्हीं जाँचे गए रिलीज़ आर्टिफैक्ट्स को प्रकाशित करता है। इस सार्वजनिक रिपॉजिटरी में टैग किए गए रिलीज़
GitHub आर्टिफैक्ट प्रमाणन उत्पन्न करते हैं; निजी फ़ॉर्क के लिए एक समर्थित योजना और स्पष्ट
ऑप्ट-इन की आवश्यकता होती है। सेटअप, सटीक कमांड और पुनः प्रयास के लिए
[पूर्ण रिलीज़ मार्गदर्शिका](../../../docs/releasing.md) देखें।

## विकास

```bash
uv sync --locked                 # runtime plus the default `dev` group
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=hostcensus
uv build --no-build-isolation
uv run twine check --strict dist/*.whl dist/*.tar.gz
```

विकास टूल `pyproject.toml` (`dev`, `fuzz`, `build`) में [PEP 735](https://peps.python.org/pep-0735/)
निर्भरता समूहों में रहते हैं, इसलिए वे कभी भी प्रकाशित पैकेज मेटाडेटा में दिखाई नहीं देते।
`uv.lock` एकल लॉकफ़ाइल है; CI `uv sync --locked` के साथ इंस्टॉल करता है और लॉकफ़ाइल
पुरानी होने पर विफल हो जाता है। `uv python`, mise (`mise exec python@3.14 -- uv sync --locked`),
या किसी भी Python 3.12+ के साथ इंटरप्रेटर चुनें।

CI 90% पैकेज कवरेज स्तर लागू करता है। यूनिट परीक्षणों में नियंत्रित लूपबैक सर्वर और
ऑफ़लाइन प्रोफ़ाइल/इतिहास/रिलीज़-सत्यापनकर्ता मामले शामिल हैं; Compose लैब एक पृथक ब्रिज पर
OpenSSH, MariaDB, nginx और net-snmp चलाता है। इसे `make test-integration` के साथ चलाएँ।
[CONTRIBUTING.md](../../../CONTRIBUTING.md) और [रिलीज़ टूलिंग](../../../scripts/README.md) देखें।

रनटाइम कंटेनर बिना होम निर्देशिका, बिना शेल लॉगिन और बिना pip के UID/GID 10001 के रूप में
चलता है, और `/app/output` में लिख सकता है। किसी भी माउंट की गई आउटपुट निर्देशिका के लिए उस
उपयोगकर्ता को लेखन पहुँच दें। इसे किसी क्षमता की आवश्यकता नहीं है और यह केवल-पठन रूट
फ़ाइलसिस्टम के साथ काम करता है, इसलिए इसे इस प्रकार चलाया जा सकता है:

```sh
docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp -v "$PWD/out:/app/output" IMAGE scan 192.0.2.0/28 -o /app/output/report.json
```

Nmap इस कंटेनर में अपने विशेषाधिकार-रहित TCP खोज व्यवहार का उपयोग करता है। Trivy द्वारा
रिपोर्ट की गई किसी भी ठीक करने योग्य HIGH या CRITICAL भेद्यता पर CI इमेज बिल्ड को विफल कर देता है।
