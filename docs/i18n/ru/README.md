hostcensus - это CLI-инструмент на Python для воспроизводимой инвентаризации сервисов в администрируемых вами сетях. Он фиксирует открытые сервисы на устройствах, сравнивает результаты наблюдений во времени и формирует скрипты импорта для Kadupul. Бэкенд по умолчанию использует сокеты asyncio без прав root; опциональное обнаружение через Nmap позволяет выявлять хосты за пределами настроенных портов сервисов.

## Зачем нужен hostcensus

Разовый отчёт о портах не отвечает на вопрос, изменилось ли состояние при следующей проверке или она просто завершилась ошибкой. hostcensus объединяет явные состояния сервисов, ограниченные по ресурсам зонды, переиспользуемые профили сканирования и локальную историю. Операторы могут повторять сканирование в тех же границах, анализировать ошибки и отличать неопределённые наблюдения от подтверждённых изменений.

- **Данные о сервисах:** идентификация SSH, приветствия MySQL, заголовки HTTP, сведения о TLS-сертификатах, а также обнаружение SNMP и запросы к system-MIB с учётными данными.
- **Воспроизводимый охват:** именованные профили TOML, аддитивные исключения, настраиваемые сервисы, лимиты хостов и зондов, а также ограниченный пул обработчиков.
- **Предварительные проверки до отправки трафика:** локальный preflight проверяет цели, инструменты, доступ к путям вывода, схему истории и настроенные наборы корневых сертификатов TLS CA.
- **История инвентаризации:** транзакционные снимки SQLite сохраняют все наблюдения; при сравнении ошибки сканера и неизвестные состояния остаются явными.
- **Совместимый вывод:** отчёты в терминале, JSON и CSV, версионированные файловые снимки и скрипты импорта для Kadupul.

CI покрывает Python 3.12, 3.13 и 3.14 на Linux и macOS, а также изолированный интеграционный стенд на базе Compose. В коде используются современные псевдонимы типов, типизированные результаты preflight, классы профилей со слотами и только именованными аргументами и структурированное асинхронное завершение работы при сохранении совместимости с этими версиями среды выполнения. Контракт совместимости SemVer и процесс выпуска релизов на GitHub описаны в документе [Управление версиями и релизами](../../../docs/releasing.md). Значок релиза отражает опубликованные артефакты, а не текущую рабочую копию: последний опубликованный тег сейчас `v0.3.0`, тогда как в этой копии указана версия пакета `3.0.0`. Чтобы использовать описанные здесь функции инвентаризации, установите пакет из текущей рабочей копии.

Начните с раздела [установка](#install), затем перейдите к [профилям и истории](#inventory-profiles-preflight-and-local-history). Подробности интеграции см. в разделах [отпечатки сервисов](#fingerprints), [сравнение файлов](#inventory-diff) и [экспорт в Kadupul](#kadupul-export).

## Установка

Требуется Python 3.12 или новее; в матрице тестирования проверяются версии Python 3.12–3.14. Установите зафиксированные зависимости среды выполнения из текущей рабочей копии:

```bash
uv sync --locked
uv run hostcensus --help
uv run hostcensus --version
uv run hostcensus preflight 127.0.0.1
uv run hostcensus scan 127.0.0.1 --services ssh -o loopback.json
```

Для опционального обнаружения хостов с помощью Nmap установите исполняемый файл Nmap через пакетный менеджер вашей платформы; дополнительные пакеты Python не требуются. XML-вывод Nmap разбирается с помощью defusedxml (одной из основных зависимостей), поэтому раскрытие XML-сущностей блокируется. hostcensus запускает найденный в `PATH` бинарный файл `nmap` напрямую с фиксированным списком аргументов, общим лимитом времени, растущим пропорционально размеру префикса, и ограничением вывода в 64 МиБ. Для бэкенда по умолчанию Nmap не нужен.

## Миграция с netprobe

hostcensus - это новое название проекта netprobe, представленное в версии 3.0.0. Проект никогда не публиковался на PyPI ни под одним из этих имён, поэтому установка выполнялась из клона репозитория или релиза на GitHub. Имя репозитория на GitHub остаётся прежним.

| Было | Стало | Совместимость |
| --- | --- | --- |
| Дистрибутив `netprobe` | `hostcensus` | Переустановите из рабочей копии репозитория; пакет со старым именем больше не выпускается. |
| Команда `netprobe` | `hostcensus` | `netprobe` по-прежнему запускается и выводит одну строку с предупреждением об устаревании в stderr. Коды возврата и stdout не изменились. Будет удалена в следующем мажорном релизе. |
| Переменные окружения `NETPROBE_*` | `HOSTCENSUS_*` | Переменная `NETPROBE_*` используется, если её аналог `HOSTCENSUS_*` не задан, с одним предупреждением в stderr, в котором называются имена переменных, но никогда их значения. При задании обеих побеждает `HOSTCENSUS_*`. Будет удалено в следующем мажорном релизе. |
| `import netprobe`, `python -m netprobe` | `import hostcensus`, `python -m hostcensus` | **Несовместимое изменение.** Прослойка совместимости для импортов не устанавливается; обновите импорты. |
| Тег образа Docker `network-discovery:test` (только для CI) и пользователь контейнера `netprobe` | `hostcensus:test`, пользователь `hostcensus` | Образ никогда не публиковался в реестре контейнеров. Пересоберите образ и используйте точку входа `hostcensus`. |
| `netprobe.toml`, `netprobe-history.sqlite3` | `hostcensus.toml`, `hostcensus-history.sqlite3` | Существующий файл со старым именем по умолчанию всё ещё используется (с предупреждением), пока не существует файл с новым именем. Явные пути `--config` и `--history` не затрагиваются. |
| Отчёты и снимки с `"format": "netprobe-report"` или `"netprobe-snapshot"` и полем `netprobe_version` | `hostcensus-report`, `hostcensus-snapshot`, `hostcensus_version` | `diff` и `export` по-прежнему загружают файлы, записанные под старым именем, а опубликованные схемы JSON принимают оба варианта написания. Новые файлы используют новые имена. Базы данных истории SQLite не изменились и загружаются как прежде. |
| Скрипты Kadupul из `netprobe export` | Скрипты из `hostcensus export` | Старые скрипты продолжают работать и при запуске по-прежнему читают `NETPROBE_SNMP_*`. Новые скрипты читают `HOSTCENSUS_SNMP_*`. |

## Коды возврата

| Команда | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| `scan` | наблюдения и отчёт записаны | ошибка preflight/бэкенда, истории или записи отчёта/снимка | недопустимая цель, параметры, конфигурация или лимиты | - | достигнут `--deadline`; записан частичный отчёт, история и снимок пропущены |
| `preflight` | проверки пройдены | локальная проверка не пройдена | недопустимая цель/конфигурация или конфликтующие пути назначения | - | - |
| `profiles` | выведен список проверенных профилей | - | нечитаемая/некорректная конфигурация или выбор профиля | - | - |
| `history` | выведен список сводок | отсутствующая, повреждённая или неподдерживаемая история | недопустимые параметры CLI | - | - |
| `compare` | сравнение сформировано, в том числе при наличии изменений | нечитаемая история, несовместимый охват/порядок или ошибка записи | недопустимые параметры CLI | - | - |
| `diff` | изменений нет | не удалось записать файл `-o` | отсутствующий, нечитаемый или неподдерживаемый входной файл либо неполное сканирование без `--allow-partial` | обнаружены изменения, неподтверждённые наблюдения или неполное сканирование | - |
| `export` | скрипт записан | не удалось записать скрипт | нечитаемые входные данные, неполное сканирование без `--allow-partial` или данные, которые нельзя безопасно экспортировать | - | - |

## Структура проекта

| Модуль | Назначение |
| --- | --- |
| `cli.py` | Параметры команд, разрешение профилей, preflight, сканирование и формирование отчётов |
| `scanner.py`, `probes.py` | Развёртывание целей, ограниченный пул обработчиков, обнаружение хостов и проверка сервисов |
| `config.py`, `profiles.py` | Определения сервисов и валидированные профили инвентаризации |
| `models.py`, `output.py` | Типы результатов и вывод в терминал, JSON и CSV |
| `history.py`, `diff.py` | История SQLite и сравнение версионированных файловых снимков |
| `preflight.py` | Локальные проверки и ограниченное по времени определение версии Nmap |
| `export.py` | Валидированные и экранированные скрипты импорта в Kadupul |

Каждое наблюдение сервиса фиксирует его состояние отдельно от объявленных идентификаторов. Операции чтения и лимиты времени ограничены; исключения при работе зондов сохраняются в ошибках хоста. История SQLite использует транзакции, явное закрытие соединений и пути только для чтения при выводе списка и сравнении. Секреты SNMP передаются только через переменные окружения или файлы с секретами; в истории инвентаризации хранятся только фактические несекретные настройки. Конвейер сканирования, его ограничения и границы доверия описаны в [Архитектуре](../../../docs/architecture.md), а правила авторизованного использования в [SECURITY.md](../../../SECURITY.md#authorized-use).


## Использование

Сканируйте только те сети, которыми вы управляете.

```bash
hostcensus scan 192.168.1.0/24              # table of alive hosts
hostcensus scan 192.168.1.1 -o results.json # JSON report
hostcensus scan 10.0.0.0/24 -o report.csv   # CSV report
hostcensus scan 10.0.0.0/24 -q -o out.json  # no table, file only
hostcensus scan 10.0.0.0/24 --format json | jq '.devices[]'  # JSON report on stdout
```

| Параметр | Описание |
| --- | --- |
| `NETWORK` | CIDR, IP или имя хоста; необязателен при использовании `--profile`. Идентификаторы области IPv6 отклоняются. |
| `-o, --output PATH` | Записать отчёт в файл. Формат определяется по расширению (`.json`, `.csv`); для остальных расширений по умолчанию используется JSON. |
| `-f, --format json\|csv\|kadupul\|auto` | Принудительно задать формат отчёта. Не действует без `--output`. Расширение `.sh` выбирает `kadupul`. |
| `-v, --verbose` | Отладочное журналирование. |
| `-q, --quiet` | Подавить вывод результатов, прогресса и информационных сообщений; предупреждения и ошибки по-прежнему выводятся в stderr. |
| `--backend asyncio\|nmap` | Обнаружение хостов. `asyncio` (по умолчанию) проверяет порты сервисов напрямую; `nmap` сначала выполняет ping-сканирование через nmap и требует наличия исполняемого файла `nmap` в `PATH`. |
| `--timeout SECONDS` | Время ожидания для зондов, не задающих собственный бюджет времени (по умолчанию 1.0). Встроенные connect-зонды используют 0.3 с, если в таблице сервисов не указан `timeout`. |
| `--concurrency N` | Число одновременно выполняемых зондов (по умолчанию 256). |
| `--deadline SECONDS` | Остановить всё сканирование, включая обход nmap, по истечении указанного времени (по умолчанию 3600, максимум 604800; переменная окружения `HOSTCENSUS_DEADLINE`). Завершённые к этому моменту хосты записываются в отчёт с `"complete": false`, история и снимок не сохраняются, а `scan` завершается с кодом 4. |
| `--config PATH` | TOML-файл с определениями сервисов и опциональными именованными настройками `[profiles]`. |
| `--profile NAME` | Использовать именованный профиль; при отсутствии `--config` по умолчанию используется `hostcensus.toml`. |
| `--exclude IP/CIDR` | Добавить исключение; можно указывать несколько раз. Исключённый IPv4-хост также исключает ведущие к нему IPv6-адреса: IPv4-mapped (`::ffff:a.b.c.d`), NAT64 (`64:ff9b::/96`) и 6to4. Цели и исключения в формате IPv4-mapped обрабатываются как соответствующие им IPv4-адреса. |
| `--max-hosts N` | Ограничение числа адресов, проверяемое до применения исключений (по умолчанию и жёсткий максимум 65 536). |
| `--history PATH` | Записать завершённое сканирование в подключаемую базу данных истории SQLite. |
| `--services NAMES` | Список имён сервисов через запятую в нужном порядке проверки (по умолчанию: все). |
| `--ports SPEC` | Список вида `NAME=PORT` (перенести сервис на другой порт) или `PORT` (добавить обычную TCP-проверку с именем `tcp-PORT`) через запятую. |
| `--snmp-community-file PATH` | Файл, содержащий строку community для SNMPv2c при запросе system MIB. Переменные окружения: `HOSTCENSUS_SNMP_COMMUNITY` (значение) или `HOSTCENSUS_SNMP_COMMUNITY_FILE` (путь). |
| `--snmp-user` | Пользователь SNMPv3. Переменная окружения: `HOSTCENSUS_SNMP_USER`. |
| `--snmp-auth-protocol`, `--snmp-auth-key-file PATH` | `MD5`, `SHA` (по умолчанию), `SHA224`, `SHA256`, `SHA384`, `SHA512` и файл с парольной фразой. Переменные окружения: `HOSTCENSUS_SNMP_AUTH_PROTOCOL`, `HOSTCENSUS_SNMP_AUTH_KEY` или `HOSTCENSUS_SNMP_AUTH_KEY_FILE`. |
| `--snmp-priv-protocol`, `--snmp-priv-key-file PATH` | `DES`, `AES` (по умолчанию), `AES128`, `AES192`, `AES192C`, `AES256`, `AES256C` и файл с парольной фразой. Переменные окружения: `HOSTCENSUS_SNMP_PRIV_PROTOCOL`, `HOSTCENSUS_SNMP_PRIV_KEY` или `HOSTCENSUS_SNMP_PRIV_KEY_FILE`. |
| `--save-snapshot PATH` | Дополнительно записать версионированный снимок для `hostcensus diff`. |
| `--tls-ca-file PATH` | Проверять HTTPS-сертификаты по этому PEM-набору вместо системного хранилища. Переменная окружения: `HOSTCENSUS_TLS_CA_FILE`. |

По умолчанию на каждом хосте проверяются SSH (TCP 22), SNMP (UDP 161), MySQL (TCP 3306), HTTP (TCP 80) и HTTPS (TCP 443). TCP-порты проверяются полным установлением соединения. SNMP проверяется запросом обнаружения движка SNMPv3 (engine-discovery), на который любой агент SNMPv3 обязан ответить без учётных данных; агенты, поддерживающие только v1/v2c, этим зондом не обнаруживаются. При использовании бэкенда asyncio хост считается доступным, если хотя бы один зонд получил ответ, включая отказ в соединении, поэтому у хоста, отбрасывающего все пакеты, устанавливается `alive=false` и ошибка "Host is down"; это не доказывает, что он физически выключен. При `--backend nmap` доступность хостов определяет nmap (ICMP при запуске от root, иначе TCP 80/443).

### Отпечатки сервисов

Для каждого открытого сервиса отпечаток снимается по данным, которые он отправляет до авторизации. Аутентификация не выполняется нигде, кроме SNMP-запроса, и только при передаче учётных данных.

| Зонд | Что читает | `version` | Ключи `details` |
| --- | --- | --- | --- |
| `ssh` | строка идентификации RFC 4253 | ПО, например `OpenSSH_10.0` | `protocol`, `software`, `comments` |
| `mysql` | начальное рукопожатие MySQL/MariaDB | версия сервера | `server_version`, `flavor`, `auth_plugin` или `error_code`/`error` |
| `http` | ответ на `HEAD /` | заголовок `Server` | `status`, `server` |
| `https` | рукопожатие TLS, сертификат, `HEAD /` | заголовок `Server` | `tls_version`, `cert_verified`, `cert_verify_error`, `cert_subject`, `cert_issuer`, `cert_sans`, `cert_not_before`, `cert_not_after` (UTC ISO 8601), `cert_self_signed`, `status`, `server` |
| `snmp` | обнаружение SNMPv3; с учётными данными - GET для sysDescr, sysObjectID, sysName | sysDescr | `engine_id`; с учётными данными `snmp_version`, `sys_descr`, `sys_object_id`, `sys_name` или `snmp_error` |

Целевое имя хоста разрешается в адрес один раз на хост, и все зонды подключаются к этому адресу, который записывается в результатах в поле `address`; само имя используется только для TLS SNI, проверки сертификата и HTTP-заголовка `Host`. Имя, которое не удаётся разрешить, даёт состояния `unknown` и ошибку `Cannot resolve`. Обратные DNS-имена сохраняются только в том случае, если они содержат допустимые символы имени хоста, при этом одновременно выполняется не более 16 запросов. Для HTTPS выполняется проверка сертификата и имени хоста по системному хранилищу или `--tls-ca-file`. Хранилище доверенных сертификатов загружается один раз на всё сканирование и переиспользуется каждым HTTPS-зондом. Время на TCP-соединение и TLS-рукопожатие ограничивается раздельно, поэтому порт, который принимает соединение, но зависает на рукопожатии, получает состояние `open` с `tls_error`, а не `filtered`. Если проверка сертификата не пройдена, в результат записываются `cert_verified: false` и `cert_verify_error`; повторные попытки с ослабленными настройками или отправка HTTP-запроса не выполняются. Сведения о сертификате и заголовки HTTP собираются только после успешной проверки. Для сервисов с частными УЦ передавайте корректный набор корневых сертификатов. Старые отчёты могут содержать поле `cert_read_unverified`, которое текущие зонды больше не формируют.

Секреты SNMP считываются только из переменных окружения или из файлов (`--snmp-*-file` или соответствующей переменной `HOSTCENSUS_SNMP_*_FILE`), но никогда из аргументов командной строки, которые видны другим локальным пользователям в списке процессов. При передаче значения через `--snmp-community`, `--snmp-auth-key` и `--snmp-priv-key` программа завершается с кодом 2 и указывает правильный параметр для замены. Файл с секретом должен быть непустым файлом в кодировке UTF-8 размером не более 4096 байт; один завершающий перевод строки игнорируется, а одновременное указание и переменной, и файла для одного секрета считается ошибкой. Сообщения об ошибках называют файл, но никогда не выводят его содержимое. Отчёты сканирования и история намеренно не включают значения учётных данных. В экспортере есть отдельный явный параметр `--include-credentials`, описанный ниже. Строка community выбирает SNMPv2c; указание пользователя выбирает SNMPv3 с аутентификацией при наличии ключа auth и с шифрованием при наличии обоих ключей (выбранный уровень фиксируется в `snmp_security_level`). hostcensus завершается с кодом 2 при попытке совместить community с пользователем v3, использовать ключ шифрования без ключа аутентификации или задать ключи без пользователя, и никогда не повторяет неудачный запрос v3 по протоколу v2c или с более низким уровнем безопасности. Агенты, поддерживающие только v1/v2c, игнорируют запрос обнаружения v3 без учётных данных, поэтому отображаются как открытые только при указании community.

Текст баннеров очищается до печатных символов и обрезается до 256 символов перед сохранением или отображением. Объём чтения также ограничен: 4 КиБ на строку, 4 КиБ для приветствия MySQL, 16 КиБ для заголовков HTTP. Идентификатор движка SNMP длиннее 32 октетов усекается перед сохранением. HTTP и HTTPS отправляют заголовок Host с IPv6-адресом в квадратных скобках и с указанием порта, если он отличается от 80 или 443. Ячейки CSV, начинающиеся с символов-триггеров формул электронных таблиц, экранируются префиксом, чтобы ячейка оставалась текстом.

### Лимиты

Один запуск принимает не более 65 536 адресов, 64 сервисов и 524 288 зондов (произведение числа хостов на число сервисов); при превышении этих пределов программа завершается с кодом 2 до отправки каких-либо пакетов. Значение `--concurrency` ограничено 4096 сокетами. Каждый зонд имеет жёсткий лимит времени, равный четырём собственным бюджетам. Зонды на базе подключения (`tcp`, `ssh`, `mysql`, `http`) используют 0.3 секунды, если для сервиса не задан `timeout`. SNMP и HTTPS используют `--timeout` (по умолчанию 1.0), если собственный таймаут не указан. Зонд, превысивший жёсткий лимит времени, получает состояние `unknown` с записью "probe timed out" в `errors`. Локальные сбои сокетов (например, нехватка файловых дескрипторов) также приводят к состоянию `unknown` с фиксацией ошибки; они никогда не считаются фильтруемым портом или недоступным хостом. Перед началом зондирования hostcensus повышает мягкий лимит открытых файлов до жёсткого лимита, чтобы вместить `--concurrency` плюс 64 дескриптора; если это невозможно, проверка preflight `open files` завершается неудачей, и `scan` выходит с кодом 1 до отправки трафика. Обнаружение через Nmap использует таймаут хоста 30 секунд. Префикс передаётся nmap в формате CIDR, и обход завершается с кодом 1, если nmap возвращает меньше адресов, чем ему было передано (например, неразрешимое имя), вместо того чтобы помечать хосты недоступными. Целевое имя хоста разрешается один раз, и nmap получает уже этот IP-адрес, поэтому этап обнаружения и зонды обращаются к одной и той же машине. Полный префикс обрабатывается одним процессом nmap с лимитом времени 35 секунд на каждые 256 адресов с округлением вверх. Обходы с исключениями выполняются пакетами по 256 хостов с лимитом 35 секунд на каждый пакет. Создание обработчиков ограничено независимо от размера диапазона. Обратный DNS и разрешение имён хостов имеют отдельный двухсекундный лимит; зависший вызов резолвера оставляется в собственном потоке и не может удерживать hostcensus сверх этих ограничений. Одновременно выполняется не более 16 запросов разрешения имён, и брошенный вызов сохраняет свой слот до возврата, поэтому число зависших потоков ограничено; если зависнут все 16, последующие запросы ждут освобождения слота вне двухсекундного лимита (отсчёт начинается после получения слота) до тех пор, пока `--deadline` не остановит сканирование. Класс `NetworkScanner`, используемый как библиотека без `deadline`, может ждать такой слот бесконечно. Параметр `--deadline` (по умолчанию один час) ограничивает общее время всего запуска поверх всех остальных лимитов.

### Настройка сервисов

Список сервисов можно изменить с помощью TOML-файла:

```toml
[services.ssh]          # same name as a built-in: replaces it
port = 2222
timeout = 0.5

[services.admin-ui]     # a new service, probed like HTTPS
port = 8443
probe = "https"
```

Поле `probe` принимает одно из значений `tcp`, `ssh`, `mysql`, `http`, `https` или `snmp` и по умолчанию совпадает с именем сервиса, если такое имя есть среди типов зондов, иначе используется `tcp`. Только `snmp` использует UDP. Имена сервисов могут содержать строчные латинские буквы, цифры, `-` и `_`. Два сервиса не могут использовать один и тот же порт и протокол; история сохраняет одно состояние для такой пары. Поле `timeout` необязательно, задаётся в секундах и должно быть не меньше 0.05. Зонды на базе подключения (`tcp`, `ssh`, `mysql`, `http`) по умолчанию используют 0.3 секунды. `snmp` и `https` используют значение `--timeout` сканирования, если для сервиса не указан собственный `timeout`. Параметр `--timeout` не переопределяет бюджет времени, уже заданный для сервиса.

Отчёты JSON представляют собой версионированные документы (`"format": "hostcensus-report"`, `"version": 1`), которые содержат цель, проверенные сервисы и настройки рядом с полем `devices`; флаг `--format json` без `-o` выводит отчёт в stdout вместо таблицы. Для каждого формата JSON-вывода опубликована схема; см. [вывод JSON](../../../docs/json-output.md). Объекты устройств сохраняют исходные поля `ip`, `alive`, `ssh`, `snmp`, `mysql`, `hostname` и `errors` и добавляют список `services` со значениями `name`, `port`, `protocol`, `state` (`open`, `closed`, `filtered` или `unknown`, если зонд завершился локальной ошибкой или превысил лимит времени), `version` и `details` для каждого зонда. Вывод CSV дополняется столбцами `services` и `versions` в конце для открытых сервисов. Булевы поля `ssh`, `snmp` и `mysql` соответствуют сервисам именно с этими именами.


## Профили инвентаризации, preflight и локальная история

Именованные профили размещаются в том же TOML-файле, что и существующие определения `[services]`. Скопируйте [hostcensus.example.toml](../../../hostcensus.example.toml) в `hostcensus.toml` и укажите администрируемые вами сети:

```toml
[profiles.office]
network = "192.168.1.0/24"
exclusions = ["192.168.1.1"]
services = "ssh,http,https,mysql"
concurrency = 32
timeout = 1.0
max_hosts = 256
backend = "asyncio"
```

```bash
hostcensus profiles --config hostcensus.toml
hostcensus preflight --profile office --config hostcensus.toml
hostcensus scan --profile office --config hostcensus.toml -o report.json
```

`preflight` разрешает параметры и профили точно так же, как `scan`, включая `--concurrency` для проверки лимита открытых файлов, поэтому успешный preflight означает, что `scan` запустится с тем же планом.

Профили поддерживают параметры `network`, `exclusions`, `services`, `ports`, `backend`, `timeout`, `concurrency` и `max_hosts`. `services` и `ports` используют стандартный синтаксис списка через запятую. Явно переданные параметры CLI переопределяют настройки профиля; повторные флаги `--exclude` добавляются к исключениям профиля. Явно указанная сеть с `--profile` должна входить в диапазон IP/CIDR этого профиля. Имена хостов по-прежнему поддерживаются для прямых сканирований, но не могут сочетаться с IP-исключениями. Лимит хостов применяется до исключений; общий лимит зондов действует и после них. Исключённые хосты пропускаются как при проверке сервисов, так и при опциональном обнаружении через Nmap.

Каждое сканирование выполняет локальные проверки preflight до отправки целевого трафика: лимиты целей и зондов, доступ к путям назначения, наличие опционального исполняемого файла или обёртки Nmap, схему истории и настроенный набор TLS CA. Команда `preflight` выводит результат в JSON, не сканирует цели и не создаёт базу данных истории. Для проверки прав записи в путь назначения она временно создаёт соседний файл, не изменяя существующее содержимое. Бэкенд asyncio по умолчанию по-прежнему не требует ни Nmap, ни прав root. Пути назначения должны отличаться друг от друга и от входного файла конфигурации, включая жёсткие ссылки; символические ссылки в путях назначения отклоняются. Проваленные проверки возвращают код 1; недопустимый охват или конфигурация возвращают 2.

Запись отчётов и скриптов экспорта требует поддержки `O_NOFOLLOW`. На платформах без неё, включая Windows, эти операции записи завершаются ошибкой без открытия или усечения целевого файла. Новые отчёты и скрипты экспорта создаются доступными только владельцу (режим 0600); перезапись существующего файла сохраняет его права доступа. Запись в именованный канал без читателя завершается ошибкой сразу, без ожидания. Новая база данных `--history` также создаётся доступной только владельцу; существующая сохраняет свой режим доступа. Сообщения журнала всегда направляются в stderr, поэтому stdout содержит только результаты. При экспорте с учётными данными всегда принудительно устанавливается режим 0600.

Ведение истории включается по желанию и дополняет существующие снимки JSON и команду `diff`:

```bash
mkdir -p output
hostcensus scan --profile office --history output/inventory.sqlite3
# Repeat later with the same targets and service selection.
hostcensus scan --profile office --history output/inventory.sqlite3
hostcensus history --history output/inventory.sqlite3 --limit 20
hostcensus compare 1 2 --history output/inventory.sqlite3
hostcensus compare 1 2 --history output/inventory.sqlite3 -o output/changes.json
```

Используйте идентификаторы из `history`; в примере предполагается новая база данных. Снимки сохраняются транзакционно вместе со временем начала и окончания в UTC, версией пакета, фактическими несекретными настройками, сводками и всеми наблюдениями по хостам и сервисам, включая ошибки отдельных хостов. Неполные наблюдения по хостам сохраняются. Прерванные запуски не записываются. Существующие контракты отчётов, снимков, экспорта и кодов возврата `scan` сохраняются.

`history` выводит сводки в JSON без чтения полных данных об устройствах за всю историю. `compare` считывает два сохранённых сканирования, требует совпадения идентификаторов целей и выбранных портов и сообщает об изменениях доступности, статуса и состояний портов. Идентификатор более раннего сканирования должен предшествовать более позднему. Если в обоих сканированиях записаны значения `timeout` или `backend` и они различаются, отчёт добавляет предупреждение, но всё равно сравнивает наблюдения. Другое время ожидания может заставить фильтруемый порт выглядеть открытым. Ошибки сканера и наблюдения с состоянием порта `unknown` помечаются как неопределённые, а не как подтверждённое исчезновение или закрытие: хосты с ошибками попадают в `uncertain_hosts`, а каждый переход состояния порта с участием `unknown` (включая `unknown` в обоих сканированиях) заносится в `unconfirmed_ports` вместо `port_changes`, за исключением порта, который стал открытым в более позднем сканировании - такой случай считается изменением порта. `compare` и `diff` классифицируют порты по одному и тому же правилу. Статус `no_longer_responding` означает отсутствие ответа, а не доказательство удаления устройства. Код возврата 0 для `scan` не гарантирует, что ответил каждый хост: проверяйте ошибки по хостам. Успешное сравнение возвращает 0 независимо от того, найдены ли изменения; файловая команда `diff` сохраняет свой контракт с кодом возврата 3. Неподдерживаемая или повреждённая история возвращает 1.

История хранит данные инвентаризации, поэтому выбирайте локальный каталог с подходящей защитой. Файлы профилей и сохранённые настройки не содержат учётных данных SNMP; передача учётных данных по-прежнему осуществляется через параметры запуска и переменные окружения.

## Сравнение снимков инвентаризации (diff)

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot monday.json
hostcensus scan 10.0.0.0/24 -q --save-snapshot tuesday.json
hostcensus diff monday.json tuesday.json             # table
hostcensus diff monday.json tuesday.json -f json     # JSON on stdout
```

Снимок представляет собой JSON с полями `format: "hostcensus-snapshot"`, `version: 1`, версией hostcensus, временем создания в UTC, целью, параметрами сканирования `timeout` и `backend` (если сканирование их записало), проверенными сервисами и доступными хостами в том же формате, что и отчёт `-o`. Недоступные хосты исключаются. `diff` также принимает обычные JSON-отчёты `scan -o`, включая сформированные до появления поля `services`.

`diff` сообщает о новых и исчезнувших хостах, открывшихся или закрывшихся портах на хостах, присутствующих в обоих снимках, и сервисах с изменившимся полем `version`. Порты, которые проверялись только в одном из двух сканирований, не сравниваются, о чём выводится предупреждение. Неудачные наблюдения никогда не трактуются как отсутствие изменений: порт со значением `unknown` в любом из сканирований и не открытый в более позднем попадает в `unconfirmed`, а не в `closed`, со значением `before`, равным `open`, `unknown` или `not-open` (проверен и закрыт либо фильтруется), и значением `after`, равным `unknown` или `not-open`; порт, открытый сейчас, попадает в `opened`, даже если более ранний зонд завершился ошибкой. Хост, у которого все зонды завершились ошибкой без ответа в любом из сканирований, попадает в `unsettled_hosts` (со значениями `before`/`after`, равными `up`, `uncertain` или `absent`, в том числе если ошибки возникли в обоих сканированиях или хост отсутствует в другом файле) вместо `vanished_hosts`; если он отвечает в более позднем сканировании, он также выводится как новый хост со своими открытыми портами. Именно для этого снимки сохраняют такие хосты с ошибками. Предупреждение также выводится при различии целей и при несовпадении записанных значений timeout или backend в обоих файлах. `-o PATH` дополнительно записывает вывод в формате JSON в файл.

Отчёт сканирования, остановленного по `--deadline` (`"complete": false`), содержит только те хосты, до которых оно успело дойти, поэтому `diff` и `export` отклоняют его с кодом возврата 2. Флаг `--allow-partial` разрешает его обработку с предупреждением в stderr: в этом случае `diff` помещает хосты, вообще отсутствующие в неполном сканировании, в `unsettled_hosts` со статусом `unscanned` вместо исчезнувших (хост, помеченный как недоступный, по-прежнему считается исчезнувшим), устанавливает `partial` в true и никогда не сообщает об отсутствии изменений, а `export` записывает предупреждение в заголовок скрипта.

Коды возврата `diff`: `0` изменений нет, `3` обнаружены изменения, неподтверждённые наблюдения или неполные входные данные (`changed` истинно, когда непуст любой список, включая `unsettled_hosts` и `unconfirmed`, либо когда `partial` равно true), `2` файл отсутствует, нечитаем, не является поддерживаемым снимком или неполный без `--allow-partial`, `1` не удалось записать файл `-o`.

## Экспорт в Kadupul

[Kadupul](https://github.com/kadupulhq/kadupul) (форк Cacti 1.2.31) не имеет пакетного импорта устройств из файла. Поддерживаемый способ добавления устройств из скрипта - это `cli/add_device.php`, по одному устройству за вызов, с аргументами вида `--option=value`. Команда `hostcensus export` формирует POSIX-совместимый скрипт `sh` из таких вызовов:

```bash
hostcensus scan 10.0.0.0/24 -q --save-snapshot inventory.json
hostcensus export inventory.json -o kadupul-import.sh --template 1
# or in one step, with template 0: hostcensus scan 10.0.0.0/24 -q -o kadupul-import.sh

# on the Kadupul server, as the user that owns the install:
export HOSTCENSUS_SNMP_COMMUNITY=...        # only if the script asks for it
KADUPUL_ROOT=/var/www/html/kadupul sh kadupul-import.sh
```

Каждый доступный хост превращается в вызов `php "$KADUPUL_ROOT/cli/add_device.php" --description=... --ip=... --template=N ...`:

- Хосты, на которых SNMP-запрос при сканировании прошёл успешно, получают `--version=2 --community=...` или `--version=3 --username=... --authproto=... --password=...` (плюс `--privproto`/`--privpass` для authPriv), `--port` и `--avail=snmp`. Для экспорта SNMPv3 требуется `--snmp-user`, а уровень noAuthNoPriv отклоняется, поскольку `add_device.php` требует пароль для v3.
- Остальные хосты получают `--version=0 --avail=ping` с параметрами `--ping_method=tcp --ping_port=` (первый открытый TCP-порт) или ICMP, если открытых TCP-портов нет.
- В `--notes` перечисляются открытые сервисы и их версии. В качестве `--description` используется обратное DNS-имя, если оно состоит из простых символов (букв, цифр, `.`, `_`, `-`), иначе IP-адрес; значение делается уникальным, поскольку `add_device.php` рассматривает существующее описание как обновление соответствующего устройства.

Каждое значение проходит валидацию и экранируется для оболочки с помощью `shlex.quote`. По умолчанию секреты SNMP в файл не записываются: скрипт подставляет `HOSTCENSUS_SNMP_COMMUNITY`, `HOSTCENSUS_SNMP_AUTH_KEY` или `HOSTCENSUS_SNMP_PRIV_KEY` во время выполнения и останавливается, если какая-либо из нужных переменных не задана. Флаг `--include-credentials` вместо этого записывает значения этих переменных окружения прямо в скрипт, создаёт файл с правами 0600 и выводит предупреждение в журнал. Сам скрипт `add_device.php` выводит community и получает секреты в аргументах командной строки, которые видны в списке процессов сервера Kadupul во время выполнения каждого вызова.

`add_device.php` завершается с кодом 1 при дубликатах и ошибках; сгенерированный скрипт продолжает работу, подсчитывает сбои и возвращает 1, если хотя бы одно устройство не было добавлено. Идентификаторы шаблонов можно получить командой `php cli/add_device.php --list-host-templates`. Коды возврата `export`: `0` скрипт записан, `2` нечитаемые входные данные, неполное сканирование без `--allow-partial` или данные, которые нельзя безопасно экспортировать, `1` не удалось записать скрипт.

## Управление версиями и процесс выпуска релизов

hostcensus следует [Семантическому версионированию](https://semver.org/spec/v2.0.0.html): обратно совместимые исправления увеличивают патч-версию, совместимые новые функции и объявления об устаревании увеличивают минорную версию, а несовместимые изменения увеличивают мажорную версию. Команды и параметры, коды возврата и схемы JSON образуют публичный контракт; устаревшее поведение продолжает работать до следующего мажорного релиза, если только исправление безопасности не потребует изменить его раньше (в таком случае причина указывается в журнале изменений).

release-please открывает релизный PR на основе заголовков Conventional Commit в ветке `main`, обновляя `pyproject.toml`, `uv.lock` и `CHANGES.md`. Его слияние создаёт тег `vMAJOR.MINOR.PATCH` и черновик релиза на GitHub, к которому CI прикрепляет протестированный wheel-пакет, исходный дистрибутив и контрольные суммы; GitHub сохраняет аттестации сборки для этих файлов через свой API аттестаций. Сопровождающий проверяет и публикует черновик после прикрепления файлов. Релизы никогда не перезаписываются.

Публикация в PyPI через доверенную публикацию (trusted publishing) подключается отдельно и требует прав владельца проекта, настроенного доверенного издателя и окружения `pypi`. Она публикует те же проверенные артефакты релиза без повторной сборки и хранения API-токена. Тегированные релизы в этом публичном репозитории формируют аттестации артефактов GitHub; в приватных форках для этого требуется поддерживаемый тариф и явное включение. Настройку, точные команды и порядок повторного запуска см. в [полном руководстве по релизам](../../../docs/releasing.md).

## Разработка

```bash
uv sync --locked                 # runtime plus the default `dev` group
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest --cov=hostcensus
uv build --no-build-isolation
uv run twine check --strict dist/*.whl dist/*.tar.gz
```

Инструменты разработки размещены в группах зависимостей [PEP 735](https://peps.python.org/pep-0735/) в `pyproject.toml` (`dev`, `fuzz`, `build`), поэтому они никогда не попадают в метаданные публикуемого пакета. `uv.lock` является единым lock-файлом; CI устанавливает зависимости командой `uv sync --locked` и завершается ошибкой, если lock-файл устарел. Интерпретатор можно выбрать с помощью `uv python`, mise (`mise exec python@3.14 -- uv sync --locked`) или любой установки Python 3.12+.

CI требует минимум 90% тестового покрытия пакета. Модульные тесты включают контролируемые loopback-серверы и автономные сценарии для профилей, истории и валидатора релизов; стенд Compose запускает OpenSSH, MariaDB, nginx и net-snmp в изолированной мостовой сети. Запустить его можно командой `make test-integration`. См. [CONTRIBUTING.md](../../../CONTRIBUTING.md) и [инструменты для релизов](../../../scripts/README.md).

Рабочий контейнер запускается с UID/GID 10001 без домашнего каталога, без оболочки входа и без pip, и имеет право записи в `/app/output`. Предоставьте этому пользователю права записи в любой примонтированный каталог вывода. Контейнеру не требуются дополнительные привилегии (capabilities), и он работает с корневой файловой системой только для чтения, поэтому его можно запускать так:

```sh
docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges \
  --tmpfs /tmp -v "$PWD/out:/app/output" IMAGE scan 192.0.2.0/28 -o /app/output/report.json
```

В этом контейнере Nmap использует свой непривилегированный режим обнаружения по TCP. CI прерывает сборку образа при наличии любой исправимой уязвимости уровня HIGH или CRITICAL по отчёту Trivy.

## Проверки цепочки поставок

[OpenSSF Scorecard](https://scorecard.dev/viewer/?uri=github.com/somethingwithproof/python-network-discovery-tool) запускается при изменениях в main и еженедельно, публикует фактическую оценку и загружает результаты в GitHub code scanning. GitHub Actions и базовые образы контейнеров зафиксированы по неизменяемым хешам; зависимости Python зафиксированы в `uv.lock`. Срабатывания Bandit завершают CI с ошибкой, а ограниченный фаззинг с помощью Atheris проверяет парсеры SSH, MySQL, HTTP, сертификатов и SNMPv3 BER без доступа к сети.

Scorecard также оценивает историческую активность ревью кода, разнообразие участников и происхождение релизов. Эти баллы отражают фактические данные и не являются заявлением о выполнении каждой проверки управления проектом или исторических релизов. См. [SECURITY.md](../../../SECURITY.md) и [происхождение релизов](../../../docs/releasing.md).
